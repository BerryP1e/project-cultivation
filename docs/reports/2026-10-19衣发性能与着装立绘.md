# 衣发性能与着装立绘

用户已认可目前衣发观感，剩余问题是换装后移动卡顿，以及元婴、化神、合体仍使用模型截图。此轮不改源模型、分区和已验收的随动参数。

## 运行计算

瓶颈为 CPU 袍面计算。把已有顺序约束迁到 OutfitGarmentJob，通过现有 Burst 编译执行；没有降低更新频率、网格精度或迭代次数。NativeArray 在换装与销毁时释放，初始化中途失败也清理已分配缓冲。主体 Transform 与 Mesh 上传仍在主线程。

缓存静止绑定位置、骨数组、同点计数、邻接计数、每帧不变的目标边长、基准三角和鞋接触方向；头发检查每次只读取一遍躯干与肩膀位置。只跳过不会被使用的固定顶点外向计算。

同机编辑器内独立推进衣发、固定 1/60 秒步长，预热后 40 次中位数；不代表全游戏帧率：

| 外观 | 优化前 ms | 优化后 ms |
| --- | ---: | ---: |
| 金丹 | 15.61 | 7.51 |
| 元婴 | 19.05 | 8.87 |
| 化神 | 18.62 | 9.21 |
| 合体 | 14.67 | 7.65 |

原托管算法与迁移后的托管内核相同输入检查，最大局部顶点误差约 3.7e-7。Burst 浮点执行不保证长期模拟逐顶点相同；强接触合成输入下会发生轨迹分歧。因此没有把“相同参数”当成画面完全相同的证明，另做真实动作与几何检查。

四套分别连续推进 540 帧，覆盖待机、行走、跑步、悬停、前飞与转身；实际 Walk、Sprint 与御风动作均进入，接缝误差为 0。三套闭襟共 36 份采样未发现原鞋与内裙三角相交。源分区、手指及鞋的保护权重检查通过，金丹源 FBX 指纹不变。实际正面、后侧与 UI 截图已检查。这些采样不保证任意姿态均无穿模，也不排除其他游戏系统导致的帧尖峰。

诊断在 `.local/diagnostics/outfit-perf-20261019/`；动作与几何画廊仍在 `.local/diagnostics/closed-outfits-20261019/review.html`。验收使用隔离存档，结束已清除隔离并核对真实存档指纹不变。

## 美术

使用内置 image_gen，以原金丹立绘作为姿态和构图母版，服饰参考三个对应模型；保持向画面左侧的头部和躯干朝向、双手在腰前交叠。保留练气、筑基、金丹原图。最初姿态各异的版本及误解成空衣袍的图标均未接入。

交付目录：`cultivation/Assets/resources/UI/InkUI/Appearance/`。

- `portrait-app_nascent.png`、`portrait-app_divinity.png`、`portrait-app_integration.png`：替换截图占位，保留原资源 GUID。
- `icon-app_nascent.png`、`icon-app_divinity.png`、`icon-app_integration.png`：方形人物图标，保留完整头部与双手；不使用空衣物图。

所有图片保留 alpha，Single Sprite、FullRect、Clamp、无 mipmap；立绘最大 2048、图标最大 512。分别接到三份外观定义及学习物品，外观页仍独立读取 portrait 资源。SectExchangeAssets 以后优先采用 icon，没有专用图标时保持 portrait 回退，不修改场景或其他物品。

完整最终提示词、生成来源与项目交付对应记录在 `.local/diagnostics/outfit-perf-20261019/selected-art.json`。外观页已逐套验证资源和物品引用，并用实际 Game View 抓图核对显示。
