# 着装方案重评：实际换装故障与成熟替代方案

状态：撤回此前“整套修复完成”的交付结论。用户已保存并授权退出运行，已自行导入Magica Cloth 2。六套生成网格的可读性故障已持久修正；成熟组件的单套性能原型已跑通，尚未替换正式求解器。用户明确认可当前合体着装飞行效果，后续必须保留这个基准；剩余重点为走路袖子及正式方案的性能。

## 本次实际故障

用户正常运行、装备合体着装时，AppearanceClothRig.约束长发表面每帧抛IndexOutOfRangeException。运行缓存发面原点长度为0，权重10332项、骨矩阵120项，长发索引最大10168。生成的金丹/元婴/化神/合体skin资产m_IsReadable为0，运行脚本读取顶点失败。此前Editor桥脚本却能读取该网格，因此“能读取/源面守恒”测试漏掉了真实游戏循环的限制。

[Unity 2022.3 Mesh.isReadable官方说明](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Mesh-isReadable.html)明确指出：非可读网格运行时不能读取数组，但在Editor的游戏及渲染循环之外允许读取。这也解释了此前桥验证与用户实际运行的差异。以后验证必须断言isReadable或使用独立烘焙缓存，并在普通MonoBehaviour循环中换装观察异常；不能只在桥脚本里直接调用应用函数。

当前会话仅通过Editor读取顶点后补齐运行缓存，未修改资产或存档；该临时恢复不解决下次换装，也不算持久修复。停止运行后的资产修正脚本已准备在.local/outfit-expansion/readability-fix.cs.txt；生成工具也必须保证需要CPU读取的网格可读，避免下次烘焙复发。

修复当前会话缓存后，对同一合体实例做开启→临时关闭→恢复三段各35帧的对照，没有改输入、相机、服装资源或存档：

| 阶段 | 帧时间中位数 | P95 |
| --- | ---: | ---: |
| 当前随动开启 | 53.18 ms | 56.11 ms |
| 临时关闭 | 6.37 ms | 14.88 ms |
| 当前随动恢复 | 54.46 ms | 56.92 ms |

实例衣料6073顶点、5852三角、42根附加骨。结果文件.local/diagnostics/outfit-live-performance.json。短时对照说明当前随动是严重耗时来源；它不是独立构建性能基准，也不能声称其余场景或全部机型都相同。第一次在每帧异常状态下测到的7～8ms是提早中断的无效性能结果，不能采用。

## 具体替换与验收路径

1. 先处理网格可读性故障，保留用户存档和原始模型；撤销“旧计数等于最终通过”的口径。
2. 单套验证正常SkinnedMeshRenderer渲染、少量骨骼承担模拟的路线，不继续扩展当前CPU逐顶点蒙皮、逐点避碰、逐三角修补与回写网格的叠加实现。
3. 腰口、肩部、袖根跟随Animator；闭襟袍面骨链横向围合，开襟不跨口连接；头发、袖尖、下摆分别配置。保持原衣型再叠加局部摆动，飞行侧身/前倾不能变成世界重力下的整片垂挂。
4. 插件不能修复错分区或错误蒙皮。先在无模拟状态确认完整手脚、袖根、袍面没有裂口；错误骨权重、源遮挡区材质由DCC处理。
5. 同机同场景记录普通换装流程、移动/停步/御风/转身/前闪的连续画面、帧时间分布和GC。初步目标为单角色附加模拟约1ms级，属于验收目标，不是当前已达到的结果。
6. 独立构建复核后才推广到其他着装；不以静态截图、无异常或固定帧数代替连续观感与性能。迁移时保证同一根衣骨只有一个求解器写入。

## 用户导入后的验证

- 已退出真实Play，未保存或覆盖场景。合体着装的飞行表现由用户确认满意，走路袖子仍未确认修复。
- 已持久修正六套生成网格的CPU可读性，并在OutfitClothBaker.Store加入生成保护。devtools/validation/outfit-readability.cs.txt六套通过；这不是几何重建，金丹源FBX及既有衣型未改。
- 隔离原型在合体着装上使用4个BoneCloth团队（围合袍面、左右袖、长发），增加虚拟链末端，使用SkinnedMeshRenderer渲染，旧CPU求解器完全停用，保证同一根骨只有一个模拟器。所有临时组件在finally清理并恢复原外观，不写正式资产。
- 同场景60帧对照两次：原方案中位数44.90/45.51ms，组件原型7.80/7.34ms；后一次P95分别48.74/11.06ms。记录.local/diagnostics/magica-prototype/performance.json。这是Editor短测，不是独立构建结果，也不说明外观已经通过。
- 原型画面出现多余描边：GameGlobalOutline缓存Renderer后，实际绘制时没有再次检查enabled/active状态，旧CPU表面停用后仍可能被CommandBuffer绘制；遮挡剪影副本也可能进入风格掩码。已修改绘制过滤，保留正常描边，并释放重收列表时遗留的临时材质，待重启后运行验证。
- 原型首次以OnBuildComplete回调次数判构建失败不正确：此版本关闭AutoBuild后，Start仍会发一次false回调。已改用Process.Result、TeamId和IsValid判断，4个团队实际均构建成功。没有修改插件代码。
- 新导入Burst在脚本重载时抛函数指针初始化异常；C#编译成功不等于原生编译器健康，正按正常退出/重启编辑器排除热加载问题，不删除Library或锁文件、不强杀进程。组件性能结果不能据此宣布完整兼容性已验收。
- 隔离结束已校验真实存档1个文件指纹未变，清除SaveSystem隔离目录覆盖；金丹源FBX哈希及源面计数未变。

## 用户明确指出分区错误后的修正

此前将两个独立的细长岛误判为袖尾、把90个袍身面改挂袖骨的判断错误，撤回该结论。用户截图明确指出这两个岛是头发：总计102个源面现全部归入Hair，不进入袖子或袍面。56个源位置的绑定改归头骨及发链，保留既有发链最低点0.339843661，避免新增低位发梢改变全部长发骨段长度。没有删除这些源面。Blender的Hair/Sleeve_L/Sleeve_R/Robe对象已按同一源面清单重建，旧分区保留隐藏供追溯。

袖子拉扯定位证据仍有效：错分时同一三角形顶点分别跟腰摆骨与袖骨，走路边长比达到7.914；但这不代表该岛应归袖子。分区正确是先决条件，不能用改变弹簧参数代替。

另已修复OcclusionOutline静态换装事件订阅及副本网格/骨架更新。运行验证合体、金丹、练气连续切换，副本绑定均与当前源渲染器一致。GameGlobalOutline禁用/隐藏Renderer过滤与材质释放验证通过。

Magica连续表面运行路径试验仍在前视出现腿部穿模及部分描边不一致，未达到整体交付要求。实验接入类已移出Assets至.local留档，正式求解器保持原方案；不能把原型5～11ms数据写成正式游戏已优化。六套普通游戏协程换装的顶点读取检查通过；重启后Burst初始化异常不再出现。

正式性能迁移、全身穿模与独立构建验收仍未完成；未发布、未push。
