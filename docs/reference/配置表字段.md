## 2. 生成链路（改一处要知道影响哪几层）

```
CSV  ──「修仙/从配置表生成资产」──▶  Generated/<类型名>/<id>.asset
                                        │
                                        │  同一个菜单里自动跟着跑：
                                        │  DialogueDatabaseBuilder.收集()
                                        │  QuestDatabaseBuilder.收集()
                                        │  回填效果引用.回填(true)   ← 填学习类物品的资产引用
                                        ▼
                              Assets/resources/任务/任务库.asset
                              Assets/resources/对话/对话库.asset
                                        │
                                        ▼
                      运行时：QuestDatabase.取() / DialogueDatabase.取()
```

**只有对话库和任务库有 Resources 副本**（因为它们是运行时按 id 频繁查表的）；其余资产在 `Generated/` 下，运行时靠 Inspector 引用或 `Resources.Load` 各自取。

### 2.1 面板目录库（`Assets/resources/面板/面板库.asset`）

**不是**由 CSV 生成的，而是**编辑器收集**出来的（菜单 `修仙/面板/收集面板目录`）：

```
Generated/ 下所有 DivineAbility/Treasure/SpiritArray/Mount/Npc
        │  修仙/面板/收集面板目录
        ▼
Assets/resources/面板/面板库.asset      ← 神通 11 / 法宝 3 / 灵阵 5 / 坐骑 9 / 真灵 233
        │
        ▼
运行时：PanelDatabase.取() → UIPanelData.从面板库灌目录()
```

**为什么需要它**：这些"目录"原来**序列化在每个场景**的 `UIPanelData` 上，于是**只有被灌过表的场景是对的** —— 实测古古镇 神通=11、宗门=0，在宗门打开神通页就是一片空白。改成运行时从一个 Resources 库读之后，**5 个场景必然一致**。

> 场景里那份序列化副本现在已经是死数据（每次进游戏都会被覆盖）。菜单 `修仙/面板/清掉场景里冗余的目录副本` 可以把它们清掉（带前置检查：面板库不存在就拒绝执行，避免清空后没人灌）。

## 3. 通用规则

- **第一行必须是表头**。导入器按列名映射到字段名（`ApplyRow` + 反射）。⚠️ 往文件开头插数据行会把表头挤下去 → 整张表读不出来（踩过）。
- **id 列**：`FindIdField(Type)` 找名为 `id` / `<类型>id` 的字段；找不到就用第 0 列。生成资产的文件名 = `Sanitize(id)`。
- **导入器只写非空值**（`if (!string.IsNullOrEmpty(val)) SetFieldValue(...)`）→ **让某字段变空时，必须先删掉对应生成资产再重导**，否则旧值残留（踩过，见 [踩坑总库](../ai/踩坑总库.md)）。
- **属性列**：`TableSpec.AttrField` / `AttrSuffixes` 指定。例如 `功法表` 的 `每级增益` + 后缀 `增益`，`被动神通表` 的 `增益`。属性列会写进 `AttributeSet` 里的对应字段（按名字匹配）。
- **小数会被截断**：`阶段`、`分段` 这类 int 字段填 `11.5` 会变成 `11`，和原行**撞号** → 只会取到一行。**要用整数重编号，不能用小数插队**（踩过）。

### 4.1 「台词 / 时间 / 观感」都在表里调 —— 对照表

**改这些东西不用动代码、不用重新编译**，改完跑一次 `修仙/从配置表生成资产` 即可。

| 我想改… | 改哪一列 | 备注 |
|---|---|---|
| 黑幕上显示什么字 | `台词` | 多行用 `|` 分隔 |
| 黑幕字打完之后停多久 | `等待秒` | 等不及可以点左键跳过 |
| 黑幕淡入快慢 | `淡入档数` | 档数 ÷ `淡步频`(12) = 秒数。**24 档 ≈ 2 秒** |
| 黑幕淡出快慢 | `淡出档数` | 同上 |
| 黑幕打字快慢 | `打字速度` | 字/秒。留空 = 18 |
| 某阶段等几秒才推进 | `等待秒` | `条件=等待秒数` 时 |
| NPC 走过来/飞过来的速度 | `动作速度` | 米/秒（代码里有 0.1 下限兜底） |
| 镜头推过去的时长/高度 | `镜头时长` / `镜头高度` | `镜头看目标` / `镜头回玩家` |
| 自动接取（测试用） | `自动接取` | 1 = 进游戏就自动接 |
| 某阶段是否需要前置任务 | `前置任务id` | |
| 任务完成发什么 | `奖励物品` | 写法 `物品id:数量|物品id:数量` |

> ⚠️ **0 与空值**：上面几个列是"0 或空 = 用代码默认"（`任务管理器.默认淡入档数` / `默认淡出档数`），因为 0 在语义上没意义；想"不淡"就填 `1`。而 `动作速度` / `镜头时长` 这类**有 `Mathf.Max` 下限兜底**的列，填 0 会被夹到下限，不会出问题。

### 4.2 加列时要一并改的地方

新加一列（像上面那三列）需要动三处：① **`QuestDefinition` 加字段**（或对应类型），字段名 = 列名；② **CSV 表头加列**，所有数据行补上占位逗号（**字段数不一致也能跑，但统一更好维护**）；③ **消费它的代码**去读这个字段（例如 `任务管理器.取淡入档数(阶段)`）。

**如果列名不打算直接映射到字段**（例如要按类型分派、或者值要转换），就在导入器里单独处理，参照 `物品效果导入`（它消费 `效果类型/效果参数id/效果说明` 三列，那三列刻意不叫 `ItemDefinition` 的字段名）。

### 4.3 任务表的两个"隐性约束"

1. **`条件=无` 会在下一帧就完成** → 一个阶段只能挂**一个**动作。要串多个演出就得拆成多行（四幕因此拆到 16 个阶段）。
2. **同一 `任务id` 下不能有两个相同 `阶段` 号** → `取阶段` 按 `(任务id, 阶段)` 取第一条，后一条永远读不到。

## 5. 重点表：对话表（`对话表.csv`，20 列）

| 列 | 字段 | 说明 |
|---|---|---|
| `id` | `id` | 段唯一 id（**任务表 `对话id` 填的就是它**） |
| `npcId` | `npcId` | 空 = 通用段（任何 NPC 都能说），`候选()` 排序时通用优先级更低 |
| `分段` | `分段` | **int**。同一个 NPC 的段靠它区分；**入口 = 最小分段** |
| `说话人` | `说话人` | 空 = NPC 自己说；写名字则比对 NPC 名字，不等就当玩家说（影响立绘缩放） |
| `文本` | `文本` | 正文 |
| `立绘` `玩家立绘` | | 资源名，走 `Resources.Load<Sprite>("立绘/…")` |
| `回答1/2/3` | | 空 = 没有回答（UI 会给一个「继续 ▸」或「结束」） |
| `跳转1/2/3` | | 0 = 关掉对话；>0 = 跳到该分段。**没有跳转链就到不了后面的段** |
| `需要标记` `排除标记` | | 分号分隔，决定这一段现在出不出现 |
| `优先` | `优先` | **同段位多条时大的赢**，平手才看别的规则 |
| `情绪` `情绪强度` | | 演出用 |
| `触发任务` | `触发任务` | 按下回答时执行（**目前表里都是空**） |
| `完成任务` | `完成任务` | 按下回答时 `完成当前阶段(<任务id>)` —— 填的是**任务id**，不是阶段id |

> ⚠️ `完成任务` 走的是 `任务管理器.处理对话绑定` → `完成当前阶段(任务id)`，它推进的是**该任务当前的阶段**，所以填任务id即可、不用写阶段号。

## 7. 加一列 / 加一张表的步骤

### 加一列到已有表
1. 在目标 `ScriptableObject` 类里加 `public` 字段（字段名 = 列名）
2. CSV 表头加同名列，各行填值
3. 跑 `修仙/从配置表生成资产`
4. 如果这一列是**派生逻辑**（不是简单赋值），在导入器里加专门处理（参照 `物品效果导入` 的做法：放在 `ApplyRow` 之后显式处理）

### 加一张新表
1. 写目标 `ScriptableObject` 类
2. 在 `DataTableImporter.Specs` 里加一行 `new TableSpec("新表", typeof(新类型), null)`
3. 建 `Assets/Data/Tables/新表.csv`
4. 若运行时需要按 id 查 → 参照 `QuestDatabaseBuilder` 写一个"收集到 Resources"的步骤，并在 `ImportAll()` 里调用
5. 跑 `修仙/从配置表生成资产`，`修仙/检查配置表是否已同步` 复查

## 8. 常用编辑器菜单

| 菜单 | 用途 |
|---|---|
| `修仙/从配置表生成资产` | **主力**：CSV → 资产（并自动收集任务库/对话库） |

| `修仙/任务/收集任务资产` | 单独重跑任务库收集 |
