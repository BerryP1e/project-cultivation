# 踩坑与注意事项

> **改代码前先扫一遍这份。** 全部是实际踩过的，每条都写了症状 → 真因 → 做法。
> 相关：[ai/工程与工具链](工程与工具链.md) · [reference/配置表字段](../reference/配置表字段.md)

---

## A. 配置表 / 导入器

### A1. 改了表但游戏里没变化
**真因**：游戏读的永远是 `Assets/Data/Generated` 下的**资产**，不是 CSV。
**做法**：改完表跑 `修仙/从配置表生成资产`。
复查用 `修仙/检查配置表是否已同步`（只读，会告诉你哪张表的 CSV 比资产新）。

### A2. 导入器**现在空值也会写**了（2026-09-27 改）
**背景**：原来 `ApplyRow` 只在非空时写字段（`if (!string.IsNullOrEmpty(val)) SetFieldValue(...)`），
于是**清空一个单元格不会撤回资产里的旧值**。

**实测症状**：`q_main_003` 第 1 阶段的 `等待秒` 早就从表里删掉了，资产里却还留着 `3` ——
表现成「进触发区后要干等 3 秒才生成野猪」，查了半天以为是逻辑问题。
（同样地，很多阶段残留着 `动作速度 3.5`、`到达半径 5`、`说话人 主角` 这些表里根本没有的值。）

**现在**：空值也写入（string→`""`、数值→`0`、bool→`false`、枚举→`0`、Vector3→`zero`），
**配置表成为真正的唯一真相源**。

> ⚠️ 策划改表时**不要留空想表达"沿用上次"** —— 没有那个语义了，留空就是清零。
> ⚠️ 只有「属性列」保持"空 = 不设该属性"（`AttributeSet` 会先 `Clear`，语义正确）。
> ⚠️ 让字段清零**不再需要**"删资产重导"，第 A3 条那个坑随之作废（但已存在的残留仍要靠重导清掉一次）。
>
> **边界（目前没有受影响的字段，但加新列时要记住）**：空值写入走的默认值对少数类型是"非零但不可用"——
> 例如 `Color` 会变成 `(0,0,0,0)`（**全透明**，表现成"看不见"）。
> 现在 `Data/` 下的 `ScriptableObject` 没有 `Color` 字段，所以没实际踩到；
> 以后要给表加 `Color` 列的话，得在 `SetFieldValue` 里单独给个合理默认值。

### A3. 曾经的坑：导入器不清空空单元格 → 删资产重导（**已被 A2 修复**）
历史做法：改了某行、让字段变空时，要先删掉生成资产再重导。
**现在不需要了**，因为空值会直接写入。保留此条只为了解释"为什么老资产里有残留值"。

### A3. 删完资产要**导两次** ⚠️
**真因**：删完立刻导，`AssetDatabase` 还没注册完删除，导入器会写出一批**空壳资产** ——
`任务id` / `阶段名` / `条件` 全空，只有 `阶段` 有值，**文件明显变小**（1518 → 1332 字节）。
**做法**：删完 → `refresh` → 跑一次导入 → **再跑一次导入**。
或者干脆用菜单重导两次，然后用 `stages:<任务id>` / 直接看资产文件复查。

### A4. CSV 表头必须在第一行
**真因**：导入器按第一行做列名映射。
**做法**：往文件开头插数据行时，**务必插在表头之后**。
（踩过：插了两行对话到开头，表头被挤到第 3 行，整张对话表读不出来。）

### A5. 小数会被截断 → 阶段/分段撞号 ⚠️
**真因**：`阶段`、`分段` 是 `int` 字段，CSV 里写 `11.5` 会变成 `11`。
**后果**：和原有 `11` 行**撞号**，`取阶段(任务id, 阶段)` 只返回其中一条，另一条永远读不到。
**做法**：想在某个阶段前插一行，**必须整数重编号**（把后面的全部 +1），不能用小数插队。

### A6. Unity 把中文写成 `\uXXXX` 转义
**真因**：`.scene` / `.asset` 里的中文字段名和字符串都是转义形式。
**做法**：**不要拿中文字面量去 grep** `.scene` / `.asset`（会假阴性）。
认物件要用**预制体来源**：`PrefabUtility.GetCorrespondingObjectFromSource(go) == 预制体资产`。
要读字段名就按 `\uXXXX` 形式搜（例如 `"\u7269\u54C1id"` 是「物品id」）。

## B. 跨场景与协程（**本项目 bug 的重灾区**）

### B1. 协程会随对象销毁而消失 —— 一切跨场景问题的根
**症状**：协程入口日志打了，**协程体内一条日志都没有**。
**真因**：`StartCoroutine` 挂在 MonoBehaviour 上；切场景销毁旧场景 → 协程直接没了。
**做法**：**任何可能跨 `LoadSceneAsync` 的长过程都不要用协程**，
改成**静态状态 + 活着的对象在 `Update` 里驱动**。

实际踩过的四个：

| 症状 | 被打断的协程 | 现在的做法 |
|---|---|---|
| 主角落点不生效（停在场景初始摆放处） | `移动玩家到` | 静态 `请求落点()` + `Update` 处理 |
| 黑幕起了不解除（一直黑） | `播黑幕` | 黑幕**自己**按「字打完 + 停留」收幕 |
| 黑幕整段被漏掉 | `播黑幕`（死在 `WaitForSeconds`） | 先落黑幕 + 开始打字，再等待 |
| 大师兄不见了 / 不飞过来 | 任务生成的 NPC 被场景销毁 | `找NPC` 找不到就**就地重建** |

### B2. 进度接力曾经是竞态
**真因**：`跨场景数据.OnDestroy` 里 `FindObjectOfType<任务管理器>()` 导出进度，
而 `LoadSceneAsync` 完成那一瞬**新旧场景短暂共存** → 可能抓到即将销毁的旧管理器，
导出残缺甚至空串。
**做法**：**切场景之前**就 `跨场景数据.钉住任务进度(导出进度())`，不依赖 OnDestroy。

### B3. `演出中` 必须是 `static`
**真因**：黑幕是 `DontDestroyOnLoad` 的（跨场景），而任务管理器随场景重建。
如果 `演出中` 是实例字段，切场景后新管理器读到 `false`，**黑幕还盖着阶段就自己推进了**。

### B4. 重复派发：三条路径碰同一阶段
**真因**：切场景那一帧，`进入阶段()`、`导入进度` 的待发动作队列、跨场景静态队列
**都会碰同一个阶段**。「生成NPC」因此跑两遍，后一个顶掉前一个 → 对话不出现。
**做法**：静态 `已执行动作`（`任务id#阶段`），在 `执行动作` **入口**登记，队列派发前先查。

> ⚠️ **别拿 `阶段开始时间` 当去重判据** —— `导入进度` 会给所有接手阶段写那个时间戳
> （「等待秒数」计时要用），于是本该补发的动作全被跳过、**主线直接卡死**。
> 两份语义必须分开。

### B5. 等待秒数会因切场景清零
**症状**：「等候大师兄禀报」等 60 秒，玩家在等待期间穿传送门 → 计时从头开始 →
看起来像"剧情卡住"。
**真因**：`导入进度` 把 `阶段开始时间` 重置成当前时间。
**做法**：切场景前记下未走完的**剩余秒**，新场景导入时把开始时间往前挪。

### B7. 「场景默认点 / 新存档出生点 / 传送落点」是三个不同的东西 ⚠️
**症状**（2026-09-28 用户报）：从宗门传送到古古镇，**没落在落点上**，落在"默认位置"。

**真因**：传送落点字段复用了 `SpawnPoint`，而 village 的 `SpawnPoint` 坐标**恰好等于**
`Player` 的场景内初始位置 —— 机制跑了、也确实摆到了 `SpawnPoint`，但它就是默认点。

三个点必须分清：

| 点 | 物体 | 什么时候生效 |
|---|---|---|
| **场景默认点** | `Player` 的初始 transform（预制体摆的） | 直接运行这个场景时的站位 |
| **新存档出生点** | `主角出生点`（小屋前，`主线开场` 用） | **创建新存档**开局时 |
| **传送落点** | 目标场景**自己那道传送门** | **每次从别的地图传送进来**时 |

`SpawnPoint` 是被 `SceneRigSyncer` 当**通用出生点**同步到 5 个场景的
（`PlayerDeathSequence` 也拿它兜底复活），它压在默认点上是"正常"的。
**错的是拿它当传送落点。**

**做法**：传送落点直接用**目标场景自己那道传送门**的点位（门脚下都是实心地面，实测站得稳）。
判断一条路线对不对：**落点名必须是目标场景里真实存在的物体名**。

> ⚠️ 这一类 bug **不报错**：`找场景物体` 返回 null 之后只是"不摆位"，
> 表现成"传送过去了但站的地方不对"，极难发现。
> 所以 `修仙/体检/场景一致性` 里加了「传送路线体检」，逐条核对落点能否解析。

### B8. "落在传送门上会来回弹" —— 已随交互方式变更而消失
第 5 轮为防"落点压在传送圈里 → 立刻再次触发 → 来回弹"，
给落点起了跟传送门**不同**的名字，并让 `找场景物体` 优先跳过带 `Teleporter` 的物体。

2026-09-28 传送改成「靠近提示按 F、按 F 才开面板」之后，
**落在门上不会自己弹面板**了，所以"落点就用传送门自己"是安全的。
`找场景物体` 那个筛选**保留**（无害的兜底），但**不再是必须的**。

### B9. 界面"开着的标记"被自愈逻辑清掉 → ESC 关不掉 ⚠️
**症状**（2026-09-28 用户报）：按 F 能唤出传送面板，但**按 ESC 关不掉**；
同时"走出传送阵也不会自动关"。

**真因**：`StationInteractor.Update` 里有一行自愈
`if (有界面打开 && 当前界面 == null) 有界面打开 = false;`（意思是"界面物件没了就把标记收回"）。
传送面板是 `Teleporter` 自己造的，开面板时**没把面板根交给 `StationInteractor`**
→ 下一帧自愈逻辑把 `有界面打开` 清成 false，
而"要不要处理关闭"的开关是 `界面已打开 => 当前界面 != null`（也是 false）
→ `if (界面已打开) { if (Input.GetKeyDown(关闭键)) 关闭界面(); }` **根本走不到**。

**实测证据**（诊断探针）：
```
① 打开后 立即    → 面板已开=True  界面已打开=True   有界面打开=True   当前界面=传送面板
   等30帧后      → 面板已开=True  界面已打开=False  有界面打开=False  当前界面=null   ✗
```

**修**：`Teleporter` 暴露 `面板根`，开面板时写进 `StationInteractor.当前界面`。

**规矩**：**任何**界面在打开时都必须把根物件写进 `当前界面`，哪怕是别人造的。
"走出范围自动关"也是同一个开关（`当前设施` + 在不在范围内）。

> 教训：**"标记"和"真值"两套状态并存时，必然有一个自愈逻辑会咬人。**
> 调试这类问题的办法就是**逐帧把两个状态打出来看第几帧开始不一致** ——
> 光看代码很难发现（这次就是靠探针在第 20 帧抓到 `有界面打开` 已经变 false）。

## C. 对话系统

### C1. 「条件=对话」的对话id 必须是**入口段**
**真因**：按 F 打开对话走的是 `最小分段(npcId)` = **第 1 段**，之后靠「跳转」往后走。
**后果**：填了一个靠后的段 → **该阶段永远达不成** → 对话无限循环。
（踩过：`q_main_003` 第 12 阶段填 `dlg_act3_dashi_7`（第 7 段），
入口是 `dlg_act3_dashi_1`（第 1 段）→ 招募对话一直重复。改成第 1 段后正常。）
**做法**：对每个 `条件=对话` 的阶段，比对「该段分段号」与「该 NPC 最小分段号」；
不等就要确认有**跳转链**能走到。链路终点是合法的（玩家点完整条链，最后一段按下时推进）。

### C2. 「对话」完成的时机是**按下回答**，不是刚显示 ⚠️ **两个地方都要改**
有**两套**任务接线，都必须在「按下回答/继续」时才生效 —— 只改一个就会留下一半的坑：

| 接线 | 数据来源 | 作用 |
|---|---|---|
| `通知对话(id)` | 任务表 `对话id` | 完成「条件=对话」的那一阶段（按 id 比对） |
| `处理对话绑定(触发任务, 完成任务)` | 对话表 `触发任务` / `完成任务` 列 | 显式接取/完成某个任务 |

**踩过两次**：
1. 第一次只把 `通知对话` 从 `显示分段` 移到 `按下回答`，**漏了 `处理对话绑定`**；
2. 于是 `完成任务` 在**这一段刚显示**时就生效了 —— 实测「按下『仙人，我准备好了』（跳到 21 段）
   → 21 段一显示就把 q_main_003 第 13 阶段做完了 → 后面按的『好』『结束』全是空跑，
   最后那下『结束』什么都没发生」。
3. 现在两件事都在 `按下回答()` 里，顺序是**先 `处理对话绑定`、再 `通知对话`**
   （前者会把阶段往前推，后者再去比对新的当前阶段，就不会误伤）。

> 「结束」按钮是 `DialogueUI` 给**没有回答的段落**自动加的（`加按钮("结束", …)`），
> 所以「仙人，我准备好了」→「好」→「结束」这三下**都是真实按键**，都能触发接线。

### C3. `逐行打` 不要自动开「打完自动收幕」⚠️
**症状**：开场那三句黑幕**不连贯**，每句之间黑幕消失一次（用户原话：
"每过一个黑幕要取消一下黑幕"）。

**真因**：`逐行打` 里设了 `落幕后自动收 = true`，而 `说()` 也走 `逐行打` ——
于是**每一句**打完（默认 `打完后的停留 = 0.5` 秒）后 `Update` 就自动收幕。
开场是**三句分开 `yield` 的 `说()`**，所以一黑一亮三次。

**做法**：`落幕后自动收` 只由 `下落并定时收起()`（"整段过场"）开启。
`说()` 只负责打字 + 落一次幕，收盘交给调用方（`主线开场` 最后自己调 `收幕()`）。
⚠️ 而且它必须在 `StartCoroutine` **之前**设：协程第一帧会调 `落下()`，而 `落下()` 会把它清成 false。

### C4. `收起()` 改成协程后会把刚落下的幕抹掉 ⚠️
**症状**：**新档开场的第一个黑幕不见了**（其他黑幕正常）。

**真因**：`Awake()` 里调 `收起()` 把幕藏起来。原来是同步的（当场 `SetActive(false)`），
改成"排一个协程几帧后淡出"之后，那次收起的后果被**推迟到之后执行**：
```
Awake()      收起()           → 排了个淡出协程
Start()      说() → 落下()     → 幕 alpha = 1（幕刚显示）
下一帧        那个协程开始跑    → 淡到 0 → SetActive(false)  ← 抹掉了
```
其他黑幕不走 `Awake`，所以只有新档开头这一条中招。

**做法**：
- 已经是隐藏状态时 `收起()` **不再排协程**，当场生效；
- **同一帧内「开始演出 → 收幕」忽略收幕**（`演出开始时刻` 判定），并打 Warning；
- `落下()` 起幕时清掉一切残留的收幕/自动收状态。

### C5. 收幕的防重入标志必须**同步**设上，否则会把淡出协程反复掐死 ⚠️
**症状**：黑幕卡住不动 —— 字已经打完显示着，**点左键、等待都没反应**，
阶段也不推进（`演出中` 永远为真）。而 Console 里阶段其实**推进过一次**。

**真因**：`立即收掉(24)` 里的防重入标志 `正在收幕 = true` 原来写在协程 `淡出幕` 的
**第一行**，而协程要到**下一帧**才跑：
```
Update 帧N: 立即收掉 → StopCoroutine(收起协程) → StartCoroutine(淡出幕)   ← 协程还没跑，标志仍 false
Update 帧N: 同一帧里再次满足收幕条件 → 立即收掉 → 又 Stop + Start        ← 把刚起步的协程掐死
下一帧:      淡出协程刚跑第一行就被上面的 StopCoroutine 杀掉 → 幕永远关不掉
```

**做法**：`正在收幕 = true` 放在 `立即收掉()` 里**同步**设，`淡出幕` 收尾时清掉；
`落下()` 起幕时也要能打断正在进行的淡出，否则两边抢 alpha。

> 教训：**改用协程实现的状态机，"进入状态"的标志要在同步调用处设，不能放在协程体内。**

### C6. 对话表里的 `完成任务` 填的是**任务id**，不是阶段id
走 `处理对话绑定` → `完成当前阶段(任务id)`，推进的是**该任务当前的阶段**。

### C7. 同段位多条候选时，**优先值必须拉开**
`候选()` 排序：优先大者胜 → 平手时 NPC 专属压过通用 → 再平手时带标记的压过无标记的
→ 最后按 id。
**后果**：任务专属回答和默认回答同优先 → 可能被默认回答顶掉（踩过）。

### C8. 出场比"该说话的时候"早的 NPC 会弹出默认对话 ⚠️
**症状**：大师兄在第 7 阶段就生成了，而它该说的招募话要到第 12 阶段才打上
`q_主线_招募中` 标记。玩家提前按 F → **弹的是无标记的默认段**，
看起来像"说错了话"。等剧情演完再按 F 就正常 —— 所以表现为"时好时坏"。

**真因**：对话选段按**标记**过滤（`候选()` 里 `对话条件.满足`）。
标记没打上时，招募段/可启程段都不满足，只剩下招募链的**中间段落**（`分段 2~7`，
本该靠跳转到达、永远不是入口）—— 于是"第一个可用段"成了默认对话。

**现在的做法**：`NpcDialogue` 每帧判定「这个 NPC 当前有没有任何满足条件的对话段」，
没有就把 `StationInteractable.现在可交互` 置 false →
**不显示「F 对话」提示、按 F 也没反应**（`StationInteractor.找最近设施()` 会跳过它）。

⚠️ **这道门槛是通用的**：任何"当前没有任何可用对话段"的 NPC 都会不可对话。
所以给 NPC 配对话时要注意留一个**无标记的兜底入口段**，否则他在标记没满足时会变哑巴。

### C9. `对话标记` 是静态内存、会跨 Play 会话残留
**做法**：编辑器里测新流程**先重启 Unity**。存档 v5 起标记会进存档（见 [design/存档系统](../design/存档系统.md)）。

## D. Unity / 编辑器

### D1. `exec_editor_script` 用的是上次编译的程序集
**做法**：改完 `.cs` 先 `refresh`（`Uni "refresh"`），否则新类型/新字段找不到。

### D2. `unity_editor refresh` 会退出 Play Mode
会丢弃运行时状态，测到一半刷新要重来。

### D3. `exec_runtime_script` 会自动进 Play Mode
跑之前**确认当前打开的场景是对的**（曾白跑两次：Play 跑在 `StartScene` 里，那里根本没有任务管理器）。

### D4. UI 构建器会重建 CharacterUI 层级
菜单 `修仙/构建角色面板 UI` 跑完会把挂在 `CharacterUI` 上的**其它组件（如 `跨场景数据`）删掉**。
**症状**：到宗门后对话不触发 + 进度不接力。
**做法**：跑完 UI 构建，**务必检查并补回 `跨场景数据`**。

### D5. 不要在协程/脚本里忙等
`while (Time.time - t0 < wait) { }` 会**冻死主线程**（`Time.time` 不前进）——
曾把 Unity 搞到闪退。**只能 `yield return new WaitForSeconds(...)`**。

### D6. 首帧新建的 UI 用内置字体 → 中文不显示
**真因**：`Resources.GetBuiltinResource<Font>("LegacyRuntime.ttf")` **不含中文**。
运行时新建的 UI 对象（`new GameObject` + `AddComponent`）Inspector 上没挂字体，
就会回落到它 → **一个字都不显示**。
**做法**：照 `DeathScreenUI` / `黑幕字幕.取字体()` 的写法，编辑器里用 `AssetDatabase`
找 `Assets/Fonts/SimHei.ttf`。
（踩过：黑幕起了、字一个都没有，排查半天以为是时序。）

### D7. 静态数据跨 Play 会话残留
`对话标记`、任务完成状态、`已执行动作`、落点状态都是 **static** → 不重启 Unity 就串局。

## F. 工具链 / 环境

### F1. 文件桥的路径曾经写死过盘符
**症状**：换台电脑后 `alive.txt` 不更新、`cmd.txt` 没人消费、桥完全不通。

此时脚本是从内存跑的，`$PSScriptRoot` **是空的** → `Join-Path` 会报空路径。
**已修**：三级回退（`$PSScriptRoot` → `$MyInvocation.MyCommand.Path` → 当前目录）。

### F3. 沙箱里的 TLS 怪问题
- 编辑器里的 **Schannel 拿不到凭证**（`SEC_E_NO_CREDENTIALS`），
  `git ls-remote` / `curl https` 都会失败。
  **绕法**：`git config --global http.sslBackend openssl`（用 git 自带的 OpenSSL）。
- 用 Node 发 HTTPS 请求可以绕过（Node 用自带 OpenSSL）。
- 装包工具（winget / choco）也因同样原因连不上源。

### F4. `sh.exe ... couldn't create signal pipe, Win32 error 5` 是噪音
push 时的这行报错**不是失败**，看有没有
`xxxx..yyyy  main -> main` 才算成功。

### F5. 编辑器的界面语言
`ChineseSimplified` 语言包**是现成的**（`Editor/Data/Localization/zh-hans.po`），不用装。
设置入口：`Edit → Preferences → Languages`。
`LocalizationDatabase.currentEditorLanguage` 只改运行时值、**不落盘**，
所以要用**界面**改一次才会持久化。

### F6. `.dsh` 的 PowerShell 脚本要存成**带 BOM 的 UTF-8** ⚠️
**症状**（2026-09-28，换到只有 PowerShell 5.1 的电脑上）：
跑 `.dsh\health.ps1` 报一堆**语法错误**：`意外的标记")"`、`不允许使用空管道元素`、
`表达式中缺少右")"`，而且报错行里的中文全是乱码（`绐楀彛` 这种）。

**真因**：脚本是**无 BOM 的 UTF-8 + 含中文**，而 **Windows PowerShell 5.1 对无 BOM 文件
按 ANSI(GBK) 解码** → 中文变乱码 → 把引号/括号吃坏 → 整个脚本解析失败。
`pwsh` 7 默认按 UTF-8 读，所以在有 pwsh 7 的电脑上从来不出问题（家里那台就是）。

**三种解法**（按推荐顺序）：
1. **给文件加 UTF-8 BOM** —— `health.ps1` / `serve-unity-mcp.ps1` 已加。
   3 个字节，pwsh 7 也认，两边都能跑。
2. 脚本**只写 ASCII**（`uni.ps1` 就是这个策略，文件头注释写明了原因）。
3. 用 `pwsh` 7 跑（但这台机器上没有，不能依赖）。

**判断某个脚本在这台机器上能不能跑**：看它「有没有 BOM」+「有没有中文」，
无 BOM 且含中文 → 在 PS 5.1 上必挂。

> 另外两个相关点：
> - `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` 才能直接 `& script.ps1`
>   （这台机器的执行策略禁止跑脚本）；不想改策略就 `[scriptblock]::Create((Get-Content $p -Raw -Encoding UTF8))`。
> - **别用 shell 拼含中文的命令**：经 harness 传过去会被损坏（本项目已知坑，
>   见 `docs/guides/对话系统使用说明.md` §5）。要写中文文件就用文件编辑工具。

## 【硬性规矩】新增字段必须想清楚"空/null 是什么语义"

> 这一条是被反复批评后立的（2026-09-27）。**不是风格问题，是正确性问题。**

### 加任何字段前，先回答三个问题

1. **它可能是 null / 空吗？**（`Resources.Load` 读不到、表里没填、旧资产没有这个字段 → 都会是 null/空）
2. **null/空 代表什么业务含义？**（"还没配置" / "不限制" / "用默认值" / "真的有 0 个"）
3. **看到 null/空 时，代码该做什么？**（用默认值 / 跳过 / **明确报错**）

**三个问题答不出来，就不要加这个字段。**

### 两条硬性要求

**① 声明时就给初值**（让"默认语义"看得见）

```csharp
public string 打标记 = "";                                   // ✓ 空 = 没有标记
public List<X> 列表 = new List<X>();                         // ✓ 空 = 一个都没有（不是 null！）
public float 打完停留 = 0f;                                  // ✓
public string 目标场景;                                      // ✗ 不给初值 → 调用方忘了就是 null
```

**集合一律 `= new List<T>()`**，绝不留 null。否则每个用它的地方都得判空，迟早漏一处。

**② 允许 null 的地方，必须"响亮地失败"**

```csharp
var 库 = PanelDatabase.取();
if (库 == null) return;              // ✗ 静默失效：面板空白，一句日志都没有，极难查
```

```csharp
if (库 == null)
{
    if (!报过) { 报过 = true; Debug.LogError("[面板库] 读不到 .../面板库.asset —— 面板会是空的。修法：菜单「修仙/面板/收集面板目录」"); }
    return;                          // ✓ 明确报错 + 说清怎么修 + 只报一次
}
```

### 已经踩过的（都是"没想清空值语义"）

| 现象 | 空值没处理的地方 |
|---|---|
| 面板页空白、毫无线索 | `PanelDatabase.取()` 返回 null 时静默 `return` |
| 12 个学习道具打包后失效 | `使用效果.神通/功法/外观` 为 null 时退到 `#if UNITY_EDITOR` 的查找，打包返回 null，**没人报错** |
| 门派便服"弄没了" | 奖励挂在**对话之后**的阶段，错位后玩家以为丢了 |
| 弟子名字变成"五个字母" | 起名界面缓冲没做长度/内容校验 |
| 回古古镇重演开场 | `演过` 是实例字段 → 每次重建都是初始值 `false` |

### 反向检查（写完一段代码后问自己）

- [ ] 我为这个新字段写了初值吗？
- [ ] 集合字段是 `new` 出来的吗（不是 null）？
- [ ] 可能为 null 的地方，是**报错**还是**静默跳过**？
- [ ] 如果静默跳过了，**排查的人能不能从日志看出发生了什么**？

### 补充：判定型条件必须保证"有基准"，且基准要**够得着**

`任务条件.NPC到位` 曾同时踩三个坑（2026-09-27，用户报"大师兄飞到我身边就没后续了"）：

1. **目标 id 只填在「动作目标npcId」上**，条件读的「目标npcId」是空的 →
   `查找在场NPC("")` 拿不到人。**修**：条件侧读不到就退回动作侧那个 id。
2. **用了只读的 `查找在场NPC`**，而任务生成的 NPC **切场景会被销毁** →
   永远等不到人。**修**：改用会重建的 `找NPC`。
3. **重建点离玩家 2 米，而判定阈值是 1.5 米** → 重建了也判不到位。
   **修**：重建距离取 `min(1.2, 到位判定距离 * 0.8)`，**必须小于阈值并留余量**。

**通用教训**：
- 判定型条件要保证「有基准」：动态落点 → 表里坐标 → 玩家位置，逐级兜底，**不能默默用 (0,0,0)**。
- 兜底路径也要**能满足判定**（重建点到判定基准的距离必须 < 阈值）。
- 兜底提示**只报一次**（写在每帧判定里会刷屏几百条 —— 我犯过）。
