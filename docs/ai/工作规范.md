> 把 `NPC表.csv` 里练功木桩的 `对主角好感度` 从 0 改回 -1，但没重新导入

## 1. 写文件：编码是头号杀手（本项目踩了 4 次）

### 1.1 所有 `.cs` 必须带 UTF-8 BOM

**症状**：`分类` 变成 `鍒嗙被`、`相机` 变成 `鐩告満`，编译报
`error CS0103: The name '鍒嗙被' does not exist`。

**原因**：某次编辑把文件写成了 GBK，或者写了无 BOM 的 UTF-8。

**规矩**：
- 用 `edit` / `write` 工具写 `.cs` **之后**，补一次 BOM：
  ```powershell
  $enc = New-Object System.Text.UTF8Encoding($true)
  [System.IO.File]::WriteAllText($路径, [System.IO.File]::ReadAllText($路径, [System.Text.Encoding]::UTF8), $enc)
  ```
- **绝对不要**用 `Set-Content` / `Out-File` 写 `.cs`（默认编码不是 UTF-8）

### 1.2 所有 `.csv` 必须带 UTF-8 BOM

**症状**：中文在 Excel / 编辑器里全变乱码（文件本身是好的）。

**原因**：中文 Windows 上，无 BOM 的 UTF-8 会被当 GBK 读。

**规矩**：
- 项目里 `Assets/Data/Tables/*.csv` **全部带 BOM**，新写的也必须带
- 写 CSV 用 `new UTF8Encoding(true)`，不是 `false`

### 1.3 PowerShell 里 `\n` 不是转义符

**症状**：往 C# 里拼代码时，`"a\nb"` 会写成一个**字面的反斜杠+n**，
结果后面的代码被 `//` 注释吞掉，编译报"某某名字不存在"。

**踩过的实例**：
```
// 坐骑不算 NPC，单独处理 —— 不写进 NPC 表\n        foreach (var 分类 in ...)
                                          ^^^^ 字面 \n，foreach 被注释吞了
```

**规矩**：
- 在 PowerShell 里拼多行，用**反引号 n**（`` `n ``），不是 `\n`
- 或者干脆**别用 PowerShell 拼多行代码**——用 `edit` / `write` 工具
- 全局替换 `\n` 会毁掉 C# 里的 `'\n'` 字符字面量，**不要全局替换**

### 1.4 写完文件自检

改完 `.cs` 后，扫一眼有没有异常字符：
```powershell
Select-String -Path $文件 -Pattern '鍒|鐩|锛|鈥'   # GBK 乱码的典型字
```

## 2. 验证：不要读 Editor.log 的尾巴（本项目被误导 5 次以上）

### 2.1 `Editor.log` 是只追加的，旧报错会一直在

**症状**：明明已经修好了，`Get-Content ... | Select-Object -Last 5 | Where error CS`
还是报同样的错，于是反复"修复"已经修好的东西。

**规矩**：判断编译是否成功，**按可靠性从高到低**：

1. **时间戳对比**（最可靠）
   ```powershell
   # dll 比源文件新 = 编译成功
   (Get-Item "...\Library\ScriptAssemblies\Assembly-CSharp.dll").LastWriteTime `
     -gt (Get-Item "...\Assets\Scripts\X.cs").LastWriteTime
   ```
2. **日志增量**（次可靠）—— 刷新前记行数，刷新后只看新增部分：
   ```powershell
   $前 = (Get-Content $log).Count
   # ... refresh ...
   $新 = (Get-Content $log)[$前..((Get-Content $log).Count-1)]
   $新 | Where-Object { $_ -match 'error CS' }
   ```
3. **试跑一个菜单** —— 能跑通说明 Editor 程序集是好的（但**不能证明**运行时程序集好了）

**绝对不要**只看日志最后几行就下结论。

### 2.2 改名/移动脚本后的报错是正常的

**症状**：把 `A.cs` 改名成 `B.cs` 之后，日志立刻出现
`error CS2001: Source file 'A.cs' could not be found`。

**原因**：文件系统改名和 Unity 重新编译之间有窗口期，Unity 会报一次旧的路径。

**规矩**：**改名后忽略这一条**，等下一轮编译自然消失。别去"修"它。

## 3. 有副作用的操作：验证之前先想清楚（本项目出过一次数据事故）

### 3.1 出过的事故

为了"验证菜单是否已经摘掉"，跑了一次那个菜单。
**明明知道它会整表覆盖 CSV**，结果：

- `NPC表.csv` 里 20 处好感度被改回旧值

**正确做法**：查编译产物时间戳就知道菜单摘没摘掉，**根本不需要真跑**。

### 3.2 规矩

**跑任何会写数据的命令之前，先问三句**：

1. 这个操作会改什么？（改 CSV？改 prefab？改场景？删文件？）
2. 有没有**只读**的办法达到同样目的？（查时间戳、读配置、看 dump）
3. 如果一定要跑，**备份了吗**？

**生成器类工具一次跑完就该摘掉菜单**，别留着——留着就是雷。
（`NpcTableBuilder` 已经因此被删除，`NPC表.csv` 现在手工维护）

## 4. 别从元数据推断"有问题"（本项目错了 3 次）

| 我的判断 | 实际 |
|---|---|
| 战骑贴图是 DXT1 无 Alpha，肯定显示异常 | 实机显示**正常**，那个模型不需要 Alpha 镂空 |
| 93 个材质"配不到贴图" | 修完 shader 后 **353 个材质都有贴图**，只有 91 个是框架垃圾材质 |
| 母鸡碰撞体"高 0.07 太小了" | **是对的**——prefab 根缩放是 12，本地 0.06 × 12 = 世界 0.7 |

**规矩**：
- 看到数值/格式"不合理"，**先查单位和空间**，不要急着"修正"
- 判断"显示是否正常"，**看实际渲染结果**，不要从文件格式推
- 加"防呆 clamp"之前想清楚：原始值是不是其实对的？

## 5. 本项目特有的坑

### 5.1 特殊目录

| 目录 | 说明 |
|---|---|
| `Assets/resources/` | **小写也是 Unity 的 Resources 目录**（大小写不敏感）。`Resources.LoadAll<GameObject>("NPC")` 能一次拿到全部 NPC prefab |

### 5.2 prefab 的根缩放不一定是 1

母鸡是 **12**。所有"用世界坐标算本地尺寸"的地方都要除以 `lossyScale`。
（`Renderer.bounds` 是世界空间，`Collider` 的尺寸是本地空间）

### 5.3 `Renderer.bounds` 在实例化的那一帧是无效的

全是 0。所以"摆物件 → 贴地对齐"必须**分两步**（先 Build 再 Align）。

### 5.4 让物件可被左键选中 / 右键锁定，需要三样

1. **碰撞体**（`CapsuleCollider` 最稳，`CharacterController` 不可靠）
2. **`NpcInstance`**（`RaycastNpc()` 用 `GetComponentInParent<NpcInstance>()`）
3. **`NpcIndicator`**（画光环 + 血条 —— **没有它，选中了也看不出来**，表现为"选不中"）

#### 5.5.1 【坑】为什么中间必须有 `unity-mcp-proxy.mjs`

**症状**：DSH 日志里反复出现
```
[mcp-client] mcp-client(unity): connection attempt failed:
  path: ["tools", 0, "inputSchema", "type"]
  message: Invalid input: expected "object"
```
然后重试 10 次放弃，**17 个 Unity 工具一个都看不到**。

**原因**：`dsh-mcp-client` 遵循「**要么完整世代，要么没有**」——工具列表是全有或全无的。
而 harness 只支持一个很窄的 JSON Schema 子集：

```
CONSTRAINT_KEYWORDS = type, oneOf, properties, required,
                      additionalProperties, items, enum, const
ANNOTATION_KEYWORDS = description, title, default, examples
```

**其余 key 一律违规**（包括 `$schema`、`$ref`、`anyOf`），而且**递归**检查，不只是根。
另外：根必须 `type:"object"`、`required` 的名字必须在 `properties` 里、
`additionalProperties` 必须是布尔、`type` 只能是单个字符串、`enum`/`const` 只能用于标量。

codely 的原始输出实测 **0/17 通过**：

| 问题 | 涉及工具 |
|---|---|
| 带 `$schema` | **全部 17 个** |
| 根是 `anyOf` 而非 `type:"object"` | `unity_editor` |
| **嵌套** `anyOf` | `unity_gameobject` 的 `properties.propertyValue` |
| `additionalProperties` 是 schema 不是布尔 | 7 个 |

**规矩**：codely.exe 是闭源二进制，所以不要试图"修"它。
`.dsh\unity-mcp-proxy.mjs` 只改 `tools/list` 响应的 `inputSchema`，递归消毒到子集内，
其余消息透明转发。它**只放宽不收紧**（非布尔 `additionalProperties` → `true`），
认不出来的形状退化成 `{}`（合法），保证不会因为翻译失败而让工具消失。

**验证改了没改对——不要靠重启试**（重启一次成本很高）：

```powershell
node .dsh\unity-mcp-proxy.mjs --transform raw-toolslist.json fixed.json
node .dsh\_diag\validate.mjs fixed.json      # 期望 17/17 通过
```

`validate.mjs` 用的是 **harness 自己的校验器**（运行时从 `app.asar` 现取，所以
DSH 升级后约束变了会立刻暴露）。详见 `.dsh\_diag\README.md`。
`fidelity.js` 用来确认不是靠"掏空 schema"换来的通过。

#### 5.5.2 兜底通道

**文件桥**（`DshBridge.cs` + `.dsh/cmd.txt` / `result.txt`），MCP 没起来时用：


### 5.6 中文标识符**可以**出现在 `exec_editor_script` 里（2026-09-21 起）

**这条老坑已经失效了。** 旧记录说会被损坏成 `?`，那是挂掉的 HTTP 桥的编码问题。

2026-09-21 换了垫片管线（`unity-mcp-proxy.mjs` → codely → TCP 桥）之后实测：

```csharp

var spec = AttackSpec.特殊主动神通;      // 中文枚举成员也能直接访问
return 中文变量 + spec.走会心判定;
// → 中文变量=中文标识符存活 | spec=特殊主动神通 | 走会心判定=True
```

所以**不必**再把中文逻辑绕进 `.cs` 文件、用 ASCII 菜单项调用了。

> 【更正】`.cs` **不带 BOM 也能编译**（实测：全项目的 `.cs` 都是无 BOM 的 UTF-8，
> 编译 0 错误、中文日志正常）。**必须带 BOM 的只有 `.csv`** ——
> `NPC表.csv` 等配置表一旦丢了 BOM，导入器读到的中文列名/名字就会乱码。

### 5.7 ★ `Resources.Load` 会挑到「和 prefab 同名的模型文件」

`Assets/resources` 里**同一个目录下同时有 `X.FBX` 和 `X.prefab`** 时：

```csharp
Resources.Load<GameObject>("NPC/Demon/YeZhu/YeZhu")      // → YeZhu.FBX  ✗（不是预制体！）
Resources.Load<GameObject>("NPC/Demon/YeZhu/YeZhu.prefab") // → null      （带扩展名没用）
Resources.LoadAll<GameObject>("NPC/Demon/YeZhu/YeZhu")   // → 两个都给你 ✓
```

拿到 FBX 的后果**极隐蔽、完全不报错**：FBX 根节点上**没有 `NpcInstance`**、
**没有 AnimatorController** → 这个 NPC 的 `移动速度` 读出 0、`有动作("Attack1")` 永远是 false
→ **走不动、也放不出招**（战阵真灵那次就是「站在那儿发呆」）。

本工程实测 **240 个真灵定义里有 17 个**是这种摆法。

**规矩：按路径实例化 NPC 一律走 `NpcPrefabs.加载(路径)`**
（它用 `LoadAll` + 「挑带 `NpcInstance` 的那个」判定，240/240 全对），
**不要**再直接 `Resources.Load<GameObject>(路径)`。

### 5.8 开局弹「Tuanjie Editor Mixusage Warning」——是提示，不是故障（2026-09-23 排查完毕）

### 5.9 ★ 给一个模型换贴图，结果**全工程同类模型全变了**（2026-09-23）

**现象**：在场景里选中一个模型，把它材质的贴图换掉 → 所有用到那类模型的地方一起变了。

**根因：环境模型的材质不是"场景引用"的，是 FBX 导入器"按名字全工程搜"出来的。**

看 `environment_stone_dabingshi_001_a.FBX.meta`：

```
materials:
    materialName: 0      # 按名字找材质
    materialSearch: 1    # 搜索范围：全工程
    materialLocation: 0  # 外部材质（External Materials）
```

也就是说 `.mat` 是**一份全工程共用的资产**，谁都不"拥有"它。两个证据：

1. **按 guid 搜场景，一个都搜不到** —— `environment_stone_dabingshi_001_01.mat` 的 guid
   只出现在它自己的 `.meta` 里，`3C_Testbed.scene` / `Sect.scene` 里都没有。
   （所以"改这个材质会影响谁"**看文件是看不出来的**，只能在编辑器里遍历 `Renderer`。）
2. **FBX 里的子网格名 = 材质名**。`..._a.FBX` 的 `internalIDToNameTable` 里子网格叫
   `environment_stone_dabingshi_001_01` / `_02`，材质文件正好叫这两个名字。
   于是 `dabingshi_001_a / _b / _c / _d / _e …` 的**同名子网格全部解析到同一份材质**。

**实测影响面**（数 `Renderer.sharedMaterials`）：

| 场景 | 用到这两个材质的渲染体 |
|---|---|
| `Sect.scene` | **14 个**（`dabingshi_001_a/b/…` 各 2 个槽） |
| `3C_Testbed.scene` | 2 个（`better ground` 的两个 MeshRenderer） |

所以改一次 `.mat` = 改这 16 个地方，**跟"预制体实例"没关系**。

#### 只想换一个怎么办

**核心：让那一个实例"不共用"——给它一份自己的材质。**

1. Project 里选中原材质 → **`Ctrl+D` 复制** → **改成不重名的名字**
   （如 `environment_stone_dabingshi_001_01_雪地.mat`）。
   ⚠️ **必须改名**：材质是"按名字被搜出来"的，同名副本可能被别的模型捡走。
2. 在**复制出来的那份**上换贴图 / 改参数。
3. 回场景，选中**那一个**实例 → 展开它的 `MeshRenderer` → 把
   `Materials → Element N` 拖成新材质。字段左边出现**蓝线** = prefab override（只属于这一个）。
4. `Ctrl+S` 保存场景。

> ⚠️ **三个别做**
> · **别改原材质**（那是共享资产，正是这次"全变"的原因）。
> · **别点 Inspector 的 `Apply`**（会把 override 写回源，又变全工程）。
> · **复制时别保持同名**。

> 反过来的需求（"整类都换、只有某一个保持旧的"）：改原材质，然后在那**一个**实例的槽位上覆盖回旧材质。

> 想让某个模型**以后有独立身份**（贴图/材质能单独配）：右键 → `Create` → **Prefab Variant**，
> 在变体里换材质。和 §22 里 NPC 变体的管法一致。

## 6. 改名规范

### 6.1 NPC 的 AI 脚本用**表里的完整 id**

```
母鸡      id = beast_muji            → NpcBrain_beast_muji.cs
野猪      id = demon_yezhu           → NpcBrain_demon_yezhu.cs
（铁匠 id = npc_tiejiang → NpcBrain_npc_tiejiang.cs：**该 NPC 已于 2026-09-26 删除**）
```

连前缀一起用，这样脚本名、`NpcDefinition` 资产名、表里的 id **三者完全一致**。

**不要**用英文意译（`Hen` / `Boar`）——项目里的目录、动画、控制器用的都是拼音。

### 6.2 改名要用 `AssetDatabase.MoveAsset` 或者连 `.meta` 一起移

只移 `.cs` 不移 `.meta` 会让 GUID 变化，**prefab 上的组件引用会断**。

用文件系统移的话：
```powershell
Move-Item $新路径 $旧路径
Move-Item ($旧路径 + ".meta") ($新路径 + ".meta")
```
