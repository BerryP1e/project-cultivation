### MCP 工具的三个坑
1. **`exec_editor_script` 跑的是「上次编译好的程序集」** → 改完 `.cs` 必须先用 `unity_editor refresh` 编译，否则新类型/新字段找不到。

## 4. 关键机制（改代码前必读）

1. **「对话」条件是在玩家按下那一段的「回答 / 继续」时才算完成的**（`通知对话` 由 `DialogueUI.按下回答` 调用，不再放在 `显示分段` 里）。
   → 旧语义是「这一段刚显示就算完成」，那是**错的**：玩家还没回复，任务就推进了。
     四幕实测症状：按下「仙人，我准备好了」、21 段文字刚显示，黑幕当场就起了，而「好」还没按。
   → 因此 `对话id` 要填**玩家会按下回复的那一段**。多段对话做阶段边界时，
     它仍然应该是你希望玩家说完回复的那一段；同时那个对话行**不要**再挂 `完成任务`，否则双重推进。
2. **任务阶段是「一行 = 一个阶段」，按 `阶段` 升序推进**；`条件=无` 会在成为当前阶段的下一帧就完成 → 一个阶段只能有一个动作。
3. **阻塞式演出用 `任务管理器.演出中` 挡住阶段推进**：黑幕、强制对话期间 `Update` 直接 return，否则「条件=无」的演出阶段会立刻完成、把后续阶段（切场景/攻击）提前触发。
4. **切场景后接手的阶段，动作由静态队列补发**（`任务管理器.跨场景待发动作`）。不要在 `导入进度` 里直接 `StartCoroutine` —— 那是在新场景 Awake 期间，场景尚未激活完，可能失败并打断整个 Awake。
5. **`播出黑幕` 会先等对话框关闭**（最多 20s）再按 `等待秒` 停顿，然后才打字。
6. **对话标记是静态内存数据、不存档**；任务完成状态也是**静态**，会跨 Play 会话残留（见坑 6.3）。

## 6. 已踩过的坑（照做能省几小时）

1. **导入器不清空空单元格**：`DataTableImporter` 只写非空值（`if (!string.IsNullOrEmpty(val)) SetFieldValue(...)`）。
   → **改了某行、让某个字段变空时，必须先删除对应生成资产再重导**，否则旧值残留。
   实例：四幕重写时 `q_main_004_6` 残留了「奖励物品：门派便服」，会在第 6 阶段就提前发衣服。
   ```csharp
   // 删掉某前缀的生成资产
   foreach (var g in AssetDatabase.FindAssets("", new[]{"Assets/Data/Generated/QuestDefinition"})) { ... AssetDatabase.DeleteAsset(p); }
   ```
2. **Unity 把中文写成 `\uXXXX` 转义**：不能拿中文字面量去 grep `.scene` / `.asset` 文件（会假阴性）。要按**预制体来源**认物件：`PrefabUtility.GetCorrespondingObjectFromSource(go) == 预制体资产`。
3. **静态数据跨 Play 会话残留**（`对话标记`、任务完成状态）：编辑器里不重载域时，上一局的进度会留到下一局 → **测新流程前重启 Unity**。
4. **UI 构建器会重建 CharacterUI 层级**：菜单 `修仙/构建角色面板 UI` 跑完会把挂在 CharacterUI 上的**其它组件（如 `跨场景数据`）删掉**。
   → 跑完 UI 构建，**务必检查并补回 `跨场景数据`**（本会话因此丢过一次，症状是"到宗门后对话不触发 + 进度不接力"）。
5. **不要在协程/脚本里忙等**：`while (Time.time - t0 < wait) { }` 会冻死主线程（`Time.time` 不前进）→ 我因此把 Unity 搞到闪退。**只能 `yield return new WaitForSeconds(...)`**。
6. **`exec_editor_script` 用的是上次编译的程序集** → 改 `.cs` 后先 `refresh`。
7. **Play 之前确认当前打开的场景**：`exec_runtime_script` 只在当前场景里跑；我因此在 `StartScene` 里白跑过两次。
8. **`Village.scene` 与 `village.scene` 是同一个文件**（Windows 大小写不敏感；Unity 会报 meta 大小写不一致并改名）。Build Settings 里两条指向同一文件，无害。
9. **给 NPC 挂 Humanoid Avatar 要小心 bind pose**：不同 Tripo 模型骨骼路径相同、静止姿势可能完全不同 → 借别人的 Avatar 会翻。**要用它自己的**。
10. **诊断脚本里的 `Func` 最多 16 个参数**（29 个参数会编译失败）→ 用局部函数。
11. **`FindObjectOfType` 只找激活对象** → 查未激活的面板页用 `FindObjectsOfTypeAll` / `FindObjectsOfType(T, true)`。
12. **`Component.enabled` 不存在**（那是 `Behaviour.enabled`）→ 反射/泛型里要先 `as Behaviour`。

## 8. 本次（2026-09-27 工作电脑）修复记录

在**工作电脑**（仓库根 `E:\game project`，Windows）上排查四幕时修掉的问题，都已实测或日志验证：

### 8.1 四幕玩家落点不生效（原 P1，已修）
- **真因**：`切换场景` 是在**旧场景**的 `任务管理器` 上跑的协程；`LoadSceneAsync` 完成时旧场景卸载，
  **挂在该实例上的协程随之被销毁** —— 实测「协程入口日志有、协程体内日志一条都没有」。
- **修法**：落点不再走协程，改成**静态状态** `请求落点()` + `Update` 每帧 `处理落点()`。
  只放置一次，偏离超过 `落点容差`(1 米) 才纠正，**1.2 秒后无条件放权**（早期版本每帧硬按 + 反复开关
  `CharacterController`，把玩家锁死在落点上，已改掉）。

### 8.2 重复派发导致大师兄被生成两遍 → 对话不出现（已修）
- **真因**：切场景那一帧有三条路径碰同一阶段（跨场景队列 / `导入进度` 的待发动作 / `进入阶段` 自己），
  「生成NPC」跑两遍，后一个大师兄顶掉前一个。
- **修法**：独立记录 `已执行动作`（`任务id#阶段`），由 `执行动作` 入口登记，队列按它跳过重复。
  ⚠ 早期我曾拿 `阶段开始时间` 当判据，那是**错的** —— `导入进度` 会给所有接手阶段写这个时间戳
  （「等待秒数」计时要用），结果本该补发的动作全被跳过、主线直接卡死。两者语义必须分开。

### 8.3 跨场景进度接力是竞态（已修）
- **真因**：`跨场景数据.OnDestroy` 里用 `FindObjectOfType<任务管理器>()` 导出进度，而
  `LoadSceneAsync` 完成那一瞬**新旧场景短暂共存**，可能抓到即将销毁的旧管理器 → 导出残缺甚至空串。
- **修法**：新增 `跨场景数据.钉住任务进度()`，在**切场景之前**就把进度钉进快照，不再依赖 OnDestroy。

### 8.4 等待秒数跨场景清零（已修）
- **现象**：四幕第 10 阶段「等候大师兄禀报」等 60 秒，玩家在等待期间穿传送门 → 计时清零重来，
  看起来像「剧情卡住」。
- **修法**：`准备切场景()` 记下未走完的**剩余秒**，`导入进度` 时把 `阶段开始时间` 往前挪，按剩余量续上。

### 8.5 黑幕「从此，一个平凡的少年踏上了修仙路」被漏掉（已修）
- **真因**：`播黑幕` 里顺序是反的 —— 先 `WaitForSeconds(等待秒)` **然后**才上锁、打日志、开始打字。
  驱动它的场景一被切走，协程就死在"等"这一步，黑幕一次都没出现（日志里连「调度：黑幕白字」都没有）。
- **修法**：改成**先落黑幕 + 开始打字**，打字与「等待秒」并行；另给 `切到场景` 加兜底 ——
  若黑幕锁仍被协程持着（`黑幕字幕.幕被协程持锁`）就先自己收幕，避免白屏切走。

### 8.6 「对话」条件语义修正（已修，重要）
- 见第 4 节第 1 条：改成**按下回答/继续**才完成，不再是「刚显示」。

### 8.7 大师兄被切场景销毁 → 「飞到」静默失败（已修）
- **真因**：`生成NPC` 造的是场景内对象；玩家在 60 秒等待里切场景，大师兄随旧场景销毁，
  之后第 11/13 阶段的「飞到」因 `找NPC` 返回 null 而静默跳过（阶段照样推进 → 对话弹了但人没来）。
- **修法**：`生成NPC` 记住 `npcId → 预制体路径`；`找NPC` 找不到时**就地重建**（生成在玩家前方 2 米）。
  另新增 `任务动作.确保NPC`（可用，表里暂未引用）。

### 8.8 黑幕没有字（已修）
- **真因**：`黑幕字幕.建字` 用 `字体 != null ? 字体 : LegacyRuntime.ttf`，而**运行时新建**的黑幕对象

  使「纯黑幕遮罩」可用。

### 8.9 黑幕改到宗门侧（已修，用户指定流程）

### 8.10 小数据坑（重要，避免重复踩）
- **导入器会把小数阶段号截断成整数**：`11.5` → `11`、`14.5` → `14`，于是和原阶段**撞号**。
  想在某阶段前插一行，必须**整数重编号**，不能用小数。
- **改了表必须删掉旧生成资产再重导**（坑 6.1），而且删除之后要**导两次**：
  删完立刻导，`AssetDatabase` 还没注册完，导入器会写出一批**空壳资产**
  （`任务id`/`阶段名`/`条件` 全空，只有 `阶段` 有值，文件明显变小）。第二次导才正常。
- **CSV 表头必须在第一行**。往文件开头插入数据行会把表头挤到第 3 行，整个表读不出来。

### 8.11 对话入口段 vs 任务要的段（已修，本会话最后一个 bug 的根因）
- **机制**：对话入口是 `DialogueDatabase.最小分段(npcId)` —— 也就是**第 1 段**。
  按 F 只会从第 1 段开始，之后靠每段自己的「跳转」往后走。
- **所以**：任务阶段 `条件=对话` 的 `对话id` 必须是**入口段**，或者是入口链路能到达的段
  （玩家点完那条链，最后一段显示/按下时就会推进）。
- **踩到的 bug**：`q_main_003` 第 12 阶段写 `对话id=dlg_act3_dashi_7`，但
  `dlg_act3_dashi_7` 是**第 7 段**，入口是 `dlg_act3_dashi_1`（第 1 段）。
  结果 **第 12 阶段永远达不成 → 招募对话无限循环**（玩家每次按 F 都只看到第 1 段
  「仙人救我狗命，请受我一拜」）。已把任务条件改成 `dlg_act3_dashi_1`。
- **怎么自查**（照这个查，别再猜）：
  ```powershell
  # 对每个 条件=对话 的阶段：该段的分段号 是否等于 该 npc 的最小分段号？
  # 不等也不一定错（可能是链路终点），但要确认有跳转链能走到
  ```
  本会话审出 2 处疑似：`q_main_003_13`（`dlg_act3_dashi_21`，链 `ready→21` 可达 ✔）、
  `q_main_002_1`（`dlg_act2_xiaomei_3`，链 `xiaomei_1→11→12` 可达 ✔）。只有上面那处是真错。
- **对话选段规则**（`DialogueDatabase.候选` 的排序）：优先大者胜 → 平手时 NPC 专属压过通用 →
  再平手时「带需要标记的」压过无条件的 → 最后按 id 稳定排序。
  ⚠ 所以同段位多条时，**优先值必须拉开**，否则你写的任务回答会被默认回答顶掉。

### 8.12 工作电脑上的工具链（环境差异）
