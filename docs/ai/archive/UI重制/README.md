## 2. 建议的视觉系统

建议以 **宣纸墨卷**作默认界面，**黛青玉简**用于暗色主题备选，**朱砂秘箓**作为符箓／危险操作的美术备选。三个是同一功能系统的不同外观，玩家不必因皮肤变化重新学习操作。

| 模板 | 主要材料与颜色 | 优势 | 使用取舍 |
|---|---|---|---|
| 宣纸墨卷 | 暖宣纸、墨绿、少量朱砂；纸边和淡墨纹 | 与水墨场景自然衔接，阅读轻松 | 纸纹限于低对比背景；文本区不落浓墨 |
| 黛青玉简 | 黛青墨底、旧玉色、细哑金线 | 夜景、塔内有较好分层 | 避免满屏荧光；正文用暖灰白 |
| 朱砂秘箓 | 深墨、旧符纸、朱砂与暗铜 | 符箓、破境有仪式感 | 朱砂保留给动作与警示，不能所有按钮都红 |

基础色：纸 `#EEE9DC`、纸亮部 `#F6F1E6`、正文 `#303D37`、辅助字 `#7B8071`、玉绿 `#526F5C`、朱砂 `#9E4E3D`、哑金 `#9C8355`。标题用楷／宋，正文用清晰现代中文黑体；开发阶段可使用系统字体，发布前确认字体授权与中文字符集。

以 1920×1080 为 Unity 参考画布。菜单安全区建议左右约 6–8%、上下约 10%；内容以 8px 间距倍数排版，正文建议 18–22px，辅助信息不小于 16px，图标交互区域不小于 48×48px。详情区固定位置，切换条目不跳动。矩形保留用于背包网格、属性列表与九宫棋盘；异形重点落在玉符槽、纸边、地块信息卡和印章按钮。

不要把水墨后处理直接作用于正文。游戏世界处理在相机栈中，uGUI 的 ScreenSpaceOverlay 保持清楚；RenderTexture 预览单独控制材质、背景与光照。正文背后的纸层应稳定，不能透出过强的树林纹理。

## 4. 立体感与操作规则

“3D 感”主要来自 **2.5D 界面层次**，不要求把所有 UI 转成世界空间模型。

| 状态 | 视觉反馈 | 建议时间 |
|---|---|---|
| 悬停玉简 | 抬高 3–5px，俯仰约 4–6°，投影略远，纸面内符纹保持清晰 | 100–140ms |
| 按下 | 回压 1–2px，避免整屏震动 | 60–90ms |
| 拾起拖动 | 超过约 7px 才开始；抬高 12–18px，轻倾斜，图标与背景分层 | 100–140ms |
| 拖过空槽 | 玉符轮廓显线，预览目标名；槽位最大放大约 1.08 倍 | 80–120ms |
| 拖过占用槽 | 显示替换后的新旧内容，不立即修改数据 | 持续状态 |
| 放入 | 玉符收敛到槽位，短墨晕；成功后数据才提交 | 160–220ms |
| 拒绝／取消 | 物品回原处，显示具体原因，不扣库存 | 140–200ms |
| 面板开关 | 轻卷舒展开，不用长时间卷轴动画阻塞输入 | 180–240ms |

取消拖动的优先级：ESC 先取消拖动，再取消待装备／摆放态，再关闭最上层界面；同一次 ESC 不穿透到暂停菜单。拖拽物体不接收射线，目标命中按自身类型和轮廓判断。点选→选择空位提供拖拽替代。减少动效时保留目标轮廓和结果提示，关闭倾斜与持续旋转。

**当前已有与交互提案必须区分：**当前点击待装备只能落到空位；当前 `EquipToSlot` 拖入占用位会直接覆盖。原型保留点击空位规则，并给拖入占用位增加替换确认。装备槽之间交换、战阵换位、材料拖拽与动作减弱是设计提案，接入时需增加接口与校验。不把新增交互包装成当前已实现功能。

六槽顺序顺时针 1–6，并始终显示编号；HUD 使用同一槽位序列，不因环形布局更改快捷键映射。被动神通另列，可启停并显示有效状态；御风与坐骑互斥逻辑继续由 `UIPanelData` 的单一入口维护。

丹房的丹炉蒸汽／墨晕只是等待与结果反馈，不新增控火、节拍、温度或手动选择品数的玩法。点击格子选择目标，同一材料重复放入数量 +1；切换材料替换为 ×1。主材与四辅材是现有界面上限，配方匹配按材料 id 总数进行。

灵田挪动必须回到世界预览：半透明地块跟随鼠标，R 以 45° 档旋转，左键确认，右键／ESC 取消。合法位置以墨绿轮廓示意，非法位置朱砂叉加具体原因。实际合法性继续走当前摆放校验；不能只看是否绿色，也不能绕开跨种类占用。

## 5. Unity 接入方法

建议沿用 **uGUI + 现有数据层**。不为视觉换皮重写战斗、存档、炼丹或灵田逻辑，不另起一套玩法状态。

| 对应脚本 | 接入内容 |
|---|---|
| `UIBuildUtils`／`CharacterPanelBuilder` | 新主题配置集中字体、色值、纸边与分隔线；先构建独立审阅 Prefab，再替换最终面板 |
| `UIActiveSkillSlot`／`UIActiveSkillBar` | 自定义玉符图形、透明 alpha 命中；固定 0–5 索引，拖拽视觉由独立组件管理 |
| `UIEntryList`／`UIEntryInfo` | 列表与网格共用条目、筛选和选中状态；大库虚拟化／对象池，详情保持固定 |
| `UIPanelData` | 所有装备、启停、清空、互斥仍由已有数据入口维护；新增交换需在这里原子处理并广播 Changed |
| `PlayerHud`／`HudHoverTarget` | 保留悬停固定幕布、冷却精度与竖向填充。异形底板有 sprite，不能使用无 sprite 的 Image 期待 fill 生效 |
| `UIMountPage`／`外观预览` | 复用 RenderTexture、隔离相机、自带光；贴图比例与面板一致；idle 使用 UnscaledTime，AlwaysAnimate |
| `CultivationUI`／`PlayerCultivation` | 按真实修为、实时概率、可用次数刷新；转修展示 `预估转修后境界`，不在 UI 重抄计算公式 |
| `炼丹界面`／`炼丹炉` | 界面布局与材料选择重构；开炉与材料扣除继续在炉逻辑执行；概率、产量、消耗来自丹方与被动加成 |
| `灵田地块界面`／`灵田摆放器` | 状态卡样式更新；种、收、升级、挪动交回原系统；地块存档与摆放规则沿用 |
| `StationInteractor`／`UiEscRegistry` | 设施走近 F；实例化预制体即打开；关界面由现有协调器处理，防同帧 ESC 穿透 |

视觉结构建议：`Canvas > Backdrop / MenuRoot / TooltipRoot / DragGhostRoot / ModalRoot / ToastRoot`。拖拽层单独 Canvas 避免频繁重建整个主面板。UI 暂停时的动画使用 `Time.unscaledDeltaTime`，角色面板开关恢复原 timeScale。主题纹理图集化；复杂墨边用静态透明 sprite，文字和交互轮廓独立，避免高频全屏材质更新。

所有新增 MonoBehaviour 使用 ASCII 类名，同名独立 `.cs` 文件，UTF-8 BOM。拖动目标不依赖视觉 mask 裁剪判定；异形不等于透明区仍可点击。预览对象移除碰撞／游戏行为，不能让预览模型运行玩家或 NPC AI。

推荐落地顺序：①主题与按钮／Tooltip基础组件；②共享六槽和 HUD；③背包／神通／属性；④丹房／修炼；⑤灵田／摆放提示；⑥战阵／坐骑／外观；⑦补充页面。每步在独立审阅资源中验证，再整体替换。保留用户当前材质和场景改动；不要为了换 UI 自动运行配置表导入器或全场景保存。

## 6. 原型能做什么

12 个主页面和 7 个行旅子页、3 个全套皮肤；异形主动槽、悬停倾斜、Pointer 拖拽、槽位换位、替换确认、点击装备与数字键选择空位；五名战阵上限与中央固定；坐骑御风互斥；丹方自动填料、手动拖料／加数量、概率结算与消耗；灵田状态、收获、种植、成熟推进、45° 旋转与取消；修炼次数、破境示例、转修确认；搜索、兑换余额、对话推进与系统菜单。

原型的数量、角色属性、技能数值、兑换价、作物产量与初始地块是 **示例会话数据**；不写游戏存档。丹方中四味基础丹的配比、成功率、消耗按 `灵丹定义.cs`。演示成功产量固定 1，正式游戏必须读取实际丹方；种植不模拟种子库存与扣除；地块摆放只做视觉状态，不进行真实世界位置验证；转修不重算境界曲线。原型法宝／灵阵只演示布局，尚未实现的玩法明确提示。

坐骑／角色预览目前是矢量图的透视旋转，不是真实 3D 模型，正式版本复用项目当前的 3D 预览。概念图内模型、纹理、部分文字／数值由图像工具自动生成，仅作美术方向参考；**不以概念图里的占位文字或额外装饰推导规则**。HTML 为可审阅的交互依据，接入后还需 Unity Play 验证。
