# 场景一致性：一类反复出现的 bug 及其根治办法

> 起因（用户原话，2026-09-27）：
> 「每次搞点什么新的东西，一去其他的场景又不行，一看，哦又是什么东西没有同步过来」
>
> 这不是一堆互不相干的 bug，而是**同一个结构性缺陷**反复发作。
> 本文说清它是什么、为什么反复、以及怎么一次治住。

---

## 一、这类 bug 的共同形状

**「应该每个游戏场景都有的东西，只在某一个场景里配了。」**

项目有 5 个游戏场景：

| 场景文件 | 显示名 |
|---|---|
| `Assets/Scenes/Village.scene` | 古古镇 |
| `Assets/Scenes/Sect.scene` | 太虚宗 |
| `Assets/Scenes/3C_Testbed.scene` | 个人洞府 |
| `Assets/Scenes/Sect_Wilderness.scene` | 宗门野外 |
| `Assets/Scenes/Demon-Suppressing Tower.scene` | 镇妖塔 |

只要一个东西是**序列化在场景里**的，它就有"只在某个场景里有"的风险。
而 `LoadSceneMode.Single` 会把旧场景的一切销毁 —— 于是换场景 = 换一套配置。

## 二、实测踩过的（全部是这一个形状）

| 症状 | 缺的是什么 | 只在哪个场景有 |
|---|---|---|
| 演过场时玩家能乱跑 | `演出锁`（挂 Player） | 古古镇、宗门 |
| 传送到个人洞府后主线进度"没地方放"，回来重放剧情 | `任务管理器` | 古古镇、宗门 |
| 在宗门打开角色面板，神通页/背包页全空 | `UIPanelData` 的**全表**（神通=11、物品=23） | 古古镇 |
| 调机位工具在别的场景按【】没反应 | `CameraYawRotator` | 古古镇、宗门 |

> 注意第 3 条的特殊性：**组件在**，但**它序列化的数据是空的**。
> 所以光检查"组件有没有"还不够，**还要检查关键字段有没有内容**。

## 三、为什么反复发作

三个原因叠加：

1. **场景是"配置的容器"，但没人负责让 5 份配置一致。**
   加一个新组件 → 在当期打开的那个场景里挂上 → 忘了另外 4 个。

2. **没有自动检查。** 只有玩家跑到那个场景去踩，才发现。

3. **有些"填数据"的编辑器工具只作用于当前打开的场景。**
   典型：`DataTableImporter.RewirePanelData()` 用 `GameObject.Find("CharacterUI")`，
   它**只能看到当前打开的场景** —— 所以当初只有古古镇被填过。
   这一类工具是"隐形的单场景操作"，最容易漏。

## 四、根治办法

### 4.0 【最重要】已经做了运行时自举 —— 新功能往这里加

代码：`cultivation/Assets/Scripts/Core/场景自举.cs`

它在**进入任何游戏场景后**自动检查并补上缺的东西：

```
任务管理器   （缺就建一个）
演出锁       （玩家身上缺就补）
玩家外观     （玩家身上缺就补）
CameraYawRotator（主相机缺就补）
```

**实测**：故意把宗门的 `演出锁` 和 `CameraYawRotator` 删掉并保存，进 Play 后
两者**自动补回来了**。

**所以"忘了在某个场景里配"这件事不再可能发生。**
新加一个"每个场景都必须有"的组件时，**往 `场景自举.补玩家与相机()` 里加一行**即可。

> 它替代了原来的 `SceneRigSyncer`（把 Player/相机/UI 从模板场景**整体搬**过去）。
> 那种做法是**覆盖式**的，而各场景早就各自调过（古古镇的相机角度、宗门外的布置…），
> 一跑就把别人的改动冲掉，所以**已经不再跑**。自举只补缺、不动已有的。

### 4.0b 面板的"目录"也改成运行时读了

代码：`cultivation/Assets/Scripts/Data/PanelDatabase.cs`（+ 编辑器工具 `面板库收集器.cs`）

面板的**目录**（神通全表 / 法宝 / 灵阵 / 坐骑 / 可获真灵）原本是**序列化在每个场景的
`UIPanelData` 上**的 ⇒ 只有被灌过表的场景是对的（实测古古镇 神通=11、宗门=0
→ 宗门里神通页一片空白）。

现在统一从 `Assets/resources/面板/面板库.asset` 读，**哪个场景进都一样**。
`UIPanelData.EnsureLists()` 里调 `从面板库灌目录()`，**只灌目录、不碰玩家数据**
（背包 / 已获得 / 已学 / 已停用 / 技能槽 / 战阵站位仍然由存档负责）。

**改了配置表并重新生成资产之后，跑一次 `修仙/面板/收集面板目录`。**

### 4.1 每加一个新功能，跑一次体检（硬性要求）

菜单：**`修仙/体检/场景一致性（只报告）`** / **`修仙/体检/场景一致性（并补齐缺失）`**

代码：`cultivation/Assets/Editor/Tools/场景一致性体检.cs`

它会逐个打开 5 个场景，把「每个游戏场景都应该有的东西」列成表格，
标出不一致的项，并可选**自动补齐**（补完保存场景）。

**新增组件时，同时把它加进 `建清单()` 里的应备项** —— 否则体检看不见它。

### 4.2 能用"运行时加载"就别用"场景序列化"

这是**从根上消除**这类 bug 的办法，优先级从高到低：

| 做法 | 会不会有"场景不一致"问题 |
|---|---|
| **运行时从数据表/生成资产加载**（如 `QuestDatabase.取()`） | ❌ 不会 —— 只有一个源头 |
| `DontDestroyOnLoad` 的单例（如 `黑幕字幕`、`跨场景数据`） | ❌ 不会 —— 跨场景存活 |
| **序列化在场景里的引用/列表**（如 `UIPanelData.神通`） | ✅ **会** —— 每个场景一份，必然漂移 |

**结论：新功能优先做成前两种。**
`UIPanelData` 那类"表数据序列化在场景里"的设计，是这类 bug 的温床，
有条件应该改成运行时从库填充（`EnsureLists()` 里补一句从生成资产加载即可）。

### 4.3 编辑器工具里禁止用 `GameObject.Find`

`GameObject.Find` / `FindObjectOfType` 在编辑器脚本里**只能看到当前打开的场景**。
凡是"要给所有场景灌数据"的工具，必须**显式遍历场景列表并逐个打开**，
或者干脆做成运行时逻辑。

### 4.4 跨场景要有"接力"机制

切场景会销毁一切，所以**任何跨场景要保留的状态**都必须显式交接：

- 静态快照：`跨场景数据.钉住任务进度()` / `拍快照()`
- 静态标记：`对话标记`（内存）+ 读档补齐 `补齐进度标记()`
- **切场景之前**必须钉住进度，否则新场景拿到旧快照 → **剧情重放**

## 五、已经统一掉的入口

切场景的**唯一**正路是：

```csharp
黑幕字幕.开始场景过渡(场景名, 显示名, 坐标, 落点名);
```

它会把整条跑完（黑幕+场景名 → 加载 → 摆位 → 字打完停 2 秒 → 淡出 → 放行阶段），
宿主是黑幕自己（`DontDestroyOnLoad`），所以不会随场景销毁。

**任何新的切场景入口都必须调它**，不要再自己写 `LoadSceneAsync`。
（踩过：`Teleporter` 早期自己造了个 `传送宿主` 裸调 `LoadSceneAsync`，
结果既没有黑幕过场，也没钉进度，导致进宗门重放"我去禀报师尊"。）

## 六、检查清单（加完新功能后逐条过）

- [ ] 新组件挂到 Player / 相机上了吗？**5 个场景都挂了吗？**
- [ ] 有新的"每场景一份"的数据吗？能不能改成运行时加载？
- [ ] 跑了 `修仙/体检/场景一致性` 吗？有没有 ★不一致？
- [ ] 新功能涉及的状态，切场景后还在吗？（不在就进 `跨场景数据`）
- [ ] 用了 `GameObject.Find` 吗？（编辑器工具里 = 只影响当前场景）
- [ ] 落点 / 目标物体**名字唯一吗**？（重名会让按名字查找命中错的那个 ——
      Sect 里传送门和落点同名，曾导致玩家被放到传送门身上）

## 七、跨场景接力：三条必须守住的规矩

用户 2026-09-27 报的「从宗门传送到个人洞府后，背包全丢、神通全没、也没落在对应落点上」
一口气踩了三条。都记在这里，以后改跨场景相关的东西逐条对照。

### 7.1 存档只在**本局第一次进游戏场景**时应用一次

`任务管理器.Start()` 里调的 `应用存档()` 原来**每个场景都跑**，而
`SaveSystem.应用到角色()` 内部：

```csharp
bool 是新档 = 存档里 背包/法宝/灵阵/坐骑/真灵 全空;
if (是新档) 面板数据.清空玩法数据();     // 连已学功法、已获得神通一起清
恢复面板(数据, 面板数据);                 // 面板.物品 = new List<>() 无条件清空重建
```

存档是空的时候（新开档还没存过），每次切场景都会：
`跨场景数据` 刚把背包接过来 → 这里又清成空 → **玩家数据全丢**。

**规矩**：`应用存档()` 用静态标记 `本局已应用存档` 挡住，只跑一次。

### 7.2 接力期间**不要**用存档位置覆盖落点

`SaveSystem` 会按 `数据.位置` 摆玩家，而切场景的目标是**目的地的落点** ——
两者冲突时**落点必须赢**，否则玩家被从落点搬回存档点。

**规矩**：`跨场景数据.正在接力` 为真时跳过"按存档位置摆放玩家"。
（由 `黑幕字幕.开始场景过渡()` 置真、过渡第 5 段位置假。）

### 7.3 `请求落点(位, 0f)` 必须真的"立刻放置"

「接管 0 秒」是**合法且有意义的**用法 = 立刻放置一次就走（传送落点就靠它）。
原来两处都错了：

- `请求落点` 里 `Mathf.Max(0.1f, 接管秒)` 把 0 抬成 0.1；
- `处理落点` 里无条件先判 `Time.time >= 落点截止时刻` → 0 秒时立刻成立 →
  `落点起始帧 = -1` 直接放弃，**位置从来没被应用过**。

表现：传送到个人洞府后玩家站在 `(0,0,0)` 而不是落点。

**规矩**：`请求落点` 尊重传入的接管秒；`处理落点` 先特判"0 秒 → 立刻放置一次"。

## 八、最容易反复发作的一条：实例状态活不过切场景

**`LoadSceneMode.Single` 会把旧场景的一切销毁并重建，包括组件上的实例字段。**
所以任何"只做一次 / 每局一次"的状态写成实例字段，切场景就会重置，表现为**重复播放**。

### 实测踩过的

`主线开场.演过` 原来是 `bool 演过`（实例字段），而 `主线开场` 只挂在古古镇：

```csharp
bool 演过;                                  // ✗ 每次进古古镇都归零
void Start() { if (进游戏就播 && !演过) { 演过 = true; StartCoroutine(开始开场()); } }
```

**表现**：从宗门回古古镇，**整个开场（三句黑幕 + 起名界面）又演一遍**。

### 正确写法

```csharp
static bool 演过;                                            // ✓ 跨场景存活

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void 重置静态() { 演过 = false; }                      // ✓ 重进 Play 时归零

void Start()
{
    if (演过) return;
    if (SaveSystem.当前存档 != null) { 演过 = true; return; }  // ✓ 读档进来不演"新开局"的东西
    演过 = true;
    StartCoroutine(开始开场());
}
```

### 判断口诀

> **这个状态如果"每次进场景都重置"，会不会导致重复播放 / 重复发放 / 重复触发？**
> 会 → 就必须是 **static**，并且想清楚"什么时候该归零"。

同类（本轮一起修的）：

| 症状 | 实例状态（被重建） | 正确形态 |
|---|---|---|
| 回古古镇重演开场 | `主线开场.演过` | static + 读档判定 |
| 背包/神通全丢 | 存档被每次进场景重复应用 | static `本局已应用存档` |
| 面板目录空白 | `UIPanelData.神通` 存场景 | 运行时从 `面板库` 读 |
| 演出锁/机位工具缺失 | 组件靠手工每场景配 | `场景自举` 运行时保证 |
