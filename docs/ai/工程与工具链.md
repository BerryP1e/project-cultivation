## 3. Unity 文件桥（`DshBridge`）—— 让 AI 能直接驱动编辑器

**这是本项目让 AI 干活的关键设施**，比 MCP 更可靠。

### 3.1 它是什么

`cultivation/Assets/Editor/Tools/DshBridge.cs`，带 `[InitializeOnLoad]`：
Unity 一编译完就加载它，之后每帧检查命令文件，执行并把结果写回结果文件。
**不需要任何外部进程或端口。**

| 文件 | 位置 |
|---|---|
| 命令 | `<仓库根>\.dsh\cmd.txt`（每行一条） |
| 结果 | `<仓库根>\.dsh\result.txt` |
| 心跳 | `<仓库根>\.dsh\alive.txt`（每 2 秒写一次，>10 秒不动 = 桥没在跑） |

路径**从 `Application.dataPath` 反推**，所以两台电脑都不用改。

### 3.2 怎么用

```powershell
. ([scriptblock]::Create((Get-Content "<仓库根>\.dsh\uni.ps1" -Raw)))
Uni "refresh"                  # 触发重编译（改完 .cs 必须跑）
Uni "console:get:50"           # 读最近 50 条 Console
Uni "play:on"                  # 进播放模式
Uni "quest"                    # 只读：任务运行时状态（进度/当前阶段/已执行动作）
Uni "stages:q_main_004"        # 只读：读任务定义资产（验证 CSV 重导是否生效）
```

> ⚠️ **点源时 `$PSScriptRoot` 是空的**（脚本是从内存跑的），`uni.ps1` 里为此加了
> 三级回退（`$PSScriptRoot` → `$MyInvocation.MyCommand.Path` → CWD）。
> 这是踩过的坑，别改掉。

### 3.3 支持的命令

| 命令 | 作用 |
|---|---|
| `refresh` | `AssetDatabase.Refresh()`，触发编译 |
| `menu:<菜单路径>` | 执行菜单项，例如 `menu:修仙/从配置表生成资产` |
| `console:clear` / `console:get[:N]` | 清空 / 读取 Console（**运行时日志只能这样拿**） |
| `play:on` / `play:off` | 进出播放模式 |
| `save` | 保存当前场景 + 资产 |
| `open:<场景路径>` | 打开场景 |
| `echo:<文本>` | 回显（测通道是否活着） |
| `shot[:路径]` / `shot2` / `bird` | 截图（主相机 / ScreenCapture / 鸟瞰） |
| `dump` | 打印当前场景结构 + Build Settings |
| `quest` | **只读**：任务管理器运行时状态 |
| `stages:<任务id>` | **只读**：读任务定义资产（验证导入是否生效） |
| `curtain` | **只读**：黑幕运行状态（字体/文本/可见性） |

### 3.4 桥不通怎么查

```powershell
Uni "echo:ok"                  # 有回显 = 通
```
没回显就按顺序查：
1. `<仓库根>\.dsh\alive.txt` 有没有、是不是 10 秒内更新过
2. `cultivation/Temp/.com-unity-codely.json` 的 `last_updated` 是不是在动
3. Unity 里 Console 有没有 `[DshBridge] 文件控制通道已启动，仓库根 = ...`
   —— **如果这行没有，或者仓库根不对**，就是桥的路径解析出了问题（曾经写死过盘符）

> ⚠️ **`Editor.log` 里没有 `Debug.Log` 输出**，运行时日志只走 Console（用 `console:get` 拿）。
> `Editor.log` 里能看到的是编译错误、导入记录、崩溃等。

### 3.5 MCP 通道（备用，主通道是文件桥）

仓库里还有一套 MCP 相关脚本：`.dsh/mcp.ps1`、`.dsh/serve-unity-mcp.ps1`、
`.dsh/unity-mcp-proxy.mjs`、`.dsh/health.ps1`。

`health.ps1` 是一个**只读体检**脚本，查四段链路：
编辑器进程 → codely TCP 桥（`cultivation/Temp/.com-unity-codely.json` 里的端口）
→ MCP 服务器（HTTP 8765 是可选手动通道）→ harness 注册行 → 文件桥心跳。

这些脚本里的路径同样都改成了**跟随脚本自身位置**，不要写死盘符。

## 4. 快捷键与常用操作

### 改完东西必须做的两件事

```powershell
Uni "refresh"                          # 改了 .cs
Uni "menu:修仙/从配置表生成资产"          # 改了 .csv
```

### 编辑器里测新流程前

**先重启 Unity。** 理由：`对话标记`、任务完成状态、`已执行动作`、`落点` 都是
**静态**数据，会跨 Play 会话残留，不重启会串局。

### 存档位置（调试时删档用）

```
C:\Users\<用户>\AppData\LocalLow\<公司名>\<产品名>\saves\slot_<n>.json
```
本机实测路径：`C:\Users\ASUS\AppData\LocalLow\DefaultCompany\cultivation\saves\`

### 游戏内调试面板（**F1**）

`Assets/Scripts/Combat/PlayerStatsDebugPanel.cs`，IMGUI 实现，不依赖 prefab / Canvas。
挂在 Player 上，**F1** 开关（`开关按键` 字段可改）。

面板内容：

| 区 | 作用 |
|---|---|
| 顶部按钮 | `从当前值同步` / `恢复常规结算` / `载入初始默认值` / `全部清零` |
| 应用 | `应用修改到角色`（走 `UseDebugStats` 属性，内部会 `Recalculate`） |
| 修炼相关 | 调试神识 / 吐纳速度 |
| **召唤 NPC** | 从 `Resources.LoadAll<GameObject>("NPC")` 拉全表（已过滤出带 Animator 控制器 + SkinnedMeshRenderer 的**prefab**，原始 FBX 会被过滤掉），可滚动选择，召在玩家前方 2 米 |
| **给背包塞物品** | 列表来源 `QuestDatabase.取().物品库`（= 物品表生成的全部物品，**物品表改了什么这里就有什么**），带**搜索框**筛选 + 滚动，选中后可「塞 1 个」/「塞 10 个」 |
| 26 项战斗属性 | 可滚动，逐项输入即刻生效 |

> 塞物品走的是 `UIPanelData.给物品(物品, 数量)`，和任务奖励同一条路径；
> 面板数据挂在 `CharacterUI` 上，不在 Player 身上，所以是 `FindObjectOfType<UIPanelData>()` 找的。
> 物品库为空时提示「先跑 修仙/从配置表生成资产」。

## 5. Git 协作约定

- **提交只用定向 `git add <具体文件>`，不要 `git add -A`**。
  工作区长期有 1000+ 个引擎重写的 `.mat`/`.prefab`（Unity 序列化格式迁移：
  旧的**二进制** Material → **YAML** 文本），`-A` 会把它们一起扫进提交。
- **换新环境永远 `git clone`**。下载 zip 没有 `.git` 历史，重新 `init` 出来的提交
  与远端**没有共同祖先**，push 会把整个项目重传一遍（而且 `git merge-base` 为空）。
- 推送需要凭据。本机可以用进程级 `GIT_ASKPASS` 传令牌，
  **不要**把令牌写进 `.git/config` 或提交进仓库。
- 工作区里的 `git个人令牌（不要推送到git）.txt` 已被 `.gitignore` 的 `*令牌*` 匹配，
  不会进仓库；但它是明文，用完请吊销。
