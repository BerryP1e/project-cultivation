## 3. Unity 文件桥（`DshBridge`）—— 让 AI 能直接驱动编辑器

**这是本项目让 AI 干活的关键设施**，比 MCP 更可靠。

### 3.1 它是什么

`cultivation/Assets/Editor/Tools/DshBridge.cs`，带 `[InitializeOnLoad]`：
Unity 一编译完就加载它，之后每帧检查命令文件，执行并把结果写回结果文件。
**不需要任何外部进程或端口。**

| 文件 | 位置 |
|---|---|
| 命令 | `<仓库根>\.dsh\cmd.txt`（每行一条） |
| 结果 | `<仓库根>\.dsh\result.txt` |
| 心跳 | `<仓库根>\.dsh\alive.txt`（每 2 秒写一次，>10 秒不动 = 桥没在跑） |

路径**从 `Application.dataPath` 反推**，所以两台电脑都不用改。

### 3.2 怎么用

```powershell
. ([scriptblock]::Create((Get-Content "<仓库根>\.dsh\uni.ps1" -Raw)))
Uni "refresh"                  # 触发重编译（改完 .cs 必须跑）
Uni "console:get:50"           # 读最近 50 条 Console
Uni "play:on"                  # 进播放模式
Uni "quest"                    # 只读：任务运行时状态（进度/当前阶段/已执行动作）
Uni "stages:q_main_004"        # 只读：读任务定义资产（验证 CSV 重导是否生效）
```

> ⚠️ **点源时 `$PSScriptRoot` 是空的**（脚本是从内存跑的），`uni.ps1` 里为此加了
> 三级回退（`$PSScriptRoot` → `$MyInvocation.MyCommand.Path` → CWD）。
> 这是踩过的坑，别改掉。

### 3.3 支持的命令

| 命令 | 作用 |
|---|---|
| `refresh` | `AssetDatabase.Refresh()`，触发编译 |
| `menu:<菜单路径>` | 执行菜单项，例如 `menu:修仙/从配置表生成资产` |
| `console:clear` / `console:get[:N]` | 清空 / 读取 Console（**运行时日志只能这样拿**） |
| `play:on` / `play:off` | 进出播放模式 |
| `save` | 保存当前场景 + 资产 |
| `open:<场景路径>` | 打开场景 |
| `echo:<文本>` | 回显（测通道是否活着） |
| `shot[:路径]` / `shot2` / `bird` | 截图（主相机 / ScreenCapture / 鸟瞰） |
| `dump` | 打印当前场景结构 + Build Settings |
| `quest` | **只读**：任务管理器运行时状态 |
| `stages:<任务id>` | **只读**：读任务定义资产（验证导入是否生效） |
| `curtain` | **只读**：黑幕运行状态（字体/文本/可见性） |

### 3.4 桥不通怎么查

```powershell
Uni "echo:ok"                  # 有回显 = 通
```
没回显就按顺序查：
1. `<仓库根>\.dsh\alive.txt` 有没有、是不是 10 秒内更新过
2. `cultivation/Temp/.com-unity-codely.json` 的 `last_updated` 是不是在动
3. Unity 里 Console 有没有 `[DshBridge] 文件控制通道已启动，仓库根 = ...`
   —— **如果这行没有，或者仓库根不对**，就是桥的路径解析出了问题（曾经写死过盘符）

> ⚠️ **`Editor.log` 里没有 `Debug.Log` 输出**，运行时日志只走 Console（用 `console:get` 拿）。
> `Editor.log` 里能看到的是编译错误、导入记录、崩溃等。

### 3.5 MCP 通道（备用，主通道是文件桥）

仓库里还有一套 MCP 相关脚本：`.dsh/mcp.ps1`、`.dsh/serve-unity-mcp.ps1`、
`.dsh/unity-mcp-proxy.mjs`、`.dsh/health.ps1`。

`health.ps1` 是一个**只读体检**脚本，查四段链路：
编辑器进程 → codely TCP 桥（`cultivation/Temp/.com-unity-codely.json` 里的端口）
→ MCP 服务器（HTTP 8765 是可选手动通道）→ harness 注册行 → 文件桥心跳。

这些脚本里的路径同样都改成了**跟随脚本自身位置**，不要写死盘符。

**静态**数据，会跨 Play 会话残留，不重启会串局。

```
C:\Users\<用户>\AppData\LocalLow\<公司名>\<产品名>\saves\slot_<n>.json
```

### NPC 表历史备份（`.dsh/_npc表备份/`）

`NpcVariantSplitter` 每次改 NPC 表前会自动备份一份。**原来的输出目录写死在
`"D:/project：cultivation"`（第一台开发机的路径）**，换机器后目录不存在、
`File.WriteAllBytes` 抛异常被静默 catch → **备份一直没生效**，而仓库根还堆着
8 个从原机器搬来的历史 `.bak`。

2026-09-27 已修：`备份目录` 改成**从 `Application.dataPath` 反推仓库根**，
落到 `.dsh/_npc表备份/`（放 `.dsh` 而不是 `Assets` 里 —— `.bak` 在 Assets 下会被 Unity 导入）；
失败时会把完整路径和原因打出来，不再静默。

根目录那 8 个已按内容去重成 6 份归档到该目录（有 `README.md` 说明来源）。
⚠️ 那些备份里的 NPC 大多**已失效**（引用的预制体在工程里不存在），
只当历史快照查数值用，不是配置。

### 游戏内调试面板（**F1**）

`Assets/Scripts/Combat/PlayerStatsDebugPanel.cs`，IMGUI 实现，不依赖 prefab / Canvas。
挂在 Player 上，**F1** 开关（`开关按键` 字段可改）。

面板内容：

| 区 | 作用 |
|---|---|
| 顶部按钮 | `从当前值同步` / `恢复常规结算` / `载入初始默认值` / `全部清零` |
| 应用 | `应用修改到角色`（走 `UseDebugStats` 属性，内部会 `Recalculate`） |
| 修炼相关 | 调试神识 / 吐纳速度 |
| **召唤 NPC** | 从 `Resources.LoadAll<GameObject>("NPC")` 拉全表（已过滤出带 Animator 控制器 + SkinnedMeshRenderer 的**prefab**，原始 FBX 会被过滤掉），可滚动选择，召在玩家前方 2 米 |
| **给背包塞物品** | 列表来源 `QuestDatabase.取().物品库`（= 物品表生成的全部物品，**物品表改了什么这里就有什么**），带**搜索框**筛选 + 滚动，选中后可「塞 1 个」/「塞 10 个」 |
| 26 项战斗属性 | 可滚动，逐项输入即刻生效 |

> 塞物品走的是 `UIPanelData.给物品(物品, 数量)`，和任务奖励同一条路径；
> 面板数据挂在 `CharacterUI` 上，不在 Player 身上，所以是 `FindObjectOfType<UIPanelData>()` 找的。
> 物品库为空时提示「先跑 修仙/从配置表生成资产」。

## 5. Git 协作约定

- **提交只用定向 `git add <具体文件>`，不要 `git add -A`**。
  工作区长期有 1000+ 个引擎重写的 `.mat`/`.prefab`（Unity 序列化格式迁移：
  旧的**二进制** Material → **YAML** 文本），`-A` 会把它们一起扫进提交。
- **换新环境永远 `git clone`**。下载 zip 没有 `.git` 历史，重新 `init` 出来的提交
  与远端**没有共同祖先**，push 会把整个项目重传一遍（而且 `git merge-base` 为空）。
- 推送需要凭据。本机可以用进程级 `GIT_ASKPASS` 传令牌，
  **不要**把令牌写进 `.git/config` 或提交进仓库。
- 工作区里的 `git个人令牌（不要推送到git）.txt` 已被 `.gitignore` 的 `*令牌*` 匹配，
  不会进仓库；但它是明文，用完请吊销。

### 5.1 换一台电脑 / 克隆之后：要不要「重序列化」？

**结论：不需要「重序列化」。** 仓库里**是带 Unity 序列化资产的**（实测统计）：

| 类型 | git 跟踪数量 |
|---|---|
| `.meta` | **10315** |
| `.asset` | **687** |
| `.scene` / `.prefab` | **943** |

`.gitignore` **没有**排除 `.asset` / `.meta` / `.unity` / `.prefab`
（它只排除 `[Ll]ibrary/`、`[Tt]emp/`、`[Oo]bj/`、`[Bb]uild/`、`[Ll]ogs/` 这些引擎生成物）。

- **`.meta` 在，就不会「需要重序列化」** —— GUID 存在 `.meta` 里，引用（场景 → 资产、
  资产 → 资产）全靠它。只要 `.meta` 跟着走，克隆下来引用就是完整的。
  **真正的灾难是 `.meta` 没提交**：那样 Unity 会给所有资产重新分配 GUID，引用全断。
- **`Library/` 被忽略是正常的**，它是引擎缓存。克隆后 Unity 第一次打开会**自动重建**
  （几分钟）—— 那是**正常导入**，不是「重序列化」。

#### 那另一台电脑为什么觉得"资产没推上去"？
最可能是这个：**`Assets/Data/Generated/**` 是导入器从 CSV 生成的，
生成完如果忘了 `git add`，那台机器就缺这些资产**（表现：面板里看不到新神通/新物品、
`Resources.Load` 拿到 null）。**2026-09-29 这次就是** —— 有 **59 个**新生成的资产
（新神通 / 物品 / 功法）一直躺在工作区没被提交，本次已补上。

#### 万一确实缺了，怎么恢复
**不用重序列化**，跑这两个菜单就行（`Generated/*` 完全由 `Data/Tables/*.csv` 生成，可复现）：
1. `修仙/从配置表生成资产`
2. `修仙/面板/收集面板目录`  ← **这个别忘**，它把 `面板库.asset` 收集好，否则面板是空的

#### 另一台电脑还需要自己准备的东西（这些**故意**不在仓库里）
- `cultivation/.codely.packages/`、`.dsh/_tools/` —— 桥/工具（`.gitignore` 排除，含 267MB 索引）
- `somenews/` —— 原始下载素材（含 118MB 的 `.c4d`，超 GitHub 单文件 100MB 上限）
- `cultivation/screenshots/` —— 验证截图（每次验证都会生成，不属于项目资产）
- 桥的令牌文件（`*令牌*` 被 ignore）

### 5.2 新增神通 / 功法：各场景要同步什么（2026-09-29 核对过）

**结论：只有一样东西是场景级的 —— `PlayerAbilityLoader` 的两张表。其余全是全局资产，不用管。**

| 做了什么 | 要在场景里登记吗 | 登记在哪 |
|---|---|---|
| **功法**（提供普攻方法） | ✅ 要 | 每个玩法场景 Player 的 `PlayerAbilityLoader.普攻方法表`：`{普攻方法id → 组件类名}` |
| **被动神通** | ✅ 要 | 同上，`被动神通表`：`{神通id → 组件类名[]}` |
| **主动神通** | ❌ **不用** | `ActiveSkillCaster` 按资产的 `结算方式` 在运行时处理；神通资产是全局的 |
| 学习物品 / 功法秘籍 | ❌ 不用 | 全局 `ItemDefinition`；背包/已学内容是存档 + 运行时状态 |
| `面板库.asset` | ❌ 不用 | 全局资源，运行时 `Resources.Load`，**场景不引用它** |

**当前 5 个玩法场景已全部登记一致**（实测逐个打开核对）：
```
普攻方法表(3)：basic_sword_01 / basic_remoteattack_01 / basic_thunder_01 → BasicThunder01
被动神通表(3)：ability_pingxu_yufeng / ability_qianjie_leiyu → QianJieLeiYu / ability_leiyun → LeiYun
```
`StartScene` / `Transition subtitles` 是 UI 场景、没有玩家，不需要登记。

**加新东西时的顺序**（否则会出现"3C_Testbed 能用、别的场景不能用"）：
1. 改 `Assets/Data/Tables/*.csv` → 跑 `修仙/从配置表生成资产`
2. 在**每个玩法场景**的 Player 上，把新行加进 `PlayerAbilityLoader` 的对应表（主动神通跳过这步）
3. 跑 `修仙/面板/收集面板目录`
4. 跑 `修仙/检查配置表是否已同步` / `修仙/场景一致性体检` 复核

**场景级组件漂移这件事本身也修了**：`主动神通开关` 以前只有 `village`/`Sect` 手挂着，
另外 3 个场景缺（它控制"技能槽空着就关掉 `ActiveSkillCaster`"）。
现在把它加进了 `场景自举.补玩家与相机`，和 `演出锁`/`玩家外观` 一样**运行时自动补齐**，不会再漂移。
