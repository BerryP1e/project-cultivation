## 2. 全局机制（一次配置、全场景生效）

### 2.1 场景自举 `场景自举.cs` —— 不许把通用组件写进场景

**核心约定**：**"每个场景都该有"的东西一律运行时自举补，不写进场景文件。**
写进场景的会漂移（某个场景忘了挂 / 被 builder 删掉），见
[踩坑总库 §专题：场景一致性](../ai/踩坑总库.md)。

自举分两类：

| 类别 | 怎么补 | 有哪些 |
|---|---|---|
| **补单例** | 场景里没有就造一个（带 `DontDestroyOnLoad`） | `任务管理器`、`时间管理器`、`灵田` |
| **补玩家与相机** | 挂到 Player / Main Camera 上 | `演出锁`、`玩家外观`、`主动神通开关`、`CameraYawRotator`、`GameGlobalGrade`、`GameGlobalBloom`、`画面基线预览`、`纪年HUD`、`灵田界面`、`任务引导`、**`日常循环`、`伏笔管理器`、`伏笔表现`** |

> ⚠️ **补出来的组件不能指望脚本默认值** —— 脚本字段默认值会被原样当成配置。
> 凡是"补"出来的，都要在自举那一层**显式设成想要的初始状态**。

### 2.2 全局后处理栈（Built-in，自写 `OnRenderImage`）

执行顺序靠 `[DefaultExecutionOrder]` 保证：

```
相机 → GameGlobalBloom（order -100，出辉光） → GameGlobalGrade（调色） → 屏幕
```

| 组件 | 作用 |
|---|---|
| `GameGlobalBloom` + `CultivationBloom.shader` | 多 mip 链辉光 |
| `GameGlobalGrade` + `CultivationGlobalGrade.shader` | 曝光 / Lift-Gamma-Gain / 对比 / 饱和 / 染色 / 暗角 / **Hable Tonemap** |
| `画面基线预览` | F2 切画面亮度基线的调试工具 |

详见 [画面统一调色](../guides/画面统一调色.md)。
⚠️ 两个 shader 的 **properties 块只能写 ASCII**（连注释里的中文都不行）。

### 2.3 全局调色与「材质统一收敛」

全工程材质已收敛到**玩家当前材质**这一把尺子：`Standard` + 金属 0 + 光泽 0 + 白染色。
工具在 `Assets/Editor/Tools/材质统一收敛.cs`。

**明确不动**：树/植被（billboard 片）、特效目录（靠叠加混合发光）。

### 2.4 存档

| 项 | 值 |
|---|---|
| 字段即清单 | `Assets/Scripts/Save/SaveData.cs`（当前版本 **11**） |
| 载体 | `UIPanelData`（场景里的角色面板数据） |
| 场景/位置 | `场景名` + `位置有效`（**不能**拿 `位置 == Vector3.zero` 当哨兵） |

详见 [design/存档系统](../design/存档系统.md)。

### 2.5 交互设施系统 `StationInteractable` / `StationInteractor`

**统一的"走近按 F"入口**（建筑 / NPC 对话 / 传送圈都用它）。

```
StationInteractable  （挂在物件上）→ 我是谁、多大、多远、按哪个键
StationInteractor    （挂在玩家上）→ 找最近的、显示提示、按 F 开界面
```

| 类型 | 打开什么 |
|---|---|
| `修炼` | `设施.界面预制体`（`CultivationUI`） |
| `炼丹` | `设施.界面预制体`（`炼丹界面`） |
| `炼器` / `布阵` | 界面预制体留空 → **占位空白幕布** |
| `对话` | 交给 `NpcDialogue`，**不走幕布** |
| `传送` | 交给 `Teleporter.开面板()`，**面板由它自己画** |

> **界面预制体 = null 时按 F 会弹一块空白幕布**（`StationInteractor` 的占位分支：
> "UI 尚未设计"）。所以"某个设施按 F 没反应"要先查这一栏。

### 2.6 通用装配同步 `SceneRigSyncer` —— UI/角色改动必须铺到所有游玩场景

**用户约定**：UI、角色这类"通用装配"的改动，要**统一同步到所有实际游玩场景**
（目前 = `3C_Testbed` / `Sect` / `Demon-Suppressing Tower`）。
菜单 **修仙 / 同步通用角色与UI到所有游玩场景**，工具 `Assets/Editor/Tools/SceneRigSyncer.cs`。

| 设定 | 值 |
|---|---|
| 源场景（装配最全的） | `3C_Testbed` |
| 通用根 | `Player` `Main Camera` `EventSystem` `HudCanvas` `CharacterUI` `暂停菜单` `SpawnPoint` |
| **总是覆盖** | `Player` `Main Camera` `EventSystem` `HudCanvas` `CharacterUI` `暂停菜单` |
| 只在**缺失**时补 | `SpawnPoint` |
| 平行光 | **不在同步范围** —— 各场景氛围不同，各自保留 |
| 位置 | 覆盖时**一律保留目标场景原有的位置/朝向**（Sect 玩家在 `(22.069,-0.685,-3.794)`、塔里在 `(0,4.99,-9)`；归零就把人丢到塔外 ✗）。⚠️ **这条规则会把场景里摆错的位置一直保留下去** —— 所以摆完必须确认脚下有地面（Sect 曾经摆在 `(-83.6,18.13,89.9)`，脚下是空的，见 §1.2） |
| 相机调参 | `TopDownCameraZoom` 的 soft/hard/每格倍数，覆盖后**原样写回**（塔的 ×1.5 靠这个保住） |
| 场景私有特效 | **不由本工具搬运** —— 改由 `Assets/resources/场景特效开关.asset` 一张表管（见 [遮挡与特效开关](遮挡与特效开关.md)） |

> **为什么 UI 也要"总是覆盖"**：原来是"缺失才补"，结果各场景里**旧版的 `HudCanvas` / `CharacterUI` 一直在**，
> 新装配永远补不进去；`Player` 同理 —— 手删角色预制体只删了子物体时，场景里会残留一个**空的 `Player` 根**，
> "缺失才补"会跳过它、留成空壳。

**★★ 实现要诀：绝不能拿 `Instantiate` 复制** —— 副本内部引用**仍指向源场景里的原件**，跨场景就是一堆空引用。
正确做法（**源场景只读**）：

```
1. AssetDatabase.CopyAsset(源场景, 临时场景)                 // 只动副本
2. 打开目标场景（Single）→ 附加打开临时场景（Additive）
3. EditorSceneManager.MoveGameObjectToScene(根物体, 目标场景) // 搬移 → Unity 自动重映射引用 ✓
4. 保存目标场景 → 关掉并删除临时场景
```

搬移后实测：`TopDownCamera.target` 仍指向 Player ✓、`UIPanelData.坐骑` 仍有 9 只 ✓、**丢失脚本 0 个** ✓。

> ★ **副作用（值得记）**：强制覆盖 `Player` 时，Sect 玩家身上那个场景私有的 `OcclusionOutline` 被一起换掉了 ——
> **这正是后来做「场景特效开关表」的直接原因**：与其每次同步都靠工具"记住/搬回"场景私有组件，
> 不如让组件铺到所有场景、由表决定谁生效。
>
> **塔内地板面在 `y = 4.94`**（塔整体悬空），所以 Player 与 SpawnPoint 摆在 `(0, 4.99, -9)`。
> **新场景加玩家时一定要摆到地板面上，否则会掉下去。**

**自查清单**：动了 UI / 角色 / 相机 → **跑一次这个工具**，三个场景都过一遍；跑完**看一眼 diff**
（新增的应该是"目标场景少了的东西"，各场景自己的相机调参与特效开关行不该被动过）；
工具会先 `SaveCurrentModifiedScenesIfUserWantsTo()`，不会默默丢掉别人正在编的场景 ✓。

### 2.7 UI 画布在编辑器里默认不显示 + F1 调试面板默认关

**用户要求**：F1 面板一开始就是打开的，要**默认关闭**；编辑场景时各种 UI/HUD 画布默认显示**很不方便**，也要默认不显示。

| 项 | 做法 |
|---|---|
| F1 调试面板 | `PlayerStatsDebugPanel.启动时显示` 默认改成 **false** —— **代码里的字段默认值 + 各场景的序列化值都要改**（只改代码没用，场景里存的是 `1` ✗）。F1 依旧开合，`Visible` / `Toggle()` 不变 |
| UI 画布 | `Assets/Scripts/UI/UICanvasBoot.cs` 挂在 UI 根上：**编辑器里** 把自己那个 `Canvas.enabled = false`（Scene/Game 视图都不画 UI，摆场景清爽）；**运行时** `Awake()` 把**自己这一个** Canvas 打开 → 玩家侧一点没变 |

> ★★ **为什么必须是 `Canvas.enabled` 而不是 `SetActive(false)`**：
> `GameObject.Find("CharacterUI")` **默认跳过未激活对象**，而 `PlayerAbilityLoader`（装卸能力组件）与
> `MountRider`（读当前坐骑）都是这么找 `UIPanelData` 的 —— 关 GameObject 会让这些**直接坏掉** ✗✗。
> 关 Canvas 组件则完全不影响查找、也不影响脚本执行（GameObject 仍是激活的）。

- 只打开**自己 GameObject 上**的 Canvas，**不动子物体的画布** —— 那些是各面板（背包页 / 坐骑页…）自己的开关，
  代打开会把本该收着的面板顶出来 ✗
- `Reset()` 里顺手把画布关掉 ⇒ **加组件的那一刻就生效**，所以生成器只要 `AddComponent<UICanvasBoot>()`
  就天然是"编辑器里不显示" ✓（`HudBuilder` 与 `CharacterPanelBuilder` 都已加；**以后手工新建 UI 根也要记得挂**）
- 想在编辑器里**临时看一眼 UI**：菜单 **修仙 / 编辑器里显示或隐藏 UI 画布**
  （`UICanvasEditorToggle`，只切当前场景根物体上的 `Canvas.enabled`，**不自动保存**）

**实测（四个游玩场景）**：`3C_Testbed` / `Sect` / `Demon-Suppressing Tower` / `village` ——
每个场景 2 个 Canvas（`HudCanvas`、`CharacterUI`）都是「关着 + 挂 `UICanvasBoot`」；
Play Mode 两个画布自动打开 ✓、`UIPanelData`（神通 11 / 坐骑 9）照常找得到 ✓、
`MountRider.面板数据` 已接上 ✓、F1 面板启动时 `Visible=False` ✓。
改完 UI 记得跑 **修仙 / 同步通用角色与UI到所有游玩场景**（见 §2.6）。

## 4. 三条最容易反复发作的规律

1. **实例状态活不过切场景** —— 静态字段/`DontDestroyOnLoad` 之外的东西切场景就没了。
   要做跨场景的东西，走 `跨场景数据` 或静态单例。
   → [踩坑总库 §专题：场景一致性](../ai/踩坑总库.md)
2. **"补"出来的组件不能指望脚本默认值** —— 见 §2.1。
3. **一个公共基础函数坏了，会伪装成 N 个不相干的业务 bug** ——
   例：`NpcBodyBounds` 读不可读网格抛异常，同时干掉血条 / 贴地 / 碰撞体。
   → [踩坑总库](../ai/踩坑总库.md)「读蒙皮网格顶点」
