## 1. 结构

| 东西 | 在哪 |
|---|---|
| 生成器（编辑器） | `Assets/Editor/Builders/HudBuilder.cs`，菜单 **修仙 / 生成游戏界面 HUD** |
| 运行时刷新 | `Assets/Scripts/UI/PlayerHud.cs`，挂在场景里的 `HudCanvas` 上 |
| 悬停转发 | `Assets/Scripts/UI/HudHoverTarget.cs`，挂在每个格子上 |
| 贴图资产 | `Assets/Resources/UI/Hud/hud_square.png`（生成器自动产出） |

布局：**左下角一小块**，参考分辨率 1920×1080，**全部方框、不显示任何名字**。

```
┌────┐ ┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐
│功法│ │1││2││3││4││5││6│     ← 名字改成「鼠标悬停弹幕布」
└────┘ └─┘└─┘└─┘└─┘└─┘└─┘
气血 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓
灵气 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓
修炼 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓     ← 距「下一次修炼次数」的进度（见 §5）
```

| 部件 | 位置 / 尺寸 |
|---|---|
| 功法 | `(20, 80)` 68×68 |
| 技能 1~6 | `(98, 102)` 起，46×46，间距 5 → 右缘 x = 399 |
| 气血 / 灵力 / 修炼 | `(20, 59)` / `(20, 38)` / `(20, 17)`，379×15 |
| 信息幕布 | `(20, 160)`，400×190（默认隐藏） |

- 竖排顺序与用户给的标注图一致：**气血 → 灵力 → 修炼**（修炼在最底下那格 17）。
  > 加「修炼」条时整块往上挪了 21：原来是 气血 38 / 灵力 17 / 功法 58 / 技能 80 / 幕布 136，现在每个 +21。
- `HudCanvas` 是 **ScreenSpaceOverlay，`sortingOrder = -1`** ⇒ 角色面板 / 暂停菜单会盖在它上面。
- 有 `GraphicRaycaster`（悬停需要），但**只有格子的「底」是 `raycastTarget = true`**，其余图一律 false —— 所以 HUD 不会抢走别处的点击。
- 生成器是**幂等**的：重复执行会先删掉旧 `HudCanvas` 再重建，且**不碰 `CharacterUI` / `PauseMenuCanvas`**。

## 2. 冷却表现

`ActiveSkillCaster` 给 HUD 提供三个查询：

| 接口 | 含义 |
|---|---|
| `冷却剩余秒(槽位)` | 还剩几秒 |
| `冷却总秒(槽位)` | 这次冷却一共几秒（读神通资产的 `冷却时间`） |
| `冷却比例(槽位)` | **1 = 刚进冷却，0 = 冷却完毕** |

HUD 把 `冷却比例` **直接喂给遮罩的 `fillAmount`**：

- 遮罩是 `Image.Type.Filled` + `FillMethod.Vertical` + `fillOrigin = Top`
  ⇒ 暗部从顶部往下盖满，再**自下而上逐渐消退**（1 → 0）。
  方框图标用**竖向扫**比径向的"钟面扇形"更清楚（径向也在 `HudBuilder` 里留着注释可换）。
- 中央 `Text` 实时显示剩余秒数：**≥1 秒显示整数，最后一秒显示一位小数**（如 `0.2`）。
- 冷却结束后遮罩与文字一起隐藏。
- 冷却文字和按键数字都加了 **`Outline` 深色描边** —— 否则压在亮色图标上看不清。

实测（焚天炎术，8 秒冷却）：

| 时刻 | 剩余 | 比例 | 遮罩 fill | 倒计时文字 |
|---|---|---|---|---|
| 0.4s | 7.60 | 0.950 | **0.951** | `8` |
| 3.5s | 4.43 | 0.554 | **0.554** | `5` |
| 7.6s | 0.24 | 0.030 | **0.031** | `0.2` |
| 8.6s | 0 | 0 | 隐藏 | 隐藏 |

## 3. 鼠标悬停的信息幕布

不显示名字，改成**鼠标移到格子上弹出一块半透明幕布**，移开就消失。实现只要三样：

1. Canvas 上有 **`GraphicRaycaster`**，场景里有 **`EventSystem`**（`3C_Testbed` 本来就有）。
2. 每个格子上挂 **`HudHoverTarget`**（`槽位`：`0~5` = 主动技能，`-1` = 功法）。
3. 格子里**只有一个** `raycastTarget = true` 的图（用的是「底」）⇒ 射线打到「底」，再沿父级往上找到 `HudHoverTarget`。

幕布正文按槽位内容分支：

| 槽位内容 | 幕布正文 |
|---|---|
| 功法 | 当前修炼功法 / 每级所需经验 / 可修炼境界 / 普攻方法 + 介绍 |
| 主动神通（已实现） | 属性 · 结算方式 / 消耗灵力 / 冷却 / 范围 / 伤害倍率 / 持续与结算间隔 / 是否需锁定 + 介绍 |
| 主动神通（未实现） | `主动神通 · <属性> · 【尚未实现】` + 介绍 |
| 灵阵 | `灵阵【尚未实现】` + 有效范围 / 持续时间 / 目标筛选 / 布置消耗灵气 |
| 法宝 | `法宝【尚未实现】` |
| 空槽 | 不弹幕布 |

> 幕布自己的图全部 `raycastTarget = false`，否则它会挡住下面格子的悬停。
> 幕布位置固定在 HUD 上方（**不跟着鼠标跑**）：换格子时只换内容、位置不跳。

## 4. 图标从哪来 / 灰罩 vs 冷却

- 技能图标 = `主动技能[i] as IPanelEntry` 的 `DisplayIcon`
- 功法图标 = `当前功法.DisplayIcon`
- **目前这些资产的 `图标` 字段全是空的**，所以 HUD 退化成用「品阶色」画一个色块（`UIEntryRow.TierColor`）。
  等美术把图标填进资产，HUD **不改代码**就会显示真图标。
- `结算方式 = 未实现` 的槽位（寒冰诀等）、以及法宝 / 灵阵，会盖一层黑 62% 的**灰罩**。
  ⚠️ **灰罩和"冷却中"是两回事**：灰罩 = 这东西还做不了；冷却遮罩 = 刚放过、正在转 CD。

## 5. 左下角「修炼次数进度条」

用户原话：
> 「每杀一只怪就记录一下还要多久才攒够一次修炼次数，在左下角新增了现存修炼次数以及本次修炼次数还需要杀多少怪物的进度条信息。**杀完一只怪进度条实时增长**」

### 5.1 数据从哪来（没有新加任何"击杀计数"）

**不需要单独记「杀了多少只」**。`PlayerCultivation.修炼次数累积` 本来就是个 **float**：
整数部分 = 现存次数，小数部分 = 距离下一颗的进度。
`NpcInstance.TakeDamage()` 在气血归零时调 `修炼.记录击杀(定义.境界)`，所以：

```
杀怪 → 记录击杀() → 修炼次数累积 += 1 × 等级差系数 → HUD 每帧读它 → 进度条自己就动了
```

HUD 侧**只读**，不碰任何业务逻辑。等级差系数见 [境界与功法设计](../design/境界与功法设计.md) §6.2。

### 5.2 条怎么画：**显示值"追"真值**，不是直接画真值

`PlayerHud.刷新修炼进度()` 维护一个 `显示修炼累积`，按 `修炼追赶速度`（默认 1.6 次/秒）往真实值爬。用户原话：

> 「如果单次增长大于一次修炼进度的话进度条满了就清空重新跑一下，比如单次长了 3.5 次修炼次数，
> 进度条最开始是 0，那就从 0 到 100 跑满 3 次，第四次跑到进度条一半」

实测（一次 +3.5）：

| 时刻 | 显示值 | 条 | 文字 |
|---|---|---|---|
| t=0.00 | 0.000 | 0% | 修炼次数 0　下一颗 0% |
| t=0.63 | 1.000 | **满** | 修炼次数 1　下一颗 100% |
| t=0.81 | 1.000 | 0%（停顿结束，重跑） | 修炼次数 1　下一颗 0% |
| t=1.44 | 2.000 | **满** | 修炼次数 2　下一颗 100% |
| t=2.25 | 3.000 | **满** | 修炼次数 3　下一颗 100% |
| t=2.44 | 3.000 | 0% → 继续跑 | 修炼次数 3　下一颗 0% |
| 结束 | 3.500 | **50%** | 修炼次数 3　下一颗 50% |

= **跑满 3 次 + 第 4 次跑到一半** ✓ 和用户描述一致。

三条规则：

| 情况 | 行为 |
|---|---|
| 进度跑满一格 | 停在 1.0、**`修炼满格停顿`（0.18 秒）**，让"满"这一下看得见，然后归零重跑 |
| 真值**变少**（修炼一次 / 闭关消耗） | `显示修炼累积` **立刻落下**，不做倒放动画（倒着跑很怪） |
| 首帧 / 读档 | 直接对齐真值，**不重放**（否则一进游戏就自己跑一遍） |

左边那个「修炼次数 N」用的是**显示值**的整数部分，不是真值 —— 这样数字和条**同步**跳（条满 → 数字 +1），
不会出现"数字已经 4 了、条还在跑第 3 格"。

实测（真杀一只 1 级怪）：真值 3.500 → 4.500，显示值 3.500 →（跑满）4.000 → 4.500，文字 `修炼次数 3` → `修炼次数 4`。
证据录像：`hud_xiulian_chase.mp4`（+3.5 一次）、`hud_kill_grow.mp4`（真杀一只）。

### 5.3 调参入口

| 想改什么 | 字段（`HudCanvas` 上的 `PlayerHud`） | 默认 |
|---|---|---|
| 条跑多快 | `修炼追赶速度`（次/秒） | 1.6 |
| 满格停多久 | `修炼满格停顿`（秒） | 0.18 |
| 条的颜色 | `修炼色` | 金 `(0.86, 0.72, 0.32)` |
| 数据源 | `修为`（留空自动 `FindObjectOfType`） | 自动 |

## 6. 坑

### 6.1 ⚠️ `Image` 没有 sprite 时 `fillAmount` 会被完全忽略

不管 `type` 是不是 `Filled`，**sprite 为空时 `fillAmount` 不起任何作用** ——
进度条永远满格、冷却遮罩永远是个满圆。（`NpcIndicator.cs` 里也记过同一条。）
所以生成器会先生成一张贴图资产再用：`hud_square.png`（4×4 纯白）——
给格子底、图标底、灰罩、冷却遮罩、条状进度**全部**用。
`PlayerHud.Awake` 里还有一层兜底：**哪个填充图缺 sprite 就现场生成一张**。

### 6.2 ⚠️ 三个条的文字都要描边

血/灵力条**几乎永远是满的**，白字压在实色上没事；但**修炼条经常是半格** ——
白字正好骑在"金填充 / 深底"交界上，不描边就糊掉。
`HudBuilder.建条()` 里统一 `加描边(文字.gameObject)`，三个条一起用，风格也一致。

### 6.3 ⚠️ 别用 `SetActive(false)` 关 F1 数值面板

`PlayerStatsDebugPanel`（F1 数值面板）是 **IMGUI `OnGUI`** 画的，而且**这个组件就挂在 `Player` 身上**。
想临时关掉它有两个办法：`面板.Visible = false`，或者 **`面板.enabled = false`**
（IMGUI 只在组件 enabled 时才跑 `OnGUI`，实测好使、更省事）。
**千万不要 `面板.gameObject.SetActive(false)`**：那会把整个 `Player` 关掉 ⇒
`ActiveSkillCaster.Update` 不再跑、**冷却永远停在初始值**，
而 `FindObjectOfType` / `GameObject.Find` 又都找不到未激活对象，
报出来的是"找不到 Player"这种和真正原因隔着好几层的错。

## 7. 怎么验证

HUD 是 **ScreenSpaceOverlay**，所以 **`Camera.Render()` 抓不到它**
（overlay 在所有相机之后直接画到屏幕）。必须用 `ScreenCapture.CaptureScreenshot`：

```csharp
ScreenCapture.CaptureScreenshot(路径);
yield return new WaitForEndOfFrame();   // 它是在帧末落盘的，要等
yield return null;
```

想看细节就把截图**裁一块再存**（`Texture2D.LoadImage` + `ReadPixels`），
否则 1920×1080 里 HUD 只占左下角一小条，根本看不清。

> ⚠️ `ScreenCapture` **偶尔会抓到全空白的一帧**（实测遇到过一张整片灰的图）。
> 稳妥做法：抓完检查像素有没有变化，空白就重试几次。

**悬停怎么自动测**（不用真的动鼠标）：走 uGUI 自己的管线 ——

```csharp
Vector2 屏点 = RectTransformUtility.WorldToScreenPoint(null, 格子.position);
var ped = new PointerEventData(EventSystem.current) { position = 屏点 };
var 结果 = new List<RaycastResult>();
EventSystem.current.RaycastAll(ped, 结果);            // 命中「底」
var 处理器 = ExecuteEvents.GetEventHandler<IPointerEnterHandler>(结果[0].gameObject);
ExecuteEvents.Execute(处理器, ped, ExecuteEvents.pointerEnterHandler);   // 等价于鼠标移上去
```

> ⚠️ `EventSystem.current` 在 **Edit Mode 下是 null**（普通 MonoBehaviour 在编辑器里不跑 `OnEnable`），
> 必须进 Play Mode 才测得到。
