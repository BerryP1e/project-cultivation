## 2. 【设计推演】为什么不能靠现成的做法

### 2.1 为什么必须写 shader

环境材质实测：**`Legacy Shaders/Diffuse`**（208 处引用，纯 Lambert），另有
`Transparent/Cutout/Diffuse`(36)、`Transparent/Diffuse`(5)、`Tree Creator Leaves`(2)、`Self-Illumin/Diffuse`(1)。
否掉的路：MaterialPropertyBlock 改内置 shader 的 `_Color.a` —— **透明度是每个 draw call 的属性、不是逐物体的**，
且内置 Opaque shader 忽略 alpha；逐物体统一降 alpha —— 边缘是**物体轮廓那样的硬边**，做不到柔和过渡。
故判断**必须逐像素**：shader 复刻 Lambert（`_MainTex * _Color`，`#pragma surface surf Lambert`），
再加"像素离轴心多远"的逐像素判断。**这就是"只处理这一块区域"的天然实现**：圆柱外像素 alpha 保持
`_Color.a`，混合结果与不透明完全一致→**画面与加功能之前一模一样**，不必按物体筛选，
也没有"物体一半在圆柱里就整块变透明"的问题。
（轴上的像素径向距离必然是 0 → shader 里的 `inside = 1` → 吃满透视强度。）

### 2.2 AlphaTest 队列 + `ZWrite On`

```hlsl
Tags { "Queue"="AlphaTest" "RenderType"="TransparentCutout" }
ZWrite On
Blend SrcAlpha OneMinusSrcAlpha
```

`Queue=AlphaTest`（2450）→ 在**所有不透明物画完之后**才画，混合时背景已就绪；
`ZWrite On` → 被透视的建筑**仍按深度互相遮挡**（照搬 ZWrite Off 会按 draw 顺序乱混）。

### 2.3 两条通路、判据教训、阴影结论

```
主相机上的 OcclusionTransparency（LateUpdate，每帧）
 ├─ ① 射线通路  相机朝主角 5 个高度点 RaycastAll → 命中的渲染体变透明（建筑/墙/石头，有碰撞体）
 └─ ② 包围盒通路 遍历树冠做「线段 vs AABB」相交 → 相交的树冠变透明（树，没有碰撞体）
```

**树冠没有碰撞体**：实测（village）树干 **153 个 `CapsuleCollider`**，树冠 **365 个子渲染体一个都没有**→
旧打射线实现**永远打不到树冠** ✗。树冠按**物件名**认：根与子件都以 `environment_Tree` 开头
（实测 9 品种：`environment_Tree_dashu_003`/`_zhangshu_01`/`_songshu_002`/`_taoshu_001` …）；
一棵树 = 最外层 `environment_Tree*` 根下所有渲染体，包围盒取并集。性能：只测**视锥内**的树
（`GeometryUtility.CalculateFrustumPlanes`+`TestPlanesAABB`），**树表 5 秒重建一次**；
规模 village 168/Sect 31/**宗门野外 1573** 棵，剔除后每帧仅几十棵。相交用 `线段近包围盒()`：
包围盒外扩 `树冠余量`（默认 0.35m）后做 **slab 法**线段 vs AABB，比 `Physics.Linecast` 便宜且**不依赖碰撞体**。

**阴影 pass 不能按名字查**：surface shader 带 alpha 系列 pragma 时**不会自动生成阴影 pass**（已知行为），
要给 pragma 加 `addshadow`；但本版本 `Material.FindPass("ShadowCaster")`/`"SHADOWCASTER"`/`"FORWARD_DELTA"`
全返回 **-1**（`FORWARD`=0、`META`=2、`passCount`=3）→**不能靠它判断阴影 pass 在不在**。改用**地面真值**：
关掉这些环境件投影→画面差 34,642 px；全局关阴影→差 34,842 px，几乎相等→
**场景 99.4% 的影子就是这些换了透视材质的物件投的**，换材质后**影子照常投射**。
"影子怪怪的"最可能是**地面被透掉、影子还留在上面**（像浮在空中）；判据不再透地面后应一并解决。

## 3. 已废弃方案：摄像机↔角色圆柱透视 ★已废弃

> ⚠️ 用户反馈：「算了，取消掉这个"摄像机透视"的修改，改为检测到摄像机与角色的连线中间有遮挡时，
> 为角色添加一个描边」。代码与场景组件**已全部删除**（`OcclusionFade.cs`、`OcclusionFade.shader`、
> Main Camera 上的组件）。保留本节因为两条教训与方案无关、仍有用：判据三版演进说明「在圆柱里 ≠ 挡住视线」；
> 测试脚手架的坑已经栽过五次。

### 3.1 参数与实现要点

「相机→角色」连线为轴撑圆柱，**柱内场景物件 70% 透视**、边缘柔和，**最好只处理这一块、别动整个场景**。
`OcclusionFade` 挂在 `Sect/Main Camera`：

| 参数 | 默认 | 说明 |
|---|---|---|
| 半径 | 2.2 m | 圆柱半径，以相机-角色连线为轴心 |
| 羽化宽度 | 1.4 m | 边缘柔和度：`smoothstep(半径, 半径+羽化, 径向距离)` |
| 透视强度 | 0.7 | 0.7 = 70% 透视（剩 30% 不透明度） |
| 起点留白 | 0.05 | 沿轴 0=相机、1=角色；贴相机的物件不透视 |
| 终点留白 | 0.92 | 角色脚下不透视（透掉地面很难看） |
| 淡入速度 | 6 | 开关时淡入淡出，避免突变 |

每帧 `LateUpdate` 把 `_OcclA`(相机)/`_OcclB`(角色)/`_OcclParams`/`_OcclParams2` 用 `Shader.SetGlobalVector`
喂进去（**参数全局、逐像素判断，与物体筛选无关**）；**只在运行时换材质**——`new Material(透视Shader)`+
`CopyPropertiesFromMaterial` 带过 `_MainTex`/`_Color`/`_Cutoff` 赋给 `renderer.sharedMaterials`，
**不动 `.mat` 资产、不动预制体、不写回场景，退出 Play 自动还原**；**同一原始材质只生成一份替换材质**共用→
合批不散；跳过 `Nature/Tree Creator Leaves`（换掉丢风吹摇摆）与 `Self-Illumin/Diffuse`，Console 会列出来。

### 3.2 【坑·测试脚手架】抓帧比对四个坑（+ 第 5 条）

1. **`Quad` 法线是 -Z**——`LookRotation(-轴)` 让它**背面朝相机被剔除**，板子只渲染出 164px。
2. **板子背光时 Lambert 全黑**，与暗背景无差异→两图几乎一样；先把 `RenderSettings.ambientLight` 设白。
3. **抓图顺序写错**：先建板子后抓"无板"基准，两图当然一模一样。
4. **玩家掉出世界**：测试里冻结又恢复 `CharacterController`，角色掉到 `y ≈ -78760`，相机跟掉→
   圆柱切不到东西、**所有扫描都是 0**，像功能完全没生效→**每次先打一行"复位确认：相机=… 角色=…"**，
   y 不合理就立刻停。
5. **同步 lambda 改参数后没等帧**：设完 `透视强度` 立刻抓图，`LateUpdate` 还没重喂全局参数→两图一样、全判 0
   →"设参数→等帧→抓图"必须写成**局部迭代函数**（`IEnumerator` 局部函数可 `yield`，lambda 不行）。

### 3.3 【坑】判据三版演进：圆柱 → 屏幕圆盘 → 角色屏幕矩形

**v1（圆柱）错**：轴心是相机→角色胸口、离地约 2m，地面就在轴心下方 ~2m→**落在半径 2.2m 圆柱内**被透掉，
可地面没挡住角色。**「在圆柱里」≠「挡住摄像机拍角色」。** 用户原话：

> 「有一部分靠近角色的脚下的场景也变得透明化了，这不是我的预期，
> 我原本的预期是只取消头顶有的，准确来说是**挡住了摄像机拍角色的**」

**v2（以角色为圆心的屏幕圆盘）也错**：延伸到脚下甚至更下，实测脚以下 246px、脚以上仅 56px——反向。
**v3 = 两条同时满足**：① **屏幕上与角色矩形重叠**（矩形=脚→头竖条，左右各扩 `横向留白`，
由角色**实际屏幕尺寸**驱动，镜头远近自动适配）；② **比角色更靠近相机**
（`smoothstep(角色距离-0.6, 角色距离-0.05, 该像素到相机距离)`，0.55m 斜坡过渡防硬缝）。
几何上等价于「以相机为顶点、穿过角色屏幕轮廓的**锥体**，在角色深度截断」；**地面在矩形外**，永不被碰。

```hlsl
// x 预先乘了纵横比，两轴都变成「以屏幕高为单位」，宽屏下形状才对
float2 p = float2(uv.x * aspect, uv.y);
float2 outside = max(max(_OcclRect.xy - p, p - _OcclRect.zw), 0.0);   // 矩形外距离
half covers = 1.0h - smoothstep(0.0h, 羽化, length(outside));
```

**参数也换了**（旧的 `半径/羽化宽度/起点终点留白` 已删除）：`横向留白` 0.35（矩形左右各扩「角色屏幕高 ×
该值」）、`纵向留白` 0.08、`羽化系数` 0.55（矩形外柔化带宽，单位：角色屏幕高）、`透视强度` 0.7。
**实测（受控遮挡，相机在角色→建筑延长线上、视线确认被挡）**：

```
① 默认视角    脚y=157 头y=192（屏幕高35px）  脚以上=21  脚以下=4 (最深9px)     ✓
② 受控遮挡    脚y=176 头y=183（屏幕高6.9px） 脚以上=74  脚以下=33(最深仅3px)   ✓
③ 受控遮挡近  脚y=176 头y=183（屏幕高7.2px） 脚以上=65  脚以下=45(最深仅4px)   ✓
```

看**「脚以下最深几 px」**：v2 圆盘延伸到脚下 6~7px 外一大片，v3 只剩 **3~4px**——
正是羽化带宽度（0.55 × 角色屏幕高），是**设计中的柔和边缘**，不是泄漏。
**为什么废弃**：判据始终在"透哪些物件"打转，而用户要的是"挡住摄像机拍角色"本身；现役改成给**角色本身**
加描边（§4），**一个场景组件都不用动**，也不存在"透错地面/透错建筑"。

## 4. 现行方案：角色遮挡描边

### 4.1 需求与方案

> 「改为检测到摄像机与角色的连线中间有遮挡时，为角色添加一个描边」

**只给角色自己挂 2 个副本、一个组件都不用动**（旧方案要给场景 248 个环境件换材质、影响整个环境）；
被挡时看到角色的**描边+半透明剪影**透过遮挡物显形。文件：`Assets/Scripts/Core/OcclusionOutline.cs`
（挂在 `Sect/Main Camera`）+`Assets/Shaders/CharacterOutlineRim.shader`+`Assets/Shaders/CharacterOutlineFill.shader`

### 4.2 描边靠**模板缓冲**，不是 Pass 顺序

| 材质 | 队列 | 做什么 |
|---|---|---|
| `CharacterOutlineFill` | `Overlay`(4000) | 画**原网格**（不膨胀），把 **stencil 写成 1** |
| `CharacterOutlineRim` | `Overlay+1`(4001) | 画**沿法线膨胀的网格、只画背面**（`Cull Front`），**只在 stencil ≠ 1 处画** |

两者都 `ZTest Always`+`ZWrite Off`，**一定能穿过遮挡物看到**。
> ★ **必须用 stencil**。第一版「先画膨胀外壳、再画剪影盖中间」→角色变**一整块实心黄**：
> `ZTest Always` 下没有深度能挡住外壳背面，背面本就铺满轮廓，剪影再半透明叠上去→全糊。
> stencil 把「剪影已画过的地方」从外壳挖掉，剩下的才是**一圈边**。

**实测（过角色中心横切像素，RGB 十六进制）**：关——角色处一片暗色（`20201A`…`4D4D4D` `6A6961` `575951`…`1B1916`）；
开 0.10——两端实心外圈（`FFE549` `FFE247` `FFE74A` `FFE548`/`FFE549` `FFE649` `FFE64A` `FFE448`），
中间半透明剪影（`B69C4E` `EFCA48`…`DBB945` `E9C753` `FBD350`）=「一圈边+看得见人」✓

### 4.3 ★★★【团结引擎 surface shader 三个坑】

连续失败三轮，每个只报一行英文错：

1. **`#pragma surface` 不能包在 `Pass { }` 里**→
   `Parse error: syntax error, unexpected TOK_PASS, expecting TOK_SETTEXTURE or '}'`。
   **正确写法照抄 `GhostSpirit.shader`**：`CGPROGRAM` 直接放 `SubShader` 里，
   渲染状态（`ZTest`/`ZWrite`/`Cull`/`Blend`/`Stencil`）也放 **SubShader 级**，不写 `Pass`。
2. **`Input` 结构体必须自己声明**，本版本**不会自动生成**→
   `Unexpected identifier "Input". Expected: ')'`（报在 `void surf (Input IN, …)` 那一行）：
   `struct Input { float3 worldPos; };   // ★ 必须显式写，哪怕字段用不上`
3. **`CGINCLUDE … ENDCG` 放 SubShader 里解析不过**（同 1 的 TOK_PASS）；
   几个 Pass 共用声明时**老老实实复制那几行**，别用 CGINCLUDE 消重。

> `Fallback Off` 可以；`Stencil { Ref 1 Comp NotEqual }` 也正常。配色坑：
> **`o.Albedo = 0; o.Emission = 颜色`+`surf Lambert` 出来的不是设定颜色**（实测角色处纯白 `FFFFFF`），
> 要改**自定义 unlit 光照函数**：
> ```hlsl
> inline half4 LightingUnlit (SurfaceOutput s, half3 lightDir, half atten)
> { return half4(s.Albedo, s.Alpha); }
> // #pragma surface surf Unlit ...   然后 surf 里 o.Albedo = 颜色; o.Alpha = 透明度;
> ```

### 4.4 遮挡检测：每帧射线

相机朝角色 **3 个高度**（脚 0.15/腰 0.5/头 0.85）各一条射线，任一条在到达角色前撞到别的就算被挡：
射线长度取 `距离 - 0.05`，跳过 `命中.collider.transform.IsChildOf(角色)`（否则打到角色自己的
`CharacterController` 与骨骼碰撞体）；`检测间隔帧` 可调（默认每帧，3 条很轻）；
描边用 `描边颜色.a *= 强度` 淡入淡出，不会"啪"地闪出。
**实测**：无遮挡→自动描边 17 px ✓ 不显示；受控遮挡（视线被挡=True，挡它的是
`environment_building_qinghuata_02_d0`）→217 px ✓ 自动显示，穿墙时建筑蓝色(`012A50`…)、
角色处出现 `FFE64A` `C1A239` `E4BF40` `C3A447` `FFE548` ✓ 透过遮挡物可见。
副本共用原件 `bones`/`rootBone`，**骨骼动画完全同步**（描边精确覆盖角色像素、无偏移，不是绑定姿势）。

### 4.5 参数与遗留

| 参数 | 默认 | 说明 |
|---|---|---|
| 描边颜色 | 暖黄 (1, 0.82, 0.25) | 外圈颜色 |
| 描边宽度 | 0.08 m | 沿法线膨胀多少；**角色在屏幕上越小越要调大** |
| 剪影颜色 | 同色，A=0.35 | A=0 只剩一圈边、中间全透 |
| 淡入速度 | 7 /秒 | |
| 采样高度 | 0.15 / 0.5 / 0.85 | 打射线的高度比例 |
| 调试_强制显示 | 关 | 勾上=不管有没有被挡都显示，确认描边画得对 |

> **描边宽度是"世界单位"，不是像素**：默认镜头角色约 35px 高时 0.08m ≈ 2px、0.10m ≈ 3px；
> 镜头拉近角色变大，同宽度看上去变细——觉得细就加大。
**遗留**：副本运行时创建（`Awake`）、**不进场景文件**，退出 Play 自动消失；
玩家换装/换模型后需重建副本（目前没有监听，重启 Play 即可）。

### 4.6 【测试脚手架·又踩三个】

1. **`FindObjectsOfType` 默认不含未激活对象**——副本初始 `SetActive(false)`，会数出"副本 = 0 个"以为没建出来，
   其实建了 2 个；要数用 `角色.GetComponentsInChildren<Transform>(true)` 或 `Resources.FindObjectsOfTypeAll`。
2. **`var a = x, b = y;` 不合法**（CS0819 隐式类型不能有多个声明符）→ 拆两行。
3. 判据别用"暖色像素数量"：**场景本身就有 64896 个暖黄像素**（大地/建筑都暖色）；
   要比就比**开关前后同位置差异**，或直接打一条横切像素。

## 5. 「大门进不去」＝ Boundary 隐形墙

### 5.1 问题与诊断结论

> 「`environment_Building_Gongdian_001_g`，这个被我用于大门的场景建筑的碰撞体好像有点问题：
> 它的碰撞体把门口给挡住了，角色进不去」

沿穿门方向逐条扫描，**第一命中者名单里 `Gongdian_001_g03` 一次都没出现过**（唯一相关命中是
`diaojiaolou` 邻居楼）——**门的碰撞体是干净的**。真正挡路的：

| 挡住者 | 说明 |
|---|---|

### 5.3 【副作用·要知道】删掉边界后没有围栏了

`Boundary` 是**唯一**阻止玩家走出场景的东西。删掉后玩家可以走出原来那圈八角形范围；

若以后要重新圈，**别用一整圈墙**——把墙摆在门两侧、**在门洞位置留缺口**，让门真正成为围栏上的出入口。

### 5.4 【方法·以后查「走不过去」照这个来】

**先别猜是哪个物体的碰撞体**，按序查最快：

1. **射线打一次命中者**：沿角色要走的方向看 `RaycastAll` 排序后**第一个**碰撞体——
   这一条就能把"是门自己"还是"别的什么"分开（这里靠它排除掉门）。
2. **玩家尺寸胶囊推进**：`Physics.CheckCapsule(底+0.3, 底+1.5, 0.3)` 沿方向每 0.2m 推一次，记录**卡住位置**
   与该处 `OverlapCapsule` 命中者+Y 范围——区分"整层高的墙"与"矮处门槛"。
3. **双轴扫描**：两轴向各扫一遍，列出"哪些横向位置能整条走通"——这里靠它发现门洞自由量仅 0.8m
   （几何净宽约 1.4m）。
4. **俯视图**：`capture_scene_view`+`focus_object` 看物体长什么样，**别靠尺寸数字猜朝向**。
5. **驱角色走一遍录像**：`record_game_view`——关键突破，"从墙外走 24m 畅通"与"从墙内走被拦"一对比即锁定起点侧。

### 6.3 材质替换三条铁律（两通路共用，抽在 `遮挡素材.cs`）

```

  · 把 r.sharedMaterials（原数组）存进台账（`遮挡素材.台账`）
  · 造一份透明材质【按源材质缓存】
  · r.sharedMaterials = 透明副本数组
不再遮挡（超过 保持 秒）：
  · r.sharedMaterials = 原数组
```

1. **绝不改 `sharedMaterial` 指向的材质本身**：树冠材质**多棵树共用**（实测 9 品种、几十个材质服务 563 个物件），
   改一处会让**所有**树一起变透明；只改渲染器的 `sharedMaterials` **数组**。
2. **透明副本按「源材质」缓存，不是按渲染器** → 500 棵树只有几十个材质实例，不爆内存。
3. **离场必须原样还回**（`OnDisable`/`OnDestroy` 调 `全还原()`），否则退出 Play 后场景文件留下被改过的材质引用。

`Legacy Shaders/Transparent/Cutout/Diffuse`，再退 `Unlit/Transparent`。树冠原材质本有三种
（`Diffuse` 153/`Transparent/Cutout/Diffuse` 140/`Transparent/Diffuse` 67），统一换真混合版本，观感一致。
两档透明度：`透明度`（默认 0.22）= 建筑，`树冠透明度`（默认 **0.12**）= 树冠，更透一点，尽量别挡视线。

## 7. 水墨淡出（2026-10-03）：把「半透明」改成「墨化开」

需求原话：「经过一些建筑和树时不是会透明化吗，我希望能够是淡入淡出的一个水墨效果」。
表现语义定下三件：**整体渐隐 + 边缘墨散 + 留一层淡墨剪影**。

| 原来 | 现在 |
|---|---|
| 硬切（只有 `保持` 0.12s 防闪） | `_Fade` 按时间插值：**淡出 0.30s / 回场 0.40s**（回场略慢，「啪」地弹回来很难看） |
| 换 `Legacy Shaders/Transparent/Diffuse`（丢光照/丢纸纹，像塑料变半透明） | 换自写 **`Cultivation/InkDissolve`**：去饱和 + 向纸色偏 25% + **三平面程序化墨蚀** + 边缘墨色 + 叠宣纸纸纹 |
| 一份副本按源材质缓存，alpha 写进材质 | 材质仍按源材质缓存（500 棵树 = 几十个实例），但 **`_Fade` 走 `MaterialPropertyBlock` 按渲染器逐帧设** —— 一份材质被多个渲染器共用时，写材质会让它们一起淡出 |

三条实现要点（都是坑换来的）：

1. **`Queue=Transparent` + `ZWrite On` + `clip(a-0.01)`**：淡出必然进透明队列，ZWrite 一关，树叶/墙体自己穿插就炸排序；
   但被侵蚀掉的像素 alpha=0 又**不能写深度**（否则空洞会挡住它后面的东西）⇒ 用 `clip` 让它们不写深度。
2. **必须自带 ShadowCaster pass**：没有它，材质一换**影子当场消失**（比物体淡出还显眼）。影子里做了同一套侵蚀，所以影子跟着一起化掉。
3. **`_Wash` 不能写成「整体提亮到纸色」**：第一版那样写，暗场景里淡出的柱子亮得像块白板、比周围亮一大截。
   改成**保留它自己的亮度结构**，只去饱和 + 25% 纸色 + ×1.15。

`遮挡素材.cs` 的入口从「变透明(alpha)」改成 **`换成水墨(r)` + `推进(r, 遮挡, 参数)` + `还原(r)`**；
`OcclusionTransparency` 新增 `淡出秒 / 回场秒 / 侵蚀 / 树冠侵蚀 / 墨边宽 / 墨边强度 / 纸纹`，
并按「是不是树冠」给两套参数（树冠是 billboard 片、365 个渲染体 ⇒ 侵蚀与墨边都减半）。
`透明度` / `树冠透明度` 两个老字段**语义变成「淡到最透时保留的剪影」**（0.28 / 0.16），不再是 alpha。

**实测**（`Sect`，临时把「建筑透明」也打开；相机与玩家手工摆位让炼丹阁挡住；录像 `screenshots/水墨淡出演示.mp4`，48s 慢放）：

```
起始             台账=0  进度=—
第1轮 淡到最透    台账=3  进度=1.00     ← 3 个渲染体（炼丹阁子部件）
第1轮 回场后      台账=0  进度=—        ← 材质完好还原
第2轮 淡到最透    台账=3  进度=1.00
```

> ⚠️ **打包注意**：这个 shader 是运行时 `Shader.Find` 找的，**没有任何材质引用它** ⇒ 出包时要么加进
> `Always Included Shaders`，要么让工程里某个材质引用它，否则会被剥离、静默退回老的透明方案。

### 7.1 ★【坑】存进场景的组件：**非序列化容器反序列化后是 null**（每帧 NRE）

`OcclusionTransparency` 是**序列化在场景里**的（Sect / 3C / 塔的主相机上都有）。这次给它加了几个
`readonly Dictionary/List` 字段（在字段初始化器里 `new`），结果运行时**每帧**抛
`NullReferenceException ... LateUpdate () (at OcclusionTransparency.cs:145)` —— 那一行正是 `_本帧.Clear()`。

**根因**：这几个容器不是序列化字段，从场景反序列化出来的实例上它们是 **null**，字段初始化器**没有**兜底。
**修法**：字段去掉 `readonly`，加 `void 确保容器()`（为 null 就地 new），在 `Awake` 与 `LateUpdate` 开头各调一次。

> **通用教训**：**「运行时由 `场景自举` AddComponent 加上的组件」和「存进场景的组件」要区别对待** ——
> 后者必须能容忍「所有非序列化字段都是 null」。见 [踩坑总库 B93](../ai/踩坑总库.md)。
### 7.2 ⚠️ 第一版做过头了 —— 用户 2026-10-03 的反馈与回退

第一版把"墨感"全套默认打开了，用户看到实物后明确否掉三样：

### 7.3 ★★ 真正的病根：**丢了贴图的 alpha**（这才是「片状物 / 像盖了张纸」的元凶）

7.2 那轮只把 ZWrite 拆开了（确实好一点），但用户复看后仍然说「还是有一片片的片状物」。
继续查才发现**真凶跟 ZWrite 无关**：

```
树 = environment_tree_purple_001_01
材质 = environment_tree_purple_001_01
shader = Legacy Shaders/Transparent/Cutout/Diffuse     ← 树叶形状是"抠"出来的
贴图 = environment_tree_purple_001_01（256x256，带 alpha）
```

**叶子/卡片的形状写在 `_MainTex.a` 里**（抠空的叶子），而我的 shader 算不透明度时**只用了自己的淡出值**：

```hlsl
// 第一版（错）
float3 albedo = tex2D(_MainTex, i.uv).rgb * _Color.rgb;   // 只取 rgb
float a = lerp(1.0, _Ghost, f);                            // alpha 自己算
```

⇒ 抠空的卡片变成**整块实心板**。这**同时**解释了两个现象：
① 「**树冠变成一块块的片状物**」= 一片片没抠空的卡片；
② 用户截图里那个「**镜头前盖了一层宣纸纹理**」= 离相机最近的那张卡片**整块糊在屏幕上**，
正好又被屏幕纸纹铺满，看着就像一张纸。

**修法**（两处）：前向 pass 里 `a *= tex.a * _Color.a` 并且 `if (texA < 0.02) discard;`；
ShadowCaster pass 里也 `clip(tex2D(_MainTex, uv).a - 0.02)`（叶子影子也得是叶子形状）。

**实测**（Sect，跟随视角走过树下）：树下 台账=9 进度=1.00 → 走完 台账=0；
静帧 `screenshots/修后2_树下走过.png`（叶形回来了、地面透得出来）、
录像 `screenshots/水墨淡出_叶子修好.mp4`。

> **通用教训（今天最值钱的一条）**：**换 shader 时，"上一版材质里哪些通道在起作用"必须逐条对齐** ——
> 颜色、alpha、`_Cutoff`、贴图 ST、混合模式、ZWrite、Cull、光照模式。
> 我接手的是一批 `Standard` / `Legacy Transparent(Cutout)/Diffuse` 材质，**只对齐了颜色**，
> 结果树叶（靠 alpha 抠形）和卡片（靠 alpha 混合）全变成了实心板。
> **判据**：换 shader 后先问一句「**这个物件的形状是靠 mesh 还是靠 alpha？**」

### 7.5 轻墨感预设 + 两个"看起来像没生效"的真 bug

**轻墨感预设**（用户 2026-10-03 选的 B 档）：`侵蚀 0.2 / 墨边强度 0.35 / 纸纹 0.08 / 淡出 0.35s`，
`树冠侵蚀` 仍为 **0**（卡片量大）。比"纯淡出"有一点墨味，但不会像第一版那样糊成纸板。

**bug ①：场景名大小写 ⇒ 整个遮挡在村庄里被静默关掉**
表资产 `Assets/resources/场景特效开关.asset` 里那行写的是 **`village`**，而 `Scene.name` 是 **`Village`**，
`场景特效开关.取()` 用 `==` 比 ⇒ **取不到** ⇒ `建筑遮挡启用/树冠透明` 全 false ⇒ 组件 `enabled = false`。
**日志里那句「建筑透明 / 树冠透明 都没开 → 关闭遮挡与特效开关组件」就是它**，一直没人注意。
修法：`string.Equals(..., OrdinalIgnoreCase)`（`任务引导` / `日常循环` / `场景自举` 早就是这么干的，这里漏了）。

> ⚠️ **当前表里的开关**（改了要重跑导入器或手动改资产）：`Sect` 建筑 ✅ 树冠 ✅｜`Demon-Suppressing Tower` 建筑 ✅｜
> `village` / `Sect_Wilderness` 只有树冠 ✅｜`3C_Testbed` 两个都关。
> 也就是说**村庄里建筑本来就不会淡**（表就是 false），要开得改表。

**bug ②：影子不跟着淡 ⇒ 看着像"什么都没发生"**
shadow map **没有 alpha 混合**，而第一版只在「侵蚀 > 0」时才在影子上打洞 ⇒
建筑本身淡到 22% 了，**它的影子还是实心黑**。俯视角下影子占的画面比楼还大 ⇒ 用户自然会觉得
「建筑的遮挡消失效果没了」。修法：影子 pass 里按 `_Fade` 做**噪声抠除**
（`clip((1 - _Fade*1.2) - noise)`）：`_Fade=0` 时影子完整，`_Fade=1` 时影子全没，中间是一块块散掉。

**实测**（Sect，完全照表、不强制任何开关）：

t+0.50s  台账=3  进度=0.75  挡者 shader = Cultivation/InkDissolve
t+1.00s  台账=3  进度=1.00

> **通用教训**：**"开关表按名字查"这类代码，一律 `OrdinalIgnoreCase`** ——
> 大小写不一致不会报错，只会让功能**静默消失**，而且日志看起来"很正常"（"都没开"）。
### 7.6 ★ 树只淡「叶子」，树干/根/枝**不淡**（2026-10-03）

用户：「现在整个树都会因为遮蔽消失，**包括树干**，但是我说过树干是不消失的」。
（注：之前村庄里"看不到树冠透明"是因为 §7.5 的大小写 bug 把整个组件关掉了；
修好之后树冠**第一次真的生效**，于是"连树干一起淡"这个老毛病才暴露出来。）

**判据不是猜名字，是材质**。实测 7 种树型（`village`）后发现这些树包结构统一：

| 树型 | 木质部（**不淡**） | 叶子（**淡**） |

| `Green_003` / `Green_005` | Diffuse | Cutout |
| `dashu_001` | `_a` Diffuse | `_b` Cutout + `_c/_d/_e` Transparent/Diffuse |

if (只淡树冠 && 遮挡素材.是树冠(r) && !遮挡素材.是叶子(r)) return;   // 树干不淡
