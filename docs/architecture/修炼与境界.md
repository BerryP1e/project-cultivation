## 1. 修炼小屋装配与接线坑

「修炼小屋」三页界面（闭关修炼 / 境界突破 / 转修功法）代码和 prefab 都在
`Assets/Prefabs/CultivationUI.prefab`，坏的是**接线**。

### 1.1 三件套装配关系

```
场景里的「cultivation room」
  └─ StationInteractable  （类型=修炼，交互距离 4 米，有 BoxCollider）
       └─ 界面预制体 = Assets/Prefabs/CultivationUI.prefab
                         └─ 挂 CultivationUI 脚本，UI 全部由代码在 Awake 里搭

玩家
  └─ StationInteractor    （右键交互；靠近显示「右键 修炼」提示）
```

`StationInteractor.打开界面()`：**`界面预制体 != null` 就 Instantiate 它，
否则弹一块「界面尚未设计」的占位幕布**。

> **诊断口诀**：右键后看到「界面尚未设计，这里是空白幕布占位」= `界面预制体` 是空的，
> **不是 UI 坏了**。

装设施用编辑器菜单 **`Cultivation/设施/安装交互`**（`StationSetup.cs`，用活动场景、没有硬编码路径，可以放心跑）。
但它**只装 `StationInteractable`，不接 `界面预制体`** —— 那一步得手动接。

### 1.2 ★【坑】`LoadAll<T>()` 按**资产名**排序，把境界表打乱了

`DataTableImporter` 里的写法：

```csharp
修炼.境界表 = LoadAll<RealmDefinition>().ToArray();   // ✗ 名字序！
```

`LoadAll` 内部 `result.Sort((a,b) => string.Compare(a.name, b.name, ...))`
—— 境界表于是变成 **元婴第10层 / 元婴第1层 / … / 化神十层 / 炼气第1层**（按名字）。
而 `PlayerCultivation.查境界()` 里有个 **`else break`**，隐含要求数组**按等级升序**：

```csharp
if (d.等级 <= 最佳.等级) continue;
if (d.累计灵气 <= S) 最佳 = d; else break;    // ★ 顺序一乱就提前退出
```

**实测后果**：玩家明明是「炼气第1层」，`查境界(0)` 却返回 **「元婴第10层」**
→ 修炼小屋的「转修后境界预估」显示成「元婴第10层」，看起来像转修功能坏了。

> 最阴的是**主界面显示是对的** —— `当前境界` 用的是**全表扫描**（不依赖顺序），
> 所以「炼气第1层」正常，只有 `查境界` 这一条路径错。两个函数两种写法，只有一种踩了坑。

**两处都修了**：

1. 接线时**显式按等级排**：`境界们.Sort((a,b) => a.等级.CompareTo(b.等级));`
2. `查境界` 改成**与顺序无关**：全表扫「累计灵气 ≤ S 且等级最高」的那一个，去掉 `else break`。
   90 条数据，开销可以忽略。

> **规矩**：凡是「按顺序取第 N 项 / 提前 `break`」的表，接线时都要显式排序，
> **不要相信 `LoadAll` / `Resources.LoadAll` 的顺序**。

### 1.3 ★【坑】团结引擎的 guid 有**两种写法**，别拿文件搜索判"引用断了"

`CultivationUI.prefab` 里 `m_Script` 写的是 **32 位十六进制** guid
（`a30c15ee55cf63c469f41e699bb558c9`），而 `CultivationUI.cs.meta` 里是**长格式**
（`Xnkf5iu...=`，64 字符）。

拿"扫所有 .meta 找这个 guid"的方式判断，**误判成"脚本引用断了"**，
于是把 prefab 里的 guid 换成长格式 —— **反而把好的弄坏了**
（Unity 报 `Could not extract GUID in text file ... at line 45`）。

> 团结引擎：**`.meta` 用长格式、YAML 里的引用用 32 位格式，是同一根 guid 的两种写法。**
> 判断引用有没有断，**要看 Unity 自己怎么说**（`PrefabUtility.LoadPrefabContents` +
> `GetComponent<T>()` 是不是 null），别靠文件搜索比对。
> 之前那个「Mixusage Warning」里 32 位/长格式混用也是同一件事。

### 1.4 【坑】父物体换了，坐标就白算

`搭转修页` 的标题和功法行是**列表块**的子物体，锚的是**列表块左下角**（高 `h−86=550`），
不是页根（高 636）。按页根算成 `h−46=590`，标题就被推到框外面去了。

原坐标是标题 `h−86−46=504`、第一行 `h−86−56=494` —— **两者重叠**，
标题被行整个盖住（概念图里标题是有的）。

修正后：标题 504、行从 `h−186=450` 起，间隔 54。实测
`标题 504~536 / 行0 450~496 / 行1 396~442`，不再重叠 ✓

### 1.5 转修页的明确反馈

原来 `点确认转修` **成功时一个字都不写**，失败时只把提示塞进「转修后境界预估」那行小字
—— 用户很容易当成"点了没反应"。现在三种情况都有明确文字：

| 操作 | 界面显示 |
|---|---|
| 没点功法行就点确认 | `请先在上面点一门功法` |
| 点了当前正在修的那门 | `已经在修「太虚炼气诀」了` |
| 转修成功 | `已转修到「太虚炼气诀」　当前境界：炼气第1层` |

> ⚠️ 反馈要**写在 `刷新()` 之后** —— `刷新()` 会把那行重算成预估，先写会被盖掉。

### 1.6 实测：转修两个方向都通

```
低→高：[修炼] 转修（低→高）：太虚炼气诀 → 青云剑诀｜K 1.0 → 2.6｜总灵气 0 → 0（扣 5% 损耗）
高→低：[修炼] 转修（高→低）：K 2.6 → 1.0｜境界不提升（封顶 1 级）｜总灵气 0 → 0
```

转完之后：界面「功法信息」跟着换、列表里的 `▶`（当前功法标记）跟着挪、预估按新功法重算 ✓

> 转修改的是 `UIPanelData.当前功法`（**场景对象的字段**），所以**退出 Play 就还原** ——
> 真存档要靠 `SaveSystem`。别把「转完再进 Play 又变回去了」当成 bug。

### 1.7 Sect 场景里没有修炼小屋

```
Sect.scene     cultivation room = 0 个    StationInteractable = 0 个    CultivationUI = 0 个
3C_Testbed     cultivation room + 4 台设施齐全，修炼界面已接上
```

要把修炼小屋搬进 Sect：把屋子模型放进去 + 跑 `Cultivation/设施/安装交互` + 接 `界面预制体`。

## 2. 转修后**实际功法没换**：`当前功法` 的唯一真来源

用户报：「转修没换过来，只是修炼小屋里显示的换了，**实际的功法没换**」。
根因是**同一个「当前功法」在三个地方各存了一份，谁都不通知谁**：

| 位置 | 存的是什么 | 谁在用 |
|---|---|---|
| `UIPanelData.当前功法` | **唯一真来源** | 界面、`PlayerAbilityLoader`、读档 |
| `PlayerCombatStats.当前功法` | **自己的一份拷贝** | **玩家实际战斗属性的汇总** |
| 玩家身上挂着哪个普攻组件 | 隐含的第四份 | 实际打出来的招式 |

转修只改了第 1 个，于是：界面换了、**属性还在按旧功法算**、**普攻还是旧的那套**。

### 2.1 【修法一】`PlayerCombatStats` 自动跟随

它原来的 `当前功法` 是**纯 Inspector 手填字段，全项目没有任何代码写它**。
实测：界面写着「青云剑诀」，它却还停在 09-21 手填的「太虚炼气诀」，
汇总攻击一直是 57 不动 → 看起来就像"转修没生效"。

现在 `Update()` 里每帧比一次引用，不一致就跟 `PlayerCultivation.当前功法` 同步并 `Recalculate()`：

```csharp
void Update()
{
    if (修炼 == null) 修炼 = GetComponent<PlayerCultivation>();
    if (修炼 != null && 修炼.当前功法 != 当前功法) 同步功法();
}
```

> **为什么用「每帧比较」而不是事件**：换功法的路径不止一条（转修 / 读档 / 以后的剧情），
> 谁都有可能忘了发通知。一次引用比较而已，但能彻底消灭这类静默不一致。

### 2.2 【修法二】普攻组件改成「启用/停用」，不销毁重建

`PlayerAbilityLoader` 原来是「需要 → `AddComponent`、不需要 → `Destroy`」。两个致命问题：

1. **手工挂在玩家身上的那份永远不会被卸载** —— 代码里 `if (GetComponent(type) != null) continue;`
   （"已经手工挂着了，不重复装"），而卸载循环只遍历**自己装的** `已装载` 字典。
   → 换功法之后**新旧两套普攻同时生效** ✗
2. **真用 `AddComponent` 新建的话配置全丢** —— `BasicSword01` 身上有
   `剑模型资源`(base_sword.FBX)、模型朝向补偿、悬浮偏移、绕行长短轴/周期、瞄准高度……
   全变默认值 ✗

**改成：只在「配置表里登记过的能力类名」范围内切换 `enabled`**，谁挂的、配了什么一概不动。
停用前对 `YufengFlight` 调 `强制落地()`。

配套：`BasicSword01` 加 `OnDisable()` 收掉剑体。剑体是**懒创建**的
（`更新悬浮` 里 `if (剑体 == null) 确保飞剑存在()`），所以停用收掉、再启用会自动重新生成 ✓
> 只在 `OnDestroy` 收的话，停用之后那把剑会**冻在原地继续挂着** ✗

### 2.3 【缺配置】功法 → 普攻的绑定少了一条

`PlayerAbilityLoader.普攻方法表` 里只有 `basic_sword_01 → BasicSword01`，
**`basic_remoteattack_01` 根本没登记** —— 而
`太虚炼气诀.普攻方法id = basic_remoteattack_01`。所以转到太虚炼气诀时
**一个普攻都装不上**。已补上 `basic_remoteattack_01 → BasicRemoteAttack01`。

> 两个普攻脚本的自给自足程度不一样，记一下：
> · `BasicRemoteAttack01`：**专为运行时 AddComponent 设计** —— `Awake` 自接
>   `玩家战斗属性`/`目标管理器`/`动画`，还自己 `Resources.Load("技能动作/普攻_远程_01")`。
>   所以新建出来就是能用的 ✓
> · `BasicSword01`：同样会 `Resources.Load("Weapons/base_sword")` 兜底模型，
>   但**悬浮/绕行/瞄准那套参数是 Inspector 里调过的值**，重建就没了 —— 所以它必须
>   以「手工挂 + 切 enabled」的方式用 ✓

### 2.4 实测（全链路）

```
① 刚进 Play（青云剑诀）  修炼.功法=青云剑诀  CombatStats.功法=青云剑诀  一致=True
                        汇总 攻击=72 气血=370   BasicSword01=启用  Remote=不存在  飞剑实例=1
② 转修到太虚炼气诀      [PlayerAbilityLoader] 停用 BasicSword01
                        [PlayerAbilityLoader] 启用 BasicRemoteAttack01
                        修炼.功法=太虚炼气诀  CombatStats.功法=太虚炼气诀  一致=True
                        汇总 攻击=57 气血=420   BasicSword01=停用  Remote=启用  飞剑实例=0
③ 再转回青云剑诀        [PlayerAbilityLoader] 启用 BasicSword01 / 停用 BasicRemoteAttack01
                        攻击=72 气血=370 复现 ✓
```

> ⚠️ **`当前功法` 只能有一个真来源（`UIPanelData.当前功法`）**。
> 以后再加任何"跟着功法走"的东西（特效、音效、被动加成），
> **一律从 `PlayerCultivation.当前功法` 读**，不要再存第二份拷贝。

## 3. 功法等级 ↔ 境界等级：换算与门槛

翻遍项目已有脚本的结论：**`灵气转换` 和 `难度系数` 早就实现好了，坏的是"等级换算"这一层** ——
同一个问题在文件里有**三套各算一套的算法**，互相差一级。

### 3.1 【坑】`当前境界` 和 `查境界` 是两套算法，差一级

```csharp
当前境界  →  d.等级 + 1      // 语义：等级 n 的那一行，显示成第 n+1 层
查境界(S) →  d.等级          // ← 没 +1
```

后果：预估转修后境界**永远比实际低一级**，看起来像"预估不准"。

**修法**：`当前境界` 改成**委托** `查境界(当前基准灵气)`，只留一套算法；
`查境界` 内部统一 `推定 = Mathf.Min(90, d.等级 + 1)`。

> 教训：**两个地方都要把"等级"翻译成"显示名"时，让它俩调同一个函数**，
> 别各写一遍 —— 这种 ±1 的错不会报错、不会崩，只会静静地偏。

### 3.2 【坑】`查境界` 依赖表的**遍历顺序**（与 §1.2 同源）

`查境界` 原本是 `foreach (var d in 表) { if (S >= d.累计灵气) 命中 = d; else break; }`，
靠 `break` 提前退出 —— **一旦表不是按等级升序就全错**。
`LoadAll<RealmDefinition>()` 是按**资产名**排序的（§1.2），所以这个 `else break`
在某些资产命名下会提前退出，`查境界(0)` 能查出「元婴第10层」。

**修法**：改成与顺序无关的写法（扫全表、取满足条件的最大等级）。

### 3.3 【坑】"境界不提升"其实涨了一级

高→低转修的封顶原本是：

```csharp
总灵气 = Math.Min(总灵气, (long)(取累计(旧等级) * 新K));   // ✗
```

但表里 **`累计灵气(n)` = 从 1 级升到 n+1 级所需**（§3.1 的 `+1` 规则）。
所以要**停在** L 级，必须用 `取累计(L − 1)`：

```csharp
int 封顶等级 = Mathf.Min(旧等级, Mathf.Max(1, 新功法.最高可修炼境界));
long 上限S  = 取累计(封顶等级 - 1);                      // ✓
总灵气 = Math.Min(总灵气, (long)(上限S * 新K));
```

同时 `预估转修后境界` 也复制了这段（原本各写一份），**现在两边共用同一套封顶等级**，
否则界面预估和实际结果又会不一样。

### 3.4 `PlayerCombatStats.功法等级` 改为「跟着境界走」

用户 09-23 定：**功法等级 = 当前境界等级**，并被当前功法的 `最高可修炼境界` 压住。

```csharp
int 期望功法等级 => Mathf.Clamp(修炼.等级, 0, Mathf.Max(1, 当前功法.最高可修炼境界));
```

`Update()` 里每帧比较 `修炼.当前功法 != 当前功法 || 期望功法等级 != 功法等级` 才同步，
所以**转修 / 读档 / 以后的剧情**任何一条路径改功法，属性都会自己跟上（理由见 §2.1）。

### 3.5 【明文决定】`修炼门槛` **只当显示用**，不拦转修

`GongFaDefinition.修炼门槛`（"可开始修炼的最低境界序号"）目前的实际情况是：

* `PlayerHud.cs:330` 显示成「可修炼境界：门槛 ~ 最高」
* `MountDefinition.修炼门槛` 在坐骑页当排序键（`UIPanelData.cs:566`）
* **`转修功法` 里从头到尾没校验过它**（`PlayerCultivation.cs:301` 只判了 null 和"已经在修了"）

也就是境界 5 的人能转修一门写着门槛 10 的功法。

**用户 2026-09-23 决定：保持现状，门槛纯展示，不做拦截。**
→ 这是**有意为之，不是 bug**，别再当漏洞翻出来修。
（现在两门功法门槛都是 1，所以这个洞本来也观察不到。）

### 3.6 顺带确认：`BasicRemoteAttack01` 运行时新建是**能用的**

`PlayerAbilityLoader` 在运行时 `AddComponent` 出 `BasicRemoteAttack01` 时会打一条警告
「新建出来的是默认配置，记得手动配一遍」。**对这个类属于虚惊** —— 它不读 `面板数据`，
全部自己拿：

* `玩家战斗属性 = GetComponent<PlayerCombatStats>()` → 攻速系数 / 神识范围 / 伤害
* `目标管理器   = GetComponent<NpcTargeting>()`
* `动画         = GetComponent<PlayerAnimationController>()`
* `普攻动作     = Resources.Load<AnimationClip>("技能动作/普攻_远程_01")`（`Awake` 里兜底）

所以"手工挂"的硬要求**只对 `BasicSword01` 成立**（它的悬浮/绕行/瞄准参数是调过的值，§2.2）。

### 3.7 实测（3C_Testbed，Play）

```
功法表：太虚炼气诀 上限9   青云剑诀 上限12

① 初始           境界=炼气第1层 等级=1   CombatStats.功法=青云剑诀 功法等级=1  攻击=48 气血=330
                 （★ 修复前这一格是 攻击=72 —— 属性一直按 5 级在算）
② 灵气堆到 20 级  境界=金丹第2层 等级=22  CombatStats.功法等级=12  ← 被青云上限 12 压住 ✓
③ 转修太虚(上限9) 预估=炼气第9层  → 实际=炼气第9层   一致=True ✓（★ 修复前差一级）
④ 转回青云       预估=炼气第5层  → 实际=炼气第5层   一致=True ✓
```
