# 传送系统

> **管什么**：`Teleporter` 怎么配、四对光圈的接线、跨场景传送为什么要用 `DontDestroyOnLoad` 宿主、再加一对的步骤。

## 1. 组件怎么用

`Assets/Scripts/Core/Teleporter.cs`，挂在**传送光圈**（`teleport1` 特效）上。

| 字段 | 说明 |
|---|---|
| `选项[]` | 每个 = `{名称, 场景, 落点, 暂未开放}`。**`场景` 留空 = 本场景内传送**；`落点` 填**物体名** |
| `半径` 1.8 | 没有 `Collider` 时自己补 `SphereCollider(isTrigger)`（用参数估，粒子尺寸没法反推）|
| `交互距离` 3.5 | 玩家离这么近才出现「F 传送」提示（**按 F 才开面板**，不是走上去自动弹）|
| `提示文字` / `提示高度` 1.6 | 键帽提示里显示的字 / 提示框离地多高（圈是平的，没有渲染体高度可用）|
| `暂未开放` | 按钮**灰掉**，点了只提示「尚未开放」 |
| `选项接管` | **选项被点时的外部接管**（`Func<int,bool>`，返回 true = 我处理了，圈不再自己传送）。镇妖塔的「进入下一层」用它 —— 那不是一次传送，是 `TowerController.下一层()` |
| `打印日志` | 打「弹出选项 / 执行了哪一项 / 放到哪个落点」 |
| `重建面板()` | 选项在运行时被改过之后调它作废旧面板（**面板开着时不重建**）|

* **找玩家**：`PlayerVitals`，或根物体名叫 `Player`（`CharacterController` 的碰撞体会被触发器打到）
* **放下玩家**（`放下玩家()`）：**先关 `CharacterController` 再挪**（不关会被它拽回原位），挪完再开；并顺手 `MountRider.强制下坐骑()`，免得坐骑跟丢
* 确认框是**自己代码建的**（借场景里已有 `Text` 的字体，不依赖内置字体名）→ 不需要美术资产、不进场景文件

## 2. 现在的接线与命名约定

| 场景 | 光圈物体名 | 世界坐标 | 选项 → 去向 |
|---|---|---|---|
| 3C_Testbed | `3ctestbed to sect1` | (−7.960, 0.000, −11.280) | 「前往 Sect」→ **Sect** · 落点 `sect1 to 3c` |
| Sect | `sect1 to 3c` | (−18.230, −0.022, 27.540) | 「前往 3C_Testbed」→ **3C_Testbed** · 落点 `3ctestbed to sect1` |
| Sect | `sect2 to tower` | (−55.430, 14.212, 52.530) | 「前往 Demon-Suppressing Tower」→ **Demon-Suppressing Tower** · 落点 `tower to sect2` |
| Demon-Suppressing Tower | `tower to sect2` | (0.300, 5.030, 9.040) | ①「进入下一层」②「出塔（回 Sect）」→ **Sect** · 落点 `sect2 to tower`。★ 这个圈的 `选项` 是**由塔控在清完怪那一刻现写**的（见下），而且它**平时未激活**（清完怪才出现）|

**命名约定**：`<本场景> to <目标场景>`；`落点` 填**对面那个光圈物体的名字**，即**传送点本身**（`TeleportTarget_*` 已全删）。

> 落在对面光圈上是**可以的**（2026-09-28 起传送要按 F，不会自己再弹一次）。实测：出塔落在宗门
> `sect2 to tower` 上，距离 0.000 m、`isGrounded=True`，屏幕上是「F 前往」提示 —— 想再进塔就按一下 F。

`Teleporter.场景` 里的场景**必须**已在 Build Settings 里，否则加载直接失败。现有 5 个：
`StartScene` / `3C_Testbed` / `Village` / `Sect` / `Demon-Suppressing Tower`

## 3. ★★【大坑】跨场景传送不能用自己的协程

第一版写「`StartCoroutine` 加载 → 等 `isDone` → 找落点 → 放玩家」，结果**永远落不到目标点**：场景确实切过去了、目标物体也确实存在，但玩家留在**新场景里保存的位置**（3C → Sect 落在该场景里保存的 `Player` 位置，当时是 (−83.6, 14.2, 89.9)，离目标 91.45m ✗；那个位置本身也是死区，已一并修掉）。

**根因**：`LoadSceneMode.Single` 销毁旧场景的一切，**包括挂着这个协程的 `Teleporter` 自己**；协程寄生在组件上，组件没了协程当场中断，后面「找落点 / 放玩家」**从未执行**。

**修法（现状，2026-09-28 起）**：跨场景那段**交给 `黑幕字幕.开始场景过渡(场景名, 显示名, Vector3.zero, 落点名)`**
—— 黑幕自己带 `DontDestroyOnLoad`，由它的 `Update` 每帧推进「落黑幕 + 打场景名 → 异步加载 → 摆位 → 停 2 秒 → 淡出」，
落点名交给它在**新场景**里按名字解析。这样**所有**切场景路径（任务表 / 传送点 / 镇妖塔出塔）都是同一套过场惯例。
（中间还写过一个自造的「传送宿主」，能落到点，但**绕过了黑幕+场景名、也没把主线进度钉进快照**，已废弃。）

> ⚠️ `落点名` 只能在**目标场景**里解析 —— 出发场景里 `Find(落点名)` 必然为 null。
> 想在出发前报"落点填错了"，只能报"**没填**"，不能报"找不到"。（踩过：一句永远出现的假 Warning）

**实测**：出塔 → Sect 落点距离 **0.000 m**、`isGrounded=True`、Y 不变化 ✓

> 通用教训：**要跨场景存活的逻辑必须挂在 `DontDestroyOnLoad` 上**，`Single` 之后原场景里的一切都不可信。

## 4. 再加一对传送的步骤

1. 两场景各放光圈 + 挂 `Teleporter`，**互填对方物体的名字**当落点；
2. 目标场景**必须**已在 Build Settings 里；
3. **别按名字批量挂组件** —— `TeleportTarget_*` 这类落点标记物名字里也含 "teleport"，会误伤；也别挂到已有 `Teleporter` 的物体的子物体上（双触发）；
4. 确认 `选项` 的 `场景` 填的是**场景名**（曾误填成 `落点` ✗）。
