## 1. 结构与快捷键

2026-10-10：寒墟已从主动神通表和学习目录移除，功能并入[沧澜寒渊录四式普攻](../guides/沧澜寒渊录.md)。四式为特殊属性普通攻击，不占主动槽、不沿用主动伤害加成；枚举值4保留空位，不改后续枚举数值。

伤害执行体统一使用`CombatDamagePipeline`与`CombatHitContext`，攻击类别取能力定义，不再由通用执行体强制写为主动神通。范围每个脉冲、冰波整条路径按目标根节点去重。环境接触读取`CombatImpactCatalog`，与实际扣血和特效结束分开；接口、护盾与事件语义见[战斗与伤害](战斗与伤害.md)。

| 东西 | 在哪 |
|---|---|
| 技能栏数据 | `UIPanelData.主动技能`（6 格，**神通 / 法宝 / 灵阵 共用**） |
| 施放器 | `Assets/Scripts/Abilities/ActiveSkillCaster.cs`，挂在 Player 上 |
| 范围伤害执行体 | `Assets/Scripts/Abilities/AreaSkillRunner.cs`，挂在临时生成的特效物件上 |
| 水炮 / 小剑阵执行体 | `DirectedAbilityRunner`；小剑阵虽手动施放，仍走被动伤害 |
| 持续禁锢 | `BindingChainSkillRunner` + `NpcMovementLock`；取消优先于冷却检查 |
| 背负邪眼 / 四种护罩 | `DevilEyeAbility` / `PassiveShieldAbilities`，由装载器在各场景运行时补入 |
| 主动四御 / 护罩互斥 | `ActiveSkillKind.四御护罩` 施放恢复4次免伤；三个减伤被动互斥并持续耗蓝，邪眼每轮扣蓝 |
| 配置表 | `Assets/Data/Tables/主动神通表.csv` →导入器→ `ActiveDivineAbility` 资产 |

**第 N 格 → 快捷键 N**（`KeyCode.Alpha1..6`，可同时支持小键盘），读取在 `ActiveSkillCaster.Update` 的 `Input.GetKeyDown(快捷键[i])`。

## 2. 范围技能打谁：敌人 + 锁定目标

`AreaSkillRunner.结算一次()` 的筛选：范围内的【敌人】（对主角好感度 < 0）→ 打；【锁定目标】→ 一定打，无关好感度；其他非敌对 NPC → 跳过；死亡目标 / 已经打过的（同一 NPC 多个碰撞体）→ 跳过。

「锁定目标无视好感度」是**按用户要求**加的：**玩家既然锁定了它又按了技能，就该对它生效** —— 和飞剑「鼠标手动右键锁定的目标不看好感度」一致。（只有 `需要锁定目标 = 是` 的技能才有锁定目标；范围填 0 的单体路径本来就不筛选好感度。）实测：锁一个 `对主角好感度 = 20` 的友好目标放焚天炎术 → 照样扣血 ✔。

## 3. 施放流程：每一步不过都只提示，**绝不白扣灵力**

```
冷却 → 结算方式是否实现 → 是否需要锁定 → 灵力够不够
     → 扣灵力、进冷却 → 生成特效 + 结算伤害
```

空槽 → 静默返回不提示；法宝 / 灵阵 → 提示「还没做」（目前只实现了主动神通）；界面开着（`UiEscRegistry.AnyOtherUiOpen()`）或暂停（`timeScale <= 0`）→ **不接收快捷键**（跟 `NpcTargeting` 的既有做法一致；想改就关掉 `界面开着时禁止施放`）。

2026-10-09新增施法动作占用：`PlayerAnimationController.占用施法/释放施法`由执行体持有；水龙炮和追踪弹在施法/收招期间阻止自动普攻和其他主动技能覆盖动作，拒绝施放时不扣灵力/充能。只释放自己的占用和定姿，结束或中断后恢复。全状态水龙炮用Attack02在43%左手出水，冰暴术/瞬雷天闪用Attack01_short在右手0～50%凝聚、58%放飞；地面、御风和骑乘使用同一动作与时序；烘焙保留源动作腕指曲线，详见三术专文和[御风动作§6](../guides/御风前进动作.md#6-全状态神通施法)。

## 4. 主动神通表的新增列与伤害时间轴

| 列 | 说明 |
|---|---|
| `结算方式` | `未实现` / `范围伤害`。**没填 = 未实现**（按下去只给提示） |
| `伤害属性` | `物理` / `特殊` → 决定走暴击还是会心 |
| `攻击类别` | 新水炮/剑阵执行体读取；水炮主动，剑阵被动。不能按装备槽推断伤害来源 |
| `每级差消耗倍率` | 持续禁锢的境界差耗蓝系数，不增加伤害 |
| `伤害倍率` | 伤害 = 攻击 × (1 + 加成 − 减免) × 加成倍率 × **伤害倍率** |
| `范围` | 米。**填 0 = 退化成只打锁定目标**。特效会按这个值同步缩放 |
| `冷却时间` | 秒 |
| `需要锁定目标` | 是 / 否 |
| `持续时长` | 秒。**0 = 一次性**；> 0 则每「伤害间隔」再结算一次。有特效时对齐特效动画时长 |
| `首次造成伤害时间` | 秒。施放后隔多久结算**第一次**伤害，**专用来把伤害生效时刻对齐特效动画**。填 0 = 施放瞬间立刻结算 |
| `伤害间隔` | 秒。首次结算之后每隔这么久再结算一次 |
| `特效资源路径` | **Resources 相对路径**（`Assets/resources` 之下，不含扩展名） |

新神通的参数与验收入口：[水龙炮](../guides/水龙炮.md)、[禁锢锁链](../guides/禁锢锁链.md)、[小剑阵](../guides/小剑阵.md)、[邪眼](../guides/邪眼.md)、[防护罩](../guides/防护罩.md)。图标和学习物品均已配置；`PlayerAbilityLoader` 的内置被动登记不依赖各场景的序列化白名单。

```
t=0                     特效生成
t=首次造成伤害时间        第 1 跳
t=首次 + 伤害间隔         第 2 跳
t=首次 + 2×伤害间隔       第 3 跳 …
t=持续时长               特效销毁（未开始的跳不会发生）
```

**跳数 = 满足 `首次 + k×间隔 < 持续` 的 k 的个数**。`首次 >= 持续` 时一跳都不结算 —— `AreaSkillRunner` 会打一条 `Debug.LogWarning` 明说，不会静默失败。

实测 A/B（临时敌对 NPC，`持续 3 / 间隔 0.75`）：首次 **1 秒** → **1.00s / 1.76s / 2.51s**（3 跳）；首次 **0 秒** → **0.01s / 0.76s**（立即，之后每 0.75 秒）。

导入器按列名映射到 `ActiveDivineAbility` 的同名 public 字段 —— **加新神通只要加一行**。没填的格子导入器会跳过，字段保持 C# 默认值（所以未填的行天然是「未实现」）。

> 早先还有一列 `特效方法id`（`vfx_xxx`），**已删除** —— 它从来没有消费者。但 `特效方法id` 这个**字段**仍留在基类 `DivineAbilityDefinition` 上，因为 `被动神通表.csv` 也有一列同名，删字段会连带影响被动神通。

## 5. 特效怎么摆

施放时按 `缩放 = 范围 ÷ 特效基准半径` 设特效的 `localScale = (缩放, 1, 缩放)`（**只缩 X/Z，Y 保持原样**）。`特效基准半径` 是 `ActiveSkillCaster` 上的字段，含义是「该特效在 scale = 1 时的视觉外缘半径」，**换特效资源就要重新标定**：

| 特效 | 实测基准半径 |
|---|---|
| `Effect_13_DangerClose`（焚天炎术现用） | **49.1 米** |
| `Effect_13_Base/Effect_13_Explosion` | 9.9 米 |

**关键：必须同时把粒子系统改成 Local 空间。** 这些特效是 `simulationSpace = World`，而 World 空间下 transform 缩放**只改变粒子的散布位置、不改变单个粒子的尺寸**：

| scale | 粒子最远水平距离 | 最大粒径 |
|---|---|---|
| 1 | 6.19 m | 9.94 |
| 2 | 12.81 m | **9.95** |
| 3 | 18.88 m | **9.97** |

→ 火焰只是被「摊开」而不是「变大」，大小跟不住范围。把实例上的粒子系统切成 `Local` 之后缩放才是等比的（外缘半径 ÷ scale ≈ 常数）。特效本身是静止的，Local / World 观感上没有区别。

实测联动（`特效基准半径 = 49.1`）：范围 6 → localScale.x **0.1222**（= 6 ÷ 49.1 ✔）；范围 12 → **0.2444**（= 12 ÷ 49.1 ✔）。

### 【重要】缩放的代价：把「从天而降」的高度一起压扁

`Effect_13_DangerClose` 的「火柱砸地」靠**很长的下落距离**撑起来（`Effect_13_Shell` 起点在 `localPos z = 30`，拖尾拉出一整条）。缩放是**整体等比**的，所以范围越小、下落越短：

| 缩放 | 对应范围 | 视觉 |
|---|---|---|
| 0.12 | 6 米 | 一小团火，**火柱几乎看不见** |
| **0.25** | **12 米** | **火柱能看清**（当前取值） |
| 0.4 | 20 米 | 成排火柱砸下，最像"天火焚天" |
| 1.0 | 49 米 | 最壮观 |

**这是"视觉严格等于判定范围"与"火柱要够长才好看"之间的固有矛盾，不是 bug。** 要做成"小范围 + 大火柱"只能把视觉与判定解耦（特效固定 scale = 1、伤害仍按 `范围` 结算），代价是看着大、实际判定小。

> 换更小/更大的特效时，用同一台**侧视相机**在 1.2 秒和 2.5 秒各拍一张来定这个值，别只靠数字。

### 【重要】朝向：`Effect_13_DangerClose` 是「倒着做」的，必须翻 180°

原样生成时**粒子全部在地面以下**，看起来是「从地底往上冒」而不是「从天而降」。把粒子的**世界坐标**打出来一眼就看出：

| 朝向 | 粒子世界 Y | 结果 |
|---|---|---|
| 原样（identity） | **−100.8 ~ −0.1** | 从地底往上 ✗ |
| **绕 X 转 180°** | **0.1 ~ 100.8** | **从天而降砸向地面** ✔ |
| 绕 Z 转 180° | 0.1 ~ 100.8 | 同样正确（只是横向漂移方向相反） |
| 绕 X 转 270° | −5.1 ~ 12.1 | 变成水平，不对 ✗ |

所以 `ActiveSkillCaster` 上有 `特效旋转` 字段（默认 `(180, 0, 0)`），生成时用 `Instantiate(prefab, 中心, Quaternion.Euler(特效旋转))`。**换特效资源时这个值也要跟着改。**

> **这个坑极其隐蔽**：粒子系统各项参数看着都正常，只有把粒子的**世界坐标**打出来，或用能看到地面以下的侧视相机，才看得出整段动画在地面之下；俯视相机里「从下往上」和「从上往下」都只是一团火。本效果粒子的 Y 范围有 **100 米**（Y 不参与缩放），火柱会冲出俯视相机画面 —— 这是「天火」该有的样子，不是 bug。

焚天每颗火球的落地点追加Break_Lava，使用粒子真实碰撞事件而非伤害计时器；不增加额外伤害。文件及验证见[命中特效管线](../guides/战斗命中特效管线.md#4-焚天落地)。

2026-10-09：焚天施放实例移除`Effect_13_Explosion`、`Effect_13_Explosion_2`层及对应子发射器引用，其余原生层和Break_Lava落地保留；下方资源包结构表描述原预制体。

焚天在`技能动作2`实际进度38%召唤，范围特效和伤害执行体届时才创建；表中首次伤害延迟和持续时长从召唤起算。节点前被打断时取消召唤，动作完整占用至收招结束。锁定与Alt落点共用该节点，各场景通过共享施放器生效。体素破坏由每颗火球实际落地触发（默认1米局部半径、1/3米深度），不再随首次范围伤害一次挖中心大坑；启用体素地图时碰撞实际坡面/坑底，敌人持续伤害仍沿用原配置。

## 6. 焚天炎术当前数值（`ability_fentian_yanshu`）

| 项 | 值 |
|---|---|
| 结算 | 范围伤害 · **特殊** · 主动神通 → 走**会心**判定 + 主动法术加成 |
| 伤害倍率 | 2.5 |
| 范围 | **12 米**（缩放 = 12 ÷ 49.1 = 0.2444） |
| 消耗灵力 | 60（灵气上限 160 → 满灵气可放 2 次） |
| 冷却 | 8 秒 |
| 需要锁定 | 是 |

| 首次造成伤害时间 | **1 秒**（对齐到火焰真正烧起来的那一刻） |
| 伤害间隔 | **0.75 秒** → 每目标 **3 跳** |

## 7. 特效包结构与两个坑

**别用「1 秒窗口 + 游戏俯视相机」判断特效看不看得见。** 曾把 `Effect_13_DangerClose.prefab` 判定为「单独放出来什么都看不到」，据此把 `特效资源路径` 改成子层 `Effect_13_Base/Effect_13_Explosion`，**结论是错的**：只观察了 **1.07 秒**，而 `Effect_13_Shell` 是 `duration = 4` 秒、`rate = 3` 慢慢发射的（火焰 1 秒多才起来，首次出现粒子实测 0.33 秒）；用的还是 13 米高、fov 40 的**游戏俯视相机**，画面本来就装不下空中的部分。**正确做法：换一个能同时看到地面和空中的侧面相机，观察至少 4~6 秒。**

```
Effect_13_DangerClose.prefab
├── Effect_13_Shell         localPos=(0,0,30) rot=(90,0,0) duration=4 rate=3 尺寸 0.25
│                           velocityOverLifetime = (0,-50,-150)  ← 从 30 米外飞入的「炮弹」
├── Effect_13_Trails        ← 拖尾容器：Effect_10_TrailSmoke / TrailParticle_2（loop=True，无限发射）
├── Effect_13_Explosion ×2  burst=1 生命 1.5 尺寸 10     ← 撞击 / 地面爆炸层
├── Effect_13_Explosion_2   burst=1 生命 1.0
├── Effect_13_Distort       burst=1 生命 1.5
└── Effect_13_ShellColider  缩放 10
```

- **它自带「飞入 → 火焰」的完整过程，不需要任何脚本**（包是 `NotScriptBased`）
- **看不到「陨石本体」**：`Effect_13_Shell` 的粒子尺寸只有 **0.25**；画面上真正的主体是拖尾 + 爆炸层烧出来的地面火焰
- `shape = Circle 半径 20` → 发射铺开约 40 米，所以基准半径高达 **49.1 米**
- 两个拖尾层 `loop = True` → **永远不会「结束」**，只能靠 `持续时长` 掐掉
- 子目录 `Effect_13_Base/` 下另有 `Effect_13_Explosion.prefab`（单次爆发，基准半径 9.9 米）与 `Effect_13_Trails.prefab`，可单独取用

> **备查**：想要真正的「陨石从天而降」，这个特效包里有 —— `EffectsSet_2(ScriptBased)/Effect_10_MeteorStrike/`（含 `Effect_10_BigMeteor` / `Effect_10_SmallMeteor` / `*HitEffect`）。但它是 **ScriptBased**，靠包里的 `MultipleObjectsMake` / `ObjectMoveDestroy` 驱动，是「范围流星雨」而非单点命中；拆单颗用需要自己接目标。别和 `Effect_13_DangerClose` 搞混。

**`unity_gameobject ensure_component` 在本项目用不了**：加组件会撞上项目路径里的全角冒号，报 `String conversion error: Illegal byte sequence encounted in the input.`（它内部有一步走 `Assembly.GetName()` 之类的反射）。**改用 `exec_editor_script` 里 `player.AddComponent<T>()` 再 `SetDirty` + `SaveScene`**（Roslyn 脚本没这个问题）——和 `cultivation/CODELY.md` 里记的老坑同源。

## 8. 怎么验证

**当前 装备唯一性**：同一主动神通只能占一个槽位。`UIPanelData.EquipToSlot` 和 `HandleSlotClicked` 放入目标前清空其他同神通槽，按引用或非空 `神通id` 判重；`EnsureSkillSlots` 清理旧重复状态并保留首槽。星位拖拽仍通过 `交换主动槽` 原子换位；待装备点已占槽仍拒绝。法宝、灵阵继续共用数组，不增加它们的唯一性限制。`inkqa:skills:validate` 新增 7 项此问题回归。

`CombatCalculator` 是纯静态函数，Edit Mode 就能测；但快捷键、特效、`Physics.OverlapSphere` 要在 **Play Mode** 测：

```csharp
var caster = FindObjectOfType<ActiveSkillCaster>();
caster.目标管理器.Lock(木桩, true);   // 需要锁定的技能
caster.尝试施放(0);                   // 等价于按「1」
```

**`尝试施放(槽位)` 是 public，不用模拟按键就能测完整条链路。**

**练功木桩不一定是敌人。** `焚天炎术` 只打**敌人**（`NpcInstance.是敌对目标` = `对主角好感度 < 0`）。`练功木桩`（`monster_wooden_dummy`）在 `NPC表.csv` 里的 `对主角好感度` **一度被改成 `0`** —— 于是它不再是敌人：技能"命中 0 个目标"、血条也不显示，表现非常像"技能坏了"。**拿它试招之前先确认那一列是负数。**

**要稳定复现，就在测试脚本里现造一个敌对目标**（别改共享资产）：

```csharp
var 定义 = ScriptableObject.CreateInstance<NpcDefinition>();
定义.对主角好感度 = -5f;
定义.属性[AttributeType.MaxHealth] = 500f;
var go = new GameObject("TempEnemy");
go.AddComponent<CapsuleCollider>();
var 敌 = go.AddComponent<NpcInstance>();
敌.定义 = 定义;
go.AddComponent<NpcIndicator>();
caster.目标管理器.Lock(敌, true);
```

> Play Mode 下改 **ScriptableObject 资产**（比如 `定义.对主角好感度`）**会写回磁盘**，要改数值请用 `Instantiate` 出来的临时副本。

视觉验证：Play Mode 里把相机 `Render()` 进 RenderTexture 再存 PNG（`DshBridge.cs` 的 `shot` 就是这套写法），看图比读日志可靠。
