## 1. 这是什么

妖魔 / 人类可以变成**真灵**上阵：缩小一半、半透明幽灵化，主动打玩家锁定的目标，但不会跑出玩家的**神识范围**；没目标时回自己的阵位，朝向和玩家一致、跟着玩家走。

| 文件 | 作用 |
|---|---|
| `Assets/Scripts/Formation/SpiritFormationLayout.cs` | 九宫格 ↔ 站位的唯一对照表（UI 和运行时都读它） |
| `Assets/Scripts/Formation/SpiritFormationManager.cs` | 挂在 **Player** 上：差量生成/销毁、幽灵化、神识范围 |
| `Assets/Scripts/Formation/FormationSpirit.cs` | 真灵 AI（继承 `NpcAiBase`） |
| `Assets/Scripts/UI/UISpiritFormationBar.cs` / `UISpiritSlot.cs` | 九宫格 UI |
| `Assets/Shaders/GhostSpirit.shader` + `Assets/resources/Materials/GhostSpirit.mat` | 真灵外观 |
| `NpcDefinition.模型资源路径`（`NPC表.csv` 新增列） | 哪个 NPC 能当真灵（填了才行） |
| `UIPanelData`：`已获得真灵` / `战阵站位` / `待上阵真灵` | 数据层（上阵流程和神通装备完全同构） |

### 数据与流程

- **谁是候选**：`NPC表.csv` 里**妖魔 / 人类**且 `模型资源路径` 非空（导入时按预制体上 `NpcInstance.定义.id` 反查自动填好）。
- **谁能上阵**：`UIPanelData.已获得真灵`。**当前 = 所有 demon / human（240 个：妖魔 148 + 人类 92）**，由 `DataTableImporter.RewirePanelData` **自动收集**。
  > 240 = 一个蒙皮版本一行的结果：单个定义的 33 个 + 按蒙皮拆出来的 207 个。
  > **排序 = `UIPanelData.比真灵`**（导入器和运行时共用同一个比较器）：① 妖魔在前、人类在后 → ② 同一族的挨在一起 → ③ 族内**由弱到强**（境界升序）→ ④ id 兜底。实测 240 条里「人类后面又出现妖魔」= 0 次，家族被拆成不相邻段 = 0 段。
  > 【用户明确要求】包括**土地公、铁匠这种 NPC** —— 所有 demon / human 完成 AI 之后都能进真灵列表供战阵选择。曾擅自收窄成"只收有专属 AI 脚本的怪"，被明确纠正 ✗ **别再自行加过滤条件**。
  > 顺带一个坑：`NpcAiBase.找物种脚本` 最后一条兜底规则是「名字里含 `_关键字`」，而 `demon_gou**tou**junshi` 里正好含 `_gou` → 会被认成**狗**的专属 AI；拿脚本推断来过滤就会误伤，这也是别用脚本判定过滤的理由之一。
- **几个同时上阵**：`SpiritFormationLayout.可上阵数 = 5`。
- **操作**：列表行上点「上阵」→ 进入待上阵 → 点任意空格子放进去；行上点「下阵」撤下。和神通的装备是同一套交互。

## 2. 九宫格与站位

**九宫格是以玩家为中心的阵**（用户明确更正过两轮，别再改回去）：

- **正中间那一格 = 玩家自己**（`SpiritFormationLayout.玩家格 = 4`），标签写「玩家」、点不动
- **上面一行 = 玩家正前方**（+Z 是玩家朝向），下面一行 = 身后 → 能放真灵的是**外围 8 格**
- 站位偏移：正前 3.8 米 / 前侧 (±3,3) / 正侧 ±3.8 米 / 后侧 (±3,−3) / 正后 −3.8 米
- `已上阵数量` 只数 8 格里的；上满 5 个之后，**剩下还空着的那几格显示「已满」**并点不动

## 3. 运行时行为

**★ 最重要的一条：真灵和敌对 NPC 用的是同一套战斗 AI。** `FormationSpirit` 继承 **`NpcAiCombatant`**（不是 `NpcAiBase`）—— 也就是妖魔 / 人类那套「接近 → 出手 → 脱战」。真灵**只覆盖「敌人是谁」和「没敌人时站哪」**：

| 覆盖点 | 真灵的实现 | 基类默认 |
|---|---|---|
| `敌人` | 主人锁定的那只怪 | 玩家 |
| `敌人还活着` / `敌人靶` | 目标没死 / `NpcTarget(目标)` | 玩家 |
| `可以开打` | **只要有目标就开打**（不看好感度） | 好感度 ≤ 阈值 |
| `敌人在索敌范围()` | 目标离**主人**没超出「追击半径」 | 玩家在自己的索敌范围里 |
| `敌人已脱战()` | **恒 false** | 到敌人距离 > 脱战范围 |
| `视玩家为敌` | false | 好感度判定 |
| `决策()` | 选目标 + 主人跟丢兜底，然后**调 `base.决策()`** | 完整的战斗决策 |
| `执行接近()` | 追目标（带冲刺倍率 + 追击半径夹取）/ 回阵位 | 直线走向敌人 |
| `执行待机()` | 没敌人时朝主人；**有敌人什么都不做**（交给基类每帧朝敌） | 播待机 |

> **为什么非改不可**：最初真灵自己把「决策 / 接近 / 可出手 / 朝向」重写了一遍，结果和怪的行为各自跑偏 —— 实测**侧翼格的真灵离目标 0.8 米、攻击距离 2.5 米，却永远不出手**（"待机朝主人"和"转向目标"互相打架，朝向判定永远过不去）✗ 用户原话：「我感觉你现在好像是专门给真灵写了一整套办法？」收敛成「只有敌人不同」之后，这类偏差**从结构上不可能再出现**：`NpcAiBase` 新增 `敌人 / 敌人还活着 / 敌人靶 / 到敌人距离 / 朝向敌人()`，`NpcAiCombatant` 新增 `可以开打 / 敌人在索敌范围 / 敌人已脱战`（默认 = 玩家那套），**敌对 NPC 行为完全不变**（回归实测：10 米生成 → 接近 → 2.49 米出手 → 打掉玩家 406.8 血 ✓）。

- **回位 / 跟随**：阵位 = `玩家.position + 玩家.rotation × 站位偏移`（玩家本地坐标，以玩家为圆心、半径约 3.8 米的一圈）。**没目标时**站桩朝向 = 玩家的朝向。
- **重新索敌冷却 = 0**：主人一锁定就立刻开打。基类那 1.5 秒是给野怪在索敌边界反复横跳用的，真灵的目标是玩家点名的、没有"发现"这个过程。

### 追击半径、分离、跟丢

- **追击半径**（`SpiritFormationManager.追击半径`，默认 **20 米**）：真灵肯为主人跑多远。**这一条修过一个 bug** —— 以前用的是「神识范围」（默认只有 14 米），于是用户锁了一只 20 米外的怪，三只真灵**连目标都不认**（`目标 = null`）、原位站桩 ✗；现在和敌对 NPC 的「脱战范围 20~22 米」一个量级。填 0/负数退回旧行为。
  > ⚠️ 现实里玩家自己也**只能锁住 14 米内的怪** —— `BasicSword01.脱锁距离 = 索敌半径 = 神识范围`，超过就 `ClearLock()`。所以「真灵不去打 20 米外的怪」有时其实是**锁已经掉了**，不是真灵的锅。排查时先看 `NpcTargeting.LockedNpc` 还在不在。
- **真灵之间的分离**（`SpiritFormationManager.LateUpdate` 里的 `分离真灵()`）：任意两只见的水平距离小于 `真灵最小间距`（默认 1.4 米）就**互相推开重叠量的一半**，单帧限速 `单帧最大推移`（0.12 米）防抖，推完各自重新贴地。实测 5 只一起打同一个目标，10 秒内最小间距 **1.378 米**，不会挤成一坨。
- **跟丢兜底**：离主人超过 `跟丢距离`（25 米，覆盖御风飞走 / 传送 / 重生）直接瞬移回阵位。

## 4. 真灵列表：排序 + 右侧滚动条（用户要求）

真灵表从 96 条涨到 **240 条**之后列表一屏只放得下 8 行 —— 用户原话「在真灵选择的右侧加一个滚动条方便快速找到需要的 npc 真灵」。排序规则见上文「数据与流程」。

`UIBuildUtils.AddVerticalScrollbar(scroll)`，在 `CharacterPanelBuilder.CreateScrollList(..., 带滚动条: true)` 里**只给 `SpiritList` 打开**（其它 6 个列表不动，免得白改一遍视口宽度）。

- 轨道 18px 宽、贴在面板右侧、顶部和视口一样让开 34px 的标题；视口右边界同步收进 24px（滚动条宽 + 6 间距）
- 可见性 = `AutoHide`（**不用** `AutoHideAndExpandViewport`：那个要靠 ugui 自己算视口扩展，这里直接构建时把视口宽度算死，更可控）
- **两个小坑**：① `UIBuildUtils.CreateImage` 默认 `raycastTarget = false` —— 轨道和滑块都要显式打开，否则**看得见拖不动**；② 滚动条节点要建在 Viewport **之后**，才能在射线检测里压住列表行（否则拖滑块会点到行上的「上阵」按钮）
- 视觉：轨道 18% 黑（叠在灰色面板上只暗一点点），滑块橙色 `(0.78,0.52,0.33)`。实测像素采样：滑块 `(198,135,92)`、轨道 `(168,168,168)`（面板底色 184），内容高 9128px / 视口 314px → 滑块占轨道的 **3.4%**，滚到底时滑到底部 ✔
- 证据：`screenshots/sp_10_scrollbar.mp4`（滚一遍的慢放录像）、`sp_11_list_top.png`（妖魔开头）/ `sp_12_list_human.png`（妖魔→人类交界）/ `sp_13_list_bottom.png`（人类结尾）

## 5. 十二个坑（都实测过）

0. **「不要挤到一块儿」不要用物理碰撞做**。真灵的碰撞体是**故意关掉的**（无敌 / 不挡路 / 选不中 / 不参与玩家 AoE），而且它们的移动是**直接写 `transform.position`**，挂 Rigidbody 会和 AI 的走位打架。正确做法是**成对的位置修正**（`分离真灵()`，在 LateUpdate），推完再贴地。
1. **★ 要序列化的 MonoBehaviour 必须独占一个「文件名 = 类名」的文件**。Unity 只认**文件名同名的那一个类**是该文件的主类；同一个文件里的其它 MonoBehaviour 在编辑期 `AddComponent` 看着完全正常，但场景一旦从磁盘重新加载（进出 Play、重启编辑器）就会变成 `<Missing!>` 脚本 —— 而且不报任何错，只是功能静默失效。
   - 战阵踩的版本：`UISpiritFormation.cs` 里塞了 `UISpiritSlot` + `UISpiritFormationBar`，文件里**一个同名类都没有** → 进 Play 后 `GetComponentsInChildren<UISpiritFormationBar>()` 返回 **0 个**，九宫格是个空壳。
   - **顺带挖出一个存量 bug**：`UIActiveSkillSlot` 一直和 `UIActiveSkillBar` 挤在 `UIActiveSkillBar.cs` 里 → 实测 **18 个主动技能格子里 14 个变成 Missing**（神通页 6/6 全坏），也就是「神通页点装备格子没反应」。已拆成 `UIActiveSkillSlot.cs` / `UISpiritSlot.cs` / `UISpiritFormationBar.cs`，进出 Play 之后 Missing = 0。
   - 全项目文本扫描（`class X : ... MonoBehaviour` 且 X != 文件名）现在只剩 **`UIEntryRow`**（在 `UIEntryList.cs` 里）。它**只在运行时 `AddComponent` 且 `hideFlags = DontSave`**，从不序列化，所以安全 —— 但**以后要把它挂进 prefab 的话必须先拆文件**。
   - 排查手法：`GetComponentsInChildren<Transform>(true)` 遍历，`GetComponents<Component>()` 里有 `null` 就是 Missing。
2. **`NpcIndicator` 在 `Awake` 里就把血条建好了**。只 `enabled = false` 不够 —— 它的 `LateUpdate`（负责同步显隐）也不再跑，于是那条血条**永远挂在真灵头顶**（实测截图里三只真灵都顶着红血条）。正确做法：先 `SetSelected(false); SetLocked(false);`，再把它生成的 `IndicatorRoot` 整个拆掉。
3. **真灵必须关掉「前方探障」**（`前方探障距离 = 0`，在 `FormationSpirit.Awake` 里设）。阵位在主人正前方，真灵要走到阵位就得从主人身上穿过去；探障一挡，**卡在离主人 1.68 米处永远不动**（状态一直「接近」、每帧位移 0）。真灵本来就是可以互相穿过的灵体，不探障更合理。
4. **必须给冲刺倍率**。主人奔跑 6 m/s，白鹿精只有 **1.5 m/s** —— 不加速就永远追不上。`冲刺倍率 = 4`（落后越多走得越快，平滑过渡）。
5. **`NpcAiBase.立即命中()` 是写死打玩家的**，真灵用它就会打主人。所以 `FormationSpirit` **自己实现 `结算伤害()`**，一律结算到 `锁定单位`。（顺带：`出手` 事件只能在声明它的类里 Invoke，所以基类加了 `广播出手()` 给子类用。）
6. **拆 prefab 自带的 AI 要用 `DestroyImmediate`**。`Destroy` 是帧末生效，而 `NpcInstance.Start` 里那句 `NpcAiBase.确保()` 会 `GetComponent` 到"正在等待销毁"的敌对 AI → 它以为"已经有 AI 了"、不再装真灵 AI。（本工程 prefab 上其实没挂 AI，这里是保险。）
7. **★【bug·已修】真灵借不到「这个物种自己的招式」，拿到的是一套冷却为 0 的通用招式**。现象：「**战阵真灵的冰魄怪一直在放神通**，但按设定应该有 12 秒冷却」。
   根因：真灵身上挂的是 `FormationSpirit`，而 `NpcAiBase.确保()` 一看到"已经有 AI"就**不会**调 `应用类型默认值()`；于是基类 `Awake` 里那句 `确保攻击方式()` 给真灵填的是三条**通用默认招式** —— `Attack1` 普攻 / `Attack2` 神通 / `Attack3` 神通，**冷却全是 0** ✗。表现：冰魄怪真灵无限神通、白鹿精真灵不放飞弹（变成近战）、白熊精真灵爪击没有冷却。
   修法：`FormationSpirit.借用物种招式()` —— 临时 `AddComponent(NpcAiBase.选脚本(自己))`，调一次 `应用类型默认值()` 让**物种自己的 `取默认参数()`** 把招式表算出来，把 `攻击方式 / 攻击距离 / 攻击间隔倍率 / 奔跑倍率 / 行走倍率 / 转向速度 / 模型朝向补偿 / 需要视线 / 视线遮挡层` 抄到真灵身上，再 `DestroyImmediate` 掉临时组件。同帧建同帧拆，`Start` 永远不会跑到它。
   实测（`exec_runtime_script` 读真灵的 `攻击方式`）：

   | 真灵 | Attack1 | Attack2 | Attack3 |
   |---|---|---|---|
   | 冰魄怪 | 冷却 **2** | 冷却 **12**（施法·冰弹·挂点 `Bip01 L Hand`） | 动作名空 → 不可用 |
   | 白鹿精 | 冷却 3（施法·飞弹·挂点 `Bip01 L Finger0Nub`） | — | — |
   | 白熊精 | 冷却 2.5 | 冷却 **10** | — |

   > **别抄 `索敌范围` / `脱战范围`** —— 真灵的追击范围走「追击半径」，由 `SpiritFormationManager` 管，抄过来只会误导。
   > 配套：`FormationSpirit.取出膛点()` 现在**先调基类实现**（基类按招式配置里的「挂点」去找出生点骨骼），只在基类返回 `Vector3.zero` 时才退回"胸口高度"。不这么改的话，冰弹仍从胸口出来、白鹿精的飞弹也不从手指出来。
8. **★【bug·已修】真灵"另写一整套战斗逻辑"= 它和敌对 NPC 的行为会各自跑偏**。用户点出来的：「我感觉你现在好像是专门给真灵写了一整套办法？」当时把「决策 / 接近 / 可出手 / 朝向」在 `FormationSpirit` 里重写了一遍，于是真灵**侧翼格 / 后排格**的离目标 **0.8 米**、攻击距离 2.5 米，却**一下都不打** —— `执行待机()` 那句"朝主人"和 `决策()` 里那句"转向目标"**每帧互相打架**，`可出手()` 的朝向判定（40°）永远过不去；只有正前方那一格能出伤 ✗
   修法（**结构上根治**）：把「敌人是谁」抽成虚属性，让真灵**继承 `NpcAiCombatant`**、只覆盖敌人相关的几个点（见上文「运行时行为」那张表）。现在真灵和怪走的是同一行 `可出手()` / 同一行"每帧朝敌"。实测 4 只真灵（0/1/2/3 格）全部 **偏 0°**、全部出手，10 秒打掉目标 4315 血 ✓
   > 回归验证（改完必须跑）：敌对 NPC 不锁任何目标、自己按好感开打 —— 10 米生成 → `接近` → 2.49 米 `攻击` → 打掉玩家 **406.8** 血 ✓ 行为不变。
9. **★★【坑·已修·最贵的一个】`Resources.Load<GameObject>(路径)` 会挑到「和 prefab 同名的 .FBX」**。本工程 `Assets/resources` 里**同一个目录下同时有 `X.FBX` 和 `X.prefab`** 的摆法有 **17 个 NPC**。`Resources.Load` 优先把那个 **FBX** 给你，而**它不报任何错**：根节点上**没有 `NpcInstance`** → `定义` 为空 → `移动速度` 读出 **0** → **一步都走不动**；**没有 AnimatorController** → `有动作("Attack1")` 永远 false → **一招都放不出来**。合起来 = 「真灵站在那儿发呆，也不过来也不打」，日志一片干净。
   实测中招的 17 个：野猪·幼 / 铁匠 / 逍遥子 / 神秘人 / 李阿翠 / 岳来峰 / 胡一鸣 / 玄冥子 / 游方道士 / 兵（山贼）/ 危月燕 / 冥妖一~三 / 鬼气将 / 赤蟒精三 / 李村医（id：`demon_yezhu_01`、`npc_shenmiren`、`npc_licunyi_01`、`demon_weiyueyan_01`、`demon_mingyao_01~03`、`demon_guiqijiang_02`、`demon_chimangjin_03`）。
   **修法**：`NpcPrefabs.加载(路径)` —— 用 `Resources.LoadAll<GameObject>(路径)` 把这一路径下的资产全取出来，**挑带 `NpcInstance`（且 `定义` 非空）的那个**。实测 240 个真灵定义**全部选对**（FBX 根节点上没有 `NpcInstance`，这是可靠的判据）。
   > **带扩展名没用**：`Resources.Load("xxx.prefab")` 实测返回 **null**，所以只能 LoadAll + 组件判定。任何**按路径实例化 NPC** 的地方都要走 `NpcPrefabs.加载()`，别再直接 `Resources.Load`。
10. **真灵不能用「到敌人的距离」判脱战**（`FormationSpirit.敌人已脱战() => false`）。基类那套是 `到敌人距离 > 脱战范围`，但真灵的敌人是**怪**不是主人 —— 主人和怪贴在一起、真灵还在 20 米外往回赶时，到敌人的距离能到 40 米，会被判定成"脱战" → `已交战 = false` → **永远站在那儿发呆** ✗。真灵的脱战判据只有一条：目标跑出**主人的追击半径**（那时 `目标` 直接算 null、走回位分支）。
11. **★【bug·已修】模型缩了一半，`攻击距离` 没缩 —— 真灵站在够不着的距离挥砍**。现象「**冰魄怪的 attack1 看着动作怪怪的**」：`Attack1` 手臂前伸（相对胸口，峰值 59%）在原尺寸（prefab 1.2 倍）是 **0.68 米**，真灵（×0.5 = 0.6 倍）只剩 **0.34 米**（手也跟着短了一半），而 `攻击距离`（中心距）**还是 2.5 米没缩** ✗。于是真灵站在 **2.5 米**外用 **0.34 米**的手挥 —— 实测**命中那一刻右手指尖离目标表面还有 1.08 米**。
   **修法**：`SpiritFormationManager` 生成时按 `模型缩放倍率` 一起缩（新增字段 `攻击距离随缩放`，1 = 全缩（默认），0 = 不缩 = 旧行为）：

   ```csharp
   float 距离系数 = Mathf.Lerp(1f, 模型缩放倍率, 攻击距离随缩放);
   真灵.攻击距离 *= 距离系数;
   真灵.出膛高度 *= 距离系数;      // 弹道退化到"胸口高度"时也别高过头顶
   ```

   修完实测（`攻击距离` 2.5 → **1.25 米**）：白熊精·王（包围盒 2.5 米宽）中心距 1.24 米、手到靶面 **0.00 米**（贴上了）✓；冰魄怪·幼（包围盒 1.7 米宽）中心距 1.25 米、手到靶面 **0.24 米**（修前 1.08 米）✓
   > **凡是"缩放一个会打架的单位"都要同时问一句：它的距离参数缩不缩？** 移动速度 / 冷却 / 碰撞半径这类不缩是对的（要跟得上主人），但**"手能伸多长"必须跟着缩**。
12. **★★【坑·已修】AI 在攻击动画播放期间转向 = 把动画自带的「转体」抵消掉**。现象「**冰魄怪的 attack1 看着动作怪怪的 / 右手刺歪了**」（不是动画坏了）：攻击动作里自带转体（挥臂时身子跟着转，手才正好扫/刺向正前方），而 `NpcAiCombatant.Update()` 每帧把根节点转回目标 —— **动画转一点、AI 纠回去一点**。实测（玩家在起手瞬间被挪到怪的右侧 4 米）：旧行为 12 帧 **+40.6°**、累计 **+90°**；新行为全程 **0°** ✓
   修法：`NpcAiBase.攻击期间锁定朝向`（默认勾）+ `转向()` 里的闸门（**所有 NPC 统一生效**），外加 `进入攻击()` 里**先瞬时对准再进状态**的顺序。
   > 副作用：量"手臂往哪挥"时坐标系就是被它污染过的（量的是根节点朝向，而根节点当时正被 AI 每帧纠着）—— **凡是"AI 在动的同时量某个相对量"，先问一句：我拿来当基准的那个东西，AI 是不是也在改它？**

## 6. 无敌 / 不挡路 / 不显示血条（用户拍板）

真灵就是**灵体**：关掉全部碰撞体（玩家选不中、玩家自己的 AoE 打不到、怪也打不到、走路不互相挤）、拆掉血条光环、好感度改成 +1000（否则玩家普攻的自动索敌会把自己的真灵当敌人）、`NpcInstance.无敌 = true`（**打不死**，用户明确要求"无限血量"）。`SpiritFormationManager.生成()` 给真灵打开 `无敌`，`TakeDamage` 直接返回 0，所以**漏过来的 AoE / 场景伤害 / 好感度改错都打不死它**，也不会误发「击杀掉修炼次数」。实测注入 999999 伤害 → 实扣 **0**、气血不变、没死 ✓（碰撞体本来也全关了，这是第二道保险。）
