# 执事阁与宗门委托

2026-10-06 首版。Sect 建筑 `environment_Building_diaojiaolou_001_h` 的执事阁组件由场景自举运行时补上，沿用 F 互动和 ESC 关闭。未重建、重存或重排 Sect 场景；用户调整另行保存为提交 `6ef55a1c`，并在 `.dsh/_diag/scene-backups/2026-10-06-sect-before-quest-ui` 备份。

## 面板

延续功德堂、传法阁的细线回纹边框、半透明黑底（全屏 0.5、中央底板 0.18）与透明周边素材。左侧分类，中间可滚动委托列表，右侧图标、介绍、进度、奖励和接取/交付按钮。长介绍独立滚动；追踪、放弃按钮放在列表下方，避开右下装饰。打开时锁定场景输入并隐藏互动提示、悬赏 HUD 和标记，关闭后恢复。

## 首批任务与暂定奖励

配置唯一来源为 `Assets/resources/宗门/宗门任务.json`，运行时通过 Resources 读取，不必重导入其他表或序列化场景。

| 类型 | 需求 / 等级 | 奖励贡献 |
|---|---|---:|
| 提交 | 生灵草 ×3 | 12 |
| 提交 | 凝露花 ×2 | 15 |
| 提交 | 聚气丹 ×2 | 30 |
| 提交 | 回春丹 ×1 | 20 |
| 悬赏 | Lv1 / Lv3 / Lv5 | 20 / 30 / 45 |
| 悬赏 | Lv11 / Lv21 / Lv51 | 70 / 110 / 240 |

提交任务在接取时不扣物品；备齐后在执事阁提交，按物品 ID 扣除准确数量，再发贡献。不同提交委托可同时接取。悬赏同时限一项，清剿完成后回阁领奖；任务可重复接取，无每日次数限制。重复点击领奖不会再发贡献。放弃不扣物品，清理该悬赏的妖魔。

## 悬赏生成与引导

悬赏等级 N 对应镇妖塔该等级的首层：`(N - 起始等级) × 每多少层一级 + 1`，受塔总层数限制。通过现有 `TowerFloorTable` 取得刷怪组、实际等级、数量倍率及强度倍率，经 `SpawnZone` / `NpcLevelScale` 同一流程生成。本版等级分别对应塔 1、21、41、101、201、501 层。

任务介绍的妖魔名称、数量从最终展开后的刷怪名单生成，使用 NPC 库中文名称，保证与实际妖群一致。只在 `Sect_Wilderness` 现有四片刷怪空地内刷怪，不启动原标记的循环，也不改塔的刷新逻辑。每个出生点单独贴地，妖魔保持直立；悬赏根节点独立于相机，移动机位不会拖动妖群。

只有本次悬赏实例的 `Died` 事件更新进度，其他妖魔、塔内击杀和清理销毁均不计入。全部清剿后不重刷，领取贡献前保留完成状态。异常销毁导致目标缺失时补回未计为击杀的目标。

宗门追踪显示在左侧主线 HUD 上方，可切换追踪已接委托。去野外时指向实际传送点，进入野外后指向尚存妖魔；完成后引导返回宗门执事阁。感叹号和边缘箭头使用 Overlay 画布，避免后处理冲淡。

## 存档与跨场景

`宗门任务` 的纯数据在场景切换中持续保留；`SaveData.宗门任务记录` 保存 JSON，包含已接任务 ID、追踪 ID 和逐只剩余妖魔 ID。`SaveSystem.从角色采集/应用到角色` 分别导出、恢复。旧档空字段视为未接取，不提高存档版本、不清空角色。部分击杀后重新进入野外或读档只生成剩余成员。完成但未领奖的悬赏读档后仍可领取。
