# 怪物近战判定（21 只妖魔）

> **这份文档管什么**：妖魔怪（`NPC/Demon/**`）的普攻 / 主动神通怎么打中玩家、
> 那些数字（出手进度、站位、接触窗）是怎么来的、换模型后要怎么重新量。
> 代码入口：`cultivation/Assets/Scripts/Npc/Ai/近战妖魔Ai.cs` + 每只怪一个 `NpcAi<模型名>.cs`。

## 1. 用户定的口径（原话）

> 「这 21 只基本和白熊精的 ai 一样，a1 普攻，a2 主动神通，**都是物理攻击**，
> 主动神通冷却 **8 秒**；有武器的用**子物件武器网格**做伤害判定，没武器的**注意观察 a1/a2 的动作范围**来做伤害判定。」

于是有两条并存的判定路子：

| | 谁用 | 怎么判 |
|---|---|---|
| **① 武器网格实时判定**（用户选的是这条） | 11 只**有武器**的 | 出手期间逐帧拿**武器子物件的网格包围盒**和玩家求交，**碰到了才出伤**，命中特效落在**接触点**上。扫空 = 这 ↓ 打空 |
| **② 按动作范围** | 10 只**没武器**的（含寒狼） | 动画播到量出来的**峰值进度**那一下结算（白熊精 / 野猪的老口径），必中，命中率照公式摇 |

> 用户当时在「A. 用碰撞体 / B. 新做武器网格实时判定」里**选了 B**。

## 3. 数字是怎么来的（**全部量出来的，一个都不许手填**）

菜单 **修仙 / 怪物 / 量近战动作范围** → `Assets/Editor/Tools/近战动作量测.cs`。
它做两件事：

1. **每 2% 采一帧**，自己做蒙皮运算（`骨骼.localToWorldMatrix × bindpose × 顶点` 加权），
   算出判定体在**角色根节点前方多少米**（世界米）→ 峰值进度 / 峰值前伸。
2. **接触窗**：把玩家当成一个 `0.8×1.6×0.8`（+ 判定外扩 0.15）的盒子摆在**站位**上，
   逐帧看判定体包围盒和它相不相交 → 输出「真正扫到玩家」的进度区间。
   这个区间就是 `普攻判定起/止`、`神通判定起/止`。

### 站位为什么是 `× 0.73`
白熊精的既有口径：武器最远伸 3.44 米 → 站位定 2.5 米（≈ ×0.73）。
**别按"判定够得着"定站位** —— 那样武器尖只是刚够到玩家，看着像打空；
要让武器**整条从玩家身上扫过去**。

两只招的前伸不一样，取 **`min`**（短的那个）：
取长的会让短的那一招武器扫不到人。

### 换模型 / 改动画之后
**重新量，然后重新生成那 11 个类的数字**（接触窗、峰值、站位都是量测输出）。

## 4. 实测验收（2026-09-29）

- **武器网格真的在生效**：牛头妖站 **8 米**（手动把 `攻击距离` 调到 8）→ 9 秒 **出手 4 次、掉血 0 次**；
  调到 **3.9 米** → **命中**。这就是"碰不到就是打空"。
- **全 21 只巡测**（每只站自己的站位、中途持续 `玩家.复活()` 防止被 290 伤害打死污染测试）：
  **20/21 至少命中一次**，冷却节奏对（普攻 ~2.5s、神通 9 秒内 1 次）。
  当时唯一漏的是穷奇（见 §5），补外扩后 **3/3 全中**。
- **动作范围那一路**也验过：寒狼站 1.3 米，16 秒打出 `Attack1 211` + `Attack2 397`。
- 网格判定**仍然过一遍命中公式**：巡测里出现过 `Attack1-`（接触到了但闪避摇中）——
  这是对的：接触 = "攻击够到了"，闪不闪开是另一层。

## 5. 坑（这一节值得单独读）

### 5.1 `Renderer.bounds` 对**蒙皮武器**不可靠 → 穷奇整场打空
穷奇的判定体 `QiongQi_wuqi` 是 `SkinnedMeshRenderer`。运行时量到它的 `bounds` 只有
**0.9×1.9×1.6 米、贴着身体**；而它**真实几何前伸是 2.60 米**（量测工具手动蒙皮算的真值）。
结果：站 1.9 米**整整 8 秒 0 次接触、0 伤害**。
修法：给穷奇单独 `判定外扩 = 0.8`（实测 0.8 与 1.2 都是 4/4 全中）。
**这是量出来的补偿，不是拍的数**；以后再出现"某只怪站在自己的站位上打空"，
先量它的判定体运行时包围盒 vs 真值前伸。

### 5.2 量测口径必须是**世界米**，不能用角色局部坐标
prefab 根节点带缩放（白熊精 1.54 倍），局部米 ≠ 世界米：
同一个 Attack1，世界口径 3.44 米、局部口径只有 2.24 米。
而运行时的 `攻击距离` 和 `Renderer.bounds` **都是世界米** → 量测必须用世界口径。

### 5.3 量测**不能为了窗口采样第二遍**
第一遍采完再采一遍，第二遍的数会跑偏（同一个实例连采两轮，峰值就变了）。
正确做法：**一遍采样，把每帧的包围盒存下来**，两招都量完之后再统一算接触窗。

### 5.4 探针复位玩家**必须调 `复活()` / `回满()`**
直接写 `玩家.当前气血 = 气血上限` **不会清 `已死亡`**，而所有敌对 NPC 决策第一行是
「玩家已死 → 待机」→ 后面所有测试都是 **0 出手**，读数全是假的（本次排查就栽在这上面，
浪费了两轮测试）。`PlayerVitals` 里已经写了这个注释，别再犯。

### 5.5 自动挂载发生在 `Start()`，不是 `Awake()`
探针里 `Instantiate` 之后**立刻**查组件会查不到（只有第一帧 `yield` 过的那只会挂上）。
要么等一帧再查，要么批量造完统一等一帧。

## 6. 还没做的

- 21 只的 **`Attack3` 全空着**（用户没要）。
- 招式**没有各自的音效 / 起手特效**（表里 `闪光特效路径` 是清空的）。
- 这 21 只的**主动神通目前只是"物理重击"**，没有特殊效果（击退 / 流血 / 破防）。
- 穷奇的 `判定外扩 = 0.8` 是**补偿**，根治办法是把网格判定的包围盒换成
  **运行时手动蒙皮求真包围盒**（量测工具里已经有这套算法，可以抽出来共用）。
