# 宗门贡献与功德堂兑换

> **管什么**：宗门里的通用货币「**宗门贡献**」——怎么来（打塔 / 任务奖励）、怎么去（功德堂兑换）、怎么进存档、一件物品怎么上架、面板与交互怎么接线、怎么调价、实测数字与两个测试环境的坑。
> **不管什么**：物品本身的用法与效果看 [design/物品系统](../design/物品系统.md)；物品表的列定义与生成链路看 [reference/配置表字段](../reference/配置表字段.md)；存档字段与版本口径看 [design/存档系统](../design/存档系统.md)；打塔怎么给贡献看 [guides/镇妖塔](镇妖塔.md)；任务表 `奖励贡献` 列看 [design/任务系统](../design/任务系统.md)；交互器与 ESC 协调看 [design/交互系统](../design/交互系统.md)。
> **本文件怎么查**：§1 它是什么 · §2 贡献怎么来怎么去 · §3 进存档（版本 13）· §4 一件物品怎么上架 · §5 功德堂面板与交互接线 · §6 实测 · §7 怎么调 · §8 坑。

## 1. 它是什么

**宗门贡献 = 宗门里的通用货币**，专门用来换那些"**别处没有来源**"的东西
（灵田开拓令 / 灵田升阶令 / 练功木桩 / 各种灵种）。

| 项 | 值 |
|---|---|
| 代码 | `Assets/Scripts/Core/宗门贡献.cs` —— **静态类**，不是单例组件 |
| 为什么是静态类 | 和 `对话标记` / `TowerProgress` 同一类：**跨场景要活着的纯数据**。挂物件上就得操心"哪个场景有、谁先创建、切场景丢不丢"；静态 + 进存档最省事也最不容易错（本工程既有做法） |
| 读当前值 | `宗门贡献.当前` |
| 改它 | 只能走 `加(点数, 原因)` / `扣(点数, 原因)` —— ⚠️ 两者都会广播 **`变化`** 事件，**界面靠它实时刷新**（不然玩家兑换完看到的还是旧数字；本工程在别处踩过同款坑 `B61`） |
| 查够不够 | `宗门贡献.够(点数)` |
| 扣不动怎么办 | `扣` 在不够时**返回 `false` 且不扣**（调用方按 false 处理，不要先查再扣） |
| 读档 | `从存档设置(值)`（**不广播日志**，避免读档刷屏） |
| 串局 | `[RuntimeInitializeOnLoadMethod]` 重置为 0（和别的静态状态一个规矩） |

```
宗门贡献.加(点数, 原因)   ← 原因只用于日志：[宗门贡献] +5（镇妖塔第 12 层清场）→ 191
宗门贡献.扣(点数, 原因)   ← [宗门贡献] -5（兑换「生灵草种」）→ 95
```

## 2. 贡献怎么来、怎么去

| 方向 | 来源 | 规则 |
|---|---|---|
| **进** | **打镇妖塔**（长线正路） | 每**清空一波**给 `max(1, 当前层 / 5 + 1)` —— **越深给得越多**，鼓励往上爬而不是在第 1 层刷（实测：第 1 层 **+1**、第 12 层 **+3**） |
| **进** | **任务奖励** | 任务表新增 **`奖励贡献`** 列；`任务管理器.发奖励` 里和 `奖励物品` **并列**发 —— **两者互不影响**（填了贡献不会吃掉物品，反之亦然） |
| **出** | **功德堂兑换** | 见 §4 / §5。这是**唯一**的消耗口 |

> 需求原文里，灵田升阶令 / 开拓令 / 练功木桩的来路写的就是「**在宗门贡献处兑换的道具**」——
> 在这之前它们**游戏里没有任何来源**（只能靠 F1 面板发），本系统就是把那条正路补上。

## 3. 进存档（**版本 13**）

| 项 | 值 |
|---|---|
| 存档版本 | `SaveData.当前版本` **12 → 13** |
| 新字段 | `SaveData.宗门贡献`（`int`） |
| 采集 | `SaveSystem.从角色采集` 里一行：`数据.宗门贡献 = 宗门贡献.当前;` |
| 恢复 | `SaveSystem.应用到角色` 里一行：`宗门贡献.从存档设置(数据.是空的 ? 0 : 数据.宗门贡献);` |
| ⚠️ 迁移口径 | 这是**加法字段、不做版本门槛** —— 老档读出来就是 **0**，而 0 正好等于"新玩家一点贡献都没有"，语义天然对齐。**和 v11 / v12 那种"破坏性升级、老档重新开局"不是一回事** |

详见 [design/存档系统 §3](../design/存档系统.md)。

## 4. 一件物品怎么上架

**判据只有一个：`ItemDefinition.兑换消耗贡献 > 0`（0 = 不上架）。**

```
物品表.csv ──「兑换消耗贡献」列──▶ ItemDefinition.兑换消耗贡献
                                        │
              功德堂兑换.上架的() 直接扫 QuestDatabase.取().物品库，挑出 > 0 的
                                        │  再按价格升序排
                                        ▼
                             面板一行一件（名字【N 贡献】— 介绍 + 兑换按钮）
```

| 设计点 | 做法 | 为什么 |
|---|---|---|
| 卖什么 | **直接扫物品库**，挑 `兑换消耗贡献 > 0` 的 | **不另建兑换表**：本工程物品都是"表里加一行就自动进游戏"，第二份清单**必然分叉**（`A10` 那条"NPC 表不是唯一来源"是同款教训） |
| 排序 | 按 `兑换消耗贡献` **升序** | 便宜的在前，玩家一眼看到能买得起的 |
| 上架一件新东西 | **给那一列填个数 + 跑 `修仙/从配置表生成资产`** | 不用改代码、不用改界面 |
| 下架 | 把那一列清成 0（或空） | ⚠️ 按导入器口径，空值会写成 0（`A2`） |

**已定价的 8 件**：

| 物品 | 贡献 | 备注 |
|---|---|---|
| 生灵草种 `item_seed_shengling` | **5** | |
| 凝露花种 `item_seed_ninglu` | **8** | |
| 回春草种 `item_seed_huichun` | **8** | |
| 清心莲种 `item_seed_qingxin` | **15** | 需一阶中品灵田 |
| 练功木桩 `item_muzhuang` | **20** | 以前**没有任何来源** |
| 赤焰芝种 `item_seed_chiyan` | **25** | 需一阶上品灵田 |
| 灵田开拓令 `item_lingtian_kaituo` | **30** | 以前**没有任何来源**（只靠任务阶段20 发 4 枚） |
| 灵田升阶令 `item_lingtian_ling` | **60** | 以前**完全没有来源**（只能 F1 面板发） |

> 灵田那边当初就留了口子：`灵田.cs` 只留一个常量 `升阶令id`，注释写着"贡献系统做出来后只要把道具挂进兑换商店、本文件一行都不用改"—— 现在正是这样，**`灵田.cs` 一行都没动**。

## 5. 功德堂面板与交互接线

### 5.1 面板自己画（不是 `界面预制体`）

和「传送圈 / 灵田地块 / 炼丹炉」一样：**行数取决于数据**（上架几件就有几行），预制体表达不了。
所以 `功德堂兑换` 组件**自己造面板、自己开自己关**。

| 项 | 值 |
|---|---|
| 画布 | `功德堂Canvas`，`sortingOrder = **2600**`（和炼丹界面一档：**高于 HUD / 任务追踪，低于暂停菜单**） |
| 布局 | 标题 `功德堂 · 贡献兑换` + 顶部 `宗门贡献：N` + 每件一行「`名字　【N 贡献】　—　介绍`」+ 每行一个「兑换」按钮 + 关闭 |
| 不够贡献时 | **按钮置灰、行文字变红**（`不足色`），点不动；点兑换会给出「贡献不够：还差 N」 |
| 刷新 | 订阅 `宗门贡献.变化` ⇒ **兑换完当场刷新**（贡献数字与每一行的可点状态一起变） |
| 关 | 面板根本身交给 `StationInteractor.当前界面` —— **这样 ESC 才关得掉** |

### 5.2 怎么打开：判据是"**这台设施上有没有这个组件**"

`StationInteractor.打开界面 / 关闭界面` 加了一条分支：看这台设施（或它的父级）上有没有
`功德堂兑换` 组件。

> ⚠️ **不是**新增一个 `StationKind`。功德堂在场景里是当**建筑**配的（`类型=修炼`），
> 加一种 `StationKind` 反而要动枚举 + 改场景数据；而"有没有组件"这个判据**不动任何数据**。
> （和灵田地块面板走同一个路子。）

### 5.3 挂在哪：**运行时补，不碰场景文件**

```
场景自举.补功德堂(场景)  ──按名字找──▶  Sect 的「environment_Building_luoxiaguan_001_d」
                                          （它的 StationInteractable.显示名 = 功德堂）
                                          └─ 补上 功德堂兑换 组件
```

实测日志：`[场景自举] 「Sect」的「environment_Building_luoxiaguan_001_d」缺 功德堂兑换 → 已自动补上`

**为什么不用"在场景里挂组件"**：保存 `Sect.scene` 会连带把它序列化着的一份**运行时 UI 列表**
重新排版（实测一次 1541 行；跑导入器那次 **+12440 行**）—— 见 [踩坑总库 A8](../ai/踩坑总库.md)。
**能和塔准入一样运行时补的，就别写进场景。**

## 6. 实测（Play 模式）

**面板内容**（贡献 0 时）：

```
[功德堂 · 贡献兑换] [宗门贡献：0] [关闭]
[生灵草种　【5 贡献】　—　一粒基础灵种。种下三日可收生灵草。] [兑换]
[凝露花种　【8 贡献】　—　…] [兑换]
[回春草种　【8 贡献】　—　回春草的种子。] [兑换]
[清心莲种　【15 贡献】　—　灵种。需一阶中品灵田方可种植。] [兑换]
[练功木桩　【20 贡献】　—　…摆在洞府里可以随时试招，打空后会自动恢复。不打人也不还手。] [兑换]
[赤焰芝种　【25 贡献】　—　…需一阶上品灵田才种得下。] [兑换]
[灵田开拓令　【30 贡献】　—　宗门贡献处兑换的令牌。在个人洞府里使用，可开垦一块新灵田。] [兑换]
[灵田升阶令　【60 贡献】　—　宗门贡献处兑换的令牌，用于提升灵田品阶。] [兑换]
```

| 情形 | 实测 |
|---|---|
| 贡献 **0** | `可兑换按钮 = 0/8`（**全灰**） |
| `宗门贡献.加(100)` | `8/8` 可点 —— **面板自己刷新了**（没重开界面） |
| 点兑换（生灵草种 5） | `[宗门贡献] -5（兑换「生灵草种」）→ 95`、**背包 38 → 39 件** |
| 再换一件 | `-5 → 90`、**背包 40 件** |
| 场景自举 | `[场景自举] 「Sect」的「environment_Building_luoxiaguan_001_d」缺 功德堂兑换 → 已自动补上` |
| 打塔（第 1 层清空一波） | 第 1 层 `+1`；第 12 层 `+3`（`12/5+1 = 3`） |

## 7. 怎么调

| 想调什么 | 改哪 |
|---|---|
| 某件物品的售价 | `物品表.csv` 的 **`兑换消耗贡献`** 列 → 跑 `修仙/从配置表生成资产` |
| 上架 / 下架一件 | 同上（`> 0` 上架，`0`/空 下架） |
| 打塔给多少贡献 | `TowerController.处理一波清空` 里的 `Mathf.Max(1, 当前层 / 5 + 1)`（**目前是硬编码**，要表驱动得另开列） |
| 任务发贡献 | 任务表 **`奖励贡献`** 列（`QuestDefinition.奖励贡献`） |
| 面板外观 | `功德堂兑换` 上那一排 `Color` / `Font`（幕布色 / 底板色 / 标题色 / 正常色 / **不足色** / 按钮可点色 / 按钮灰色） |
| 功德堂是哪栋楼 | `场景自举.功德堂物体名`（默认 `environment_Building_luoxiaguan_001_d`） |
| 删掉某个 NPC/物品的目录缓存 | 不涉及；兑换是**实时扫物品库**，改完表跑导入即可 |

## 8. 坑

### 8.1 ⚠️ 交互器会"走出范围自动关界面" —— 测面板必须站进交互距离

`StationInteractor` 有"**玩家走出交互范围就自动关界面**"。测试时把玩家放在 **4~7 米外**，
面板**当场被关掉**，表现成"**面板打开失败 / 兑换没反应**"—— 其实组件是好的。
功德堂的 `StationInteractable.交互距离` 是 **6.0 米**。

**规矩**：测这类面板，先把玩家放进 `StationInteractable.交互距离` 内（或临时把距离调大）。
这条也解释了另一件事：**"界面没反应"要先区分"没打开"和"被自动关掉了"**（同类：`B79`）。

### 8.2 ⚠️ 测试里用 `transform.parent` 找"哪一行的按钮"会命中整块面板

想点某一行的按钮时，**不能**用 `按钮.transform.parent.GetComponentsInChildren<Text>()` 去找那一行 ——
按钮的 parent 就是**整个面板**，会把**所有行的文字**都算进来 ⇒ **点错按钮**
（本次实测就点成了"生灵草种"）。

**规矩**：断言 / 点击要用**下标**（第 i 行），或者**给按钮起唯一名字**再按名字找。详见 [踩坑总库 B85](../ai/踩坑总库.md)。

### 8.3 还没做的

- **打塔给的贡献是硬编码公式**，没进表（见 §7）。
- 面板**没有分页 / 搜索**（8 件还好，上架几十件就得做）。
- **没有"贡献来源一览"界面**，玩家只能从日志和变化数字感知。
- 兑换**没有二次确认**（点一下就扣）；也没有"批量兑换"。
