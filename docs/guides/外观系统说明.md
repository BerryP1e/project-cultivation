## 0. 一句话原理（最重要）

**换外观 = 保留玩家骨架，换兼容绑定矩阵的网格与材质。**

本项目两套玩家模型的骨骼层级与索引相同 —— 实测：

Tripo肩关节过于靠内属于骨架比例问题，需使用 [Tripo肩关节修复工具](Tripo肩关节修复.md)。以下外观绑定兼容处理解决的是模型轴向不同导致的反扭，不会自动外移肩位。

```
「成男村民」节点=81    玩家「Player_Visual」节点=81
路径除根名外逐段相同：…/Armature/BoneRoot/Hip/Pelvis/L_Thigh/L_Calf/…
两个 SkinnedMeshRenderer 的骨骼：78 根，**同名同序**
```

所以：**不换 `Player_Visual`、不换 Animator、不动朝向补偿、不做动画状态同步**。
但同名同序不代表绑定姿势相同。2026-10-05实测：村民与玩家右前臂的绑定矩阵最大元素差约1.98，局部绑定朝向相差接近180°。直接换原网格会让多个动作的右臂、袖口反扭。

`AppearanceMeshBinding`复制外观网格，保留顶点、权重与材质，替换为目标骨架原网格的bindposes。两件现有外观使用共同模型坐标空间；不重新摆顶点，也不通过LateUpdate强扭手骨。玩家与外观预览按源网格缓存兼容副本，组件销毁/预览关闭时释放；导入的FBX和Mesh资产不改。骨骼数量或顺序不匹配时拒绝换装并提示原因。此方案仅适用于共同模型空间、同骨骼索引的外观，新骨架必须另做重定向，不能直接套用。

身体网格必须按骨骼选，不能取层级中第一个 SkinnedMeshRenderer。传送到新场景时，功法装载器可能先挂上武器，手骨下的武器渲染体会排在身体前面。玩家外观优先选择骨骼列表含玩家 Avatar 髋骨的渲染体，排除武器实例子树；没有 Humanoid 髋骨时才按骨骼数量选主体。否则换外观会把身体网格塞到单骨武器上，出现 NaN 顶点、武器消失和动作判定异常。复验必须检查实际网格绑定及 BakeMesh 顶点，不能只看组件 enabled。

> ⚠️ 曾经走过一条弯路：以为要"整套 Player_Visual 换掉"，于是写了缓存引用转移、
> 通知 `PlayerDeathSequence`、动画状态桥接……**全是多余的**，用户一句"他们骨骼应该是一样的"点破。
> 结论：**先量骨骼，再写代码。**

## 1. 现有文件

| 文件 | 作用 |
|---|---|
| `Assets/Scripts/Data/AppearanceDefinition.cs` | 一件外观：id / 外观名 / 模型资源路径（或直接给预制体）/ 介绍 / **默认拥有** / **解锁标记** / 解锁即装备；`取模型()` 负责在 Resources 里找到模型 |
| `Assets/Scripts/Data/AppearanceDatabase.cs` | 运行时外观库（`Assets/resources/外观/外观库.asset`），`取(id)` / `取默认()` |
| `Assets/Scripts/Player/玩家外观.cs` | 挂在 **Player** 上：按规则自动穿、`装备(外观)` / `还原()`、订 `对话标记.变化` 实现任务自动解锁切换 |
| `Assets/Scripts/Player/AppearanceMeshBinding.cs` | 校验骨骼顺序，以原骨架bindposes创建兼容网格，避免换装后右臂反扭 |
| `Assets/Scripts/UI/外观预览.cs` | 面板右侧「模型3D展示」的控件：隔离相机 + RenderTexture + **只能左右转** |
| `Assets/resources/外观/` | `外观库.asset`、`成男村民外观.prefab`、`修仙者.prefab` |

当前库里有两件：`村中少年`（默认拥有，模型 = 成男村民）、`修仙者`（门派便服，使用外观道具获得；当前表中解锁标记为空）。

外观状态按 ID 保存：会话记录包含当前穿戴 ID 与已获得 ID 集合，新场景的玩家在 Start 恢复拥有列表和穿戴。存档 v15 新增 `已获得外观`，采集时连同 `外观id` 写入；读档替换完整记录，新档/空记录不能继承上一角色的衣服。传送接力期间不使用旧存档覆盖会话外观。对话标记只解锁本次标记实际涉及的外观，无关任务标记不能重新选择默认村民外观。

v14 及更早的存档没有拥有列表，只能把其中记录的当前穿戴外观补为拥有；此前已消耗、但没有任何存档记录的其他外观无法从空数据中推断。修复不改写或删除已有存档文件。

第八页由 `UIInkAppearancePage` 运行时接管，左侧水墨持有列表，右侧上部为透明半身立绘，下部为独立滚动介绍与换装按钮。点击列表只选中预览，点击「换上此装」才装备。长介绍自动换行并由 RectMask2D 裁剪，溢出时可滚动；滚动条沿用背包风格。旧纸面板和 3D 展示在该页停用，父导航与其他子页保持原入口。立绘在 `Assets/resources/UI/InkUI/Appearance/portrait-<外观id>.png`，导入为单张 RGBA Sprite。

## 2. 加一件新外观（照做即可）

### 第 1 步：准备模型
用**同一套骨骼**的模型（Tripo 再出一版同角色、或从现有模型改）。放进 `Assets/resources/外观/<名字>.prefab`。

- 也可以直接复用现成的 NPC 模型，例如 `NPC/Human/成男村民/成男村民`（`成男村民外观.prefab` 就是这么来的）。
- 预制体里**不要留脚本、碰撞体、NPC 组件**，只留 `Transform + Animator + SkinnedMeshRenderer`。
  反例：直接从 NPC 复制会带上 `NpcInstance/NpcIndicator/NpcDialogue/StationInteractable/朝向补偿/胶囊`，
  要么手动删，要么像 `成男村民外观.prefab` 那样程序化剥一遍（注意**反复扫到没有为止** ——
  `NpcInstance` 会因为 `NpcIndicator` 依赖它而删不掉，得先删依赖方）。

### 第 2 步：建外观资产
`Assets` 右键 → **Create → 修仙 → 外观**，填：

| 字段 | 说明 |
|---|---|
| `id` | 唯一 id，建议 `app_xxx` |
| `外观名` | 列表里显示的名字 |
| `模型资源路径` | `Assets/resources/` 下、不带扩展名，例：`外观/修仙者` |
| `模型预制体` | 也可以直接拖预制体（填了就忽略路径） |
| `介绍` | 面板里显示 |
| `默认拥有` | 勾上 = 开局就拥有并装备（村中少年就是它） |
| `解锁标记` | 拥有它需要的标记（分号分隔，全部满足才解锁）。**任务完成时写的标记填这里** |
| `解锁即装备` | 解锁后是否立刻换上 |

### 第 3 步：**塞进外观库** ← 最容易漏的一步
打开 `Assets/resources/外观/外观库.asset`，把新资产加进 `全部` 列表。
**忘了加 = 运行时 `取(id)` 找不到它、`取默认()` 可能返回 null（开局没外观）。**

### 第 4 步：想让它靠任务解锁，就写标记
任务表里那条阶段的 **`完成加标记`**（例：`q_入宗门_完成`）＝ 外观的 `解锁标记`。
**任务侧一行代码都不用改** —— `玩家外观` 订了 `对话标记.变化`，标记一上就自动换。

### 第 5 步：测
进 Play Mode，看 Console：

```
[外观] 换上「村中少年」（网格 tripo_node_ba8348ad）
```

手动换：任意脚本里 `玩家.GetComponent<玩家外观>().装备(某外观资产)`；只有外观资产配置了对应解锁标记时，加标记才自动换：
`对话标记.添加("q_入宗门_完成")` → 应看到 `[外观] 换上「修仙者」…`。

## 3. 半身立绘与旧 3D 预览

当前外观页使用 `UIInkAppearancePage` 加载 `portrait-app_cunmin.png` 和 `portrait-app_player.png`。两张为同一角色、身体和脸均向左的透明半身图，介绍和按钮位于独立水墨底内。素材须保持 alpha，禁止用不透明背景裁图代替；更换 Sprite 后重进页面即可。提示词与参考见 `ui-rework-2026-10-03/appearance-portraits/提示词.md`。

以下 3D 控件仍保留供其他用途，不再作为外观页默认展示：

- 面板右侧那块「模型3D展示」：把它的 `RawImage` 拖到 `外观预览.画布` 上（留空会自动往上找）。
- 预览环境是**隔离**的：模型实例放在 `y = -1000` 的"预览台"，专属相机 `farClip = 12` + 纯色清屏 →
  **不用动工程的 Layer 设置**，也不会把世界渲进去。
- **旋转规则（用户明确要求）**：`OnDrag` 只吃 `delta.x` 累加到 `当前偏航`，
  模型欧拉角恒为 `(0, 当前偏航, 0)` —— **俯仰永远是 0，翻不过来**。
  这不是"限制角度"，是根本不给俯仰赋值的路径。
- 换预览模型：`外观预览.显示(外观资产)`（内部同样是只换网格 + 材质）。

## 4. 已经踩过的坑（别再踩）

1. **骨骼不同名同序 = 换上去会扭曲**。加新模型前先比：
   两个 `SkinnedMeshRenderer.bones` 的**名字序列**是否逐项相同（本项目的玩家/村民都是 78 根同名同序）。
2. **别用 `Resources.Load<GameObject>(路径)`**：`Assets/resources/NPC/...` 下同时躺着同名 FBX，会拿到 FBX。
   要用 `Resources.LoadAll` 再挑带 `Animator` 的那个 —— `AppearanceDefinition.取模型()` 里已经这么做了。
3. **别去换 `Player_Visual` / Animator**：`PlayerDeathSequence.玩家视觉` 和
   `PlayerAnimationController` 的补偿根都在 `Start` 里缓存过，换掉会变"销毁对象"。
   只换网格就完全绕开这个问题。
4. **预览台别放到玩家附近**：靠 `y=-1000` + 短 farClip 隔离，挪近了主相机会看到它。
5. **忘了进外观库**：见第 3 步，症状是"资产明明建了，游戏里却只有默认那件"。
6. **外观预制体里留了脚本/碰撞**：预览会实例化它，脚本会跟着跑（预览里已主动清 `Collider`，
   但脚本得在预制体那边删干净）。
