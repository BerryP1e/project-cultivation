## 绑定与随动

玩家外观按 Avatar 髋骨选身体 SkinnedMeshRenderer，排除武器子树。不能用层级中的第一个蒙皮，因为武器可能先挂载并排在身体之前。

原村民采用已经验证的共同模型空间绑定方式。新的指定着装由 OutfitClothBaker 预处理：检查 78 根人体骨名与顺序，按源/目标 rest pose 适配新网格，然后增加衣服和长发蒙皮。顶点重定位只在该预处理明确启用；不能把它普遍套到村民，否则会出现手臂打结回归。

成品位于 Assets/Art/Characters/OutfitCloth/，AppearanceDefinition.衣服随动引用对应配置。原 FBX 不改写，运行时由 AppearanceClothRig 在人体骨架下创建额外骨链并绑定成品网格。村民仍为 78 根人体骨，练气总计 102 根，筑基/金丹总计 120 根。

衣摆与宽袖使用有阻尼的世界空间弹簧、固定段长、每节限角及躯干/腿/臂避让。长发根部固定在头骨，背后和两侧发束分开，摆幅更收敛；增加头颈、肩部、胸背与手臂的胶囊约束。算法不使用人物布娃娃刚体，也不执行全网格布料自碰撞。

长发区域同时根据源模型头/颈权重、空间位置与原贴图颜色识别，避免把脸、头冠、衣领和短发当作发尾。裤腿、靴和手保持人体动画；头发不绑定到衣摆骨。暂停停止推进，大幅传送/低帧间隔重置惯性，换装移除旧附加骨。

## UI 与立绘

外观页使用 portrait-<id>.png 半身立绘。新增两张透明立绘与原模型衣色、发色对应，接入列表图标；完整工具模式、参考图和最终提示词见[制作记录](../reports/筑基金丹着装立绘.md)。

神通/法则 3D 预览克隆自己的骨架，调用 AppearanceClothRig.同步预览 后，在手动动画推进之后、渲染之前推进随动。不能只复制 sharedMesh 并沿用上一个外观的 bones，也不能让预览引用游戏角色的骨节点。

## 维护与验收

沿用“修仙 → 外观 → 一键：生成表 + 导入 + 收集”，只导入外观表并调用同一预处理，不重建全场景 UI。加新模型前先检查真实姿态、源骨架与衣型，不能仅凭骨名相同或 Avatar 有效就推断兼容。

Mesh 更新必须刷新实际顶点/权重等原生缓冲；仅 CopySerialized 可能出现 CPU Bake 正常、实际 GPU 仍用旧顶点的差异。验证使用原生帧截图、实际蒙皮顶点、转头、站走跑、施法、御风、连续换装、预览隔离和传送复位。当前配方为 appearance-cloth-runtime，报告和前后视角放在 .local/diagnostics/outfit-cloth/。历次绑定方式见[历史记录](../archive/pre-home-20261016/guides/外观系统说明.md)。
