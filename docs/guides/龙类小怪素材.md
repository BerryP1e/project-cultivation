## 资源位置

资源归入 `cultivation/Assets/Art/Characters/Imported/DragonMob`，不放入运行时 Resources 自动加载库。

| 子目录 | 内容 |
| --- | --- |
| `Model/DragonMob.fbx` | 待机MAX的模型、配套Generic骨架与 `DragonMob_Idle` 动作，作为五个独立动作的共同模型 |
| `Animations/DragonMob_{Attack,Hit,Death,Run}.fbx` | 四个仅含骨架和动作的FBX，不重复导入蒙皮网格；使用主模型Avatar |
| `Materials/DragonMob.mat` | 共享Built-in材质，所有模型复用 |
| `Textures/DragonMob_Albedo.tga` | 原始 `怪物_龙类小怪.tga`，保持纹理内容 |
| `Controllers/DragonMob.controller` | Idle、Run、Attack、Hit、Death五个预览状态，默认Idle；玩法接入时再配置切换 |
| `Prefabs/DragonMob.prefab` | 配套模型、材质、Avatar与预览控制器，可拖入场景或预制体模式查看 |
| `Reference/DragonMob_Combined.fbx` | “整合”MAX的高面数蒙皮参考模型；源文件没有有效动作曲线，不生成空动画 |
| `Reference/DragonMob_BindReference.fbx` | “绑定”MAX的独立骨架参考模型，部分父子层级与动作版本不同，不用于替换主模型骨架 |

单独未绑定的根目录MAX与待机模型使用相同基础网格，不重复引入。五个BIP保留在外部来源目录，本轮使用已配套的独立MAX动作，不将BIP或MAX复制到Assets。原始文件没有改写或删除。

## 动作与转换

| 动作 | 原MAX | 原帧范围 / 帧率 | 时长 | 循环 |
| --- | --- | --- | ---: | --- |
| Idle | `输出/怪物_龙类小怪待机.max` | 0～6 / 8 fps | 0.75 s | 是 |
| Run | `输出/怪物_龙类小怪跑步.max` | 0～6 / 8 fps | 0.75 s | 是 |
| Attack | `输出/怪物_龙类小怪攻击.max` | 0～8 / 8 fps | 1.00 s | 否 |
| Hit | `输出/怪物_龙类小怪被击.max` | 0～3 / 8 fps | 0.375 s | 否 |
| Death | `输出/怪物_龙类小怪死亡.max` | 0～3 / 8 fps | 0.375 s | 否 |

源单位为厘米，导入后为米。保留骨骼、Skin权重、节点变换和贴图；不套玩家Humanoid重定向，不自动改变作者的速度或地面偏移。导出排除相机、灯光和粒子视图，保留完整骨架及末端节点。主模型4896个三角形，Unity按UV/法线拆点后3644个顶点，130个蒙皮引用骨骼，模型层级185个Transform。

Unity对原8 fps的FBX按30 fps采样，部分末帧会被截到前一个采样点。最终在Max临时会话中改为24 fps逐帧烘焙，只改变采样密度；原关键帧时间、动作时长和源MAX保持原样。五个Clip都是24 fps。关闭动画压缩和骨架优化，保留路径；Idle/Run开启循环，不做额外循环姿态修正。预制体关闭Root Motion，正式接入时结合NPC移动处理。

## 验证与范围

五个动作各在起始、中间、结束姿态对照Max的实际Skin顶点，累计15组；另检查两个参考模型，合计17组。动作路径、材质/贴图/骨骼引用完整，时长一致；预览Animator实际播放五个状态，关节均有变化，五张动作渲染已人工查看。没有在正式场景放置怪物或修改NPC表。

对照采用稀疏顶点和包围盒，不表示每个顶点完全一致。五个动作最大取样位置偏差约2.79厘米；整合参考模型约6.29厘米、包围盒差约1.32厘米，只作为参考版本保留，不视为已验证的正式动画模型。报告、来源SHA-256与截图位于被忽略的 `.local/diagnostics/dragon-mob`。源场景旧mental ray插件缺失，不影响模型、Skin、动画和纹理导出。
