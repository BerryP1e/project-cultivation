## 3. 武器：`八九玄功_三尖两刃刀.prefab`

### 3.1 源与产出

**源**：`Assets/resources/NPC/Human/YangJian/YangJian_03.prefab` 里的**独立蒙皮网格节点** `YangJian_03_Weapon` ——

| 项 | 值 |
|---|---|
| 顶点数 | **341** |
| 网格本地长轴 | **4.9154**（米，网格自身尺度） |
| 材质 | `YangJian_03_Weapon` |
| 骨骼 | `Bone01`，其**父节点是 `Bip01 R Hand`** ⇒ 原模型是**握在右手** |

**产出**：`Assets/resources/Weapons/八九玄功_三尖两刃刀.prefab`，层级三层：

```
根
└─ Bone01                 ← 保留源里"相对手骨"的本地 TRS
   └─ YangJian_03_Weapon  ← 蒙皮网格节点，bones / rootBone 都指向新的 Bone01
```

`Bone01` 的本地 TRS 照抄源值：`pos (0.0046, 0.0655, −1.7155)` / `rot (86.4, 257.0, 170.9)` / `scale 0.9451`。
（新 prefab 里 `Bone01` 的父就是 prefab 根，所以这份"相对手骨"的 TRS 在挂到玩家手骨之后**语义与在杨戬身上一致**。）

**生成脚本**：`.dsh/_diag/build_weapon_prefab.cs.txt`，通过 MCP 的 `exec_editor_script` 跑。

### 3.2 挂点与缩放

挂在玩家的**右手骨**下，整条链是：

```
Player/Player_Visual/Armature/BoneRoot/Hip/Waist/Spine01/Spine02/R_Clavicle/R_Upperarm/R_Forearm/R_Hand
```

- local **位置 / 旋转 = 单位**（不额外补偿 —— 补偿量已经在 `Bone01` 的 TRS 里）
- local **`localScale = 0.4911`**

**这个 0.4911 是算出来的，口径是「武器长 ÷ 身高」对齐**（不是"看着差不多"）：

| 步骤 | 数 |
|---|---|
| ① 杨戬身高（身体网格 `YangJian_03` 的世界高度） | **2.664** 米 |
| ② 武器世界长（原模型里） | **4.181** 米 |
| ③ ⇒ 原比例 = ② ÷ ① | **1.570** |
| ④ 玩家身高 | **2.618** 米 |
| ⑤ ⇒ 玩家该拿的武器长 = ④ × ③ | **4.107** 米 |
| ⑥ 玩家手骨 `lossyScale` | **1.8007** |
| ⑦ 武器蒙皮长轴（网格本地） | **4.9154**，`Bone01` 缩放 **0.9451** |
| ⑧ ⇒ 缩放 = ⑤ ÷ (⑦ × ⑥ × 0.9451) | **≈ 0.4911** |

**实测结果**：武器世界长 **4.108** 米、比例 **1.569** ✓（与目标 4.107 / 1.570 一致）。

### 3.3 ⚠️ 别拿 AABB 最长边当"长度"参照

**反面教训**：一开始想省事，用"杨戬本体那把武器的 **AABB 最长边**"当参照 —— 静止姿势下刀是**斜放**的，AABB 最长边只有 **3.151 米**，**小于真实长 4.181 米**；按它硬套会算出 **0.3846**，**偏小 21.7%**（刀短一截，配不上身）。

**判据**：**AABB 是朝向相关的**，量"这个东西多长"不能用它 —— 要用**网格 `localBounds.size`（沿长轴） × 骨骼链的 `lossyScale`**。同一条规矩在别处也适用：量位置/长度一律走 **transform**，别用 `renderer.bounds`（见 §6 与 [踩坑 D12](../ai/踩坑总库.md)）。

## 4. 御风适配片段

### 4.1 为什么要烘这几个片段

需求：**御风时普攻要"上半身打、下半身御风"** —— 不能因为出手就从御风姿势变成站桩，也不能因为普攻就把玩家从御风里拽出来（玩家在空中，腿必须保持御风 Idle 的盘腿/垂腿姿态）。

Unity 的 Humanoid 重定向是**整套动作一起重定向**的，做不到"半个身子用 A、半个身子用 B"，所以**得自己合成一条新片段**。

### 4.2 合成口径

| 项 | 做法 |
|---|---|
| 读什么 | 两边都读**人形肌肉曲线**（`path` 为空的那些曲线），按**肌肉名**判上下半身 |
| 上半身取谁 | **攻击动作**（四个来源之一） |
| 下半身取谁 | **御风 Idle** |
| **下半身 = 16 条肌肉** | 名字含 **`Upper Leg` / `Lower Leg` / `Foot` / `Toes`**（左右各 8 条） |
| 御风 Idle 源 | `Assets/Animations/凭虚御风/御风_Idle.anim`（**2.40 s**、`humanMotion=True`、**102 条曲线**） |
| ⚠️ 时长不匹配怎么办 | 攻击比 2.40 s 长时，御风那侧按 **`Mathf.Repeat(t, 2.40)` 循环采样**（腿不会"走到一半停住"） |
| **根位移取谁** | **取御风 Idle** —— 所以普攻**不会跟着攻击跳起来**（杨戬 Attack2 那条 3.6 米腾空位移被丢掉） |
| 产出形态 | **新的 Humanoid 片段**：**95 条肌肉 + 7 条 `RootT/RootQ` = 102 条曲线**，30 fps、`loopTime=false` |

### 4.3 产出清单

都在 `Assets/resources/技能动作/八九玄功/`，各 **102 条曲线**，**30 fps**、`loopTime=false`。
⚠️ **必须放在 `resources` 下**：普攻组件取片段走的是 `Resources.Load<AnimationClip>("技能动作/…")`（现有 `普攻_远程_01` 就是这条约定，见 `BasicRemoteAttack01.cs`），放在 `Assets/Animations/` 下**运行时取不到**。

| 片段 | 时长 | 帧数 |
|---|---|---|
| `长刀女_Attack1_御风.anim` | 1.67 s | 50 |
| `长刀女_Attack2_御风.anim` | 2.33 s | 70 |
| `杨戬_Attack1_御风.anim` | 1.33 s | 40 |
| `杨戬_Attack2_御风.anim` | 2.17 s | 65 |

**生成脚本**：`.dsh/_diag/bake_yufeng_attacks.cs.txt`（同样走 MCP `exec_editor_script`）。

### 4.4 实测

- **抽查逐点一致**：下半身 `Left Upper Leg Front-Back` **新 = 0.6080 / 御风 = 0.6080**；上半身 `Right Arm Front-Back` **0.2502 = 0.2502** ✓
- **全量骨骼对比**（在**玩家自己的骨架**上比骨骼本地旋转）：**腿的骨骼一根都不在差异列表里**，差异只出现在 **`Hip`** 与**上半身** ✓
- **没有跟着攻击跳起来**：头的世界高度 **−498.65（新） vs −498.64（御风）** ✓

## 5. 怎么复验

脚本都在 `.dsh/_diag/`，参数走同名的 `*.args.json`（PowerShell 转义太痛，**参数一律写文件**），调用方式是 MCP 的 `exec_editor_script` / `exec_runtime_script`（用法见 [工程与工具链 §3.5](../ai/工程与工具链.md)）。

| 脚本 | 干什么 |
|---|---|
| `inspect_rig.cs.txt` | 只读盘点：玩家骨架/Animator、四个攻击 FBX 与人形状态、`YangJian_03` 武器网格、御风片段、玩家控制器 |
| `inspect_weapon.cs.txt` | 只读盘点：武器骨骼挂点与祖先链、武器蒙皮、玩家手骨、四个攻击片段的根位移 |
| `measure_scale.cs.txt` / `measure_scale2.cs.txt` | 量杨戬与玩家的世界身高/包围盒；**用身体网格世界高度定武器缩放比例** |
| `build_weapon_prefab.cs.txt` | **抽出武器为独立 prefab**（`Bone01` + 蒙皮），并量玩家尺度 |
| `bake_yufeng_attacks.cs.txt` | **烘焙四个"上半身攻击 + 下半身御风 Idle"的人形片段** |
| `verify_weapon_final.cs.txt` | 武器缩放 0.4911、全身机位，四段动作各出"前右 + 正侧"两图 |
| `verify_final2.cs.txt` | 正确口径的最终验证：**强制重算蒙皮 + 用变换量测** + 四张图 |
| `verify_weapon_attack.cs.txt` / `compare_weapon.cs.txt` | 修正采样目标与武器缩放后重拍；以及"杨戬本体 vs 玩家+挂刀，同一动作同一机位三视图"对照 |
| `verify_yufeng_clips.cs.txt` | **验收御风适配片段**：脚对御风、手/武器对攻击，并出图 |
| `diag_skinning2.cs.txt` | 查证 Edit Mode 手动采样后是否需要 `forceMatrixRecalculationPerRender` |
| `diag_bones.cs.txt` | **全量对比采样后哪些骨骼不同**（§4.4 那张"腿骨不在差异列表里"的判据就出自它） |
| `diag_root.cs.txt` / `diag_foot.cs.txt` | 逐条对比新片段与御风 Idle 的根曲线；定位脚部偏差（根/髋/盆/踝/肌肉） |

1. **武器长度对得上**：世界长 **4.108** 米、`÷ 玩家身高` = **1.569**（对着 §3.2 的表算，别用 AABB）。
2. **腿是御风的**：拿 `diag_bones.cs.txt` 的差异列表看 —— **腿骨必须为空**（⚠️ **不要**用踝关节的绝对坐标差当判据，见 §6）。
3. **没有跟着攻击跳起来**：头/髋的世界高度与纯御风 Idle 基本相等（实测差 **0.01** 米）。

## 6. 已知偏差

### 6.1 `Hip` 会跟着上半身转 —— 这是**人形求解的固有权为**，不是合成错

采样"上半身=攻击 + 下半身=御风 Idle"的片段时：**腿骨（`L_Thigh / L_Calf / L_Foot / R_*`）的本地旋转与纯御风完全一致**（一根都不在差异列表里），但 **`Hip`（= Hips 骨）的本地旋转与纯御风差 24.5°**，因此**踝关节世界位置差 0.27 米**。

**排除过的四个方向（都实测过）**：

| # | 查了什么 | 结果 |
|---|---|---|
| 1 | 两边的曲线集合 | **完全相同**（各 102 条：95 肌肉 + 7 根），根曲线 `RootT/RootQ` 七条**逐点相同** |
| 2 | 根曲线的绑定类型 | 两边都是 `Animator`，**不存在**"绑到 Transform 上"的差异 |
| 3 | `SampleAnimation` 有没有残留 | **确定性、无残留**：同一片段连采两次 `Hip` 完全一致，换片段互不污染 |
| 4 | 玩家 Avatar 的人形映射 | **标准正确**：`Hips←Hip`、`Spine←Waist`、`Chest←Spine01`、`UpperChest←Spine02`、腿←`L_Thigh/R_Thigh`（**不是**"脊椎挂在腿的父骨上"） |

**真正的原因**：**Unity 的人形求解本来就会把脊椎和手臂的旋转分一部分到 `Hips` 骨上**。逐组替换实测（基准 = 纯御风 Idle 的 `Hip` = `(36.06, 121.06, 138.91)`）：

| 只把这一组肌肉换成攻击 | `Hip` 本地旋转 |
|---|---|
| 脊椎组（`Spine` / `Chest` / `UpperChest`） | `(34.85, 123.88, **120.04**)` |
| **左臂组** | `(40.28, 123.77, 138.27)` |
| 右臂组 | `(35.33, 121.59, 139.02)` |
| 颈头组 / 手指组 | 与基准**完全一致**（不影响 `Hip`） |

⇒ **固有权为，不是配错**："上半身取攻击、下半身取御风"在**肌肉层面已经做到位**。

**要把髋也完全锁死**只剩一条路：把合成后的姿态**烘焙成玩家骨架上的 Generic 片段**（照 `Assets/Editor/Builders/师傅御风重定向.cs` 的做法 —— 就是师傅御风用过的那条"逐帧重定向 + `AnimatorOverrideController`"路子），**代价是片段绑死骨架路径**（换模型就废）。

**判据（唯一可靠）**：验证"下半身是不是真的御风"，**看腿骨在差异列表里是否为空**；**不要用踝关节的绝对坐标差** —— 那个差值随骨架/映射而变，换个模型就换了数。
