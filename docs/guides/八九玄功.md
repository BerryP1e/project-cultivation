# 基础长戟（原八九玄功动作模组）

当前按E执行物理普通攻击四式，左键仍执行修行功法。先查[动作定稿与重建边界](动作定稿与重建边界.md)及[武器与修行功法](武器与修行功法.md)。

## 1. 要求与接线

基础长戟与青山剑法宝的物理攻击进入结算后一律100%命中；此规则覆盖所有物理属性攻击，由CombatCalculator统一跳过闪避，详见 [战斗与伤害 §2](../architecture/战斗与伤害.md)。近战武器求交和飞剑穿体判定仍保留。

基础长戟是独立武器，原八九玄功仅作为资源/代码模组名保留。四段地面攻击使用长刀女 Attack1、Attack2、杨戬 Attack1、Attack2 的完整动作；武器使用 YangJian_03_Weapon。御风 A1/A3 合成攻击上身和御风下身；A2/A4 使用对应地面攻击的完整肌肉与 RootQ，仅保留旧御风 RootT 位置轨迹，避免替换髋部后把上身和兵器扭向左边。日常持戟右臂与刀刃方向参考杨戬Idle，身体保留玩家自然待机；地面移动使用Magical-Knight_Set的move_run_01完整步态，覆盖持戟右臂。移动速度仍由玩家控制器决定。御风待机和移动保留Flying Mage的躯干与腿，见[御风待机与八方向移动](御风前进动作.md)。

地面版保留髋部、腿部、踏步和杨戬 Attack2 的腾空翻转，不把髋部硬换成待机。御风 A2/A4 也保留完整姿态和 A4 翻转，但位置仍锚定旧御风轨迹；不能再按通用拆接覆盖。JiubaMotionBaker 已同步这一例外。历史四个世界朝向的八次实际出手（现为E）共33项通过：每次物理命中一次，A2 实际命中进度约0.277～0.294，A4约0.800～0.803；不会提前到下劈之前。记录在 `.local/diagnostics/jiuba-flight-a2-a4-20261020`。离屏测试 Animator 必须 AlwaysAnimate，不能把剔除导致的骨骼冻结误判为动画不命中。

近战按四段顺序轮转。默认距离门槛2.3米、基础冷却0秒、普通出手进度0.4、判定窗口长度0.55、外扩0.75米。第一、三段窗口为0.40～0.95，第二段长刀女Attack2（含御风）为0.20～0.95；第四段杨戬Attack2（含御风）改为0.80～0.95，等翻身蓄势后的下劈，不能在40%时由刀杆提前触发。仅改特殊段起点，结束点保持不变。窗口内刀身接触目标胶囊后只结算一次，走AttackSpec(物理, 普通攻击)，按动画进度随攻速同步。2.262米隔离测试中地面、御风四段均各命中一次。配置表导入只用「修仙 / 工具 / 安全导入配置表（不动场景）」。

普攻节奏按用户 2026-10-05 要求改为收招后直接接下一段，不新增四段末尾的整轮停顿。基础冷却表示「两次起手的最小间隔」，从起手计时，与当前动作并行；默认 0 时由动作播放锁防止重叠。旧组件即使仍留着 1.1 秒，也只补起手计时尚未走完的部分，不能在收招后重启整段冷却。当前播放状态包含原 Animator 的收招过渡，不强行截断攻击、改命中窗或重建公共控制器。

近战起手通过 PlayerController.对准攻击方向瞬时对准锁定目标，包含 visualYawOffset；出手动作中暂停 FaceDirection 的转向，移动本身仍由控制器处理。身体的转体在动画姿态里，不能由移动输入持续改变起手参考方向。

编辑器直接启动洞府自动获得测试物品和三把武器，正式菜单角色不赠送。正式获取使用获得武器物品，成功后进入已拥有武器列表，再于装备页选择；不能恢复已退役秘籍。

跨场景与读档由WeaponCatalog、UIPanelData武器拥有记录、当前武器和v26存档接力。新增武器后定向导入武器/物品表并收集面板目录；不要修改场景序列化功法表。

刀身为单骨骼100%权重时，判定使用原网格长轴端点和实际bone.localToWorldMatrix×bindpose，几何只标定一次。避免BakeMesh后再次乘挂载缩放导致判定刀身短于显示网格，尤其在第四段延后下劈后误判御风打空。其余蒙皮保留BakeMesh退路；离屏判定不依赖renderer.bounds。没有动画或武器时组件有降级结算，验收必须确认真实网格接触，不能把降级伤害当通过。

## 2. 片段重建

工具：[JiubaMotionBaker.cs](../../cultivation/Assets/Editor/Tools/JiubaMotionBaker.cs)。打开含 Player 的场景，停止 Play，运行 **修仙 / 动画 / 重建八九玄功动作（不动场景）**。

只更新 Assets/resources/技能动作/八九玄功 的 13 个 .anim，CopySerialized 保留原 GUID，不修改源 FBX、不保存场景。

| 成品 | 来源与处理 |
|---|---|
| 长刀女_Attack1/2 | resources/NPC/Human/ChangDaoNv_Animation/ChangDaoNv@Attack1/2.FBX；完整 Humanoid 复制，1.67 / 2.33 秒 |
| 杨戬_Attack1/2 | resources/NPC/Human/YangJian_Animation/YangJian@Attack1/2.FBX；完整 Humanoid 复制，1.33 / 2.17 秒 |
| 上述四段 _御风 | A1/A3合成御风下身并校正平刺；A2/A4保留完整攻击姿态，只沿用御风位置轨迹 |
| 持刀_站 | 玩家原Idle的胸腰与腿，加杨戬Idle全循环的右臂持握；不复制杨戬脊柱后弯 |
| 持刀_走/跑 | 用户指定Knight move_run_01的完整移动步态，加持戟右臂；不再混合杨戬Run的骨盆/胸廓反扭；保留文件名兼容控制器 |
| 持刀_御风Idle/御风前进 | 原御风完整躯干与腿，加按躯干基准传递的杨戬Idle持戟右臂 |

混合片段以 60 Hz 采样目标骨架，通过 HumanPoseHandler 写成 95 条肌肉与 7 条 RootT/RootQ 的 Humanoid 曲线。Generic 下半身源用实际路径曲线求值，不能依赖 Humanoid Animator 的 Generic SampleAnimation。采样台只复制视觉骨架，不复制 Player 玩法组件。

上下半身在局部骨架空间合成，避免替换髋部后还把攻击的世界翻转强塞到脊椎。非循环攻击末帧不能 Repeat 回到起点；四元数符号保持连续，恒定曲线压缩为首末两键。

地面攻击的 Y 根轨迹和根转体都烘入姿态（loopBlendPositionY=true、keepOriginalPositionY=true、loopBlendOrientation=true、keepOriginalOrientation=true）；Animator.applyRootMotion=false 仍由代码控制玩家位置。杨戬 Attack2 腾空是原始动作，不能当成异常抖动压掉。两段 Attack1 御风版保留飞行位置与腿部肌肉，但 RootQ 取原刺击并烘入姿态，不能使用整骨架混合后随摆臂偏转的根方向。

这是 [敌人AI §7.5 的冰魄怪根旋转问题](../architecture/敌人AI.md) 的同类问题：关 Root Motion 会同时丢掉转体。NPC 由 OnAnimatorMove 消费 deltaRotation，玩家这里改专用片段的烘焙设置，不让 RootT 接管角色位移。

## 3. 武器握持

玩家具备完整的手腕、30个手指关节和蒙皮。杨戬、长刀女旧Avatar仅映射部分指节；`HandMotionRetargeting` 仍负责属性命名和源缺失指节的通用补全，但八九右手不能直接沿用这些源值。旧持刀站姿腕侧偏约0.87，拇指/食指部分指节接近极值，即使在[-1,1]内也明显折腕和钩曲。

`JiubaHandPoseBaker`制作逐指逐节包握；`JiubaCarryPoseBaker`按杨戬Idle的躯干、臂段、手掌与实际03刀刃重新求解右臂腕。枪尖为网格+Z端，原版Idle侧视时斜指前下方，柄尾位于后上方；不能人为加90°或按无符号主轴翻转。前臂分担轴向旋转。日常头部按绑定躯干的正面标定，移除固定偏头，不照搬源胸腰曲线。攻击保留各自源动作；A1/A3另按最新水平前刺校正，不能重新变为前下方刺。13段基础/攻击、9段御风、4段闪避均处理；完整重建使用`JiubaHandPoseBaker.Rebuild()`。

源为 resources/NPC/Human/YangJian/YangJian_03.prefab 的 YangJian_03_Weapon，341 顶点，配套骨骼 Bone01。成品 resources/Weapons/八九玄功_三尖两刃刀.prefab 挂在玩家 R_Hand，不改源网格与材质。

八向御风不能直接保留Flying Mage腕臂，也不能固定成地面参考的世界旋转。现按人体双肩、胸、髋构造的朝向基准传递杨戬持戟方向，右臂随飞行前倾和侧身变化。完整HumanPose与RootT/Q一起重新编码，避免只改右臂曲线导致躯干分解偏移。最新16相位复核中，站立及两段御风的髋到胸倾角与各自基础片段一致，Knight移动最大差约0.20°。双手保留专门制作的逐节握姿，外层TRS见下表。

| 挂载参数 | 当前值 |
|---|---|
| 本地位置 | (0,0,0) |
| 本地旋转欧拉 | (2.328,254.529,263.733) |
| 本地缩放 | 0.3173 |
| 刀身量测 | 约 2.67 米；近战组件按当前网格重新标定 |

外层TRS沿用中立HumanPose的手骨轴标定。内层按原版实际启用的03武器在人体基准中的方向与滚转校准；原预制体里还有启用Renderer但物体未激活的01武器，不能选它作为几何参考。两端必须是同一个sharedMesh。不同Avatar的Chest骨轴不同，不能直接复制胸骨四元数。

上表仍是外层挂载TRS。内部`GripCorrection`按四指弯曲弧中心校准握柄。该341顶点武器100%受单骨骼驱动，编辑器标定使用与GPU一致的bone.localToWorldMatrix×bindpose×vertex，并断言单骨骼权重；修复了此前BakeMesh后再TransformPoint重复缩放、导致刀柄偏在拳外的问题。源网格与材质不变。修改握柄后应同时检查实机近景和攻击接触，不能仅凭“有命中”判定姿态正确。

缩放按 Avatar 比例校正：(玩家 humanScale 0.493647 × 模型缩放 1.8007) / (杨戬 humanScale 1.52885 × 模型缩放 0.9) ≈ 0.646。原网格身高标定的 0.4911 偏大，当前为 0.3173。换 Avatar 后重新标定，不套用旧数。

## 4. 播放与贴地

WeaponCarryAnim 覆盖地面Idle/Walk/Sprint、十四段地面侧后方向片段及九段八向御风；保留旧御风片段名兼容历史控制器。换武器还原，使用原片段名的字符串索引器。

2026-10-20移动头部修正：原来非攻击Carry每帧写固定世界头部朝向，抹掉了run01头颈运动。现在从指定Generic/move_run_01.fbx的原始FK曲线提取连续运动，以原Knight的T姿态骨架采样，去除周期的静态俯角并映射到玩家面部基准；保留原有点头、偏转与侧摆。前进身体与腿仍用Knight原动作，持戟只覆盖右臂；不是运行时盯鼠标写头骨。单独维护入口为JiubaMotionBaker.重建地面移动，然后GroundDirectionalBaker.Build；不需重新生成攻击。

PlayerAnimationController 的 Action 覆盖器复用同一实例，不每次攻击再包一层。创建时先展开基础控制器并显式复制已有覆盖映射，再只替换 Action 占位片段。Unity 不会自动继承嵌套 AnimatorOverrideController 的持械映射；只包一层会使第一次攻击后退回普通待机。驱动器记录动作基础控制器，持械组件收到面板 Changed 时据此保留当前动作覆盖，不能重置正在播放的攻击。

贴地只统计真正受脚部骨骼驱动的顶点。没有脚部顶点的武器、披风网格跳过；全部筛不到时退回脚骨，不能退回整网格最低点。空闲时先初始化筛选并记录同一种脚底基准，收招后的残余补偿逐渐归零。御风高度由 YufengFlight 管，动作贴地补偿跳过。

## 5. 验证与边界

最新水平前刺和武器地面/御风分流检查79项通过：A1/A3地面及御风在40%、45%、50%攻击相位近水平；A2/A4、待机/移动不因这次局部修复重建。相关证据与配方范围见[统筹报告](../reports/2026-10-22系统与文档统筹.md)。

检查真实骨架与刀身、完整起收动作和接触，不用曲线数量或“有命中”代替姿态验收。离屏Animator使用AlwaysAnimate。Play检查必须隔离正式存档，结束停止并撤销覆盖，不保存场景；正式人物仍有衣物交叠等视觉限制。
