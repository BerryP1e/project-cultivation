# 八九玄功（近战普攻与持械动作）

> **管什么**：功法接线、完整攻击重定向、御风与持械合成、武器标定、重建与实机检查。
> **不管什么**：通用施放看 [主动技能与神通](../architecture/主动技能与神通.md)；飞行高度看 [坐骑与御风](../architecture/坐骑与御风.md)；伤害看 [战斗与伤害](../architecture/战斗与伤害.md)；贴地原理看 [动画竖直处理](动画竖直处理.md)。
> **本文件怎么查**：§1 要求与接线｜§2 片段重建｜§3 武器握持｜§4 播放与贴地｜§5 实机复验。
> **来源**：用户原始动作要求、源码检查、Play 逐帧量测与动作图。

## 1. 要求与接线

八九玄功是近战普攻功法。四段地面攻击使用长刀女 Attack1、Attack2、杨戬 Attack1、Attack2 的完整动作；武器使用 YangJian_03_Weapon。御风攻击才合成「上半身攻击、下半身御风 Idle」。待机、御风 Idle 与御风前进使用杨戬 Run 的持械上半身。地面移动按用户最新要求直接使用杨戬 Run 全身动作，取消 Walk/Sprint 下半身混合；移动速度仍由玩家控制器决定。

地面版保留髋部、腿部、踏步和杨戬 Attack2 的腾空翻转，不把髋部硬换成待机。御风版保持飞行下半身，不继承攻击的腾空根轨迹。

| 件 | 位置与约定 |
|---|---|
| 功法与学习物品 | gongfa_jiuba_xuangong / item_gongfa_jiuba_xuangong；表源 Assets/Data/Tables，运行资产 Assets/Data/Generated |
| 普攻 | Assets/Scripts/Combat/Weapons/BasicJiuba01/BasicJiuba01.cs；方法 id basic_jiuba_01 |
| 挂载 | Assets/Scripts/Combat/Weapons/武器挂载/武器挂载.cs |
| 持械覆盖 | Assets/Scripts/Combat/Weapons/WeaponCarryAnim/WeaponCarryAnim.cs |
| 登记 | PlayerAbilityLoader 内置登记，运行时补组件，不保存五个游玩场景 |

近战按四段顺序轮转。默认距离门槛 1.7 米、基础冷却 1.1 秒、出手进度 0.4、判定窗口长度 0.55、外扩 0.45 米。窗口 0.40～0.95 内刀身线段接触目标胶囊后只结算一次，走 AttackSpec(物理, 普通攻击)，攻速同时缩短动画与冷却。配置表导入只用「修仙 / 工具 / 安全导入配置表（不动场景）」。

测试背包获取：进入 Play 后运行「修仙 / 调试 / 给予八九玄功秘籍（仅当前 Play 背包）」。已有一份时不重复添加，不直接学功法、不写场景；退出 Play 后要重新给予。秘籍使用走物品使用器，成功学会后扣一份，已学会时不能再次使用。物品表、生成的秘籍、学习效果和功法资产必须一并保留，效果内的功法引用不能为空。

跨场景与读档：功法定义由 Resources/面板/面板库.asset 的功法目录统一引用，PlayerCultivation.取功法优先查该目录，旧场景功法表只作兼容退路。新增功法后运行「修仙 / 面板 / 收集面板目录」，此菜单不保存场景。秘籍在任务库的物品库中引用，背包按 id 读档可以恢复；玩家已学与当前功法仍由跨场景数据接力。不能只给 Sect 的序列化功法表增加引用。

刀身使用 SkinnedMeshRenderer.BakeMesh 标定当前局部网格的长轴，不能手算 bone × bindpose 代替实际蒙皮。离屏包围盒可能不更新，判定不依赖 renderer.bounds；接触使用刀身线段与目标体积。没有动画或武器时组件有降级结算，验收必须确认日志为「武器网格扫到」，不能把降级伤害当网格判定通过。

## 2. 片段重建

工具：[JiubaMotionBaker.cs](../../cultivation/Assets/Editor/Tools/JiubaMotionBaker.cs)。打开含 Player 的场景，停止 Play，运行 **修仙 / 动画 / 重建八九玄功动作（不动场景）**。

只更新 Assets/resources/技能动作/八九玄功 的 13 个 .anim，CopySerialized 保留原 GUID，不修改源 FBX、不保存场景。

| 成品 | 来源与处理 |
|---|---|
| 长刀女_Attack1/2 | resources/NPC/Human/ChangDaoNv_Animation/ChangDaoNv@Attack1/2.FBX；完整 Humanoid 复制，1.67 / 2.33 秒 |
| 杨戬_Attack1/2 | resources/NPC/Human/YangJian_Animation/YangJian@Attack1/2.FBX；完整 Humanoid 复制，1.33 / 2.17 秒 |
| 上述四段 _御风 | 上半身取攻击，髋与腿取 Assets/Animations/凭虚御风/御风_Idle.anim |
| 持刀_站 | Run 上半身冻结在 50% 姿态，下半身取原 Idle |
| 持刀_走/跑 | 完整杨戬 Run 循环；保留文件名以兼容控制器，不再混入 UAL Walk / Sprint |
| 持刀_御风Idle/御风前进 | Run 上半身，下半身取原御风 Idle / 前进 |

混合片段以 60 Hz 采样目标骨架，通过 HumanPoseHandler 写成 95 条肌肉与 7 条 RootT/RootQ 的 Humanoid 曲线。Generic 下半身源用实际路径曲线求值，不能依赖 Humanoid Animator 的 Generic SampleAnimation。采样台只复制视觉骨架，不复制 Player 玩法组件。

上下半身在局部骨架空间合成，避免替换髋部后还把攻击的世界翻转强塞到脊椎。非循环攻击末帧不能 Repeat 回到起点；四元数符号保持连续，恒定曲线压缩为首末两键。

地面片段 Y 根轨迹烘入姿态（loopBlendPositionY=true、keepOriginalPositionY=true）；Animator.applyRootMotion=false 仍由代码控制玩家位置。杨戬 Attack2 腾空是原始动作，不能当成异常抖动压掉。

## 3. 武器握持

源为 resources/NPC/Human/YangJian/YangJian_03.prefab 的 YangJian_03_Weapon，341 顶点，配套骨骼 Bone01。成品 resources/Weapons/八九玄功_三尖两刃刀.prefab 挂在玩家 R_Hand，不改源网格与材质。

| 挂载参数 | 当前值 |
|---|---|
| 本地位置 | (0,0,0) |
| 本地旋转欧拉 | (2.328,254.529,263.733) |
| 本地缩放 | 0.3173 |
| 刀身量测 | 约 2.67 米；近战组件按当前网格重新标定 |

旋转先让两个 Avatar 进入同一套中立 HumanPose，计算 Inverse(玩家手骨世界旋转) × 杨戬手骨世界旋转。手骨坐标轴不同，单位旋转会使刃柄方向错误。

缩放按 Avatar 比例校正：(玩家 humanScale 0.493647 × 模型缩放 1.8007) / (杨戬 humanScale 1.52885 × 模型缩放 0.9) ≈ 0.646。原网格身高标定的 0.4911 偏大，当前为 0.3173。换 Avatar 后重新标定，不套用旧数。

## 4. 播放与贴地

WeaponCarryAnim 只覆盖 Idle、Walk、Sprint、御风 Idle、御风前进五条片段；换功法还原。使用原片段名的字符串索引器。

PlayerAnimationController 的 Action 覆盖器复用同一实例，不每次攻击再包一层。持械组件收到面板 Changed 时保留外层动作覆盖器，不能重置正在播放的攻击。

贴地只统计真正受脚部骨骼驱动的顶点。没有脚部顶点的武器、披风网格跳过；全部筛不到时退回脚骨，不能退回整网格最低点。空闲时先初始化筛选并记录同一种脚底基准，收招后的残余补偿逐渐归零。御风高度由 YufengFlight 管，动作贴地补偿跳过。

## 5. 实机复验

脚本在工作区 .dsh/_diag，用 mkargs.mjs 生成参数，通过 exec_runtime_script 调用；管线见 [工程与工具链](../ai/工程与工具链.md)。每次改脚本后重新进入 Play，不用旧实例验收。

| 脚本 | 检查 |
|---|---|
| jiuba-motion-audit.cs.txt | 四段完整周期的髋高、脚高、模型补偿与单帧跳变 |
| jiuba-visual-review.cs.txt | 13 段实际播放，各四帧同机位图片；采样图不等于真实御风流程 |
| jiuba-flight-check.cs.txt | 实际升空，四次普攻选择 _御风，落地 |
| jiuba-grip-calibrate.cs.txt | 中立姿态手骨轴差 |
| jiuba-hit-check.cs.txt | 关闭自动出手，等待动作与冷却结束，1.2 米木桩连续八次手动出手；逐次记录实际接受与伤害 |
| jiuba-scene-check.cs.txt | 五个游玩场景依次切换，检查当前与已学功法、独立 id 查找、三个能力组件和普攻播放；临时关闭进场剧情锁以隔离战斗检查 |

截图与量测在 cultivation/screenshots，不入库。逐帧图 jiuba-review-片段名.png，量测 jiuba-motion-audit.txt。

改前模型补偿最大约 1.6 米，旧脚骨最低低于玩家基准约 0.62 米。修复后四段补偿最大约 0.09 / 0.19 / 0.04 / 0.14 米；杨戬 Attack2 髋高约 0.39～3.21 米为保留的腾空轨迹。脚骨最低约基准上方 0.074 米，脚骨不是鞋底。

当前 Play 复验：13 段均为 Humanoid 并有实际动作；关闭自动攻击后的八次手动出手全部被接受、全部命中 1.2 米木桩；四段真实御风攻击全部选中 _御风，落地正常，运行时错误为 0。御风测试补满灵气以隔离耗尽自动落地，不能把灵气耗尽后的地面攻击误判为片段选择错误。结果文件为 jiuba-hit-check.txt、jiuba-flight-check.txt、jiuba-review.txt。

跨场景复验的独立 id 查找由五场景全部 False 改为全部 True；3C_Testbed、village、Sect_Wilderness、Demon-Suppressing Tower、Sect 均保留已学/当前功法、组件启用，手动出手与动作播放通过。结果在 jiuba-scene-check.txt；这是隔离剧情锁的测试，不能用于宣称过场期间也允许普攻。

验收同时看握持方向、足部接地、起收招过渡、御风下半身与侧面机位。长武器挥砍可能触地或与衣摆局部交叠；本套不包含武器与衣物的碰撞/布料解算，不能只凭命中日志判断这些视觉问题。
