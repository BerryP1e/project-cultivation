## 3. 武器：`八九玄功_三尖两刃刀.prefab`

### 3.1 源与产出

**源**：`Assets/resources/NPC/Human/YangJian/YangJian_03.prefab` 里的**独立蒙皮网格节点** `YangJian_03_Weapon` ——

| 项 | 值 |
|---|---|
| 顶点数 | **341** |
| 网格本地长轴 | **4.9154**（米，网格自身尺度） |
| 材质 | `YangJian_03_Weapon` |
| 骨骼 | `Bone01`，其**父节点是 `Bip01 R Hand`** ⇒ 原模型是**握在右手** |

**产出**：`Assets/resources/Weapons/八九玄功_三尖两刃刀.prefab`，层级三层：

```
根
└─ Bone01                 ← 保留源里"相对手骨"的本地 TRS
   └─ YangJian_03_Weapon  ← 蒙皮网格节点，bones / rootBone 都指向新的 Bone01
```

`Bone01` 的本地 TRS 照抄源值：`pos (0.0046, 0.0655, −1.7155)` / `rot (86.4, 257.0, 170.9)` / `scale 0.9451`。
（新 prefab 里 `Bone01` 的父就是 prefab 根，所以这份"相对手骨"的 TRS 在挂到玩家手骨之后**语义与在杨戬身上一致**。）

**生成脚本**：`.dsh/_diag/build_weapon_prefab.cs.txt`，通过 MCP 的 `exec_editor_script` 跑。

### 3.2 挂点与缩放

挂在玩家的**右手骨**下，整条链是：

```
Player/Player_Visual/Armature/BoneRoot/Hip/Waist/Spine01/Spine02/R_Clavicle/R_Upperarm/R_Forearm/R_Hand
```

- local **位置 / 旋转 = 单位**（不额外补偿 —— 补偿量已经在 `Bone01` 的 TRS 里）
- local **`localScale = 0.4911`**

**这个 0.4911 是算出来的，口径是「武器长 ÷ 身高」对齐**（不是"看着差不多"）：

| 步骤 | 数 |
|---|---|
| ① 杨戬身高（身体网格 `YangJian_03` 的世界高度） | **2.664** 米 |
| ② 武器世界长（原模型里） | **4.181** 米 |
| ③ ⇒ 原比例 = ② ÷ ① | **1.570** |
| ④ 玩家身高 | **2.618** 米 |
| ⑤ ⇒ 玩家该拿的武器长 = ④ × ③ | **4.107** 米 |
| ⑥ 玩家手骨 `lossyScale` | **1.8007** |
| ⑦ 武器蒙皮长轴（网格本地） | **4.9154**，`Bone01` 缩放 **0.9451** |
| ⑧ ⇒ 缩放 = ⑤ ÷ (⑦ × ⑥ × 0.9451) | **≈ 0.4911** |

**实测结果**：武器世界长 **4.108** 米、比例 **1.569** ✓（与目标 4.107 / 1.570 一致）。

### 3.3 ⚠️ 别拿 AABB 最长边当"长度"参照

**反面教训**：一开始想省事，用"杨戬本体那把武器的 **AABB 最长边**"当参照 —— 静止姿势下刀是**斜放**的，AABB 最长边只有 **3.151 米**，**小于真实长 4.181 米**；按它硬套会算出 **0.3846**，**偏小 21.7%**（刀短一截，配不上身）。

**判据**：**AABB 是朝向相关的**，量"这个东西多长"不能用它 —— 要用**网格 `localBounds.size`（沿长轴） × 骨骼链的 `lossyScale`**。同一条规矩在别处也适用：量位置/长度一律走 **transform**，别用 `renderer.bounds`（见 §6 与 [踩坑 D12](../ai/踩坑总库.md)）。

## 4. 御风适配片段

### 4.1 为什么要烘这几个片段

需求：**御风时普攻要"上半身打、下半身御风"** —— 不能因为出手就从御风姿势变成站桩，也不能因为普攻就把玩家从御风里拽出来（玩家在空中，腿必须保持御风 Idle 的盘腿/垂腿姿态）。

Unity 的 Humanoid 重定向是**整套动作一起重定向**的，做不到"半个身子用 A、半个身子用 B"，所以**得自己合成一条新片段**。

### 4.2 合成口径

| 项 | 做法 |
|---|---|
| 读什么 | 两边都读**人形肌肉曲线**（`path` 为空的那些曲线），按**肌肉名**判上下半身 |
| 上半身取谁 | **攻击动作**（四个来源之一） |
| 下半身取谁 | **御风 Idle** |
| **下半身 = 16 条肌肉** | 名字含 **`Upper Leg` / `Lower Leg` / `Foot` / `Toes`**（左右各 8 条） |
| 御风 Idle 源 | `Assets/Animations/凭虚御风/御风_Idle.anim`（**2.40 s**、`humanMotion=True`、**102 条曲线**） |
| ⚠️ 时长不匹配怎么办 | 攻击比 2.40 s 长时，御风那侧按 **`Mathf.Repeat(t, 2.40)` 循环采样**（腿不会"走到一半停住"） |
| **根位移取谁** | **取御风 Idle** —— 所以普攻**不会跟着攻击跳起来**（杨戬 Attack2 那条 3.6 米腾空位移被丢掉） |
| 产出形态 | **新的 Humanoid 片段**：**95 条肌肉 + 7 条 `RootT/RootQ` = 102 条曲线**，30 fps、`loopTime=false` |

### 4.3 产出清单

都在 `Assets/resources/技能动作/八九玄功/`，各 **102 条曲线**，**30 fps**、`loopTime=false`。
⚠️ **必须放在 `resources` 下**：普攻组件取片段走的是 `Resources.Load<AnimationClip>("技能动作/…")`（现有 `普攻_远程_01` 就是这条约定，见 `BasicRemoteAttack01.cs`），放在 `Assets/Animations/` 下**运行时取不到**。

| 片段 | 时长 | 帧数 |
|---|---|---|
| `长刀女_Attack1_御风.anim` | 1.67 s | 50 |
| `长刀女_Attack2_御风.anim` | 2.33 s | 70 |
| `杨戬_Attack1_御风.anim` | 1.33 s | 40 |
| `杨戬_Attack2_御风.anim` | 2.17 s | 65 |

**生成脚本**：`.dsh/_diag/bake_yufeng_attacks.cs.txt`（同样走 MCP `exec_editor_script`）。

### 4.4 实测

- **抽查逐点一致**：下半身 `Left Upper Leg Front-Back` **新 = 0.6080 / 御风 = 0.6080**；上半身 `Right Arm Front-Back` **0.2502 = 0.2502** ✓
- **全量骨骼对比**（在**玩家自己的骨架**上比骨骼本地旋转）：**腿的骨骼一根都不在差异列表里**，差异只出现在 **`Hip`** 与**上半身** ✓
- **没有跟着攻击跳起来**：头的世界高度 **−498.65（新） vs −498.64（御风）** ✓

## 5. 近战普攻组件（`BasicJiuba01`）

`Assets/Scripts/Combat/Weapons/BasicJiuba01/BasicJiuba01.cs` —— 与 [玄霄雷决与雷动千闪 §2.2](玄霄雷决与雷动千闪.md)、`BasicFrostSpike01.cs` 同构（字段命名、出手门槛、冷却口径、日志开关都照它们），区别只是"召雷"换成"挥刀砍锁定目标"。

| 项 | 值 / 做法 |
|---|---|
| **动作序列（顺序轮转）** | `技能动作/八九玄功/` 下四段：`长刀女_Attack1` → `长刀女_Attack2` → `杨戬_Attack1` → `杨戬_Attack2` → 回到第一段（`Mathf.Repeat(出手序号, 4)`）。**不做连段窗口**（用户 2026-10-04 选定"顺序轮转"） |
| **御风换片段** | 御风时给名字拼 `御风动作后缀`（默认 `_御风`）再 `Resources.Load`；**取不到只警告一次**并退回地面版。判据 = `YufengFlight.御风流程中` |
| 出手时机 | `PlayerAnimationController.动作进度 >= 出手进度`（默认 **0.4**），照既有普攻 |
| **近战判定** | 窗口 `[出手进度, 出手进度 + 判定窗口]`（默认 **0.4~0.65**）内**逐帧**拿**武器网格**（`武器节点名` 默认 `YangJian_03_Weapon`，取渲染体并集、跳过粒子，外扩 `判定外扩` 0.15）与**锁定目标**求交，**命中只结算一次**；窗口过了没扫到 = **打空、不结算**（口径同 [怪物近战判定](怪物近战判定.md) 的 NPC 侧） |
| 伤害 | `锁定单位.受到攻击(玩家属性, new AttackSpec(物理, 普通攻击, false, 伤害倍率), this)` ⇒ 内部走 [CombatCalculator](../architecture/战斗与伤害.md) |
| 冷却 | `实际冷却 = 基础冷却(1.1) ÷ 攻速`；**没锁定目标就不出手也不进冷却** |
| 触发 | 组件自己听 `Mouse1`（`自动出手` / `按住连发` / `攻击键`），自动化里可直接调 **`出手()`**（public） |
| 只读状态 | `可以出手` / `出手动作中` / `出手序号` / **`当前动作路径`** / **`当前是御风版`** / `冷却剩余` |

**武器挂载**（`Assets/Scripts/Combat/Weapons/武器挂载/武器挂载.cs`）：读 `UIPanelData.当前功法` 的 `功法id`，等于 `显示条件功法id`（默认 `gongfa_jiuba_xuangong`）才把武器实例化到 `挂点骨骼名`（默认 `R_Hand`）下，local 缩放 **0.4911**（§3.2 的实测值）；不匹配就销毁实例。订阅 `面板数据.Changed`、成对退订。
⚠️ **已知耦合**：`OnDisable` 是按"当前功法还匹不匹配"决定收不收刀 —— 因为**过场 `演出锁` 和换功法都是 `enabled = false`**，但要求相反（过场要留刀、换功法要收刀）。所以把 `显示条件功法id` 改成**空（一直显示）之后，换功法就收不掉刀**。

脚本都在 `.dsh/_diag/`，参数走同名的 `*.args.json`（PowerShell 转义太痛，**参数一律写文件**），调用方式是 MCP 的 `exec_editor_script` / `exec_runtime_script`（用法见 [工程与工具链 §3.5](../ai/工程与工具链.md)）。

## 7. 已知偏差与待调

### 7.1 `Hip` 会跟着上半身转 —— 这是**人形求解的固有权为**，不是合成错

采样"上半身=攻击 + 下半身=御风 Idle"的片段时：**腿骨（`L_Thigh / L_Calf / L_Foot / R_*`）的本地旋转与纯御风完全一致**（一根都不在差异列表里），但 **`Hip`（= Hips 骨）的本地旋转与纯御风差 24.5°**，因此**踝关节世界位置差 0.27 米**。

**排除过的四个方向（都实测过）**：

| # | 查了什么 | 结果 |
|---|---|---|
| 1 | 两边的曲线集合 | **完全相同**（各 102 条：95 肌肉 + 7 根），根曲线 `RootT/RootQ` 七条**逐点相同** |
| 2 | 根曲线的绑定类型 | 两边都是 `Animator`，**不存在**"绑到 Transform 上"的差异 |
| 3 | `SampleAnimation` 有没有残留 | **确定性、无残留**：同一片段连采两次 `Hip` 完全一致，换片段互不污染 |
| 4 | 玩家 Avatar 的人形映射 | **标准正确**：`Hips←Hip`、`Spine←Waist`、`Chest←Spine01`、`UpperChest←Spine02`、腿←`L_Thigh/R_Thigh`（**不是**"脊椎挂在腿的父骨上"） |

**真正的原因**：**Unity 的人形求解本来就会把脊椎和手臂的旋转分一部分到 `Hips` 骨上**。逐组替换实测（基准 = 纯御风 Idle 的 `Hip` = `(36.06, 121.06, 138.91)`）：

| 只把这一组肌肉换成攻击 | `Hip` 本地旋转 |
|---|---|
| 脊椎组（`Spine` / `Chest` / `UpperChest`） | `(34.85, 123.88, **120.04**)` |
| **左臂组** | `(40.28, 123.77, 138.27)` |
| 右臂组 | `(35.33, 121.59, 139.02)` |
| 颈头组 / 手指组 | 与基准**完全一致**（不影响 `Hip`） |

⇒ **固有权为，不是配错**："上半身取攻击、下半身取御风"在**肌肉层面已经做到位**。

**要把髋也完全锁死**只剩一条路：把合成后的姿态**烘焙成玩家骨架上的 Generic 片段**（照 `Assets/Editor/Builders/师傅御风重定向.cs` 的做法 —— 就是师傅御风用过的那条"逐帧重定向 + `AnimatorOverrideController`"路子），**代价是片段绑死骨架路径**（换模型就废）。

**判据（唯一可靠）**：验证"下半身是不是真的御风"，**看腿骨在差异列表里是否为空**；**不要用踝关节的绝对坐标差** —— 那个差值随骨架/映射而变，换个模型就换了数。

### 7.2 待调：`判定窗口` **还没标定**

- 现在固定 **0.25 个动作进度**（窗口 0.4~0.65）。四段动作 1.33~2.33 秒，实际长度差一倍 ⇒ **长片段的窗口偏短**（实测出现过一次「打空：没被武器扫到（进度 0.651）」），短片段的窗口可能偏长。
- `判定外扩 = 0.15` 是**沿用 `近战妖魔Ai` 的默认值**，没有针对玩家这四段动作量过。
- **正确做法**（照 NPC 那套）：把玩家的四段动作逐帧采样，量"武器尖能伸到身前多少米"，再据此定窗口与站位；工程量与 [怪物近战判定](怪物近战判定.md) 里量白熊精那套一样。
- 现成复验脚本：`.dsh/_diag/playtest_jiuba.cs.txt`（四次出手 + 轮转 + 掉血）与 `playtest_yufeng_branch.cs.txt`（御风分支 + 截图）。

### 7.3 其它要留意的小事

- **判定体的取用**：目标侧**优先走 `Collider.bounds`**（便宜），**没有碰撞体的目标才退回 `NpcBodyBounds.取`**（它逐顶点蒙皮，`NpcBodyBounds.cs` 自己写明"不在每帧用"），且每次出手只算一次。
- **两组件的默认值写在代码里**（运行时 `AddComponent`），改参数要改代码 —— 这是走"内置登记"的代价，见 [工程与工具链 §6.2.1](../ai/工程与工具链.md)。
- **数值来源**：`功法表` 那一行的品阶/难度/最高境界/全部增益**整行沿用玄霄雷决**（用户选定），**不是**新编的数；要改口径改 `功法表.csv` 那一行并重跑安全导入。
- **武器只在装备八九玄功时显示**：换成别的功法，`武器挂载` 会把实例销毁（实测日志「已把…挂到 R_Hand」只在切到八九玄功时出现）。

## 8. 持械移动替换与近战判定口径

### 8.1 五个「持刀」片段怎么进游戏（`WeaponCarryAnim`）

`持刀_站 / 持刀_走 / 持刀_跑 / 持刀_御风Idle / 持刀_御风前进` 是拿 **杨戬 Run 的上半身**重定向出来的（下半身取各自的 Idle/Walk/Sprint/御风Idle/御风前进）。
它们不能直接改 `PlayerLocomotion.controller`（**全局资产**，会给别的功法也换掉），所以由 `Assets/Scripts/Combat/Weapons/WeaponCarryAnim/WeaponCarryAnim.cs` 在运行时用 `AnimatorOverrideController` **只覆盖这五条**：装备八九玄功 ⇒ 换成持械版；换功法 / 组件被停用 ⇒ **立刻还原**。
登记走 [工程与工具链 §6.2.1](../ai/工程与工具链.md) 的**内置登记**（同一个 `basic_jiuba_01` 下挂 `BasicJiuba01` + `武器挂载` + `WeaponCarryAnim`），**5 个场景一个都没动**。

⚠️ **覆盖必须用官方字符串索引器**：

```csharp
覆盖["Armature|Idle_Loop"] = 持刀_站;      // ✅ 对
```

**别用 `GetOverrides` 自己配对**（读出来 pairs 里的 key 是 Unity 造的**占位片段**，名字跟控制器里的原片段对不上）—— 实测那样**只换中 1 条、还换到了别的片段上**（日志出现 `普攻_远程_01 → 持刀_御风Idle`）。

### 8.2 ⚠️ 近战判定口径**待改**：`Renderer.bounds` 对长兵器不可靠

**现象**：站在练功木桩正前方 **2.0 米**连打 4 次，**时中时不中**（有时 45.59 伤害、有时整轮全"打空"）。
**实测数据**（逐帧打武器盒与靶子盒，靶子 `CapsuleCollider` 盒中心 `(16.26, 0.18, 0.77)`）：

```text
t+0.6s：武器盒 中心=(21.23,-0.03,2.65) 尺寸=(3.36,2.78,1.78) ｜ 与靶子中心距=5.32 ｜ 相交=False
t+0.9s：武器盒 中心=(22.18, 0.05,1.13) 尺寸=(2.63,2.50,2.99) ｜ 与靶子中心距=5.93 ｜ 相交=False
```

⇒ 武器 `Renderer.bounds` 的 AABB **中心在挥砍过程中会跑到靶子 3~6 米外**（尺寸也在 0.5~3.9 米之间乱跳）。对这把 **4.9 米长、边挥边转**的长兵器，用"两个 AABB 相交"当命中判据**不可靠**。
**同款坑工程里已有先例**：NPC 侧穷奇用 `Renderer.bounds` 实测 **8 秒 0 次接触、0 伤害**，最后靠 `判定外扩 = 0.8` 才全中（见 `NpcAiQiongQi`）。

**下一轮的方向（择一，别再靠调外扩硬凑）**
1. **用武器骨骼两端点做线段扫掠**（`Bone01` 的局部 ±X 两端 → 世界坐标 → 线段，对目标胶囊做最近距离判定），比 AABB 稳得多；
2. 或者在判定窗内**逐帧取"武器盒与目标盒的最近距离"**，并按**武器当前朝向**动态给外扩（而不是固定 0.15）；
3. 或者给武器**加一根尖端骨骼**（美术侧）后按 1 做。

**现状不影响"功法能玩"**：判定窗、距离门槛、冷却、轮转、御风换片段都实测正常，只是**命中率不稳**。

### 8.3 ✅ 判定口径已按实测定死（2026-10-04 收尾）

§8.2 的"时中时不中"**已经解决**，结论是**参数没按实测定**，不是判定算错。三步定位：

| 步 | 做了什么 | 结果 |
|---|---|---|
| 1 | 刀身线段改用 `SkinnedMeshRenderer.BakeMesh` 标定（**问引擎要蒙皮顶点**，不再手算 `bone × bindpose`） | 刀身线段 **4.13 米**、半径 **0.114 米**（数值合理，和工件尺寸对得上） |
| 2 | 每次出手打印「判定窗内刀与目标的**最小距离**」 | 靶子放 2.0 米时：**最近 1.82 米**、阈值 0.89 ⇒ **刀根本够不着**（不是差一点） |
| 3 | 量刀身两端在**玩家本地空间**的范围 | **X（左右）−1.94~1.60 / Y（上下）−0.17~3.19 / Z（前后）−0.38~0.36** ⇒ 这四段是**贴着身体竖直面的大开大合劈砍，几乎不向前伸** |

⇒ 这两个默认值原来是**拍的数**，与实测差一个量级：

| 字段 | 原值（拍） | 改成（实测） | 依据 |
|---|---|---|---|
| `出手最大距离` | 4 米 | **1.7 米** | 刀的真实触及面在体侧/竖直方向，前后仅 ±0.37 米；1.7 米 ≈ 双方胶囊半径 + 外扩 + 余量 |
| `判定外扩` | 0.15 米 | **0.45 米** | 工程近战怪同款口径（穷奇实测最后靠 0.8 才全中）；0.45 让 7/8 命中 |

**实测（靶子 1.2 米、8 连打）**：累计伤害 **341.9**（平均 42.7/次），**7 中 1 空**，每次命中都落在进度 **0.400~0.401**（窗口 0.40~0.95 内）。
⇒ **近战判定：贴到身前才打得到（这就是近战该有的样子）**；`出手最大距离 = 1.7` 保证"够不着时不出手、也不白扣冷却"。

> ⚠️ 想让刀**够得更远**，正确做法不是继续加外扩，而是**换动作**（要向前突刺/前劈的片段）或给武器**加一根尖端骨骼**后按尖端扫掠。
