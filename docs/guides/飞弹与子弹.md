## 0. 一句话

**飞弹 = 一个带「飞行脚本 + 刚体 + 碰撞体 + 拖尾/粒子」的小物件。它自己往前飞，撞到东西就把「命中特效」放出来然后自毁。**

| 路线 | 什么时候用 | 代码在哪 | 命中判定 | 要刚体吗 |
|---|---|---|---|---|
| **A. 借 QFX 的实体弹丸** | 主题能用包里现成的 15 套之一 | 已接好，只填 3 个路径 | 物理碰撞（会被墙挡住） | **要** |
| **B. 用我们自己的 `NpcProjectile`** | 想自定义 / 包里没有的效果 | 已写好，挂上去就行 | 到达目标点（直线飞到底、会穿墙） | 不要 |

> **弹道 prefab 自带飞行脚本 → 走 A；否则 → 走 B**（自动判断，不用手选）。

## 1. QFX 包解剖：三件套 × 15 主题

一次「发射」拆成三段，**同主题的三个拼起来就是完整一发**：

```
发射瞬间            飞行途中              命中瞬间
 Flash     +     Projectile      +      Impact
（枪口闪光）      （弹道/弹丸）          （命中爆炸）
```

**15 个主题**：`Ares 战神 / Comet 彗星 / Curse 诅咒 / Cyber 赛博 / Dark Magic 暗魔法 / Demon 恶魔 / Kawaii 可爱 / Lightning 闪电 / Magic 奥术 / Nature 自然 / Priest 圣光 / StarlightFairy 星灵 / Succubus 魅魔 / Vampire 吸血鬼 / Winter 寒冰`
—— 正好分给不同属性/门派的敌人（妖魔 → `Demon`/`Curse`/`Dark Magic`，仙家 → `Priest`/`StarlightFairy`/`Nature`）。

### 1.1 目录分类 + 两种弹道怎么选

| 目录 | 数量 | 是什么 | 怎么用 |
|---|---|---|---|
| `VFX_Prefabs/Flashes/` | 15 | `VFX_<主题>_Flash` 枪口闪光 | 发射瞬间在**出膛点**生成，一秒内销毁。纯装饰、不结算伤害 |
| `VFX_Prefabs/Impacts/` | 15 | `VFX_<主题>_Impact` 命中爆炸 | 命中点生成。用实体弹丸时**不用自己管** |
| `VFX_Prefabs/Projectiles_Particles/` | 15 | `VFX_<主题>_Projectile_Only` **纯粒子弹道** | 粒子自己往前飞。要自己控制位置/结算 |
| `VFX_Prefabs/Projectiles_Particles_Complete/Projectiles/` | 15 | 粒子弹道**完整版**（带拖尾） | 推荐用这个当粒子弹 |
| `VFX_Prefabs/Projectiles_Objects_Complete/Projectiles/` | 15 | **实体弹丸**（有模型）+ `PFX_ProjectileObject` 飞行脚本 | ✅ **最省事**：生成、设 forward 和 Speed 就行 |

**实体弹丸 vs 纯粒子弹道**：实体弹丸（`Projectiles_Objects_Complete/Projectiles`）有实体模型（箭/球/飞镖…）、
**自带 `PFX_ProjectileObject` 脚本**（设 `Speed` 就自己飞）、**自带 `ImpactFX` 字段**（到点自动生成命中爆炸），
接入选最低；纯粒子弹道（`Projectiles_Particles*`）是纯粒子流、粒子自己飞、命中要自己生成。
> **推荐**：NPC 施法优先用**实体弹丸**那套，飞行和命中它自己全包了。

### 1.2 三件套的真相

`Flashes/` 和 `Impacts/` 里的东西**是 `VFX_X_Projectile` 的拆件**：`Glow` 分支 ≡ `VFX_X_Flash`（发射瞬间的闪光）、`Impact` 分支 ≡ `VFX_X_Impact`（命中爆炸）。

- **实体弹丸** `VFX_X_Projectile_Object` 只含"飞行"部分 —— 闪光和命中要**另外指定**（这就是 `闪光特效路径` / `命中特效路径` 两个字段的来由）
- **粒子版** `VFX_X_Projectile` 三合一，但**没有飞行脚本**（粒子原地发射），要靠 `NpcProjectile` 带着它飞
- `VFX_X_Projectile_Only` = **只有弹道** → 配自己的飞行和命中；`VFX_X_Projectile`（在 `_Complete/Projectiles/` 里）= **三合一** → 只适合原地放

### 1.3 路径变更史与验证状态

★ **路径变过两次（2026-09-28）**：`QFX` → `飞弹特效` → **`CombatVFX/Projectiles`**，最终前缀 = **`CombatVFX/Projectiles/`**（更早的 `QFX/...` 按同一条链路换算）。`Resources.Load` 按**路径**找，改名时同步改了 5 个脚本里的默认路径（`BasicRemoteAttack01` / `NpcAiBaiLuJing` / `NpcAiBingPoGuai`）和 4 个自带 shader 的声明。

**验证状态（2026-09-21 收工前）**：资源可加载 ✔、弹道自带脚本识别 ✔、伤害照常结算 ✔（玩家 420 → 13）；但**"飞行中的弹道"和"闪光"还没在实测里被采样到**，下次要补一次确认（大概率是随机选招没轮到第 1 条 + QFX 弹道「一碰就爆」存活太短，采样窗口要更密）。
> 导入日期：2026-09-21　共 **105 个特效 prefab**、4 个自定义 shader、3 个演示脚本。

## 2. 路线 A：借 QFX 实体弹丸（推荐，最省事）

**只要填 3 个字符串**。`VFX_<主题>_Projectile_Object` 长这样：

```
VFX_Demon_Projectile_Object            ← 根
├── ★PFX_ProjectileObject              飞行脚本
├── Rigidbody                          isKinematic=false, useGravity=false, drag=0
├── SphereCollider                     radius=0.1, isTrigger=false
├── Trail_1 / Trail_2                  TrailRenderer 拖尾（宽1 / 0.32~0.36 秒）
├── Projectile                         飞行主体粒子（一次，寿命 2s）
└── Sparks_Along                       一路的火花（**循环**）← 接给脚本的 FXToDeatch
```

### 2.1 飞行脚本的全部逻辑

```csharp
public class PFX_ProjectileObject : MonoBehaviour
{
    public ParticleSystem FXToDeatch;        // 飞行中拖着的粒子（作者笔误，应为 Detach）
    public float Speed = 15f;
    public GameObject ImpactFX;
    public float ImpactFXDestroyDelay = 2f;
    public float ImpactOffset = 0.15f;

    void FixedUpdate()
    {
        if (Speed == 0) return;
        transform.position += transform.forward * (Speed * Time.deltaTime);   // ← 就这么简单
    }

    void OnCollisionEnter(Collision collision)
    {
        var contact = collision.contacts[0];
        if (contact.otherCollider.name.Contains("Projectile")) return;   // 忽略弹丸互撞（靠名字，hacky）

        Speed = 0;
        var hitPosition = contact.point + contact.normal * ImpactOffset;  // 沿法线外推，别嵌进墙里

        if (ImpactFX != null) { Instantiate(ImpactFX, hitPosition, ...); Destroy(..., ImpactFXDestroyDelay); }

        FXToDeatch.transform.parent = null;    // ★把拖尾「脱开」，让它留在命中点自然消散
        FXToDeatch.Stop(true);
        Destroy(FXToDeatch.gameObject, ImpactFXDestroyDelay);
        Destroy(gameObject);
    }
}
```

**读出 4 条硬要求**：① 要 `Rigidbody` + 非 trigger 的 `Collider`（否则 `OnCollisionEnter` 不触发、飞弹穿墙）；② `useGravity = false`（否则往下掉，不是直线）；③ `isKinematic = false`，脚本直接改 `transform.position`，靠 Unity 把 transform 同步给物理（⚠️ 和项目 §8.2 那条"别让 transform.position 和物理打架"看着冲突，但这里是**唯一的运动来源**、没有第二个组件在推它；**别再加第二个会推它的东西**）；④ 方向靠 `transform.forward`，生成时**必须把 forward 设成目标方向**。

> ⚠️ 另外两个坑：**反射取字段写错名字** —— 速度和命中特效**静默不生效**（`设字段` 找不到就跳过；出膛点让开量 = `NpcAiBase.出膛余量()` = 碰撞体半径 + 0.35），
> 包里的字段名是 `Speed` / `ImpactFX` / `ImpactOffset` / `FXToDeatch`（**Deatch 是作者笔误**），改包版本后要重新核对；
> **`FXToDeatch` 没接** —— 命中时 `NullReferenceException`（实体弹丸上它接的是 `Sparks_Along`，自己搭的话记得接）。

### 2.2 配置示例 + 路径规则

```csharp
new NpcAttackConfig
{
    动作名 = "Attack3",
    伤害属性 = DamageNature.特殊,
    攻击类别 = AttackKind.主动神通,
    技能倍率 = 1.8f,
    出手进度 = 0.5f,

    是施法 = true,                       // ★打开才会走飞弹流程
    子弹速度 = 16f,
    闪光特效路径 = "CombatVFX/Projectiles/ProjectilesFX/VFX_Prefabs/Flashes/VFX_Demon_Flash",
    子弹特效路径 = "CombatVFX/Projectiles/ProjectilesFX/VFX_Prefabs/Projectiles_Objects_Complete/Projectiles/VFX_Demon_Projectile_Object",
    命中特效路径 = "CombatVFX/Projectiles/ProjectilesFX/VFX_Prefabs/Impacts/VFX_Demon_Impact",
}
```

路径规则：**相对 `Assets/resources`、不带扩展名**，`特效资源清单.md` 里 75 个的路径都能直接抄。
一次完整施法 = **闪光 + 弹道 + 命中**：出膛点先生成闪光（约 0.8 秒后销毁）→ 弹道 `forward` 指向目标 → 飞行时间 = `出膛点到目标的距离 ÷ 子弹速度`，到点结算伤害 → 玩家掉血 + **伤害飘字**（飘字自动）。

> ⚠️ **主题名大小写坑**：命中/闪光里是 `Dark_Magic`，实体弹丸里是 `DarkMagic` —— **没有下划线**，抄清单别手打。

## 3. 路线 B：用我们自己的 `NpcProjectile`

包里没有想要的、或想用自己做的特效时走这条：**`NpcProjectile` 不依赖刚体和碰撞体** ——
它自己按直线插值飞，到达就回调，所以用在**任何特效 prefab** 上都可以。

```csharp
var 弹道 = Instantiate(你的特效prefab, 出膛点, Quaternion.LookRotation(方向));
var 飞 = 弹道.AddComponent<NpcProjectile>();
飞.设置飞行(目标点, 速度);
飞.到达时 += () => { 结算伤害(); 生成命中特效(); };
```

| | 路线 A（QFX 实体弹丸） | 路线 B（`NpcProjectile`） |
|---|---|---|
| 飞行 / 命中判定 | 包自带脚本（`FixedUpdate` + 物理碰撞），**撞到才有** | 我们自己的插值，**到达目标点**（按时间） |
| 需要刚体/碰撞体 | **要** | 不要 |
| 命中特效 / 会不会打偏 | 包自己放；会被障碍挡住（更真实） | 自己放；直线飞到底（会穿墙） |

### 3.1 两种飞行模式 + 白鹿精 / 太虚炼气诀的差别

| | 白鹿精（`basic_remoteattack_01` 以外）| 太虚炼气诀普攻（`basic_remoteattack_01`）|
|---|---|---|
| 飞行 | **直线匀速、不追踪** = `NpcProjectile.设置直线飞行()`：起飞锁方向，躲开就打不中 | **持续追踪**（限速转向）= `NpcProjectile.设置追踪飞行()` |
| 结束 | 飞到锁定点 / 超 22 米消散 | 命中 / 超出**神识范围** / 超 **8 秒** |
| 出生点 | 左手骨骼末端（03 是右手近似武器末端）| **右手骨骼末端** |
| 角色动画 | 无（NPC 走 Attack1）| **播玩家攻击动作，40% 处出弹** |
| 冷却 | 3s（03 神通 8s）| 3s，**被攻速缩放** |

> ⚠️ **「不追踪」的正确实现不是「飞到一个点」**：第一版写成"飞到起飞时锁定的那个点"，结果
> **玩家躲开了还是会打中旧位置** ✗。正确做法：每帧沿固定方向前进 → 判断「目标还在不在弹道上」
> （命中半径）：在 → 命中；不在 → 继续飞 → 超过 `最大飞行距离` → 消散。

## 4. 给 NPC 做飞弹：照着做

1. 挑主题（或自己做一个特效 prefab 放进 `Assets/resources/` 下）
2. 打开那个 NPC 的 `NpcAi<名字>.cs`
3. 在 `取默认参数()` 里把某一条出手方式改成施法：

```csharp
protected override void 取默认参数()
{
    base.取默认参数();

    // 第 3 条出手 = 施法飞弹
    攻击方式[2].是施法 = true;
    攻击方式[2].伤害属性 = DamageNature.特殊;
    攻击方式[2].攻击类别 = AttackKind.主动神通;
    攻击方式[2].技能倍率 = 2f;
    攻击方式[2].出手进度 = 0.5f;

    const string 包 = "CombatVFX/Projectiles/ProjectilesFX/VFX_Prefabs/";
    攻击方式[2].闪光特效路径 = 包 + "Flashes/VFX_Demon_Flash";
    攻击方式[2].子弹特效路径 = 包 + "Projectiles_Objects_Complete/Projectiles/VFX_Demon_Projectile_Object";
    攻击方式[2].命中特效路径 = 包 + "Impacts/VFX_Demon_Impact";
    攻击方式[2].子弹速度 = 16f;
}
```

> ⚠️ `攻击方式` 默认只有 3 条（Attack1/2/3），**而且只有 Animator 里真有的动作才会被选中**
> （`可用出手方式()` 会过滤掉没有对应动画的）。所以别把飞弹配到一条没有动画的动作上。

4. 进 Play，让 NPC 打你，看是否：出膛点有闪光 → 有东西飞过来 → 命中点有爆炸 → 你掉血 + 飘字

## 5. 给玩家做飞弹

**现状：玩家的"飞弹"目前没有。**普攻是近战（`BasicSword01`），主动技能走
`ActiveSkillCaster` + `AreaSkillRunner`（**立即结算的范围伤害，没有飞行过程**）。

**5.1 最省事：给主动神通加一个"飞弹"结算方式** —— 在 `ActiveDivineAbility` 上加一个
`结算方式 = 飞弹`，然后 `ActiveSkillCaster.施放()` 里把 `AreaSkillRunner` 换成"生成一发飞弹、
到达后再结算"（照路线 A 或 B；到点后 `目标.ReceiveAttack(自己, new AttackSpec(神通.伤害属性,
AttackKind.主动神通, false, 神通.伤害倍率))`）。**好处**：和 NPC 那套复用同一个 `NpcAttackConfig` 思路，
数据表加一列 `首次造成伤害时间` 就能对齐动画。

**5.2 更贴做法：抽一个通用的 `ProjectileLauncher`** —— 把"生成闪光 → 生成弹道 → 按飞行时间/碰撞结算 →
放命中特效"抽成静态工具，**NPC 和玩家都调它**，只是"攻击方"和"受击方"换一下；
玩家要飘字/演出就挂在它的"命中后"回调上。
> 现在 `NpcAiBase.生成子弹` 里已经是这套逻辑了，只是写死在 NPC 基类里。
> **建议下次做玩家飞弹时先把它抽出来**，别再复制一份。

## 6. 命中特效放对（位置 / 朝向 / 缩放）

三个容易错的点，都在 `NpcAiBase.在目标结算()` 里：

**1. 位置：用弹道的真实命中点，别用目标身上** —— `NpcProjectile` 在**到达/被拦截时**把 `命中点`
记下来，回调里读；目标会动，直接放目标身上会飘。

```csharp
Vector3 命中点 = 弹 != null ? 弹.命中点 : 目标点;
命中点 = Vector3.Lerp(弹.命中点, 目标判定点, 0.85f);   // 但要往身上拉 85%
```

弹道是"进到 `命中半径`（默认 1 米）内"就判定命中的，位置**离身上还差几十厘米**，爆炸会悬在身前。
实测：拉之前离判定点 0.89 米，拉之后 **0.14 米** ✅

**2. 朝向：迎着飞来的方向** —— `Vector3 朝向 = -弹.飞行朝向;`（爆炸朝施法者那侧张开）

> ⚠️ **坑：`Quaternion.LookRotation(up, up)` 是退化调用** —— 前向和上方向平行时 Unity 会报错并返回
> identity，特效朝向就变随机的。竖直方向要换个 up 轴：
> ```csharp
> Quaternion 旋转 = Mathf.Abs(Vector3.Dot(前, Vector3.up)) > 0.999f
>     ? Quaternion.LookRotation(前, Vector3.forward)
>     : Quaternion.LookRotation(前, Vector3.up);
> ```

**3. 缩放**用 `NpcAttackConfig.命中特效缩放`（`生成装饰特效` 返回 GameObject，调用方自己乘）。
**白鹿精取值**：弹体 `0.65`（普攻）/ `1.1`（神通），命中特效 `1.25`（普攻）/ `1.6`（神通）
—— **弹体缩小、爆炸做大**，打击感靠命中特效撑。

## 7. 术语规范：伤害目标一律叫「锁定单位」

> 策划原话：*"以后有关伤害的统一以**锁定单位**作为目标 —— NPC 假如要打我，那就是 NPC 以我为锁定目标，这样比较规范。"*
> 原因：以后 **NPC 也可能作为召唤单位帮玩家打怪**，那时候"敌人"就不一定是玩家了。
> **所以飞行路径 / 命中效果 / 消灭点 这些描述里，别再写"玩家"，写「锁定单位」。**

代码落点 `Assets/Scripts/Combat/ICombatTarget.cs` —— 接口 + 两个薄适配器：

| 适配器 | 包谁 | `受到攻击` 转发到 |
|---|---|---|
| `NpcTarget` | `NpcInstance` | 它自己的 `ReceiveAttack(攻击方属性, 规则)` |
| `PlayerTarget` | `PlayerVitals` | `CombatCalculator.Resolve(...)` → `PlayerVitals.受到伤害(...)` |

工厂 `CombatTargets.取(obj)` / `CombatTargets.从(go)`；**故意不改 `NpcInstance`/`PlayerVitals` 内部**，
适配层很薄，风险最低。**谁是谁的锁定单位**：玩家普攻 → 被锁定/选中的那只 **NPC**；NPC 打玩家 → **玩家**；
NPC 被收服成召唤物后打怪 → 它**锁定的那只怪**。
**两个入口**：玩家侧 `BasicRemoteAttack01.锁定单位` ← `NpcTargeting.LockedNpc`；NPC 侧 `NpcAiBase.锁定单位`
（默认 = 玩家）。**被收服成召唤物时覆盖这个属性**让它去锁怪 —— 飞弹瞄准 / 追踪目标 / 命中结算 /
命中特效 全都走它，**不用改别的**。

## 8. 参数速查

| 参数 | 在哪 | 说明 |
|---|---|---|
| `是施法` | `NpcAttackConfig` | **开关**，不开就一直走"立即命中" |
| `子弹速度` | `NpcAttackConfig` | 米/秒。也决定结算延迟 = 距离 ÷ 速度 |

## 10. 出生点怎么量（武器顶端 / 尾部）

菜单 **`修仙 / 怪物 / 量飞弹出生点`**（`Assets/Editor/Tools/飞弹出生点量测.cs`）：用户说「右手骨骼」「武器顶端」「尾部（模型末端）」这种人话，而 `挂点` 要的是**一个骨骼名 + 一个局部偏移**：

- **武器根本不是骨骼** —— `GouTouJunShi_01_Weapon` 是**蒙皮网格**（只有 1 根骨骼 `Bone01`，网格本身长 1.97 米）；`LaoGuiJing_wuqi`、`JianMo_01_02` 同理
- **玄蜂连尾巴骨骼都没有** —— 整个模型就一个蒙皮网格，只有脚趾/头顶那几个 `*Nub`

**工具流程**：① 把动作 `AnimationMode.SampleAnimationClip` 采样到**用户给的百分比**那一帧；② 用**手动蒙皮**算目标点（`骨骼矩阵 × bindpose × 顶点` 加权 —— `Renderer.bounds` 和 `BakeMesh` 在编辑模式下都不跟骨骼，见[怪物近战判定 §5](怪物近战判定.md)）：`武器顶端` = 指定网格里**离它自己骨骼最远**的顶点（尖端）、`武器中部` = 网格顶点包围盒的**中心**（箭魔要的是中部）、`模型末端` = **整个模型**里**最靠后**（本地 Z 最小）的顶点（尾巴/尾针）；③ 在**所有骨骼**里找离该点**最近的那一根**（武器网格自己的骨头优先），输出 `挂点 = 骨骼名`、`挂点偏移 = 骨骼.InverseTransformPoint(世界点)`。

| 怪 | 挂点 | 偏移 | 说明 |
|---|---|---|---|
| 狗头军师 | `Bone01` | a1 `(-1.658, 0.826, 1.921)` / a2 `(-2.734, -0.130, 0.240)` | 离骨骼 1.97 米 = 武器尖端 ✓ |
| 老龟精 | `Bone07` | a1 `(-1.863, 0.285, 0.410)` / a2 `(-3.122, -1.245, -1.054)` | 离骨骼 2.32 米 ✓ |
| 箭魔 | `Bone11` | a1 `(0.266, 0.375, 0.450)` / a2 `(0.289, 0.671, 0.380)` | 包围盒中心 ✓ |
| 蜘蛛精 | `Bip01 Tail3` | `(0.222, 0.437, -0.010)` | 工具自己找到的尾骨 ✓ |
| 玄蜂 | `Bone04` | `(-0.549, 0.380, 0.899)` | 没有尾骨，取最近骨骼 ✓ |

> **每招的偏移不一样**（a1 / a2 分开量）：武器在两次动作里位置不同，而发射发生在**各自的百分比那一帧**。

### 10.1 三个坑

1. **`InverseTransformPoint` 要的是世界坐标**：第一版把**角色本地坐标**直接喂进去，量出来是 `248 / -208` 这种几百米的鬼数字。
2. **同名 FBX 会骗过 `Resources.Load`**：`MingYao_01.FBX` 和 `MingYao_01.prefab` **同目录同名**，`Resources.Load` 拿到哪个不确定 —— 拿到 FBX 会显示"没有控制器/没有 AI"，量出来全是错的。工具里改成**按文件夹全取、挑带 `NpcInstance` 的那个**。
3. ★ **最大的坑：找"挂哪根骨"要看蒙皮权重，不能用"离得最近的骨骼"猜**。症状（用户 2026-09-29）："**玄蜂的箭不是从屁股射出来的**"。真因：第一版「取模型最靠后的顶点 → 找离它最近的骨骼」得到 `Bone04 + (-0.549, 0.380, 0.899)`，**离屁股 1.83 米**（`Bone04` 在身体中上部）✗。**正解**：那个顶点**蒙皮在哪根骨头上**就挂哪根骨头 —— 实测玄蜂屁股最靠后的 8 个顶点 **100% 权重**都在 `Bone13` / `Bone13(mirrored)` 上（左右各一半）→ 挂 `Bone13` ✓。**权重 1.0 意味着偏移在骨骼空间里是刚性的，任何姿势都精确贴在屁股上**（改后离屁股 **0.001 米**）。工具已改成**优先用「驱动这个点的蒙皮主骨」**，只有拿不到（比如"武器中部"取的是包围盒中心）才退回"最近骨骼"。

**尾巴骨链那节**：「整个模型最靠后的顶点」是**姿势相关**的 —— 蜘蛛精在吐丝那一帧最后面的其实是**后腿**（主骨 `Bone14`），不是尾巴 ✗。所以工具又加了一条：**模型里只要有名字带 `Tail` 的骨骼链，就只在"尾巴骨驱动的顶点"里找**。改正后蜘蛛精的尾尖是 `(0.19, 0.33, -0.58)`、主骨 **`Bip01 Tail2`**（原来错挂在后腿区域）。

| 怪 | 改前 | 改后 |
|---|---|---|
| 玄蜂 | `Bone04`，离屁股 **1.83 米** | **`Bone13`，离屁股 0.001 米** |
| 蜘蛛精 | `Bip01 Tail3`（量到的是后腿） | **`Bip01 Tail2`**（只在尾巴骨顶点里找） |

## 11. 那支箭 `Object135` 与玄蜂

> 这一节原本叫「箭魔 / 玄蜂」，**箭魔已经删掉了（见 §16.1）**，但它烘出来的那支箭**被玄蜂继续用着**，所以资产留着、做法也留着。

`Object135`（原来在剑魔/箭魔模型里）是**蒙皮网格**（246 顶点，1 根骨骼 `Bone12`）→ 用 `BakeMesh` 烘成静态网格资产 `CombatVFX/Projectiles/专属/箭矢_Object135_Mesh.asset`，再做成 prefab `CombatVFX/Projectiles/专属/箭矢_Object135.prefab`。**它是独立资产，模型删掉之后照样能用** ✓（实测玄蜂删后仍然 3/3 命中、箭飞 9.8 米）。

**烘的时候必须做两件事**（第一版漏了，用户当场看出"箭是斜着飞的"）：

| 坑 | 现象 | 修法 |
|---|---|---|
| **网格里的箭是"斜"的** | 烘出来包围盒是 `1.23 × 0.50 × 1.61` —— 看着像"扁盒子"，实际里面是**一根斜着的杆**（斜着放，AABB 被撑成方的）。直接当弹体 → **箭斜着飞**，不是正对飞行方向 | 用**主轴**对正：找**相距最远的一对顶点**当轴向（`(-0.601, 0.196, 0.775)`），`Quaternion.FromToRotation(轴, Vector3.forward)` 转过去。对正后包围盒变成 **`0.150 × 0.122 × 1.916`** —— 一眼就是根 1.9 米的箭 ✓ |
| **网格中心不在原点** | 包围盒中心 `(-0.96, 0.85, 1.47)` → 箭会**飘在手外面 ~1.9 米** | 顶点全部**减去包围盒中心**，居中 |

### 11.1 朝向（"+Z = 飞行方向"）怎么定

`NpcProjectile` 是 `transform.forward = 飞行方向`，所以箭尖必须在 **+Z**。判断办法两条一起用：① **算**：取轴向两端各 18% 的顶点，算**平均横向铺开** —— 细的那端是箭尖（实测 `-Z` 端 0.023、`+Z` 端 0.060 → **尖端在 -Z，反的**）；② **看**：侧视渲一张，+Z 放方块、-Z 放球，一眼就知道尖端朝哪边。确认反了 → 重烘时多乘一个 `Quaternion.Euler(0, 180, 0)`。证据图：`screenshots/箭矢侧视图.png`（反的，箭羽在方块那侧）/ `箭矢侧视_翻后.png`（对的，**箭尖对着方块**）。

> prefab 是**光板一层**（MeshFilter + MeshRenderer），**没有**用来纠朝向的子节点 —— 朝向已经烘进网格里了，这样 `NpcProjectile` 怎么转它都对。实测：箭飞出去**朝向与指向玩家的夹角 = 0°** ✓。

### 11.2 让动画里那支箭真飞出去（用户建议，替代"另生成一支箭"）

用户原话：
> 「我感觉**箭的生成点位有问题**，是这样的：他射箭的动画中其实**已经有了箭这个组件**，但是动画结束这个箭就会消失掉，**能否让动画结束了箭也不消失，让它真正的飞出去**？来替代你现在生成箭的行为」

**做法**（`飞弹妖魔Ai.动画弹体节点名`，箭魔填 `Object135`）：

| 步骤 | 细节 |
|---|---|
| 1 发射那一刻量位置 | **手动蒙皮**算出 `Object135`（动画里那支箭，蒙皮到 `Bone12`）此刻的**真实世界中心**。不能用它自己的 `Renderer.bounds` —— 蒙皮包围盒不反映真实蒙皮范围（真实长 1.9 米，`bounds.size` 只有 0.14 米，见踩坑 B40/B47） |
| 2 把它藏起来 | `动画弹体.enabled = false` —— **这就是"它飞出去了"** |
| 3 飞出去的是副本 | 烘好的静态网格 `CombatVFX/Projectiles/专属/箭矢_Object135`，沿飞行方向飞 |
| 4 动作结束放回来 | 订阅 `状态变化`，离开「攻击」状态就把模型里那支箭恢复 ✓（下次拉弓还要用） |
| 5 **不要前移** | 基类的 `出膛余量()`（推出自己碰撞体）只对 QFX 那种"飞行中一碰就炸"的实体弹丸有必要；这支箭是纯网格、不和场景碰撞 → 覆盖成 0。**不移的话箭会凭空往前跳 1.075 米** |

**实测**：飞出的箭 与「动画里那支箭此刻位置」的误差 **0.000 ~ 0.019 米**（6 发）✓；箭在飞的时候模型里那支箭 隐藏 **979 帧 / 可见 0 帧** ✓；没箭在飞的时候 模型箭可见 **3235 帧** ✓（恢复了）；出手 / 命中 6 次 / 5 次（那一次是闪避摇中）✓

> 好处：出生点**永远和动画里那支箭重合**，不用再靠"量出来的骨骼 + 偏移"去近似（而且那些偏移 a1/a2 还得各量一套）。**玄蜂没有 Object135**，它继续用尾巴挂点出膛。

## 12. 射击时不要把身体纠向玩家

> ⚠️ 这一节记的是我改错了一次又改回来的过程，留着是为了别再犯。

用户先报"**箭魔的拉弓瞄准方向不是他朝向的方向**"，我量出攻击期间 `transform` 偏航从 180° 甩到
257°（= 离玩家最多 **77°**），于是**把 `攻击期间锁定朝向` 设成 false**（每帧把身体纠向玩家）。
改完 `transform` 确实 0° 了，我以为是修好了。用户紧接着说"还是不太对"，并给了正确的方向：

> 「**射击开始时的朝向就是射箭的正确方向，射击过程中的转体会让朝向和射箭方向偏离**」
> 「**对于箭魔这种，在射击时不要朝向玩家就好了**」

**正解是反过来的**：这套施法/射箭动作**自带它自己的站位和转体**（弓手本来就是侧身站、身体随拉弓转，
只有持弓的手指向目标）。AI 每帧把身体纠向玩家 = **跟动作抢方向盘** —— 把动作的转体整个抵消掉，
看起来才"瞄的方向和朝向对不上"。

**现在**：`攻击期间锁定朝向` 保持默认 **true**（射击时不纠），让动作自己演 ✓；再配合 §11 的
「用动画里那支箭当弹体」，位置和朝向都来自动画本身，天然就对得上。
> 近战怪当然也是 true（它们的注释里写着"边播边转会把手刺歪"）。

## 13. 混合怪的距离门槛

蜘蛛精 a1 是**近战**、a2 是**飞弹**，而 `可用出手方式()` 是**随机挑**的 —— 它站在 12 米外也可能随机挑到
a1，**对着空气挥爪子**。所以 `NpcAttackConfig` 加了两个字段（**对所有怪都通用**）：
`出手最小距离` = **太近不出这一招**（0 = 不限）；`出手最大距离` = **太远不出这一招**（0 = 不限）。

蜘蛛精：a1 只在 **≤3.5 米**出、a2 只在 **≥3.0 米**出（留 0.5 米重叠，免得出现"两招都不能出"的空档）。
**实测**：贴到 2.5 米 → 出手 3 次**全是 Attack1 近战** ✓；放到 11 米 → 出手只有 **Attack2 飞弹** ✓。
