## 1. 它在养成闭环里的位置

```
灵田（挂机产出灵草） → 炼丹（主动消耗灵气+材料） → ┬ 聚气丹（+总灵气）→ 修为提升
                                                    ├ 破境丹（服下 → 破境成功率↑）→ 破境
                                                    ├ 清障丹（回灵力）/ 愈伤丹（瞬回气血）
                                                    └ 回春丹（气血回复增益，缓回）
```

**闭环现在是通的**：一阶四味丹方只用**一阶下品灵田就能种**的生灵草、凝露花、回春草，
所以"开局种地 → 收草 → 炼丹 → 涨修为"这条路从第一步就走得通。
（`聚气丹 +25 总灵气`，而炼气期单次修炼只有 2 点 —— 一颗丹约等于十来次修炼。）

需求原文（用户 2026-10-01）：

> 炼丹需要对应材料以及消耗灵气，每种丹方都有**成功概率**以及 **1-9 品**（品 = 丹药珍贵程度、对应境界），
> 炼丹通常需要**一味主材和多味辅材**。

`炼丹阁` 上已经有 `StationInteractable`（类型 = `炼丹`），

> **"被实例化出来 = 就是要显示"** —— 在 `Awake` 里 `关闭()` 会导致按 F 后一片空白。

> ⚠️ **`StationInteractable.界面预制体 = null` 时按 F 只会弹一块空白幕布**
> （`StationInteractor` 的占位分支）。加新设施时一定要挂预制体。

## 3. 丹方怎么定义

丹方就是 `灵丹定义` 上**多填了几个字段**（`主材id` 非空即视为可炼）。一套数据两用：
`灵丹库` 里那 9 颗**破境丹**同时是丹方，也同时是破境时可服的道具。

| 字段 | 作用 |
|---|---|
| `主材id` + `主材数量` | **一味主材**。留空 = 不可炼制 |
| `辅材` | **多味辅材**，格式 `物品id:数量\|物品id:数量` |
| `灵气消耗` | 基础灵气消耗（走 `PlayerVitals.当前灵气`） |
| `成功率` | **这一味丹**的成丹率（越珍贵的丹越低） |
| `品` | **丹药自己的品（1~9）**，= 珍贵程度 = **对应境界**。**不是每炉可选的档位** |
| `对应大境界` | 喂错境界不生效（破境丹必须与当前大境界一致） |
| `产量下限` / `产量上限` | 炼成后产出几个（`掷产量()`） |
| `作用` | `无` / `破境` / `加修为` / `回气血` / `回灵力` |
| `作用数值` | 加修为 = 总灵气点数；回气血 / 回灵力 = 回复点数 |

### 「品」到底是什么（**曾经做错过，别再走回去**）

用户的定义：

> 「筑基丹是 2 品丹药，邪神究极无敌狂霸破灭神丹是 9 品丹药，
>   丹药的品阶只是说明**丹药珍贵程度**的东西，**对应境界**。」

⇒ `品` 是**这颗丹的固有属性**：炼气破境丹 = 1 品、筑基 = 2 品 …… 登仙 = 9 品；
一阶基础丹（聚气 / 清障 / 愈伤 / 回春）= 1 品。**品越高 = 越稀有 = 越难炼**，
这是**丹与丹之间**的差别，不是同一炉里的档位。

> ❌ **已废弃的错误做法**：原先 `灵丹定义` 上有一组 `最高可炼品` + `品阶衰减` + `品阶加耗`，
> 让玩家在同一炉里选 1~9 品，选高品则成功率下降、耗气上升 ——
> 但**产出的物品 id 完全一样**，品根本没被记下来，"选品"这个动作对结果毫无实际意义。
> 这套字段、以及炼丹界面上的整排「品按钮」**已删除**。`炼制()` 现在只收一个 `丹方id`。

### 三类丹：**按 `作用` 分流**

| | 破境丹（9 颗） | 一阶基础丹（4 味） | 属性增益丹 |
|---|---|---|---|
| `作用` | `破境` | `加修为` / `回灵力` / `回气血` | `无` |
| 怎么生效 | 背包里点「**使用**」→ 提升**当前破境成功率** | 背包里点「**使用**」→ 立即生效 | 效果写在**物品自己的「使用效果」**上 |
| 物品表 | `可使用 = 1` + `效果类型 = 服丹` + `效果参数id = <自身id>` | 同左 | `效果类型 = 属性增益` |
| 数值在哪 | 提升到 `RealmDefinition.服丹成功率` | 药力在 `灵丹定义.作用数值` | 在增益资产上（例：`hui_fu_5pct`） |

> ⚠️ **`效果参数id` 必须填，且要能对上 `灵丹库` 里的一条 `id`**。
> `服丹效果` 先按 `丹方id` 查、查不到再按物品 id 兜底；**两条都对不上就静默无效**。
> 导入器（`物品效果导入.cs`）会对 `灵丹库.取(参数id ?? 物品id) == null` **打警告**，别忽略。

### 一阶四味（只用的上一阶下品就能种的灵草）

| 丹 | `品` | 作用 | 药力 | 主材 | 辅材 | 耗气 | 成功率 |
|---|---|---|---|---|---|---|---|
| **聚气丹** `item_dan_juqi` | 1 | 加修为 | **+25 总灵气** | 生灵草 ×2 | 凝露花 ×1 | 8 | 90% |
| **清障丹** `item_dan_qingzhang` | 1 | 回灵力 | **+30 灵力** | 凝露花 ×2 | 生灵草 ×1 | 8 | 90% |
| **愈伤丹** `item_dan_yushang` | 1 | 回气血 | **+80 气血（瞬回）** | 生灵草 ×1 | 凝露花 ×2 | 8 | 90% |
| **回春丹** `item_huichundan` | 1 | 无 | 气血回复 +5% / 1h（增益） | 回春草 ×2 | 凝露花 ×1 | 10 | 88% |

> **愈伤丹 vs 回春丹**：愈伤丹**瞬回**气血，回春丹是**缓回增益**（走属性增益效果），两者并存。
> 回春丹原来没有丹方（只有物品），已补上：丹方 `item_huichundan` + 灵草「回春草」（`lingcao_huichun`，凡品 / 3 天 / 产物 `item_huichuncao`，种子 `item_seed_huichun`）。

### 服破境丹：改的是**一个时时变化的值**

`PlayerCultivation` 上有：

| 成员 | 含义 |
|---|---|
| `破境加成` | 丹药吃出来的**加法**加成（存档字段，v9 起进档） |
| `当前破境成功率` | `Clamp01(当前境界.基础成功率 + 破境加成)` —— **UI 只读这一个值** |
| `设置破境加成(float)` / `清空破境加成()` | 服丹时写、破境判定后清。**两个都会广播 `修为变化`** |

`服丹效果` 走 `破境` 分支时把加成设成 `服丹成功率 − 基础成功率`（例：75% → 95%，加成 +20%）。
**`尝试破境()` 用 `当前破境成功率` 判定，并`不论成败` 都 `清空破境加成()`** ——
所以"服丹后成功率"不是一个写死的展示数字，而是实时值。

> **值变了要广播，显示它的界面要订阅**：`CultivationUI` 与 `UIRealmBar` 都订阅 `修为变化`。
> ⇒ 界面**开着**的时候服丹，成功率会自己从 75% 跳到 95%（实测），不用关掉重开。
> ⚠️ 订阅必须**成对退订**（`OnDisable` + `OnDestroy`）—— 本界面是"用一次就 Destroy"的预制体（踩坑 B53）。

> ⚠️ 同一大境界**只能嗑一颗**：`破境加成 > 0.001` 时 `服丹效果.能使用` 直接拒绝。
>
> ⚠️ `边界`：`尝试破境()` **只为小境界**放行，**大境界突破故意不受理**（需要专属丹药，那套还没做）。

## 4. 炼制流程与代价

`炼丹炉.炼制(string 丹方id)`：

1. `能炼(丹方, out 原因)` 校验：丹方合法 → **材料够** → **灵气够**
   （任一条不过就**不受理**，什么也不扣，并给出人话原因）
2. **扣材料 + 扣灵气**（不论成败）
3. `Random.value < 实际成功率(丹方)` 判定
4. 成功 → 产出进背包（走 `UIPanelData.给物品`，和任务奖励同一条入口）

> **失败也扣材料与灵气** —— 这是"炼丹是主动玩法、消耗资源"的定位。
> 界面上会明确写"材料与灵气已耗去"，不做静默。

### 界面布局

```
┌────────────────────────────────────────────┐
│ 丹房 · 炼丹         灵气 150/150  加成 +10% │
├──────────────┬─────────────────────────────┤
│ 丹方          │ 炼气破境丹                  │
│ [炼气破境丹]  │ 【材料】生灵草 ×3（有 12）   │
│ [筑基破境丹]  │ 　　　　凝露花 ×2（有 5）    │
│              │ 【1 品丹】成功率 85% 耗灵气 20│
│              │        [ 炼　制 ]            │
└──────────────┴─────────────────────────────┘
```

**没有「选品」这一排按钮**（那是废弃做法，见 §3）；右上只显示 `品` 与 `成功率`。

## 5. 被动技能加成（接口已留）

需求：做几个被动技能 `xx炼丹术` 提升 xx 品丹方成功率；另做几个减少炼丹的灵气消耗。

`炼丹炉` 上已有两个公开字段，**等着被被动技能灌进来**：

| 字段 | 作用 |
|---|---|
| `成功率加成` | **乘法**加成（0.1 = 成功率 ×1.1），`实际成功率` 上限 95% |
| `耗气减免` | 灵气消耗减免（0.2 = 少花 20%），`实际耗气` 至少 1 |

**还没做**：真正把这些被动技能做成可学会的条目并接到这两个字段上。

## 6. 加一个新丹方 / 新丹药（操作步骤）

1. 在 `Assets/Data/Tables/物品表.csv` 加**产物**那一行（`物品id` 必须与丹方 id 一致）；
   需要的话再加**主材 / 辅材**的物品行。
   - 能吃的丹：`可使用=1` + `效果类型=服丹` + **`效果参数id=<自身id>`**
   - 增益类丹：`效果类型=属性增益` + `效果参数id=<增益资产名>`
2. 在 `Assets/Scripts/Data/灵丹定义.cs` 的 `灵丹库.确保()` 里加一条 `灵丹定义`，
   填上 `品` / `对应大境界` / 主材/辅材 / 灵气 / 成功率 / `作用` / `作用数值`。
3. 跑菜单 **「修仙/从配置表生成资产」**（否则产物 id 在物品库里不存在，收成会丢）。
4. 进游戏点**炼丹阁**验证：材料不足时它应给出**具体缺哪一味**，而不是静默失败。

> ⚠️ 加完记得**跑一次场景一致性体检**（见 [ai/踩坑总库](../ai/踩坑总库.md)）。
> ⚠️ 改 CSV 用 Excel 会**丢 UTF-8 BOM**，见 [踩坑总库 §F7](../ai/踩坑总库.md)。
