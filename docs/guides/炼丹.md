## 丹房教学与关窗推进

师兄在身旁引导前往丹房，抵达后介绍炼丹并给四张一阶丹方与材料；丹方不在清晨招呼时提前发放。主线判定任意一种丹药炼成，待炼丹操作窗关闭后，师兄夸赞并通知师父在洞府等候，之后才出现回洞府目标。

介绍、炼丹等待和完成传话沿用同一师兄对象与原站位，不因玩家在丹房旁移动而把他拉进建筑。炼制、成品领取及成功率机制不变；实际入包通过统一获得提示显示图标、名称和数量。

## 1. 它在养成闭环里的位置

```
灵田（挂机产出灵草） → 炼丹（主动消耗灵气+材料） → ┬ 聚气丹（+总灵气）→ 修为提升
                                                    ├ 破境丹（服下 → 破境成功率↑）→ 破境
                                                    ├ 清障丹（回灵力）/ 愈伤丹（瞬回气血）
                                                    └ 回春丹（气血回复增益，缓回）
```

**闭环现在是通的**：一阶四味丹方只用**一阶下品灵田就能种**的生灵草、凝露花、回春草，
所以"开局种地 → 收草 → 炼丹 → 涨修为"这条路从第一步就走得通。
（`聚气丹 +25 总灵气`，而炼气期单次修炼只有 2 点 —— 一颗丹约等于十来次修炼。）

需求原文（用户 2026-10-01）：

> 炼丹需要对应材料以及消耗灵气，每种丹方都有**成功概率**以及 **1-9 品**（品 = 丹药珍贵程度、对应境界），
> 炼丹通常需要**一味主材和多味辅材**。

## 3. 丹方怎么定义

丹方就是 `灵丹定义` 上**多填了几个字段**（`主材id` 非空即视为可炼）。一套数据两用：
`灵丹库` 里那 9 颗**破境丹**同时是丹方，也同时是破境时可服的道具。

| 字段 | 作用 |
|---|---|
| `主材id` + `主材数量` | **一味主材**。留空 = 不可炼制 |
| `辅材` | **多味辅材**，格式 `物品id:数量\|物品id:数量` |
| `灵气消耗` | 基础灵气消耗（走 `PlayerVitals.当前灵气`） |
| `成功率` | **这一味丹**的成丹率（越珍贵的丹越低） |
| `品` | **丹药自己的品（1~9）**，= 珍贵程度 = **对应境界**。**不是每炉可选的档位** |
| `对应大境界` | 喂错境界不生效（破境丹必须与当前大境界一致） |
| `产量下限` / `产量上限` | 炼成后产出几个（`掷产量()`） |
| `作用` | `无` / `破境` / `加修为` / `回气血` / `回灵力` |
| `作用数值` | 加修为 = 总灵气点数；回气血 / 回灵力 = 回复点数 |

### 「品」到底是什么（**曾经做错过，别再走回去**）

用户的定义：

> 「筑基丹是 2 品丹药，邪神究极无敌狂霸破灭神丹是 9 品丹药，
>   丹药的品阶只是说明**丹药珍贵程度**的东西，**对应境界**。」

⇒ `品` 是**这颗丹的固有属性**：炼气破境丹 = 1 品、筑基 = 2 品 …… 登仙 = 9 品；
一阶基础丹（聚气 / 清障 / 愈伤 / 回春）= 1 品。**品越高 = 越稀有 = 越难炼**，
这是**丹与丹之间**的差别，不是同一炉里的档位。

> ❌ **已废弃的错误做法**：原先 `灵丹定义` 上有一组 `最高可炼品` + `品阶衰减` + `品阶加耗`，
> 让玩家在同一炉里选 1~9 品，选高品则成功率下降、耗气上升 ——
> 但**产出的物品 id 完全一样**，品根本没被记下来，"选品"这个动作对结果毫无实际意义。
> 这套字段、以及炼丹界面上的整排「品按钮」**已删除**。`炼制()` 不接收品阶参数；可选 `自动入包` 只控制领取方式。

### 三类丹：**按 `作用` 分流**

| | 破境丹（9 颗） | 一阶基础丹（4 味） | 属性增益丹 |
|---|---|---|---|
| `作用` | `破境` | `加修为` / `回灵力` / `回气血` | `无` |
| 怎么生效 | 背包里点「**使用**」→ 提升**当前破境成功率** | 背包里点「**使用**」→ 立即生效 | 效果写在**物品自己的「使用效果」**上 |
| 物品表 | `可使用 = 1` + `效果类型 = 服丹` + `效果参数id = <自身id>` | 同左 | `效果类型 = 属性增益` |
| 数值在哪 | 提升到 `RealmDefinition.服丹成功率` | 药力在 `灵丹定义.作用数值` | 在增益资产上（例：`hui_fu_5pct`） |

> ⚠️ **`效果参数id` 必须填，且要能对上 `灵丹库` 里的一条 `id`**。
> `服丹效果` 先按 `丹方id` 查、查不到再按物品 id 兜底；**两条都对不上就静默无效**。
> 导入器（`物品效果导入.cs`）会对 `灵丹库.取(参数id ?? 物品id) == null` **打警告**，别忽略。

### 服破境丹：改的是**一个时时变化的值**

`PlayerCultivation` 上有：

| 成员 | 含义 |
|---|---|
| `破境加成` | 丹药吃出来的**加法**加成（存档字段，v9 起进档） |
| `当前破境成功率` | `Clamp01(当前境界.基础成功率 + 破境加成)` —— **UI 只读这一个值** |
| `设置破境加成(float)` / `清空破境加成()` | 服丹时写、破境判定后清。**两个都会广播 `修为变化`** |

`服丹效果` 走 `破境` 分支时把加成设成 `服丹成功率 − 基础成功率`（例：75% → 95%，加成 +20%）。
**`尝试破境()` 用 `当前破境成功率` 判定，并`不论成败` 都 `清空破境加成()`** ——
所以"服丹后成功率"不是一个写死的展示数字，而是实时值。

> **值变了要广播，显示它的界面要订阅**：`CultivationUI` 与 `UIRealmBar` 都订阅 `修为变化`。
> ⇒ 界面**开着**的时候服丹，成功率会自己从 75% 跳到 95%（实测），不用关掉重开。
> ⚠️ 订阅必须**成对退订**（`OnDisable` + `OnDestroy`）—— 本界面是"用一次就 Destroy"的预制体（踩坑 B53）。

> ⚠️ 同一大境界**只能嗑一颗**：`破境加成 > 0.001` 时 `服丹效果.能使用` 直接拒绝。
>
> ⚠️ `边界`：`尝试破境()` **只为小境界**放行，**大境界突破故意不受理**（需要专属丹药，那套还没做）。

## 4. 炼制流程与代价

`炼丹炉.炼制(string 丹方id, bool 自动入包 = true)`：

1. `能炼(丹方, out 原因)` 校验：丹方合法 → **材料够** → **灵气够**
   （任一条不过就**不受理**，什么也不扣，并给出人话原因）
2. **扣材料 + 扣灵气**（不论成败）
3. `Random.value < 实际成功率(丹方)` 判定
4. 成功 → 返回产物数量，默认直接入包（`UIPanelData.给物品`）；拖拽丹房传 `自动入包=false`，成丹暂留炉中等待领取
   **并且**给这个丹方打上**两个**标记（`对话标记`）：
   · `丹方_<丹方id>` = **学会**了这张丹方 —— `炼丹界面` 靠它决定列不列出来（炼出来过 = 学会，见 §3）。
     ⚠️ 这个标记**任务表阶段24 也会写**（大师兄一次留 4 张丹方给你），所以它**不能**当"玩家炼过丹"的判据。
   · `炼成_<丹方id>` = **真的炼成过一次** —— 只有这里会写，供 `炼丹炉.炼成过的种类数`
     判 `任务条件.炼过丹`（主线阶段27 的验真条件："**任意一种**丹药炼成过就行"）。
   两者都进存档（标记是存档的一部分），所以存档-退出-再炼也不会漏。

> **失败也扣材料与灵气** —— 这是"炼丹是主动玩法、消耗资源"的定位。
> 界面上会明确写"材料与灵气已耗去"，不做静默。
> ⚠️ 失败**两个标记都不打** —— 所以"炼过丹"这个条件只认**成功**。

### 4.1 拖拽丹房界面

水墨模式由原 `炼丹界面` 在 Awake 中创建 `UIInkAlchemyPage`，沿用设施预制体与开关，不改场景。左上丹方区的左侧依次显示**成品丹药图标、丹方名与介绍**，右侧按药材逐片展开竖排竹简，每片显示主辅类别、数量、药材图标、名字及介绍。右上已学丹方使用卷竹简图标。下方中间为独立炉身与炉盖，主材在中间、四个辅材位置在两侧。

炉旁左右列表都显示同一套背包药材，按 id 去重，只列当前数量大于零且能用于丹方的物品。两侧均为居中单列、等距排列，行尺寸 150×108、间距 116，药材图标约 60×60，名称在下方、数量在右上；更多材料向下滚动。**左侧投到主材位，右侧投到辅材位**；两侧共享背包数量和暂存总量。选定丹方后拒绝类别不符合要求的投料；未选丹方也分别记录主辅材，类别与数量均完全匹配某个已学丹方才可开炼，不能互换主辅材后只按总量匹配。

丹方、药材列表使用背包同款滚动条；介绍独立滚动，过多药材竹简可横向滚动。未选丹方只显示闭合卷竹简。切换先约 0.22 秒收合旧丹方、闭合约 0.1 秒，再展开新丹方；各片约 0.3 秒展开、间隔约 0.065 秒。连续选择以最后点击为准，收合期间不能开炼、投料或取回材料。**不自动填料**，未学丹方不显示。

丹房与角色页等交互界面共用场景输入锁：保留 UI 滚动和拖拽，阻断摄像机滚轮缩放、旋转、移动、新攻击与施放、NPC 交互、御风/坐骑切换。多界面同时打开时必须全部关闭才解锁，详见 [游戏HUD §3](../architecture/游戏HUD.md)。

**测试添加丹方**：按 P，在靠上的“添加丹方”区域按名称或 id 筛选，选中后点“添加选中丹方”，或点“学会全部丹方”。这里只写 `丹方_<id>` 学习标记，沿用现有存档保存；不写 `炼成_<id>`，不增加丹药、不冒充炼丹成功，不主动写存档。已学会的不会重复添加；丹房列表自动刷新。P 面板整页可滚动，低分辨率下不会把新增工具和原属性区挤出屏幕。

| 操作 | 实际行为 |
|---|---|
| 拖动药材 | 图标随鼠标移动；接近炉口时约 0.2 秒抬盖；松开时必须落在炉口实际区域内才接受 |
| 成功投料 | 约 0.5 秒吸入、缩小、散光与合盖；炉身显示药材和暂存数量 |
| 取消投料 | 图标沿弧线回原位，炉盖合上；不改变炉内数量，也不扣背包 |
| 点击药材 | 作为拖拽的辅助操作，执行同一投料演出 |
| 点击炉身材料位置 | 取回一份暂存药材；“取回药材”清空整炉；均不增减背包 |
| 开炼 | 材料必须精确匹配；约 3.2 秒持续烟气、灵光及轻微炉身摆动；忙时不能换丹方或继续投料 |
| 成功出丹 | 抬盖、丹丸弹出及微粒散开；产物暂留炉中，炉盖持续打开直到领取，“取回药材”变为“取回丹药”，领取才入包，未领取不能继续投料、换方或开炼 |
| 取回丹药 | 按产量一次入包并合盖，重复点击不重复发放；关闭界面时自动收取，避免遗失 |
| 炼制失败 | 正常消耗材料与灵气，墨烟散去，不产生待领取丹药 |
| 炼制中关闭 | 停止未完成协程，不调用结算、不扣材料；若已经结算，产物和消耗保留 |

投料是界面的暂存清单，不立即移除背包物品；可用数量显示“实际背包数量 − 暂存数量”。选中丹方后拒绝不需要的药材、超量药材以及重复拖拽中的新操作。炼制演出结束仅调用一次 `炼丹炉.炼制`，它仍会重新校验材料与灵气、抽取成功率、扣料、返回产量并广播。这里不再重复手动处理旧界面的结果事件。演出中外部消耗了药材或灵气时，由既有业务校验拒绝这一炉。

血量、任务与纪年 HUD 在丹房打开时隐藏，关闭或销毁恢复各画布原状态。`InkUIRuntimeSkin` 跳过独立丹房，防止改回旧纸卷与金框。动效用 unscaled 时间，暂停期间仍能完成演出。

## 6. 加一个新丹方 / 新丹药（操作步骤）

1. 在 `Assets/Data/Tables/物品表.csv` 加**产物**那一行（`物品id` 必须与丹方 id 一致）；
   需要的话再加**主材 / 辅材**的物品行。
   - 能吃的丹：`可使用=1` + `效果类型=服丹` + **`效果参数id=<自身id>`**
   - 增益类丹：`效果类型=属性增益` + `效果参数id=<增益资产名>`
2. 在 `Assets/Scripts/Data/灵丹定义.cs` 的 `灵丹库.确保()` 里加一条 `灵丹定义`，
   填上 `品` / `对应大境界` / 主材/辅材 / 灵气 / 成功率 / `作用` / `作用数值`。
3. 跑菜单 **「修仙/工具/安全导入配置表（不动场景）」**（否则产物 id 在物品库里不存在，收成会丢）；不要为了 UI 接入重跑场景生成器或保存场景。
4. 进游戏点**炼丹阁**验证：材料不足时它应给出**具体缺哪一味**，而不是静默失败。

> ⚠️ 加完记得**跑一次场景一致性体检**（见 [ai/踩坑总库](../ai/踩坑总库.md)）。
> ⚠️ 改 CSV 用 Excel 会**丢 UTF-8 BOM**，见 [踩坑总库 §F7](../ai/踩坑总库.md)。
