## 1. 一句话结论（要不要换渲染管线）

**不换，留在 Built-in**，力气花在材质收敛 + 后处理补完上（利弊见 §10）。

1. "像第三方、动不了"的 shader **全都有源码**（工程内共 31 个 `.shader`）⇒ "换 URP 会烂特效"**不成立**；
   但换过去要改写**约 1000 个材质的着色逻辑**。
2. **"卡通/动漫化"是美术方向给的，不是管线给的**：平涂、色块分明、高饱和、亮部辉光，换 URP 一件都不会自动发生。
   真正缺的是**后处理栈不完整**（无 Bloom / LUT / Tonemapping），它在 Built-in 下已有现成的机器（§8）。

## 2. 整体思路：三层收敛，按"影响面 ÷ 风险"排序

| 层 | 问题 | 做法 | 状态 |
|---|---|---|---|
| **① 材质** | 全工程 **1580 个 `.mat`** 混用 6 种 Legacy shader | 统一到**玩家当前材质**（§3） | ✅ 已完成 1343 个 |
| **② 光照** | 塔内 33 盏灯、点光无阴影、range 远大于房间尺度 ⇒ 隔墙灌光、对比被抹平 | 降强度 + 缩半径（§4） | ✅ 已完成 |
| **③ 后处理** | 只有单道调色，**没有 Bloom / LUT / Tonemapping** | 在 `Cultivation/GlobalGrade` 上扩 | ⬜ 未做（§8） |

> 材质排第一：它同时是"最像第三方、最不敢动"和"影响最大"的一层，而且**幂等、可回滚**，性价比最高。

## 3. 材质收敛：唯一基准 = **玩家当前的材质**

基准来自玩家材质 `better_player_test.mat`：

| 属性 | 值 |
|---|---|
| shader | `Standard` |
| `_Color` | `(1, 1, 1, 1)` 纯白 |
| `_Metallic` | **0** |
| `_Glossiness` | **0** ← 完全哑光 |
| `_MainTex` | 有贴图 |

**哑光（光泽 0）是这套基准的灵魂**：没有高光就不会被 2~3 强度的暖色点光打出爆白斑点。
这跟塔材质原先的 `光泽 0.25~0.42` **正好相反**，那才是"火光过曝"的元凶之一。

### 3.1 收敛规则

| 项 | 怎么处理 |
|---|---|
| shader | 一律 → `Standard` |
| `_Color` / `_MainTex` | **原样保留** |
| `_BumpMap` | 搬过去 |
| `_Metallic` | → 0 |
| `_Glossiness` | → 0；**只有 `Specular` 族**给极弱高光（原 `_Shininess × 0.35`，上限 0.22），否则金属/石面变塑料 |
| 自发光族 | **不补自发光，彻底改成受光** |
| 渲染模式 | `Cutout` → 镂空（保留 `_Cutoff`）；`Transparent` → Fade；其余 → 不透明 |

### 3.2 ⚠️ 最大的割裂点：NPC 是**自发光**的

收敛前统计：`Legacy Shaders/Diffuse` 841（建筑/地形/道具）、
**`Legacy Shaders/Self-Illumin/Diffuse` 335（其中 318 个是 NPC）**、
`GAPH Custom Shader/Shader_IntegradedEffect` 592（法术特效）、`Standard` 309（原本就有）、
`Legacy Shaders/Particles/*` 等（粒子特效）。NPC 材质实测属性：

```
shader = Legacy Shaders/Self-Illumin/Diffuse
属性   = _Color:Color, _MainTex:TexEnv, _Illum:TexEnv, _Emission:Float
_Color = (0.588, 0.588, 0.588)      ← 注意这个暗灰
_MainTex = 128×128 贴图
_Emission = 0（是个 Float 滑块，不是颜色）
```

**自发光 shader 完全不吃光照** ⇒ NPC 是"贴图 × 0.588 直接怼屏幕"，玩家却是 `Standard` 受光，
**两者根本不在一个色彩体系里** —— 这就是"材质和整体游戏不搭界"最根本的来源。
选的是「**改成和玩家一样的受光 Standard**」（三条路之一）；代价是塔内偏暗处 NPC 会暗一点，
但这才是真正的"统一"，§4 暗部抬升与 §8 Bloom 会补回来。

### 3.3 结果

| 指标 | 收敛前 | 收敛后 |
|---|---|---|
| `Standard` 材质 | 309 | **1652** |
| 残留 Legacy 受光材质 | 1343 | **0** |

### 3.4 明确**不动**的（改了会直接坏）

用 `Assets/Editor/Tools/材质统一收敛.cs` 的排除表控制：

| 排除对象 | 原因 |
|---|---|
| `Assets/Environment/Tree/**`、`Terrain`、`Vegetation` | 多是 **billboard 片**，转 Standard 会从"通透"变"实心发暗"。**已验证：111 个树材质全部保持 Legacy、0 个被误改** |
| `Assets/Effect/**`、`Assets/resources/特效/**` | 靠**叠加混合发光**，转成不透明直接坏（试运行里有 10 个这种） |
| 所有 `Particles` / `Trail` / `Decal` / `Skybox` / `GUI` / 第三方特效 shader | 另一套渲染逻辑，不属于"受光实体" |

### 3.5 工具与备份

`Assets/Editor/Tools/材质统一收敛.cs`（菜单「工具/材质/① 试运行 ② 执行 ③ 校验」，**幂等可重跑**）；
备份在 `.dsh/_材质备份_全局收敛/`（**1580 个 `.mat`**，回滚直接拷回去）。

> 工具**走材质 API 改属性**，不是手改 YAML（2900 个文件手改必然出错）。**先试运行再执行**：
> 试运行打印"按 shader 分布 / 按目录分布 / 抽样 8 个前后对比"。

## 4. 镇妖塔的光照收敛

### 4.1 改前为什么"昏暗"

用户要求：「镇妖塔的材质和整体游戏很不搭界，光照也很难受，很昏暗」。实测塔内 **33 盏灯**：

| 灯 | 数量 | 强度 | range | 阴影 |
|---|---|---|---|---|
| `层光` | 8 | 2.00 | **40** | 无 |
| `火光` | 7 | **3.40** | 26 | 无 |
| `梯灯` | 12 | 2.20 | 16 | 无 |
| `灯光` | 4 | 1.60 | 16 | 无 |
| 方向光 / 补光 / 蓝点光 | 3 | — | — | 主光有软阴影 |

**问题不是"不够亮"，而是"没有暗"**：① **`层光` range 40 而塔半径只有 27** ⇒ 光**隔着墙灌进来**；
② **点光全部无阴影** ⇒ 光穿透一切几何体；③ 强度 2.0~3.4 叠加，任意一点都累加到 2.0 以上
⇒ **远超过曝点**；④ 暗部被抬成灰、对比被抹平，画面一层**琥珀色雾霾**。

### 4.2 改法与结果

| 灯 | 强度 | range |
|---|---|---|
| `层光` | 2.00 → **1.15** (×0.58) | 40 → **28** (×0.70) |
| `火光` | 3.40 → **2.20** (×0.65) | 26 → 22 |
| `梯灯` | 2.20 → **1.50** (×0.68) | 16 → 14 |
| `灯光` | 1.60 → **1.10** (×0.69) | 16 → 14 |

> **收敛方向是"降强度 + 缩半径"，不是加光。** 这个场景的病根是光太多太散。

其余保持：环境光 `Trilight` / `ambientIntensity 0.72`、定向光 1.35、冷色补光 0.22。
（注：`ambientIntensity` 曾按**还没转 Standard 的**旧 Legacy 材质调成 1.45；材质收敛后过亮，已降到 0.72。）

`Assets/Editor/Tools/塔灯光收敛.cs` —— 菜单「工具/画面/① 只报告 ② 执行」；原值备份在
`.dsh/_灯光备份/塔内灯光原值.txt`。它**按灯名做前缀匹配**定系数，改场景里序列化的值、且幂等。

> ⚠️ 幂等是"可以重复跑"，但**重复跑会继续变小**（每次乘一遍）—— 要重来请先从备份恢复原值。

## 5. 地面贴图：为什么必须**自己生成**

### 5.1 病根：一张 128×256 的贴图铺满了 54 米

```
地面板（24 顶点）         UV 范围 = [0.00~1.00, 0.00~1.00]
材质 digongwall_001_02    tiling = (1, 1)
贴图                     128 × 256
```

**整个 54×54 米的塔层地面，UV 只有 0~1，贴图只有 128×256** —— 即"一张小图拉伸铺满全场"。
相机是**俯视视角**，画面主体就是这块地板 ⇒ 近景一片纯色糊。

### 5.2 靠平铺救不回来（实测）

| tiling | 观感 |
|---|---|
| 1（原） | 一片糊 |
| 14 | 几道斜纹 |
| 32 | 细密杂纹（源图本身几乎没有细节，放大只是把糊变成噪） |

所以**直接生成一张适配塔尺度、细节清楚的地面贴图**。设计取向是**大色块 + 清晰描缝**、
不用噪声堆高频细节：8×8 砧石、每块独立色相/明度抖动；接缝压到很暗的冷灰 ⇒ 石块分得开；
靠边压暗 ⇒ 有圆角与厚度感；石面轻微打磨痕 + 细颗粒；偏冷灰蓝基色（明度 0.30~0.42），**暗部留给提灯**。

### 5.3 ⚠️ 平铺次数必须**实测**

| 平铺 | 每块石板 | 观感 |
|---|---|---|
| 6× | ~1.1m | ❌ **整屏马赛克网格，比原来还糟** |
| **3×** | **~2.7m** | ✅ **采用**：石板读得清又不抢戏 |
| 1.5× | ~5.3m | ❌ 太平，等于没贴 |

`Assets/Editor/Tools/塔地面贴图生成.cs` —— 菜单「工具/画面/③ 生成 ④ 应用」，
生成到 `Assets/resources/Environment1/Common/Textures/TowerFloor/tower_floor_slab.png`。

> 贴图是**确定性哈希**生成的（不用 `Random`），每次结果一致、可复现。
> 材质染色压到 `0.62`，进一步降对比，避免地面抢视线。

## 6. 自动挂载（不要写进场景）

调色 shader = `Assets/Environment/CultivationGlobalGrade.shader`（`Cultivation/GlobalGrade`），
组件 = `Assets/Scripts/Core/GameGlobalGrade.cs`（挂主相机，`OnRenderImage`）。
`场景自举.补玩家与相机()` 给**每个场景**的主相机补上 `GameGlobalGrade`，所以不写进场景也不会漂移
（原因见 [踩坑总库](../ai/踩坑总库.md)）。

> 想给某个场景单独调：手动把 `GameGlobalGrade` 加到那个场景的主相机并改参数。
> 自举**不会覆盖已有组件**，手动调过的会保留。

### 6.1 参数

| Inspector 名 | 中文 | 默认 | 说明 |
|---|---|---|---|
| `Exposure` | 曝光 | 1.14 | >1 提亮。**觉得昏暗先调这个** |
| `Gain` | 高光乘算 | 白 | 压高光就调 <1 |
| `Gamma` | 中间调 | 白 | **小于 1 提亮中间调**（比单加曝光更保暗部） |
| `Lift` | 暗部加算 | 0.055/0.058/0.062 | 把死黑抬起来。⚠️ 太大会整片发灰/发红。水墨要"淡墨"不要死黑 |
| `Contrast` | 对比度 | 0.97 | ⚠️ **>1 会压暗部**，本来就暗的场景会更黑 |
| `Saturation` | 饱和度 | 0.82 | 水墨去饱和。**别低于 0.7**，会变成灰泥 |
| `Tint colour` / `Tint amount` | 染色 / 强度 | 青灰 / 0.22 | 整体色调偏向 |
| `Vignette` / `Vignette softness` | 暗角 / 柔和度 | **0（关）** | 见 §7 |

> ⚠️ 上表默认值 **2026-10-03「水墨路线A」重调过**（原来是曝光 1.06 / 饱和 1.06 / 染色 0.06）。
> 这些是**所有场景共用**的默认值，改一个数全场都变 —— 新增的水墨参数见 §13。

> ⚠️ **Shader 里属性名必须 ASCII**（`_Exposure` 可以，`_曝光` 不行）—— 中文属性名会让 ShaderLab
> 解析崩，而且**报错行号会骗人**。见 [踩坑总库](../ai/踩坑总库.md)。

## 7. ⚠️ 调参踩过的坑（现行默认值是踩出来的）

早先默认值 `曝光 1.12 / 对比度 1.06 / 饱和度 1.10 / 染色 0.18 / 暗角 0.35`，
**实测反而把画面变得更暗更红**（截图对比：不调色 2.0MB → 调色 0.9MB，大量细节被压掉）：

1. **对比度 >1 是"压暗部、提亮部"** —— 本来就偏暗的场景观感是**更黑**
2. **暗角 0.35 太重** —— 屏幕边缘吃掉一大块，画面变闷
3. **染色 0.18 偏黄红** —— 冷色素材（石板、金属）被染成暖褐色，反而更脏

现在默认值**很保守**（对比度 1.0、暗角 0、染色 0.06）。**要"好看"得按场景实际亮度慢慢调，不能一次给猛。**
另：调色只能**重新分配**已有亮度、**不能凭空造光**，所以"画面昏暗"要按 §3→§4→§5 的顺序动材质与光照，
而不是把曝光拉爆。

## 8. 后处理栈：现在有什么、缺什么

| 能力 | 现状 |
|---|---|
| 曝光 / Lift-Gamma-Gain / 对比 / 饱和 / 染色 / 暗角 | ✅ 有（`Cultivation/GlobalGrade`） |
| **Tonemapping（Hable / Uncharted2）** | ✅ **已加**，但对当前内容**几乎无效果**（§8.2） |
| **Bloom 辉光（多 mip 链）** | ✅ **已加** —— 动漫感提升最明显的一项 |
| LUT 重映射 | ❌ 没有 |

### 8.1 Bloom —— "动漫感"的关键

法术、灯火、描边、金属高光：**有辉光才叫"发光"，没有就只是一块块死白的色斑。**
实现：`Assets/Environment/CultivationBloom.shader`（4 个 pass：亮部提取 / 可分离高斯 / 升采样加算 / 合成）
+ `Assets/Scripts/Core/GameGlobalBloom.cs`（`OnRenderImage` 驱动的多 mip 链）。

| Inspector 名 | 中文 | 默认 | 说明 |
|---|---|---|---|
| `Threshold` | 阈值 | 0.85 | **只有超过它的像素发光**。调低 = 更多东西发光（易糊） |
| `Soft Knee` | 软膝 | 0.5 | 阈值附近过渡的柔和度。**0 = 硬切会闪烁** |
| `Intensity` | 强度 | 0.9 | 叠加到画面的量。0 = 关 |
| `Blur Radius` | 模糊半径 | 1.0 | 每级采样半径倍率 |
| `Levels` | 级数 | 5 | 越多辉光范围越大、开销也越大 |

**实测效果**（**冻结画面**逐像素 A/B）：

| 场景 | 平均亮度 | 标准差 | 变亮% |
|---|---|---|---|
| 塔 | 0.1890 → 0.1944 (+2.9%) | 0.1008 → 0.1056 (**+4.8%**) | **11.0%** |
| 宗门 | 0.0878 → 0.0878 (**0.0%**) | 0.0607 → 0.0607 (0.0%) | **0.0%** |

> **⚠️ 宗门完全没生效，这不是 bug**：塔里**只有 0.7% 的像素 ≥0.85**，宗门更暗（均值 0.088）
> **一个都没有**。所以阈值 0.85 在这两个场景里只对"真正的亮点"（法术、灯火、传送门）起作用 ——
> 这正是想要的行为。若希望宗门也泛光，把阈值降到 ~0.6。

### 8.2 ⚠️ Tonemapping 加了，但对当前内容**几乎无效果**

| | 平均亮度 | 标准差 |
|---|---|---|
| Tonemap 关 | 0.1427 | 0.1734 |
| Tonemap 开 | 0.1364 (**−4.4%**) | 0.1740 (**+0.36%**) |

**两种情况下过曝像素都是 0%** —— 塔里**根本没有超过 1.0 的亮度值**，Hable 曲线没有东西可压。

> **它现在是"地基"而不是"成果"**：Bloom 会大量产生 >1 的值，那时它才真正起作用
> （把过曝压成柔和滚降而不是死白）。保留它是正确的，但**不要拿它当这一轮的观感提升来汇报**。

**踩坑记录（重要）**：这个结论差点报错 —— 先用"前后两帧"对比量出标准差 +29%，看起来效果显著；
**但那两帧不是同一时刻**，第二张多了一个蓝色法术爆发，把均值和标准差都抬高了。
**冻结画面（`Time.timeScale = 0`）后重测，真实差异只有 +0.36%。**

> ★ 通用教训：**任何"画面前后对比"，必须冻结画面。** 同场景不同时刻的两帧，光照/特效/动作都在变，差值**绝大多数是噪声**。这个坑同一天踩了两次。

### 8.3 顺序（靠 `DefaultExecutionOrder` 保证）

```
相机 → GameGlobalBloom（出辉光，order = -100） → GameGlobalGrade（调色） → 屏幕
```

Bloom 必须**在调色之前**跑完，否则辉光不会被调色、会和画面脱节（发光的东西色温和周围不一致）。

### 8.4 ⚠️ Bloom 实现里两个必须知道的点

**① 升采样用 `Blend One One`，不在 shader 里相加。** 升采样是"把小图加到中图"，
读自己写自己 = 未定义行为；交给 blend 状态就彻底避开。这是 Unity PostProcessing 栈 Upsample
的标准做法，配 ping-pong 缓冲。

**② 临时 RT 必须 `Release()`。** 不释放会一路泄漏显存，切场景几十次就爆。
三处都释放：`OnDisable`、参数变化重建前、**以及关掉开关时**。

### 8.5 还没做的

**LUT 重映射** —— 用户点名要过。需要一张 **strip 格式（如 1024×32，16 级）** 的 LUT 贴图资产；
⚠️ 注意 strip 布局与 sRGB/Linear 的对应，否则颜色会整体偏。

**当前亮度基线偏低** —— 塔内画面均值只有 **0.19**（宗门 0.088）。这是"阴暗囚塔"想要的氛围，
但作为整体基线偏暗：要做足"动漫感"（高饱和 + 亮部发光）得**先把曝光基线抬起来**，
否则 Bloom 只有 0.7% 的像素在参与 —— **这是下一步最该调的旋钮。**

## 9. 与「特殊 shader」会不会撞车？

**结论：不会撞，它是「全屏最后一道 pass」，不是替换材质。** `OnRenderImage` 拿到的是一张
**已经画完的场景图**，处理完再交给屏幕；它**不碰任何材质的 shader、不改任何 sharedMaterial**：

| 系统 | 实现方式 | 和调色的关系 |
|---|---|---|
| **角色/真灵描边** `Cultivation/CharacterOutlineRim` + `Fill` | `new Material(shader)`，换渲染器的 `sharedMaterials` | 照常画，**也一起被调色** |
| **树冠/建筑遮挡透明** | 只改 `sharedMaterials` **数组**指向副本（连原材质都不动） | 同上 |
| **GrabPass 扭曲类特效** (`Shader_DistortionEffect` / `Distortion` / `GlassStainedBumpDistort` …) | 采样**当时的**相机图 | 采到的是**未调色**的场景，但整块结果**最后会被一起调色** ⇒ 观感一致 |

> **GrabPass 采到的"未调色画面"不会显得突兀** —— 那张图连同它周围的一切，最后都会经过同一道调色。

### 9.1 ⚠️ 要注意的两点

**① 预览相机不走调色** —— `UI/UIMountPage.cs`（坐骑预览）与 `UI/外观预览.cs`（外观预览）
**自己建相机并 `targetTexture = 贴图`**；`OnRenderImage` 在"渲染到贴图"的相机上**默认不触发**，
所以预览图不会被调色。若全局调色比较重，**预览里的角色/坐骑颜色会和游戏画面不一致**。
`场景自举.找主相机()` 找的是名为 `Main Camera`（或 tag `MainCamera`）的那个，所以**不会**误挂这些预览相机 ✓。
要统一有两条路（**都还没做**）：给预览相机也挂组件并手写 `targetTexture` 下的 Blit；或在预览 UI 层做一次同样的调色。

**② HUD / UI 不参与调色**（ScreenSpaceOverlay 在 `OnRenderImage` 之后合成）。这通常是**想要的**
（界面不该被场景色调污染、也不该被暗角压暗）；但**暗角只压场景、不压 UI**，所以 UI 在暗角里会显得更亮、有点"浮"。

## 10. 换渲染管线的利弊分析

用户要求：「因为本身追求的是偏向卡通化的动漫化的……与其改善资产，会不会改渲染管线会更好一点，
当然我也不懂，你分析一下利弊看着来」。

### 10.1 关键事实：特效 shader **全都有源码**

原本"换 URP 风险大"的核心理由是**特效会烂**，查过后**不成立**：
`GAPH Custom Shader/Shader_IntegradedEffect`（592 个材质，源码 `Assets/resources/特效/法术/Shader_ForEffects/`）、
`特效/飞弹/ProjectilesFX/*`（4 个，~200 个材质，源码 `Assets/resources/特效/飞弹/.../Shaders/`）、
`Combat Magic VFX`（2 个，源码 `Assets/resources/特效/战斗法术/.../shaders/`）、
`Cultivation/CharacterOutlineRim` / `Fill`（描边，`Assets/Shaders/`）、
`Cultivation/GlobalGrade`（后处理，`Assets/Environment/`）。工程内共 **31 个 `.shader` 文件**，
特效相关的**全部有源码、可改写**。

### 10.2 收益

自带 Volume / 后处理栈：**Bloom、Tonemapping、Color Grading、AA 开箱即用，不用手写**；
有可视化调参面板；长期官方维护，未来可上 HDRP / 更好的光照。

### 10.3 代价

约 **1000 个材质**依赖**只对 Built-in 写的手写 HLSL**，换管线后**不是变丑，是直接编译失败或渲染错乱**，
全部要重写；已做的描边 / 全局调色栈 / 幽灵效果全部作废重做；
**Shader Graph 对本工程无用**（走 toon 化就该手写 HLSL，本来也不打算用节点图）。

### 10.4 判断

**"卡通/动漫化"与渲染管线无关。** URP 的默认 PBR 出来**还是写实的** —— 平涂、色块分明、
高饱和、亮部辉光，换管线一件都不会自动发生。**真正缺的是后处理栈不完整**（§8），
而它所需的机器在 Built-in 下**已经就位**（`OnRenderImage` + 自写 shader，零依赖、改参数不用重导入资源）。
所以**留在 Built-in**：§3 材质收敛已完成，§8 后处理待补完。

> **给未来的判断标准**：如果哪天需求变成"需要大量实时光追 / 复杂体积光 / 现代 PBR 工作流"，
> 那**才**值得付那 1000 个材质重写的代价。纯粹的"画面风格不好看"不构成换管线的理由 ——
> 那永远是美术方向和后处理的问题。

## 11. 已知的第三方资源问题

刷新时 Console 长期有这些**与本次改动无关**的错误（`FX PACK 1`，特效包自带）：

```
Shader error in 'FX PACK 1/Particles/Trail Additive Turbulence':
  'vert': output parameter 'o' not completely initialized at line 103 (on d3d11)
（另有 Alpha Blended Turbulence / Energy Ball / Additive Turbulence / Distortion）
```

`output parameter not completely initialized` 是 **d3d11 严格性**的经典报错 —— 老资源没给输出结构体
每个字段赋值。**这些特效在当前平台是渲染不出来的**（或异常）。这是"用大量第三方资源"的典型代价：
它们的 shader 未必在新平台/新引擎版本上编译通过。

## 13. 水墨路线A（2026-10-03）：后处理能走多远、缺什么资源

**背景**：需求是"最后有一点点偏向水墨风格的画面"。先做**路线A（全部靠后处理，不动任何模型/贴图资产）**，
确认方向对不对，再决定要不要付路线B（换 URP / 重做美术）的代价。

### 13.1 四步各自的落点

| 步 | 做法 | 落在哪 | 状态 |
|---|---|---|---|
| ① 调色 | 去饱和 + 抬暗部 + 青灰染色 + 抬曝光 | `GameGlobalGrade`（§6.1） | ✅ |
| ② 纸纹 | 屏幕空间纸纤维，**程序化噪声兜底** | `GameGlobalGrade.纸纹`（可填真贴图） | ✅ 占位版 |
| ③ 毛笔化描边 | 近粗远细（提按）+ 飞白断笔 + 远处墨淡 | `GameGlobalOutline` + `OutlineComposite.shader` | ✅ 见 [描边](描边.md) |
| ④ 墨分五色 / 留白 | 亮度压成 N 档墨色；亮部推向"纸色" | `GameGlobalGrade` | ✅ |

### 13.2 新增参数（都在 `GameGlobalGrade` 上）

| 字段 | 默认 | 说明 |
|---|---|---|
| `墨阶数` | 5 | 压成几档墨。0 = 关 |
| `墨阶强度` | 0.35 | 0 = 原样，1 = 硬分层（3D 画面会很假）。**觉得脏就往下调** |
| `留白强度` | 0.25 | 亮部变成纸的量 |
| `纸色` | 0.96/0.95/0.935 | ⚠️ 别用纯白，宣纸是暖白 |
| `留白阈值` | 0.86 | 超过它才算纸。调低会吃掉细节 |
| `纸纹` | 空 | **空 = 用程序化纸纹兜底**（不做"忘填资产就静默失效"的黑盒） |
| `纸纹强度` / `纸纹平铺` | 0.20 / 2.2 | 0.3 以上开始像噪点 |

### 13.3 实测（村庄同机位、冻结画面、相机渲到 RT）

| | 平均亮度 |
|---|---|
| 后处理全关（基线） | 38.8 |
| 水墨全开 | **49.2**（+27%） |

### 13.4 ⚠️ 边界：后处理**不是**水墨，它只解决"墨"和"纸"

现在的观感是"**偏灰青、有纸纹的 3D 画面**"，不是水墨画。差距**不在后处理**，在美术：

| 缺的东西 | 为什么后处理替代不了 |
|---|---|
| 真正的宣纸纹理 | 程序化噪声只有颗粒，没有纸的纤维走向与"云斑" |
| 皴法 / 墨点 / 笔触贴图 | 山的质感是**画上去的**，靠调色永远调不出笔触 |
| 山石/树/建筑的模型与贴图 | 现在是写实 PBR 资产，边缘与结构都是"实物"逻辑 |
| 空气透视 / 留白的构图 | 需要场景层面控制哪些东西**根本不出现**，不是把它调淡 |

⇒ **若要继续推水墨，下一步必须是美术资产，不是继续调参数。** 见 §12 与路线B结论（§1/§10）。
