## 2. 代码在哪

| 文件 | 干什么 |
|---|---|
| `Scripts/Combat/Weapons/BasicFrostSpike01/BasicFrostSpike01.cs` | **新增**。管"播普攻动作 → 40% 节点召冰刺 → 结算" |
| `Data/Tables/功法表.csv` | + 一行（`沧澜寒渊录`，普攻方法 `basic_frostspike_01`） |
| `Data/Tables/物品表.csv` | + 一行（`item_gongfa_canglan_hanyuanlu`，学功法） |

**没有改任何公共代码**：这一份是照 [玄霄雷决与雷动千闪](玄霄雷决与雷动千闪.md) 的普攻（`BasicThunder01`）抄的骨架，**只删掉了闪电链那一整块**（本功法没有蔓延），伤害/缩放/特效摆放全部复用现成的 `AttackSpec` 与 [`特效摆放`](../../cultivation/Assets/Scripts/Combat/特效摆放.cs)。

### 2.1 出手机制跟着**动画**走（和 `basic_thunder_01` 同一套口径）

`Update()` 里 `if (动画.动作进度 >= 出手进度) 召冰刺();` —— 不跟表里的"首次造成伤害时间"。播不上动作（没有 `PlayerAnimationController` / 找不到片段）就**立刻召冰刺**，免得因为动画问题变成哑炮。

★ **必须先用右键锁定**：没锁定就不出手、也不进冷却（和 `BasicRemoteAttack01` / `BasicThunder01` 同一套规矩）。

### 2.2 特效大小随敌人体型缩放

和 `BasicThunder01` 一字不差的算法：`敌人高度 ÷ 基准敌人高度`，夹进 `缩放下限~缩放上限`。敌人高度用 `特效摆放.量高度()` 量（优先碰撞体包围盒，其次渲染体，都取不到用基准值）。

**嫌小/嫌大就调 `基准敌人高度`**：调大 → 冰刺变小；调小 → 冰刺变大。开 `打印战斗日志` 会打出「高的 Xm ÷ 基准 Ym = 缩放 Z」。

### 2.3 特效用【子节点 `spikes-second`】当中心（根节点不在中心上）

用户指出：**`frost-shock` 的根节点不在几何中心**，真正的中心是子节点 `spikes-second`。实测这个 prefab 的层级（相对根的世界位置）：

```text
frost-shock              ← 根（自身 localPos = (−2.753, 0, 3.205)，本来就不在中心）
  spikes-main     y=+0.460   scale=1.2
    spikes-second   y=+0.196  z=−0.220   ← ★ 真正的中心
    rays-second     y=−1.748  z=−1.840   ← 地面射线/闪光，在下方
      rays-main / flash / light / whirls / shockwave …
```

所以 [`特效摆放`](../../cultivation/Assets/Scripts/Combat/特效摆放.cs) 新增了「**按子节点对齐**」：`找子节点()` / `对齐子节点到()`。`BasicFrostSpike01.对齐参考子节点 = "spikes-second"`，生成后把该子节点的世界位置**三维对齐**到锚点（敌人脚下 + `冰刺抬高`）。

**实测偏差**（3C_Testbed 三个练功木桩，运行时量的）：

| 对齐方式 | 与锚点的距离 |
|---|---|
| **子节点 `spikes-second`（现用）** | **0.0000** ✓ |
| 根节点 | 0.196 |
| 旧的「粒子几何中心」（`只对齐水平`） | **0.840 ← 之前就是歪了这么多** |

找不到该子节点时自动退回旧的「粒子几何中心只对齐水平」，并打一条警告。⚠️ 换特效要注意：**同一个 prefab 的根不一定在哪**，新特效要重新量一次中心节点（把名字填进 `对齐参考子节点`）。

### 2.4 特效存活**按 prefab 自然总时长自动算**（别写死短秒数）

用户报：「冰刺特效消失得很突兀，原版好像是慢慢消失的」。原因是 `冰刺特效存活` 曾被写死成 **1.2 秒**，而 `frost-shock` 的自然总时长是 **9.1 秒**：

| 粒子系统 | duration | startLifetime(min~max) | 单个总时长 |
|---|---|---|---|
| `spikes-main` / `spikes-second` | 0.10 | **0.00~9.00** | **9.10** |
| `flash` | 0.10 | 2.00~3.00 | 3.10 |
| `rays-main` / `rays-second` | 0.10 | 1.50~2.00 | 2.10 |
| `whirls` | 1.00 | 0.60~0.70 | 1.70 |
| `shockwave` / `shockwave-additive` | 0.10 | 0.70~1.00 | 0.80 |
| `sparks` | 0.10 | 0.30~2.00 | 0.60 |

→ `spikes-*` 的粒子寿命是 **0~9 秒随机**，所以原版是**慢慢融化消失**；写死 1.2 秒等于把后面 7.9 秒直接切掉。

**修法**：

- [`特效摆放`](../../cultivation/Assets/Scripts/Combat/特效摆放.cs) 新增 **`量特效总时长()`** —— 所有粒子系统取 `startDelay + duration + startLifetime(最大)` 的最大值（各自再除以 `simulationSpeed`）。
- `BasicFrostSpike01` 新增 `存活按特效自动 = true`（默认）、`存活倍率 = 1.05`、`存活上限 = 0`（不封顶）。`冰刺特效存活` 退化成**兜底值**（只有关掉自动、或量不出时长时才用）。

**实测淡出曲线**（单发冰刺，运行时每秒采一次存活粒子数）：

| t | 存活粒子 |
|---|---|
| 1s | 520 |
| 2s | 191 |
| 3s | 95 |
| 4~8s | 91（长寿命余粒，视觉上已经看不见了） |
| 9s | 73 |
| 10s | **0**（对象自然销毁，不再硬切） |

日志里会打「**特效存活 9.56s**」（= 9.1 × 1.05）✓

⚠️ 嫌它虽然看不见、却在地上留到 9.5 秒，就把 `存活上限` 填个 4；**填得比自然时长小会重新出现硬切**，只是没那么突兀。

### 2.5 与 `BasicThunder01` 的两点差异

| | BasicThunder01（玄霄雷决） | BasicFrostSpike01（沧澜寒渊录） |
|---|---|---|
| 目标 | 锁定目标 | 锁定目标（同） |
| 命中后 | 按概率蔓延闪电链 | **没有**（所以也没有"索敌范围"那几个字段） |
| 特效对齐 | 按**粒子几何中心**只对齐水平 | 按**子节点 `spikes-second`** 三维对齐（见 §2.3） |
| 特效旋转 | `lightning-ray` 需绕 X 转 **−90** | `frost-shock` 也是 **−90**（§4 拍图实测） |

改其中一个的时候**建议两边一起看一眼**，别让它们漂移。
