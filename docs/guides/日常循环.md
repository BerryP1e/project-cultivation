## 1. 它是什么

第四阶段的原文要求是「**机制打通 + 每日清单 + 伏笔按天发酵**」：

- **日常循环**：把"一天该做的事"串成一圈（收灵草 / 炼丹 / 打坐 / 进塔），
  把"今天该做什么"记成一份清单（**只做机制，没有常驻 UI**）；
- **两大伏笔**：把"灵田异常灵气 / 镇妖塔妖力共鸣"从**两句说过就完的台词**
  做成**按天 / 按次逐级推进的异象等级**，为后续「灵田异变 / 塔解封」留钩子。

| 文件 | 作用 |
|---|---|
| `Core/日常循环.cs` | 一天**四件事**的状态机 + 跨天刷新 + 位掩码存档 |
| `Core/伏笔管理器.cs` | 两大伏笔的**异象等级 0~3**（起点锚点 / 节奏 / 每级一句台词） |

**挂载**：四个都由 `场景自举.补玩家与相机()` 补到**主相机**上（和 `纪年HUD` / `任务引导` 同一处），
**不写进场景** —— 见 [architecture/系统总览 §2.1](../architecture/系统总览.md)。

## 2. 一天的四件事

```
收灵草 ──── 订阅 `灵田.收获`
炼丹 ────── 订阅 `炼丹炉.炼制完成` 且 `结果.成功`
打坐 ────── 轮询 `时间管理器.今日次数 > 0`
入塔 ────── 轮询 当前场景名 == `塔场景名`（默认 Demon-Suppressing Tower）
```

**为什么前两件用订阅、后两件用轮询**（不是随手写的）：

- 收获 / 炼制**本来就有事件**，订阅最准（**失败的一炉不算**）；
- "打坐"和"进塔"**没有对应事件**，但它们的状态**本来就在别处维护**
  （`时间管理器.今日次数` 每天自己归零、场景名每帧都能问）——
  再引一层事件只会多一处**会断的线**。

**两条硬规矩**：

| 规矩 | 为什么 |
|---|---|
| **订阅要"补齐"**：`Update` 里每帧比对 `灵田.取()` / `炼丹炉.取()`，**换了实例就重订** | 切场景后这两个单例会换成新实例；"`Start` 订阅 + `OnDestroy` 退订"追不上重建（`B` 段那类坑） |
| **跨天只比对 `时间管理器.当前天数` 变没变**，**不订阅 `过了一天`** | 那个事件只在时间推进时发，**读档进来不补发**；比天数两条路都覆盖 |

清单**自己进存档**（`天` + 一个**位掩码**），所以读档回到**同一天**时勾还在；
换了天自然作废（不用清）。`日常循环.项` 枚举：`收灵草=0 / 炼丹=1 / 打坐=2 / 入塔=3`。

`记下(项)` 里两件事：打日志 `[日常] 完成「X」→ n/4`，以及**四件都勾上时**弹一条
`今日事毕 —— <纪年>` 的 Toast。

## 4. 两大伏笔：异象等级（0~3）

| 线 | 起点（对话标记） | 节奏（每级） | 满级 |
|---|---|---|---|
| **灵田异常灵气** | `q_伏笔_灵田异样`（阶段37「灵田的异样」到达洞府） | **每 2 天**一级（第 2 级要第 4 天、第 3 级要第 6 天） | 3 |
| **镇妖塔妖力共鸣** | `q_主线_塔已讲解`（阶段33 师父讲完塔的规矩） | **每进塔 2 次**一级 | 3 |

**为什么塔线的起点不用阶段38**：阶段38「塔中的共鸣」要**炼气五层**、是**长线钩子**，
正常流程很久都碰不到；而伏笔要"**持续发酵**"就得从玩家**开始刷塔**那一刻起有反馈
⇒ 起点放在"塔的规矩讲完"（阶段33），**阶段38 的台词改成这条线的"正式揭示"**
（一条是机制、一条是剧情，两边不冲突）。

**为什么要"起点天 / 起点次数"两个锚点**：等级**不能只按"天数 % N"算** ——
那样玩家在阶段37 之前攒的天数会**一次性追补成满级**（一进洞府就三级异象）。
锚点让"发酵"从**拿到标记的那一天**开始数。

**每级一句台词**（口吻是"主角心里咯噔一下"，不是说明文）：

| 级 | 灵田线 | 塔线 |
|---|---|---|
| 1 | 土里的灵气比昨天活泛了些……是错觉吗。 | 塔身偶尔震一下，很轻，像有什么在里头翻身。 |
| 2 | 叶尖泛着不该有的光，掐下来看又什么都没有。 | 那股妖力开始应和你的脚步，一进塔就压得胸口发闷。 |
| 3 | 夜里经过，田垄底下像是有什么在呼吸。 | 共鸣越来越清楚 —— 塔里封着的东西，认得你。 |

升级时：打一条 `[伏笔] … → N 级：<台词>` 的日志 + 弹一条 **3.2 秒**的 Toast + 广播 `变化`。

## 6. 存档（**版本 14**）

| 项 | 值 |
|---|---|
| 存档版本 | `SaveData.当前版本` **13 → 14** |
| 新字段 | `日常_天`（int，勾的是哪一天；**-1 = 还没勾过**）、`日常_掩码`（int，按 `日常循环.项` 的位存）、`伏笔_灵田`、`伏笔_塔`（各 0~3） |
| 恢复 | `SaveSystem.应用到角色` 里：`日常循环.取().导入(数据.是空的 ? -1 : 数据.日常_天, 数据.是空的 ? 0 : 数据.日常_掩码)`；`伏笔管理器.取().导入(数据.是空的 ? 0 : …, …)` |
| 采集 | `日常循环.导出(out 天, out 掩码)` / `伏笔管理器.导出(out 田, out 塔)` |
| ⚠️ 迁移口径 | **四个都是加法字段、不做版本门槛** —— 老档读出来是 `天 = -1` / `掩码 = 0` / 两条伏笔 `0` 级，正好等于"今天还没做事、伏笔还没开始发酵" |

详见 [design/存档系统 §3](../design/存档系统.md)。

**实测**（洞府）：

```
打坐   `加日常机会(1)` → `消耗一次修炼()` = True   ⇒ [日常] 完成「打坐修炼一次」→ 1/4
收灵草 放一块田 → 种生灵草 → 推进生长(99) → 收一块（收获 ×3）⇒ [日常] 完成「收一次灵草」→ 2/4
入塔   把 `塔场景名` 临时改成当前场景名           ⇒ 立刻勾上（轮询判据有效）
跨天   `推进(4.2)`                                ⇒ 两条"新的一天"日志、清单自动清空
伏笔   打上 `q_伏笔_灵田异样` + 推进 4.2 天        ⇒ 1 级（2 天）→ 2 级（第 4 天），两级台词都进日志
```

## 8. 坑与遗留

### 8.1 ⚠️ `SerializedObject` 按中文名找属性找不到 —— 要**逐项对拷**

做师傅独立 prefab 时要把原变体的字段一个个抄过去。用
`SerializedObject.FindProperty("定义")`（**中文属性名**）去取，**拿不到**：
`定义` 被**静默抄成基底的值**、`显示名` 抄成**空串**；而 `m_Center` 这类 **ASCII 名却正常**
—— "部分抄对"极具迷惑性。

**正解**：两个 `SerializedObject` 各取一个迭代器，
`while (itS.NextVisible(true))` + `itD.NextVisible(true)` **逐项对拷**，
**只比对 `propertyPath` 是否一致**，**永不按名字查**。详见 [踩坑总库 B88](../ai/踩坑总库.md)。

### 8.2 ⚠️ 右上角会挤：`ToastUI` 与 `纪年HUD` 都在右上角

`纪年HUD` 顶边距 **18**，`ToastUI` 原来是 **24** ⇒ 实测"新的一天"和
`太虚历 X 年 Y 月 Z 日 · 时辰` **糊在同一行**。修法：`ToastUI.顶边距` 默认值 24 → **104**
（= 18 + 纪年两行约 70 + 余量）。**改脚本默认值就能全局生效**，因为 `提示()` 里是
`AddComponent` **现建**提示条、位置只来自默认值（场景/prefab 里没有第二份）。详见 B89。
