# 雷云（被动神通）

> 2026-09-28 新增。地品被动神通，`ability_leiyun`。

---

## 1. 效果（策划说明）

```
装备该被动神通后**持续消耗灵力**
在角色身边生成一朵雷云（特效 lightning-cloud）
当角色**锁定目标**时，雷云每隔一段时间召唤闪电
  · 那道闪电的特效**暂时空置**（⚠ 见下）：
    一端是**锁定目标**、一端是**雷云**
  · 然后在敌人那里生成受击特效 lightning-arc-flash
  · 受击特效的大小取决于**敌人尺寸**
  · 敌人受到【特殊 + 被动神通】伤害
```

> ⚠️ **雷云那道闪电的特效现在空置待补**（用户 2026-09-28 决定，我自制的 `雷链` 表现不合格已删）。
> `LeiYun.闪电特效路径 = ""` → **雷云照样出手、照样掉血，只是看不到那道落雷**。
> 接了特效照 [闪电链特效](闪电链特效.md) 填路径并重新标定。
> （雷云本体 `lightning-cloud` 和受击特效 `lightning-arc-flash` 都是资源包原生件，**保留**。）

## 2. 和【千劫雷狱】的区别（容易混）

|  | 千劫雷狱 | **雷云** |
|---|---|---|
| 触发条件 | 敌人进入**范围**就自动挨打 | **锁定了目标**才劈 |
| 表现 | 脚下常驻雷罚 + 一圈黑环 | 头顶一朵云 + 一道线连到目标 |
| 伤害 | 特殊 + 被动神通 | **特殊 + 被动神通**（同一套加成） |
| 范围来源 | 神识范围（黑圈大小） | `最大距离`（锁定目标太远就不劈） |

两者可以**同时启用**（各自独立扣灵）。

## 3. 三个特效

| 部位 | 资源 | 缩放依据 |
|---|---|---|
| 雷云 | `lightning-cloud` | `雷云缩放`（固定值）+ `雷云偏移` 挪到头顶 |
| 闪电 | **⚠️ 空置待补**（`闪电特效路径 = ""`） | 接上后：**拉伸**，三维距离 ÷ `闪电基准长度`（和闪电链同一套） |
| 受击 | `lightning-arc-flash` | **敌人模型高度** ÷ `受击基准敌人高度` |

### 3.1 闪电走「拉伸链」这个共用工具

`LeiYun.生成闪电()` 调 `特效摆放.生成拉伸链()` ——
它和玄霄雷决的闪电链**用的是同一套代码**（原来是 `BasicThunder01` 里的私有实现，
2026-09-28 抽到 `特效摆放` 共用）。
**路径为空时 `生成拉伸链` 直接返回 null（不打警告）**，所以现在不会报错、也不会有闪电。

拉伸逻辑（`特效摆放.生成拉伸链`）：

```
1. 让特效的「长度轴」指向终点：LookRotation(终点 − 起点) 再按长度轴补一个旋转
2. 该轴 localScale = max(三维距离 − 长度补偿, 最小长度) ÷ 基准长度
3. 另外两根轴 = 粗细
```

⚠️ **长度轴不是固定的**，必须按 prefab 自动探测（`探测长度轴`）；
探不出来才用 `闪电兜底拉伸轴`。

⚠️ 接新特效时 prefab 有**两条硬要求**：`scalingMode = Hierarchy`（`Shape` 会把 `localScale`
作用两次）+ `renderMode = Billboard`（`Stretch` 在速度≈0 的粒子上几乎完全看不见），
而且 `基准长度`/`长度补偿` 要**用 `GetParticles` 重新量**（别信 `renderer.bounds`）。
**全部细节见 [闪电链特效](闪电链特效.md)**。

⚠️ **必须用三维距离**：雷云的雷是从 +3.5m 的云上斜劈下来的，
早期只算水平距离，实测链的两端各差 ~1.35m，够不着目标。现已修。

### 3.2 闪电连到敌人**中部**，不是脚下

和闪电链一个口径：`敌中点 = 敌人根 + up × (敌人高度 × 0.5)`，
免得线贴地穿模。雷云那一端用 `云位置`（云的**实际**世界坐标，即插值后的位置）。

### 3.3 云跟着角色（**插值拖尾**，2026-09-28 改）

> 用户原话：「雷云跟随在角色旁边，感觉卡的太死了，能否让它有一种比如插值旋转，
> 主角移动后跟随的感觉，而不是卡死在主角旁边」。

以前 `维护云()` 是每帧 `云.position = 角色 + 雷云偏移` —— **硬贴**，所以看着"卡死"。
现在走 `Vector3.SmoothDamp` **插值跟随**：角色一动，云先拖在后面、再慢慢追上来，
停下后自己归位。朝向也用 `Quaternion.RotateTowards` 插值。

| 字段 | 默认 | 说明 |
|---|---|---|
| `跟随用插值` | `true` | 关掉就回到老行为（硬贴），可以用来对比手感 |
| `跟随平滑时间` | `0.35` | 越大越"懒"、拖得越明显 |
| `跟随最大速度` | `14` | 追上去的速度上限（米/秒），0 = 不限制 |
| `跟随瞬移距离` | `20` | 角色瞬移（传送/复活/上坐骑）时超过这个距离就**直接跟上**，免得拖一条长尾巴；0 = 永远插值 |
| `朝向插值速度` | `240` | 度/秒，只在 `雷云跟随朝向` 打开时有用 |

**调参规律（实测确认）**：角色匀速跑时，
```
稳定落后距离 ≈ 角色移动速度 × 跟随平滑时间
```
实测（假角色 6 m/s、平滑时间 0.35s、跑满 3s 进入稳态）：
**滞后 2.09m vs 理论 6 × 0.35 = 2.10m** ✓。
所以**默认 0.35 在角色 6 m/s 时大约拖后 2m**；想更明显就把 `跟随平滑时间` 往 0.5~0.8 调。
停下后大约 **1 秒**内归位（实测等 2s 只剩 0.11m）。
瞬移 60m 后 2 帧内就跟上了（阈值 20m）✓。

> ⚠️ `云位置` 用的是**插值后的真实位置**，所以闪电也是从拖在后面的那朵云发出来的 —— 这是想要的效果。
>
> ⚠️ **探针注意**：想测"角色跑起来云拖多少"时，**别用 `玩家.transform.position += …` 推角色** ——
> `PlayerController` 每帧会按输入重算位置把它覆盖掉（实测我推了 2.14m，角色只走了 0.67m，
> 于是滞后量全测错）。用一个"没人管"的假角色来测，或者直接读角色的**真实**位移算速度。

## 5. ⚠️ 待定：耗灵 2/s **低于**玩家回灵 4/s

玩家默认 `AttributeType.SpiritRegen = 4/s`，而本被动只扣 2/s → **灵力一直满着**，
"持续消耗灵力"实际上没有代价。**千劫雷狱（3/s）也是同一个问题。**

要真有消耗压力，`维持消耗灵力` 得提到 **> 4**（建议 6~8）。
数值待策划定。
