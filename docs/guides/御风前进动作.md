# 御风前进动作

> **管什么**：舒展滑行循环的制作、骑乘共用、持械兼容与复验。
> **不管什么**：高度与骑乘控制见 [坐骑与御风](../architecture/坐骑与御风.md)；近战攻击见 [八九玄功](八九玄功.md)；跨动作右臂反扭见 [外观系统说明](外观系统说明.md) §0。
> **本文件怎么查**：§1 当前动作｜§2 重建｜§3 实测与预览。
> **来源**：用户2026-10-05提出仙人御风前进的飘逸感；YufengGlideBaker与隔离模型Play取样。

## 1. 当前动作

普通前进不再保持一张斜身姿势：3.2秒循环、整体约7°轻前倾，双臂自然后展，双腿错落；肩、手腕、膝盖、脚尖依次延迟跟随，避免跑步式的交替抬腿。动作是原创肌肉曲线，参考用户提出的立身漂浮感；尚未按指定角色的视频逐帧复刻。

前进片段仍为`Assets/Animations/凭虚御风/御风_前进.anim`，名称和GUID不改。PlayerLocomotion的Yufeng_Forward继续引用它；MountRider前进时通过设置外部御风与FlyMoving共用同一状态，无须为坐骑另存场景。

八九玄功前进保留杨戬持械上身，根旋转与腿脚采用新循环。握持上身曲线保持常量，避免左手再次抬起放下。保持持械片段原根高度，不给整个角色叠加上下位移。

## 2. 重建

停止Play，菜单 **修仙 / 动画 / 制作飘逸御风前进（不动场景）**。

工具在`Assets/Editor/Tools/YufengGlideBaker.cs`，仅更新普通与持械两个前进片段，以悬停片段作为稳定肌肉基准。CopySerialized保留GUID；循环首尾的值与切线匹配，根X/Y/Z保持固定，位移和高度仍由游戏控制。

不要为了换动作重跑角色或场景生成器。旧“生成凭虚御风动画片段”会重新生成四个旧片段；如果以后确实使用旧工具或重建八九玄功13片段，应最后运行本工具恢复这套前进循环。

## 3. 实测与预览

`.dsh/_diag/yufeng-glide-check.cs.txt`克隆外观模型、禁用克隆业务组件，按61个相位播放普通/持械前进、悬停、原始待机、稳定跑步、持械站姿、长刀女Attack1和杨戬Attack1，共8种状态；不改真实玩家的功法、御风开关或坐骑。两种视角四相位图与60帧动图源保存到`cultivation/screenshots/`，不入库。

|---|---|---|
| 首尾肌肉误差 | 0 | 0 |

普通旧版侧倾跨度为0，姿势几乎不变；新版的变化集中在舒展和肢体跟随。当前外观没有新增布料物理，飘逸感由骨骼姿态呈现。

预览：`cultivation/screenshots/yufeng-glide-preview.gif`；对照图：`yufeng-glide-before-default.png`、`yufeng-glide-after-default.png`；持械同目录以weapon结尾。

右臂复查发现跨动作变形的共同原因是换外观时沿用错误bindposes，不是各片段都写反手骨。修正见AppearanceMeshBinding；8种状态的修后截图同目录以after开头。新前进动作同时采用原始待机的手臂轴向基准，保持舒展后掠。`.dsh/_diag/appearance-binding-check.cs.txt`验证两件外观双向兼容：绑定矩阵误差0、顶点变化0、源资产变化0，实际玩家BakeMesh无NaN/Infinity。上述截图只检查动画与蒙皮，没有在隔离模型上执行真实攻击伤害或传送。
