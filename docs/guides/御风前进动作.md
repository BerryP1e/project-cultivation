# 御风待机与八方向移动

> **管什么**：Flying Mage 御风待机、八方向移动、锁定朝向、持械兼容、三种神通施法与复验。
> **不管什么**：高度与骑乘控制见 [坐骑与御风](../architecture/坐骑与御风.md)；近战攻击见 [八九玄功](八九玄功.md)；跨动作右臂反扭见 [外观系统说明](外观系统说明.md) §0。
> **本文件怎么查**：§1 当前动作｜§2 重建｜§3 实测与预览。
> **来源**：用户2026-10-09导入 Flying_Mage_Volume2，先强化idle/move和持械，随后指定水龙炮、冰暴术、瞬雷天闪的御风动作与出手节点。

## 1. 当前动作

素材来自 `Assets/resources/Animation Library/Flying_Mage_Volume2/Animations/Humanoid/Inplace/`：`idle_Flying_inplace`（2秒）和 `move_Flying_*_inplace`（各1.333秒）。移动采用前、右前45°、右、右后45°、后、左后45°、左、左前45°八段原地动作。源文件已有有效 Humanoid Avatar，保留全身八向运动；腕指和持械右臂按下述规则单独校准。

派生片段放在 `Assets/Animations/凭虚御风/八向御风/`，名称统一为 `御风八向_悬停/前/右前/右/右后/后/左后/左/左前`。保留源Humanoid的+Z正面，不额外旋转RootQ/RootT；根高度以原御风基准0.946归一化，保留原动作的轻微浮动和各方向倾身。各游玩场景实际序列化的 `visualYawOffset=0`，代码默认值也已对齐为0。角色位移与对地飞行高度仍由 PlayerController/YufengFlight 管理，`applyRootMotion=false`。

PlayerLocomotion 保留 `Yufeng_Idle` 与 `Yufeng_Forward` 状态名及原有 Action 返回路径；前者用新悬停，后者用 `御风八向.asset` 的2D Freeform Directional混合树（中心悬停+八个单位方向）。`FlyX/FlyY` 根据经过加减速的世界水平速度、玩家视觉朝向与飞行满速计算，方向平滑0.10秒，待机/移动状态间过渡0.18秒。速度较低时向中心悬停混合，反向时不会瞬间切姿势。

御风锁定或选中目标时，移动保持正面朝向目标；地面与坐骑仍沿用现有朝向插值。PlayerAnimationController 在移动和战斗组件后更新（execution order 50），兼容施法控制器包装；旧自定义控制器没有 FlyX/FlyY 时不写缺失参数。MountRider 保留原外部御风接口，骑乘满速按坐骑速度归一化。

八九玄功、太虚剑决、灵虚剑决的三套变体放在 `Assets/resources/技能动作/御风八向/<功法>/`。`YufengHandPoseBaker` 以60Hz重做双手40条手指曲线：各指三个关节有不同的自然屈曲量，自由手有轻微循环变化；八九/太虚右手采用持柄屈指，避免原动作的过度张开和末节极限钩曲。自由手腕减少侧折幅度。

八九玄功另在实际玩家Avatar上，以 `持刀_站` 的上臂、前臂、手腕整体方向作为御风持刀参考，刀刃保持地面时的斜向下姿态，不靠强扭单个手腕或改挂载角度补偿。只写右臂腕肌肉与必要的根重心补偿，躯干、左臂和腿部保留原八向动作。

灵虚剑御风时双手放松，独立剑按状态收放：待机回到身后，普通移动时移至脚下；战斗待机和边移动边战斗均保持后方。脚下姿态以网格+Z为剑尖方向，九段动作均烘焙剑尖朝人物正面、双脚下方居中的10条TRS曲线，随脚部浮动。最下方脚骨到剑身最高处的间隙约0.073米（模型缩放1时，正式玩家约0.132米），留出鞋底空间。

武器prefab上的 `LingxuFlightSword` 在Animator后只插值独立剑节点，收放0.3秒。脚下姿态依据本帧实际混合后的双脚重算，不拿上一帧被改写的Transform反复插值，避免常量曲线缓存/方向混合造成位置累积和穿鞋底。后方偏移、朝向和比例由烘焙器从地面Ready起始姿态相对髋骨标定；有效锁定目标、选中敌对目标或出招后1.2秒内视为战斗，连续出招间不反复回脚下。攻击及其Animator进出过渡期间完全交还原Prop1轨迹；不覆盖剑的攻击判定路径。地面和升降过渡仍使用原动画。`LingxuSwordAssets` 重建武器时也重新附加和标定该组件，避免重建丢失行为。WeaponCarryAnim 按片段名覆盖九段动作。

待机/移动改造保留既有升空、落地、普攻和源FBX；随后新增的三种御风神通见§6。旧 `御风_Idle/御风_前进` 资产留作历史工具依赖，当前控制器不再引用它们。

## 2. 重建

停止Play，菜单 **修仙 / 动画 / 重建八向御风（不动场景）**。

工具 `Assets/Editor/Tools/YufengDirectionalBaker.cs` 生成9段基础片段、27段持械变体与混合树，调用 `YufengHandPoseBaker.cs` 校准手部，再只替换现有控制器的待机/移动motion；保留攻击返回、升空与落地的状态和过渡。重复烘焙用CopySerialized保留GUID，高度基准固定，不累加补偿，不保存场景。所有校准均使用玩家FBX的Avatar，不依赖当前打开哪张场景；运行时不额外增加IK或手骨覆盖，仅灵虚独立剑按状态平滑收放。

不要为了换动作重跑角色或场景生成器。旧 YufengGlideBaker 仅维护旧的3.2秒单方向动作，已不是本轮构建入口。YufengAnimatorBuilder 在重建御风四态时会重新接入已存在的八向资源；日常更新应使用上述专用烘焙菜单，避免清除再重建状态对其他工具的引用造成影响。

补充验证 `.dsh/_diag/flight8-edges.cs.txt`：五种世界朝向×前后左右共20组映射正确；连续旋转混合348帧无非法权重或权重丢失；坐骑借用的外部御风接口在移动、悬停和落地清参时均通过。所有启用的游玩场景通过AssetDatabase依赖检查引用同一PlayerLocomotion；7张场景文件哈希均未改变，最终停在Sect编辑模式且场景未脏。编译0错误，保留11条已有警告。

外观蒙皮继续使用 AppearanceMeshBinding 的目标骨架绑定矩阵；不要为新动作改写共享模型bindposes，背景见 [外观系统说明](外观系统说明.md)。

手部近景/持刀地面对照为 `.dsh/_diag/flight-hands-inspect.cs.txt`，预览用BakeMesh避免同帧GPU蒙皮缓存；图片和测试脚本不入库。当前手部实机回归为 `.dsh/_diag/flight-hands-runtime.cs.txt`，在原32组方向检查中增加实际挂载武器、持刀角差和脚下剑朝向/间隙断言。

## 4. 朝向基准修正

首版误用 PlayerController 旧代码默认90°和未动画模型的−X正面，对所有新片段额外烘焙−90°；实际所有游玩场景早已配置为0°，导致视觉侧对目标。修复时从源重新生成36段片段，移除这次额外左旋（相对首版统一右转90°），灵虚剑轨迹同步重烘焙。不能只改混合树参数轴，否则模型的侧身偏差仍存在。

验收补充使用真实场景补偿和 Avatar 中性头部轴：四套悬停×四个世界朝向共16组，实际头部正面相对目标约0.942°，保留源动作的自然侧身；前、后、左、右倾身判据改为玩家+Z正面的坐标系。上节首版参数/权重测试没有检查视觉正面，不能用来证明朝向正确；当前 `YufengDirectionalChecks` 已包含该检查。修正后重新执行32组锁定移动及停下/攻击返回/落地回归，全部通过。

## 6. 全状态神通施法

`DivineCastingBaker` 菜单 **修仙 / 动画 / 重建神通施法（不动场景）** 从Humanoid原FBX生成 `Assets/resources/技能动作/神通施法/水龙炮_施法.anim`（Attack02，1.6秒）和 `追踪弹_施法.anim`（Attack01_short，3.166667秒）。两者非循环，保留全身源动作/朝向，根高度以同一御风0.946基准归一化，双手保留源动作腕指曲线及关节限位，不改源文件。

水龙炮43%左手出水，引导期间定住；出水结束后解开姿势，继续播放剩余收招，粒子停止发射并以0.65秒渐淡。冰暴术和瞬雷天闪起手就在右手生成球，0～50%按动画进度平滑放大，58%飞出，动作不中途暂停。球/光束的挂点在动画补偿后的LateUpdate读取，避免慢一帧；`PlayerAnimationController`动作占用阻止自动普攻/其他神通覆盖施法，收招或中断后释放。

地面、御风、骑乘均使用上述新片段和相同时序。小剑阵仍沿用原接线。详细行为见 [水龙炮](水龙炮.md)、[瞬雷天闪](瞬雷天闪.md)、[冰暴术](冰暴术.md)。2026-10-09全状态实机检查 `.dsh/_diag/all-state-casts-runtime.cs.txt`：地面、御风、实际碧水兽骑乘各施放三术，共9次，覆盖动画节点、左右手挂点、凝聚/尾散、追踪伤害、命中特效、自然收招及角色根高度；全部通过，无运行错误。腕指实际骨骼检查为 `.dsh/_diag/casting-hands-check.cs.txt`。临时脚本、报告和预览不入库。

施法烘焙使用 `HandMotionRetargeting` 保留源动作逐帧的腕指曲线及关节限位，不再使用待机的固定屈指/缩腕规则。源Avatar和玩家Avatar均包含双手手腕与30根手指骨；在玩家骨架上对每段动作采样61帧，32根关节全部实际运动，局部旋转与限位后的源动作最大角差为0°。

补充 `.dsh/_diag/flight-casts-edges.cs.txt` 已通过无锁定手动落点、未放飞时打断/禁用清球、手动58%放飞与收招、占用时拒绝施法不扣灵力、水炮前摇打断、施法者停用后柔和尾散/释放及无残留执行体。验证停用时需先隔离`主动神通开关`，它会按装备槽每帧重新启用施放器；这是测试夹具需处理的既有行为。两组实机回归均无运行错误。

场景接线复查 `.dsh/_diag/flying-cast-scenes-audit.cs.txt`：启用的6个游玩场景（3C_Testbed、Village、Sect、Demon-Suppressing Tower、village、Sect_Wilderness）均具备相同ActiveSkillCaster、PlayerAnimationController、YufengFlight和有效玩家Humanoid Avatar，引用同一PlayerLocomotion控制器，visualYawOffset均为0；开始场景无玩家。两个共享施法片段通过共享Resources路径加载，场景无需单独复制/覆盖片段。预览方式只读检查、不保存场景，无运行错误。本轮三术已统一全状态，不再按御风选择不同施法动作。
