## 2. 功法：玄霄雷决（`gongfa_xuanxiao_leijue`）

- 学习物品：`item_gongfa_xuanxiao_leijue`（**玄霄雷决 秘籍**），效果 `学功法`
- 提供的普攻：`basic_thunder_01` → 组件 `BasicThunder01`
  （在 `PlayerAbilityLoader.普攻方法表` 里登记，**5 个场景都要登记** —— 这个表是逐场景序列化的）

### 2.1 普攻：对**锁定目标**召雷下劈 + 概率闪电链

- **必须先右键锁定一个目标**（曾误做成"自动挑周边最近的敌人"，已改）
- 在动画的 **40%** 节点 → 对**锁定的那个敌人**召一道闪电（`lightning-ray`）
  - 没锁定就完全不出手（也不会进冷却）
  - 特效有最小体型，但会**随敌人大小**等比缩放
  - 造成**特殊 + 普通攻击**伤害；攻速影响冷却，和太虚炼气诀同一套换算
- 命中后**有小概率**生成闪电链（这里是"找周边的人"，不是开局就自动选目标）
  - 链到**周围某个敌人**，特效按两者距离**拉伸**
  - 被链中的敌人有命中特效（`lightning-arc-flash`）
  - 同样有概率继续生成下一条链，去找周边的人
  - 链的大小也随敌人体型变化

### 2.2 实现要点（`BasicThunder01.cs`）

| 点 | 做法 |
|---|---|
| **锁定门槛** | 照抄 `BasicRemoteAttack01`：`锁定单位` 从 `NpcTargeting.LockedNpc` 取（死了当没锁）+ `NpcTarget` 适配器缓存；`可以出手` 里要求 `锁定单位 != null` |
| 出手时机 | 照抄 `BasicRemoteAttack01`：`动画.动作进度 >= 出手进度`（默认 0.4） |
| 闪电链找目标 | `Physics.OverlapSphere` + `GetComponentInParent<NpcInstance>`；同 NPC 多碰撞体按实例去重 |
| 按体型缩放 | 量敌人的**碰撞体包围盒高度**（没有就退渲染体），`高度 ÷ 基准敌人高度(1.8)`，夹进 0.6~2.5 |
| ⚠️ **特效为什么以前放不大** | 旧 prefab 的 12 个部件全是 `scalingMode = Shape` —— 缩放只拉开部件间距、**不放大粒子**。实测：`Shape` 下 localScale 1→4 粒子世界高度 3.56→3.62（没变）；`Hierarchy` 下 4 倍时到 14.18。所以 `生成雷()` 里加了 `开等比缩放()` 统一改成 `Hierarchy`（新特效本来就是 `Hierarchy`，这条是保险） |
| 闪电链不回头 | `已访问` 集合**整条链共享**（不能只排除上一个，否则 A→B→A 来回弹到跳数上限） |
| 链的拉伸 | ⚠️ **拉伸轴不是固定的**：运行时按 prefab 的 shape 自动探测最长的那根轴，探不出来才用字段配的 `闪电链拉伸轴`。**特效槽现在空置**，接了新特效要重新标定 |
| 链长 | `拉伸 = max(三维距离 − 闪电链长度补偿, 最小长度) ÷ 闪电链基准长度`。这两个数**换特效必须重新量**（别信 `renderer.bounds`，见 [闪电链特效](闪电链特效.md) §4） |
| ⚠️ prefab 两条硬要求 | `scalingMode = **Hierarchy**`（`Shape` 会把 localScale 作用两次，链糊成一团）+ `renderMode = **Billboard**`（`Stretch` 在速度≈0 的粒子上几乎完全看不见）。**原理见 [闪电链特效](闪电链特效.md)** |
| 链的基准长度 | `闪电链基准长度` 默认 **2**（对应 `Box scale=2.0`）；拉伸系数 = 两敌距离 ÷ 基准长度 |
| 链从**中部**发出 | 两端各自按**自己那个敌人的半高**抬高（`取敌人高度() × 0.5`），不再用固定的「基准敌人高度 × 0.5」——矮目标上以前会贴地 |
| **下劈雷的朝向** | 旧特效必须转 270°；**新特效 `lightning-ray` 是独立的射线特效，朝向按 `雷特效旋转` 调**（默认不转） |

`基础索敌范围 / 每点神识范围 / 索敌范围上限`（=> `索敌半径`）现在**只用于闪电链的搜索起点距离**，下劈的雷不再用它（它劈的是锁定目标）。⚠️ **能不能锁上这个目标，不归雷决管** —— 右键索敌的射程由 `NpcTargeting` 统一按**神识范围**（`4 + 神识×0.8`，上限 40）判定，所有武器共用一条规则（见 [交互系统](../design/交互系统.md)）；雷决的 `索敌半径`（3.5+神识×0.55，上限 18）**不再是**它能打多远的上限。调试开关：`打印战斗日志` 关掉可以静音；`闪电链概率` 调成 1 能稳定复现全链路。

### 2.4 旧特效 `Electro_Strike_01` 的四个症状（下次接"按固定机位做的 2D 特效包"时对照）

| 症状 | 真因 | 结论 / 修法 |
|---|---|---|
| ① 整个特效"零件散了"（雷横躺） | 12 个部件全部沿本地 +Z 轴排开（z 从 0 到 1.42）：**z=0 那端是【雷柱尖】**、**+Z 那端是【雷球】**（`p2_glow_01/glow_r01`，z≈1.34~1.42）；用 `Quaternion.identity` 生成 → 横躺 | 装特效前先搞清哪一端是"底"，再定旋转 |
| ② 改完埋进地下 / 方向来回翻 | `ParticleSystemRenderer.bounds` 会把粒子体积算进去（`startSize` 到 3.0），把只有 1.4m 的真实部件偏移糊掉 → 连续两轮改错方向 | **判断"部件 A 在 B 上方还是下方"要量 `transform.position`**，不要用 `bounds` |
| ③ 改 prefab 的 scale，只有部件间距变大 | 12 个部件全是 `main.scalingMode = Shape`：scale **只作用于粒子的发射形状（shape）**，只拉开部件间距、**单粒子尺寸完全不变** | `BasicThunder01.开等比缩放()` 生成后统一改成 `Hierarchy` |
| ④ 场景视图正常、游戏相机里歪斜（压垮它的最后一根稻草） | 12 个部件全是 `renderMode = Billboard, alignment = View`（粒子永远正对相机），本质是一叠 2D 贴图：正面看笔直居中，游戏相机 `pitch 50° / yaw 45°` 俯视时同一张贴图被**斜着投影** → 看着歪斜。**部件位置其实完全对齐**（实测 Δx = Δz = 0.00），不是位置错 | 这类"按固定机位做的 2D 特效包"在 50° 俯视下必然如此、无解 → **换特效** |

① 实测各部件相对锚点(y=0)的高度（scale 1.5，用 `transform.position` 量）：

| 旋转 | 雷球 `p2_glow` | 雷柱 `p7_Lt` | 特效占据 |
|---|---|---|---|
| `270,0,0` | +2.01 | +2.06 | y 0 ~ +2.13 |
| `90,0,0` | −2.01 | −2.06 | y 0 ~ −2.13 |
| `0` / `180` | ±2.14 | ±2.06 | 横躺，水平偏移 ~1.9m |

③ 实测（`p2_glow_01` 世界高度）：

```text
scalingMode = Shape      localScale 1 → 3.56 ｜ 2 → 3.58 ｜ 4 → 3.62   ✗ 基本不变
scalingMode = Hierarchy  localScale 4 → 14.18                          ✅ 等比放大
```
### 2.5 新特效 `lightning-ray` 的旋转 / 竖直 / 水平对齐

**（a）旋转：`雷特效旋转欧拉 = (-90, 0, 0)`** —— 三个值都试过才对：

```text
0    = 躺平（横着）
+90  = 倒过来
−90  = 正确 ★   （−90 与 270 是同一角度，日志会打印成 (270,0,0)）
```

**（b）竖直：不做任何自动重定位**，特效就生成在 `目标.根.position`（根部）。试过的两种"聪明"对齐都是错的，都会把效果挪到"中部"：

| 做法 | 结果 |
|---|---|
| 按"最低部件贴地" | 地面效果反而浮到锚点上方 ✗ |
| 按"几何中心对齐" | 整体被抬到目标中部 ✗ ← 用户骂的就是这个 |
| **竖直放锚点、只修水平** | ✅ **正确** |

**"中部"是闪电链的规则，不是下劈雷的**：闪电链两端按各自敌人的半高抬高（见 §2.2「链从**中部**发出」），下劈雷必须贴根部。⚠️ **改动前先读清用户说的是哪一件事**：曾把"对齐错了"误读成"旋转也错了"，顺手把已经正确的 −90 改成 +90，白折腾一轮。**用户只指出 A 有问题时，不要顺带改 B。**

**（c）水平（XZ）**：仍按**部件中心对齐**到目标正上方。因为 prefab 的部件常常整体偏出去（实测 `lightning-impact` 偏 1.68m），不修会横着错开目标。

实现（`BasicThunder01.把底部对齐地面()`，只动 XZ、Y 一律保持）：

```csharp
t.position = new Vector3(
    t.position.x + (锚点.x - 范围.center.x),
    t.position.y,                                  // ★ Y 不动
    t.position.z + (锚点.z - 范围.center.z));
```

⚠️ **量范围时不能只量"根级"部件、也不能跳过子发射器。** 这个 prefab 的层级是**层层嵌套**的：`ground-dust → ground-pebbles → ground-flashes → lightning-ray`，真正的雷柱在最深处，加过滤就会漏掉它（第一版就踩了）。

**实测（最终版）**：

```text
玄霄雷决普攻   目标根部 (−3.68, 0, 1.21)   rot=(90,0,0)
               实例根 = (−3.68, 0.00, 1.17)  → 竖直对齐根部 ✓、水平居中 ✓
               部件相对根部：lightning-ray Δy=+1.24（雷柱朝上）
                             ground-*      Δy=−0.38（地面爆点在脚下）
```

**雷动千闪的两个特效**用同一口径（`BlinkSkillRunner.把底部对齐()`）：水平按中心对齐、竖直就放锚点。想微调整体上下用 `雷抬高`（普攻）或 `特效抬高`（闪烁）。

### 2.6 播放速度与缩放

**`雷特效速度 = 2`（两倍速）**：做法是 `main.simulationSpeed = 雷特效速度`（`BasicThunder01.开播放速度()`），把粒子的**发射节奏、生命周期、速度**一起乘上倍率 —— 真正的"整个特效加速"。

> ⚠️ **不要**去逐个改 `duration` / `startLifetime` / `startSpeed`：这个 prefab 有 7 个嵌套部件，漏改一个就不同步，而且子发射器的时机也会错。

**存活时间要跟着缩短**：`雷特效存活` 是**真实时间**，加速后如果还按原值销毁，特效早就播完了还挂一段空等；`存活随速度缩短`（默认开）会自动算 `存活 ÷ 速度`。实测：`7 个部件 simulationSpeed 全部 = 2.00 ✓`、`存活 1.2s ÷ 2 = 0.60s → 实测 0.52s 自行消失 ✓`。

**缩放** = `敌人高度 ÷ 基准敌人高度`，再夹进 `缩放下限 ~ 缩放上限`。木桩实测高 **1.6m**：`基准 1.8 → 缩放 0.89`、`基准 1.0 → 1.60`。开 `打印战斗日志` 会打出「缩放 0.89 = 高的 1.6m ÷ 基准 1.8m」，照着调 `基准敌人高度`。

### 2.7 雷特效存活：别写死

用户报「玄霄雷劫的普攻使用的特效好像也有提前消失的问题」。量了 `lightning-ray` 的自然总时长是 **4.50 秒**：

| 粒子系统 | duration | startDelay | startLifetime | 单个总时长 |
|---|---|---|---|---|
| `ground-dust` | 2.00 | 0.50 | 0.00~2.00 | **4.50** |
| `ground-pebbles` | 2.00 | 0.50 | 0.00~1.50 | 4.00 |
| `lightning-ray` / `lightning-glow` | 1.00 | 0 | 2.50~3.00 | 4.00 |
| `ground-flashes` | 1.40 | 0.30 | 0.00~2.00 | 3.70 |
| `ground-sparks` / `ground-arcs` | 2.00 | 0.50 | 0.00~0.70 / 0.50 | 3.20 / 3.00 |

而组件里原来写死 `雷特效存活 = 1.2s`，**粒子数峰值正好在 1.2~3 秒**，等于**砍在最强的时候**，看起来就是突兀消失。

**修法**：新增 `存活按特效自动`（默认勾上）+ `存活倍率`（1.05）：

```text
存活 = max(手动值, prefab 自然总时长 × 存活倍率)      // 再按 `存活随速度缩短` ÷ 速度
```

命中特效（`lightning-arc-flash`，自然 **2.10s**）同样处理（原来写死 0.8s）。和冰刺 / 寒墟是同一套口径（见 [沧澜寒渊录](沧澜寒渊录.md)）。

**实测**（单发下劈雷，每秒采存活粒子数）：

| t | 存活粒子 |
|---|---|
| 1s | 30 |
| 2s | 381 |
| **3s** | **504（峰值）** |
| 4s | 146 |
| 5s | 0（粒子散完，物件还在） |
| 6s | 物件销毁（≈ 4.5 × 1.05 = 4.73s，自然结束） |

### 2.8 手感三连调

用户要求：普攻特效播快一点 —— 恢复完整特效时长后，攻速会导致上一个特效没消失下一个就出现，而且整体播放速度偏慢、没有雷系干净利落的感觉；给普攻命中的目标也加上闪电链的命中特效；命中特效调到比现在小一些（现在有点主副颠倒）。

| 改动 | 之前 | 现在 | 说明 |
|---|---|---|---|
| `雷特效速度` | 1（原速） | **1.8** | 整棵树 `simulationSpeed` ×1.8；存活按 `存活随速度缩短` 一起缩短 |
| 命中特效挂在**主目标** | 只有被链到的敌人才有 | **主目标也挂** | `出手()` 里劈完就 `生成命中特效(目标, 缩放)` |
| `命中特效大小倍率`（**新字段**） | —（直接用体型缩放值） | **0.6** | 在体型缩放之后再乘一道：0.89 → **0.53**；雷劈是主、命中闪是副 |

**为什么加速能缓解"上一个没消失下一个就来了"**：`存活随速度缩短` 会把存活一起除掉 —— `4.5 × 1.05 ÷ 1.8 = `**2.63s**（原来是 4.73s），而普攻冷却 ≈ `1.1s ÷ 攻速`，所以同屏不再堆三四道雷。

**实测**（单发，每 0.3 秒采一次存活粒子数）：

| t | 雷劈粒子 | 命中特效粒子 |
|---|---|---|
| 0.9s | 142 | 300 |
| 1.8s | **519（峰值）** | 78 |
| 2.4s | 151 | 1 |
| 2.7s | 21 | 0（≈2.1s 自然结束） |
| 3.3s | 0（物件销毁 ≈2.63s） | — |

| 检查项 | 结果 |
|---|---|
| 雷劈物件 scale | 0.89（= 1.6m ÷ 1.8m）✓ |
| 命中特效 scale | **0.53**（= 0.89 × 0.6）✓ 明显比雷小 |
| 两者都在**同一个主目标**身上 | ✓ |
| 雷劈存活 | **≈2.63s**（= 4.5 × 1.05 ÷ 1.8）✓ |

拍图：`cultivation/screenshots/雷劈与命中特效.png`（雷柱为主、脚下小闪为副）。

> 若攻速拉到很高还嫌同屏叠雷，可以再加一条「**新雷覆盖同目标的旧雷**」—— 现在**没做**（怕把还在半空的雷掐掉）。

## 3. 主动神通：雷动千闪（`ability_leidong_qianshan`）

- 学习物品：`item_active_ability_leidong_qianshan`（**雷动千闪 神通玉简**），效果 `学主动神通`
- 表里：结算方式 = **闪烁位移**、伤害属性 = 特殊、倍率 2.2、范围 6、冷却 10、**可积攒次数 3**、不需要锁定

### 3.1 效果与特效

朝**鼠标方向**（只是方向）闪烁位移；所指方向超出**神识**时最远只闪到神识边缘。**原地**和**落点**各留一蓬雷（表里 `持续时长` 0.6s 后消失），并对**当时在那里的敌人**各结算一次**特殊 + 主动神通**伤害。冷却 10 秒，但**可积攒 3 次**。

| 位置 | 特效 | 来源 |
|---|---|---|
| 落点 | `特效/战斗法术/Combat Magic VFX Vol.1/resources/lightning-fx/lightning-impact` | **神通表「特效资源路径」列**（表里填的是**落点**） |
| 起点 | 同目录 `lightning-arc-flash` | 代码自动推导，见下 |

**起点特效怎么来的**（表里只有一列，所以是约定）—— `ActiveSkillCaster.推起点特效路径()` 三条规则按顺序试：

```text
1. 落点叫 xxx_02 → 找同目录的 xxx_01        （老写法，Electro_Lightning_02 那套）
2. 同目录里找 起点特效同目录名（默认 lightning-arc-flash）   ← 现用这条
3. 都没有 → 和落点用同一个（至少不会没特效）
```

起点特效名可以在 `ActiveSkillCaster.起点特效同目录名` 里改。旧写法用的 `Electro_Lightning_01 / _02` **已从 `resources/` 删除**。

### 3.2 两个新机制（都是这次为它加的）

**① `ActiveSkillKind.闪烁位移`** —— 新的结算方式档位，由 `BlinkSkillRunner` 执行（`ActiveSkillCaster.施放闪烁` 建它）。和 `范围伤害` 是两套节奏，所以单独分流。

**② 充能式冷却（`可积攒次数`）** —— `ActiveDivineAbility` 新字段 + 神通表新列。普通技能（=1）行为完全不变；>1 时：

```text
开场满充能（3）
  · 放一次扣一次；从"满"掉下来才开始倒计时
  · 倒计时走完 → 回 1 次，并立刻重新开始下一轮（只要还没攒满）
  · 攒满了就不倒计时
```

⚠️ **踩过的坑**：不能用"充能数 == 0 就补满"做懒初始化 —— 充能式技能**正常用光**之后充能数也是 0 且没在倒计时，会被误判成"还没初始化"→ 刚放完三下立刻又满三次。现在改成**记住每格装的是哪个神通**（`充能上次内容`），只有换人了才重置充能与冷却。

### 3.3 落点与安全性

- 闪烁距离 = `min(鼠标所指距离, 神识范围, 最大闪烁距离)`
- 落点做一次**地面探测**（上方 30m 往下打）；打不到就**原地不动**（不闪进虚空）
- **鼠标在游戏画面外时**（实测 `Input.mousePosition` 会拿到窗口外坐标，比如 **-2399**）退回**角色正前方** —— 否则按技能会朝莫名其妙的方向闪
- 位移时先关 `CharacterController` 再挪（和 `Teleporter.放下玩家` 同一个坑）

### 3.4 ⚠️ 御风 / 骑乘时必须保持高度

**症状**：骑乘坐骑或御风时，使用雷动千闪会回到地面上然后再次飞起。

**真因**：`算落点()` 最后无条件把落点的 y 贴到地面 +0.05。御风悬浮在 2.4m、坐骑最高 5.64m，闪一下就被摔到地上；而 `PlayerController.ApplyFlightHeight / ApplyMountHeight` 是**比例控制回拉**（`verticalVelocity = (目标Y - y) × 8`），于是又被拉回原高度 → 看起来就是"落地又飞起"。

**修**：`算落点()` 先判 `在空中()`（`MountRider.骑乘中` 或 `YufengFlight.御风流程中`），是则走 `算空中落点()`：**保持玩家当前高度，只做水平位移**。实测：

```text
御风悬浮 y=5.64 → 闪烁后 y=5.64  ✓ 保持
御风悬浮 y=2.40 → 闪烁后 y=2.40  ✓ 保持
御风已落地      → 闪烁后 y=0.05  ✓ 地面分支行为完全不变
```

**唯一允许的竖直变化**：落点下方有**比玩家更高**的地形（山脊 / 屋顶）时抬上去，免得横穿山体（实测：玩家 y=0.20、落点是 4m 高的墙 → 抬到 y=4.05 ✓）。

⚠️ **这里连踩三个坑**：

1. **探地必须从高处往下打**。曾从"玩家高度 +1"往下打 —— 落点处若有一堵比自己高的墙，起点就在**墙内部**了，而 Physics 默认不命中背面（`queriesHitBackfaces = false`），射线直接穿过去打到地面 → 永远探不到。实测 `WallSeg_17`（box 高 4m）：从 y=3 往下打只中 y=0 的地面，从 y=10 往下打才中 y=4.00 的墙顶。
2. **判断方向别写反**。射线从上往下打，命中点必然 ≤ 起点 y，所以用「命中点 > 起点y」当条件**永远不成立**；要的是「命中面 > 玩家脚下 → 抬上去」。
3. `RaycastAll` **不保证有序**，取最高面要遍历，不能 `break`。

### 3.5 施法动作：**留空**

用户要求：闪完恢复 idle 就行 —— **不要额外的施法动作**。所以神通表 `施法动作` 列**留空**（`播施法动作()` 开头就 `IsNullOrEmpty → return`，完全不播）。只有 `焚天炎术` 配了 `技能动作2`，别动它。

## 5. 加类似内容时的检查清单

1. **表**：功法表 / 主动神通表 / 物品表 各加一行 → 跑菜单「修仙/从配置表生成资产」
2. **新列**（如 `可积攒次数`）：**先给类加同名字段**，否则导入器会静默忽略这一列
3. **新枚举值**（如 `结算方式 = 闪烁位移`）：**先加进枚举**，否则导入时报"不是合法枚举值"
4. **新普攻方法**：写组件 + 在 `PlayerAbilityLoader.普攻方法表` 登记 —— **5 个场景都要**加
5. **学习物品**：物品表加行，导入器会自动建「效果资产 + 回填引用」
6. **改电路径**：一律相对 `Assets/resources`、**不带扩展名**；`Resources.Load` 读不到只返回 null 不报错
7. 编译 0 error → Play 实测 → 更新本文与工作日志
