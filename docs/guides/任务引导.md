# 任务引导（主线追踪）

> **管什么**：**屏幕右上角**（避开顶部 Toast）的主线追踪面板、目标头顶的金色感叹号、目标出画面时的屏幕边缘箭头 —— 这三样各自**什么时候出现、指哪、怎么算出来的**，以及它读哪几列表、画布层级和实测数字。
> **不管什么**：任务阶段本身的条件/动作/标记怎么跑在 [design/任务系统](../design/任务系统.md)；剧情里谁说了什么在 [design/主线剧情](../design/主线剧情.md)；`任务表.csv` 新增那四列的字段定义在 [reference/配置表字段](../reference/配置表字段.md)；跨场景与投影类坑的原文在 [ai/踩坑总库 B 段](../ai/踩坑总库.md)。
> **本文件怎么查**：§1 它是什么 / 挂在哪 · §2 引导**哪一条**主线（★ 踩过两次） · §3 目标从哪来（自动推 + 两列覆盖） · §4 三部分长什么样 · §5 图层与隐藏规矩 · §6 实测数字 · §7 坑与遗留。
> **来源**：`Assets/Scripts/Quests/任务引导.cs`（类头注释是本文件的第一手来源）+ Play 模式实测。

## 1. 它是什么 / 挂在哪

`任务引导` 是**一个组件做三件事**，全部**只读** `任务管理器` 和 `QuestDefinition`，**不改任何任务数据**：

| 部分 | 长什么样 | 什么时候出现 |
|---|---|---|
| **追踪面板** | 屏幕**右上角**深色小牌（2026-10-02 用户要求从左侧挪过来）：`主线 · 任务名` / 当前目标（`阶段名`）/ `说明` / `目标：X　NN 米` | 只要有一条**主线**阶段在跑 |
| **头顶感叹号** | 目标（NPC 或地点）**上方**一个金色「！」，**屏幕空间**画的 | 目标投影落在**画面内**时 |
| **边缘箭头** | 屏幕边缘一个金色三角，朝着目标的方向 | 目标**出画面**（含身后）时 |

| 项 | 值 |
|---|---|
| 组件 | `任务引导`（`Assets/Scripts/Quests/任务引导.cs`） |
| **挂载** | 由 `场景自举` 的 `补玩家与相机()` 自动补到**主相机**上（和 `纪年HUD` / `灵田界面` 同一处），**不写进场景** |
| 为什么挂相机 | 三个都是 `ScreenSpaceOverlay` 自搭 Canvas，挂相机只是为了有个**跟着场景走、又不进场景文件**的宿主 —— 手工往 5 个场景里摆 UI 是场景一致性的老病根 |
| 谁提供数据 | `任务管理器.进行中的阶段()`（挑主线）+ `QuestDefinition`（阶段名/说明/引导列）+ `NpcInstance` / `DialogueDatabase` / `NpcDatabase库`（解析目标） |

> 它**每个游玩场景自动都有**，不需要任何接线；`3C_Testbed` / `Sect` / `village` / `Sect_Wilderness` / 镇妖塔都一样。

## 2. 引导**哪一条**主线 ★

**规则：只看 `类型 = 主线`；多条主线同时挂着时，取 `任务id` 最大（字符串序）的那条。**

为什么是"最大"：本工程的 `任务id` 是**按剧情顺序编的**（`q_main_001` 村口 → `q_main_004` 拜入太虚宗），
**越大 = 越靠后 = 玩家此刻在演的那一幕**。

> ⚠️ **这里连着踩过两次，别再改回去**（两次都是同一个根因：**"在跑的主线"不等于"玩家现在要做的事"**）：
>
> | 试过的写法 | 实测表现 |
> |---|---|
> | ① "`任务id` **最小**优先"（先来的先做完） | 存档里 `q_main_001`（村口交回春丹）**长期挂着没交**，于是进洞府后面板**一直显示「交一株回春丹」**，而玩家在推宗门那一幕 |
> | ② "**最近开始**的那个阶段优先" | 也不行 —— `初入山门` 第 1 阶段是 `自动接取` 的，一进场景就先 fire 一次「阶段开始」，于是它**永远"最近"** |
> | ③ **`任务id` 最大**（现在） | 与剧情顺序一致，实测洞府里稳定显示 `q_main_004`，走完阶段27 后整块面板消失 |

支线 / 悬赏**不进追踪面板**。以后要做多线追踪，再加"手动钉一条"，别动这里的默认口径。

### 2.1 ⚠️ 不能只靠 `阶段开始 / 阶段完成` 事件

`任务引导` 订阅了 `阶段开始` / `阶段完成` / `任务全部完成` 来触发重算，但**光靠事件不够**：

读档和"跨场景接手上一场景的进度"走的是 **`任务管理器.导入进度()`**，它**故意不发事件**
（读档不能重放剧情动作）。只订阅事件的话，面板会一直显示**进场景那一刻**挑中的那条 ——
实测：进度明明是 `q_main_004:27`，面板却挂着 `q_main_001` 的「交一株回春丹」。

**所以每 `解析间隔 = 0.4` 秒无条件自检一次**（重新挑阶段 + 重新解析目标）。
成本是每 0.4 秒一个很小的 `List`，完全可以接受。**加新阶段时不用管这件事**，它自动跟上。

> 另一个必须留在原地的顺序：**重算在"可见性判断"之前**。早期把重算挪到 `if (!该显示) return;` 后面，
> 结果开局 `当前阶段` 是 `null` → 可见性 false → 直接 return → `当前阶段` 永远是 `null`，**面板一个字都不显示**。

## 3. 目标从哪来（表里显式填的 → 按条件自动推 → 都没有才用坐标）

`解析目标(阶段)` 的实际顺序（**这个顺序就是优先级**）：

| # | 来源 | 指向 |
|---|---|---|
| ① | 表里 `引导npcId` | `NpcInstance.定义.id` 相符、且**没死**的那个 NPC；标记顶在它**身高之上**（`取身高()`：渲染体最高点，兜底 1.8 米）。**填了就无条件指他** |
| ② | 自动：`条件 = 对话 / 击杀 / NPC到位` | `目标npcId` 那个 NPC；`条件=对话` 而 `目标npcId` 空时，拿 `对话id` 去 `DialogueDatabase.取NpcId()` **反查是哪个 NPC**。**这跟 `任务管理器.确保对话NPC在场()` 用的是同一个方法** —— 引导要指的那个人，任务系统会保证他在场（见 [design/任务系统 §9.4](../design/任务系统.md)）。⚠️ **只有"点名的对话此刻真能出来"（`阶段对话能出`：标记 + 场景门禁都满足）才指他**，见 §3.3 |
| ③ | 表里 `引导坐标` | 一个**地点**（`x;y;z`）；名字取 `引导地点名`，留空显示「目的地」 |
| ④ | 自动：`条件 = 到达` | `坐标X/Y/Z` |

**所以加新主线阶段通常一个字都不用填。** 只有"去某座建筑走一趟""去某个传送门"这种
既没有 NPC、条件也不是 `到达` 的阶段，才需要填 `引导坐标` / `引导地点名` / `引导场景`。

| 情况 | 面板怎么写 | 画标记吗 |
|---|---|---|
| 目标 NPC 在本场景 | `目标：大师兄　12 米` | 画 |
| 目标 NPC 不在本场景 | `目标：去找「大师兄」` | 不画 |
| 地点在本场景 | `目标：宗门炼丹阁　17 米` | 画 |
| **地点标了别的场景**（`引导场景` 填了、而玩家不在那个场景） | `目标：宗门炼丹阁（在「Sect」）` | **不画** |
| 什么都没有（推不出目标） | `（按任务说明进行）` | 不画 |

### 3.1 ⚠️ 跨场景**绝对不画标记**

表里写了 `引导场景`（例 `Sect`）而玩家不在那个场景 → 面板照写名字，但**一个标记都不画**。

理由：**两个场景的坐标是两套空间**。拿宗门的 `(-4.59, 3.48, 29.92)` 在洞府里投影，
会指向一个**毫不相干的方向**（实测很容易被当成"引导坏了"）。跨场景时面板改写成
「目标：X（在「Sect」）」，把"要换场景"这件事说清楚就够了。

### 3.2 距离怎么算

`Vector3.Distance(玩家, 标记点)`，标在 `目标：名字　NN 米` 一节。
`≥ 10` 米显示整数、`< 10` 米显示一位小数（角标里 `0.#`）。玩家找不到时（极端情况）只写名字。
**玩家位置按 `PlayerVitals` 组件找，退回 `GameObject.Find("Player")`** —— 和落点那套一致。

**近处不画**：玩家离标记点 `< 近处不画 = 2.2` 米时**两个标记都藏起来**（人就在眼前了，别挡视线），面板不受影响。

### 3.3 ⚠️ 别把「！」顶在一个**现在说不了话**的人身上（2026-10-02）

自动推出来的 NPC（第 ② 行）只是**表意上**该跟他说话 —— 那段对话此刻可能**根本出不来**：

> 实测（用户报「还没进洞府，大师兄就把洞府那一幕演完了」）：阶段17 点名的
> `dlg_act5_dongfu_1` 被 `场景_3C_Testbed` 锁在洞府里，而玩家还站在**宗门传送点**、
> 大师兄就在旁边 ⇒ 原来的「！」顶在他头上，玩家当然去按 F，**而不是走进传送光**。

**现在的口径**：自动推的 NPC 要过一道 `DialogueDatabase.阶段对话能出(阶段)`
（= 点名那段的 `需要标记` / 场景门禁都满足）才指他；出不来就**落到「地点」分支**。
配合阶段17 填的 `引导坐标 = -18.23;0.5;27.54`（`引导地点名 = 洞府传送点`、`引导场景 = Sect`），
表现为：**在宗门 → 箭头指传送光；进了洞府（那段话能说了）→ 「！」回到大师兄头上**。

`任务管理器.确保对话NPC在场()` 用的是同一个判断：这段话现在说不出来，
就**不要**把那个 NPC 凭空补到玩家跟前。

## 4. 三部分长什么样

### 4.1 追踪面板（**屏幕右上角**，避开顶部 Toast）

```
┌──────────────────────────────┐
│ 主线 · 拜入太虚宗            │  ← 任务名（金色，25 号）
│ 走近丹房                     │  ← 阶段名（白色，24 号）= 当前目标
│ 丹房就在前面——走近按 F，…    │  ← 说明（灰色，18 号；空则不显示这一行）
│ 目标：宗门炼丹阁　17 米      │  ← 目标与距离（淡金，18 号）
└──────────────────────────────┘
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `右边缘` | `18` | 离屏幕**右边**像素（1080p 参考分辨率下） |
| `上边缘` | `150` | 离屏幕**顶边**像素。让开顶部 Toast（纪年已移到右下）|
| `面板宽度` | `400` | |
| 水墨底 | `(0.025,0.035,0.035)@0.95` | `UIInkDialogueBackdrop` 与对话同源，旧底板色字段保留兼容 |
| `标题色` / `目标色` / `说明色` / `距离色` | 金 / 白 / 灰 / 淡金 | |
| `标题字号` / `目标字号` / `说明字号` / `距离字号` | 25 / 24 / 18 / 18 | |
| 高度 | **跟着内容走**（`ContentSizeFitter` + `VerticalLayoutGroup`） | 说明有几行就多高 |
| 字体 | 留空自动找 **SimHei** | 找不到会打一条 Warning（会显示成方块） |

墨底边缘按实际尺寸晕染，内容留白为左右 40、上下 28，说明换行后幕布自动增高。水墨模式固定使用暖金标题、米白目标、灰绿说明与淡绿距离，四行右对齐。

四行字**每行都带黑描边** —— 底板是半透明的，压在亮场景上也要看得清（和 `灵田地块牌` 同一个理由）。

### 4.2 头顶感叹号 / 边缘箭头（屏幕空间投影）

两个标记都挂在**铺满屏幕的「标记层」**下、锚点在正中，所以 `anchoredPosition` 就是
**"以屏幕中心为原点"的画布本地坐标**。算法：

```
世界点 ──Camera.main.WorldToScreenPoint──▶ 屏幕点
       ──RectTransformUtility.ScreenPointToLocalPointInRectangle(画布根, 屏幕点, null)──▶ 本地坐标
       · 在身后（屏.z ≤ 0.01）时投影会左右/上下翻转 → 本地坐标取反，方向才是对的
```

| 判据 | 用的是 | 结果 |
|---|---|---|
| **在画面里** | **整个视口**（`|x| ≤ 画布半宽 且 |y| ≤ 画布半高`） | 画**感叹号**，位置 = 投影点（再夹进视口内 `感叹号大小 × 0.6` 的边距，别被屏幕边切掉） |
| **出画面** | 上面不成立 | 画**箭头**：把"屏幕中心 → 目标"这条射线夹到**内缩 `边缘留白 = 78` 像素**的框上，`localRotation` 按 `Atan2` 转到指向目标 |

| 参数 | 默认 |
|---|---|
| `边缘留白` | `78` 像素（箭头贴边用；太小会被刘海/边框切掉） |
| `叹号大小` / `箭头大小` | `52` / `44` |
| `头顶抬高` | `0.5` 米 |
| `近处不画` | `2.2` 米 |
| `标记色` / `描边色` | 金 `(1,0.82,0.2)` / 黑 `@0.85` |

**箭头贴图是运行时画的**：64×64、朝上的实心三角 + 深色描边（`取三角精灵()`，静态缓存一份），
染色后靠 `localRotation` 旋转指方向。工程里没有箭头图，为一个 44 像素的小三角去导一张 png 不值当
（和 `StationInteractor` 现画圆角精灵一个路子）。

感叹号已经在 ScreenSpaceOverlay 中，不受场景后处理影响。本次变淡的根因是 `InkUIRuntimeSkin` 将亮字重染为深墨并禁用 Outline；现跳过整个 `QuestGuideCanvas`，保留感叹号的金色、不透明 alpha 与黑描边。任务目标解析和投影规则保持原口径。

### 4.3 ⚠️ 为什么"头顶感叹号"用**屏幕空间投影**，不是世界空间牌子

世界空间那块牌子（像 `灵田地块牌` 那样）有三个绕不开的问题：

1. 处理不了**"被树挡住"**（牌子会插进树冠里）；
2. 离远离近要自己管大小 / 淡出；
3. **它没法顺势变成屏幕边缘的箭头** —— 那是两套东西。

改成投影之后：**在镜头里 → 就在目标头顶画「！」**（看起来一样是"头顶的感叹号"）；
**出画面 / 到身后 → 同一个目标变成屏幕边缘的箭头，方向天然是对的**。
一套投影同时满足两个需求，还**不往场景里塞任何物件**（没有场景漂移、不用收拾）。

## 5. 图层与隐藏规矩

| 项 | 值 |
|---|---|
| 画布 | `QuestGuideCanvas`，`ScreenSpaceOverlay`，`CanvasScaler` 参考分辨率 **1920×1080**、`matchWidthOrHeight = 0.5` |
| `sortingOrder` | **2300** —— 低于**纪年 HUD 2400**、塔 2500、对话 2600、黑幕 2900，所以要能被它们盖住 |
| `GraphicRaycaster` | **关掉**（`enabled = false`）—— 屏幕右侧一整块面板不能吃射线，否则挡住点击 |
| 演出期间 | `黑幕字幕.演出中` **或** `DialogueUI.正在显示` → **面板与两个标记整体隐藏**（过场时屏幕一角挂一块任务牌很跳） |
| 没有主线在跑 | 面板隐藏、标记隐藏（`当前阶段 == null`） |

```
      [丹房就在前面——走近按 F，打开丹炉试试炼丹。]
      [目标：宗门炼丹阁　17 米]
```

| 情形 | 实测 |

| 目标在**画面内** | `感叹号=True 位置=(323, 490) 箭头=False` —— 截图 `cultivation/screenshots/引导_感叹号.png` 里能看到**左侧面板 + 右上一个金色「！」** |
| 目标在**身后** | `感叹号=False 箭头=True 位置=(-760, -462) 旋转=121°` —— 截图 `cultivation/screenshots/引导_边缘箭头.png` |
| 走到丹房跟前（离站点 **2.9 米**） | `阶段号=0`（`q_main_004` **整条完成** ✔）、**面板与两个标记全部消失** |

→ 面板显示「走近丹房 / 宗门炼丹阁 17 米」+ 感叹号 → 走到跟前 → **「拜入太虚宗」全部完成 ✔**。

**洞府那一幕（大师兄不在场 → 被任务系统补出来）**：

```
[主线 · 拜入太虚宗] [灵田初见] [大师兄说，修行根基在于自给自足。] [目标：大师兄　2.7 米]
头顶感叹号 激活=True
```

截图 `cultivation/screenshots/引导_洞府大师兄.png`（洞府里的大师兄 + 左侧面板 + 头顶感叹号）。
妙处在于**引导这边什么都不用改**：任务系统把大师兄补出来之后，`解析目标` 下一次自检
（≤ 0.4 秒）就找到他了，面板与标记自动出现。

**反面对照（不该补的时候一个都不补）**：在一个**从头开始**的场景里（`village`，没跑过主线），
等 2 秒后场上 NPC 数量**没变**（`9 → 9`）、感叹号/箭头都是 `False` ——
"补 NPC"只对**任务自己生成过**的 NPC 生效，**不会凭空造出场景里本来没有的路人**
（截图 `cultivation/screenshots/引导_村庄.png`）。

## 7. 坑与遗留

### 7.1 ⚠️「在画面里」不能用"内缩后的框"判

一开始拿**内缩 78 像素后的框**当"在画面里"的判据。结果：俯视机位下，**17 米外的地面目标投影在屏幕底部 50 像素处**
→ 落在内缩框外 → **只出箭头，头顶的感叹号永远不出现**（看起来像"感叹号没做"）。

**内缩只该用来决定"箭头贴在哪条边上"**，"在不在画面里"必须按**整个视口**判。
两者在代码里是两组变量（`全宽/全高` 判可见性、`半宽/半高` 夹箭头），别合并。

### 7.2 NPC 会走会死会生成 → 目标要**定时重解析**

`解析目标` 每 `解析间隔 = 0.4` 秒跑一次，不是每帧（每帧全场景找 `NpcInstance` 太浪费）。
代价是**目标最多迟 0.4 秒**才跟上，实测肉眼看不出来。
