### 2.3 去掉光环里的电弧 `zaps`（用户要求）

用户 2026-09-28：*「去掉光环中的 flames 组件，只保留剩下的」* →
澄清：*「我就是不想要那个电弧了」*。

**真实层级关系**（第一次搞错过，记下来）：

```
black-border-tint
  ├─ flames              ← 本身也是个粒子部件（留下是对的）
  │   └─ zaps            ← ★ 这才是那根"往外甩的电弧"，用户不要
  │       ├─ lightnings-circles
  │       └─ rays/flashes
  └─ black-border-dust   ← 黑圈（保留，它是范围标杆）
      └─ black-border-particles
```

**配置**：`QianJieLeiYu.光环去掉的部件 = ["zaps"]`，删的是**整棵子树**。

> ⚠️ **踩过的弯路**：第一版我写成"删 `flames` 但把子物件提到上一层"
> （想着保住电弧）—— 结果用户**根本不想要电弧**，白绕一圈还留了一堆。
> **别自作聪明保子物件；先问清"要的到底是哪一个"。**

**实测**（`去掉光环部件` 会打印含子树的物件数）：

```
去掉光环部件「zaps」（含子树共 4 个物件）
★ zaps / lightnings-circles / rays / flashes 全部消失 ✓
★ black-border-tint / flames / black-border-dust / black-border-particles 保留 ✓
```

### 2.4 雷罚高度：`雷罚抬高 = −0.18`（用户手调后反推）

用户 2026-09-28 手调了其中一个雷罚的高度，让我参考。**反推方法**：
代码里是 `根Y = 锚点.y + 抬高 − 部件范围.min.y`，所以

```
抬高 = 根Y − 锚点.y + 部件范围.min.y
```

实测三个雷罚：

| 木桩 | 雷罚根 y | 部件范围 y | 反推抬高 |
|---|---|---|---|
| 木桩(2) ← **用户调的** | −0.240 | 0.060 ~ 0.303 | **−0.180** ★ |
| 木桩(1) / 木桩 | +0.579 | 0.879 ~ 1.121 | +1.457（旧的 1.0） |

所以 `雷罚抬高 = **−0.18**`（允许负数）。几何中心落到脚下 −0.18m、
部件实际覆盖约 0.06~0.30m —— 薄薄一圈贴在敌人脚背上。

**实测**：三个木桩的雷罚几何中心全部 = `−0.18` ✓

> **反推手感数值的通用套路**：先看代码里"输入参数 → 最终位置"的公式，
> 再把当前实际位置代回去解出参数。比反复试值快得多。

### 2.5 竖直摆放：抬起来，别埋地下也别挡血条

用户 2026-09-28：*「这个特效的显示层级有点太高了，实际上没这么高，把血量和选中的 ui 给遮住了」*
→ 改完 *「雷罚和光环都可以稍微往上抬一点，现在看不到完整的特效」*。

⚠️ **这里有个量测陷阱，害我改了好几轮**：

`black-border-dust` 的粒子 `startSize` 很大，**粒子会从发射器节点向下延伸好几米**。
实测（scale 2.962、玩家脚下 y=0.02）：

```
发射器节点 y = +0.62     ← 节点本身位置
粒子包围盒 y = −6.16 ~ +7.40   size.y = 13.55
```

所以：
- **看"节点/发射器"在哪** → 用 `transform.position`
- **看"粒子铺到哪"** → 用 `ParticleSystemRenderer.bounds`（会大出一大截）

**别拿 `renderer.bounds.min` 去对齐** —— 那会把整个发射器推到天上去。
`QianJieLeiYu` 的对齐逻辑是把**发射器节点的最低点**放到 `锚点.y + 光环抬高`，
然后靠 `光环抬高` 这个旋钮调"露出来多少"。

| 参数 | 值 | 说明 |
|---|---|---|
| `光环贴地` | true | 勾上 = 按节点最低点对齐（避免几何中心对齐把圈抬到 8m 高挡血条） |
| `光环抬高` | **1.5** | 发射器节点离地高度。想整圈都露出来就往上加 |
| `雷罚抬高` | **1.0** | 雷罚相对敌人脚下抬高 |

**实测（最终版）**：

```
玩家脚下 y = 0.02
黑圈发射器节点 y = +1.52   = 0.02 + 光环抬高 1.5 ✓
雷罚根 y = +0.58
```

### 2.4 ⭐ 骑乘时对齐坐骑根节点（特殊情况）

用户 2026-09-28：*「光环类技能在装备一些骑乘类坐骑（也就是上古神龙，灵翅以外的坐骑）时，
应该是对齐坐骑的根节点而非角色的」*。

**为什么**：人骑在坐骑背上（坐骑 `骑乘高度` 1~5.64m），
光环贴角色脚下的话圈会**穿过坐骑身体**。所以骑乘类坐骑要贴**坐骑根节点**。

**例外**（`不贴坐骑的坐骑id`，默认两个）—— 它们不是"骑着"的：

| 坐骑id | 名称 | 为什么不贴 |
|---|---|---|
| `mount_shenlong_01` | 上古神龙 | 环身特效，本来就围在角色周围 |
| `mount_chibang_01` | 灵翅 | 长在背上的翅膀 |

其余坐骑（狼/鹿/熊猫/麒麟/灵鹤…）自动贴坐骑根。判定走
`MountRider.骑乘中` + `MountRider.坐骑实例` / `坐骑定义.坐骑id`。

**实测**：

```
不骑坐骑        锚点 = Player        ✓
骑「狼骑」      锚点 = 坐骑_狼骑      ✓ 骑乘类贴坐骑根
骑「上古神龙」   锚点 = Player        ✓ 例外贴角色
```

### 2.5 三个特效的缩放与旋转

| 特效 | 资源 | 缩放依据 |
|---|---|---|
| 光环 | `lightning-arc-black-ring` | **范围**（= 神识范围）÷ `特效基准半径` |
| 雷罚 | `lightning-whirling-arc-zone` | **敌人模型高度** ÷ `雷罚基准敌人高度` |

**⚠️ 两个特效都必须绕 X 转 −90°**（`QianJieLeiYu.特效旋转欧拉 = (-90,0,0)`）。
用户 2026-09-28 实测：不转是躺平的，转 +90 会倒过来，**−90 才对**

摆放统一走共用的 **`特效摆放`**（`Assets/Scripts/Combat/特效摆放.cs`）：


### 2.6 光环基准半径 = `black-border-dust` 的半径（用户指定）

用户 2026-09-28 要求：*「光环下面组件有一个 `black-border-dust`，
以它的尺寸作为缩放标杆，这个组件的尺寸大小要和实际能够作用的敌人范围对齐」*。

**实测 `lightning-arc-black-ring` 在 scale = 1 时各部件相对锚点的水平半径**：

| 部件 | scale 1 半径 | 用途 |
|---|---|---|
| **`black-border-dust`** | **4.727** | ★ **取它当基准**（黑圈边界 = 伤害边界） |
| `black-border-particles` | 4.309 | 黑圈上的碎屑（在圈内侧，不用管） |
| `black-border-tint` | 5.001 | 大一圈的底色 |
| `flames` | 5.561 | |
| `zaps` / `lightnings-circles` | 10.8 / 11.4 | 电弧**会甩到黑圈外面，属正常**，不是 bug |
| `rays` | 3.281 | |
| `flashes` | 4.574 | |

所以 `特效基准半径 = 4.727`，缩放 = `半径 ÷ 4.727`。

**实测对齐结果**（神识 12.5 → 半径 14m → 光环 scale 2.962）：

```
black-border-dust        ≈ 14.00m   ★ 正好等于伤害半径 14m ✓
black-border-particles   ≈ 12.76m
black-border-tint        ≈ 14.81m
zaps / lightnings-circles ≈ 31.9 / 33.8m（电弧甩出圈外）
```

> **换特效时必须重新标定**：改 `光环特效路径` 后，量一遍新 prefab 里
> "代表范围边界"那个部件的 scale-1 半径，填进 `特效基准半径`。

### 2.7 雷罚的表现：**常驻**，不是闪一下

用户 2026-09-28：*「那个雷罚特效不是消失又出现的，而是一直出现在受影响的单位的脚下」*。

所以 `雷罚常驻 = true`（默认）。生命周期规则：

```
敌人进入范围 → 脚下建一个雷罚，一直挂着
敌人移动     → 雷罚跟着走（每帧对齐）
敌人离开范围 → 收掉
敌人死亡     → 收掉
光环关闭     → 全部收掉
```

**伤害结算和特效是两回事**：伤害仍按 `伤害间隔`（1.5s）跳，
但特效**一直**在脚下，不跟着跳动闪烁。

关掉 `雷罚常驻` 就退回旧行为（每次结算现放一个、播完自己消失），
那时才用得到 `雷罚存活` 和 `雷罚重放间隔`。

**实测**：

```
① 范围里没敌人 → 雷罚 0        ✓
② 敌人进范围   → 雷罚 1        ✓
③ 再等 1.8s（跨过伤害间隔）→ 仍是 1  ✓ 常驻、不闪不留
④ 敌人移动     → 雷罚跟着走     ✓
⑤ 移出范围     → 雷罚 0        ✓
⑥ 再进范围     → 雷罚 1        ✓
关闭光环       → 雷罚 0        ✓
```

### 2.9 `特效摆放` 这个共用工具是怎么来的

玄霄雷决普攻、雷动千闪、千劫雷狱三处都要做同一套「生成 → 旋转 → 对齐 → 等比缩放」，
原来是**各抄一份、各踩一遍同样的坑**。抽成 `特效摆放` 后，三个坑集中记在那一处：

| 坑 | 症状 | 正确做法 |
|---|---|---|
| 旋转没给 | 特效躺平 / 倒立 | **必须按特效实测给欧拉角**（本包多为 −90） |
| 只量根级部件 | "对齐"后主体沉在地下 | 量**所有**粒子系统，**不跳子发射器**（prefab 常层层嵌套） |
| 用 `renderer.bounds` 量位置 | 偏移被粒子体积糊掉 | 用 `transform.position`（见 §2.3 那个陷阱） |
| `scalingMode = Shape` | 缩放只拉开间距、不放大粒子 | 改成 `Hierarchy` |

## 3. ⭐ 「被动法术」伤害档位是**本来就设计好的**，只是没接线

这是本次最重要的一个结构发现。原来只有两个伤害档位：

```
普通攻击 → 普攻伤害加成    / 普攻伤害减免
主动神通 → 主动法术伤害加成 / 主动法术伤害减免
```

**但实际上属性系统里一直躺着第三档**，而且**默认属性里就带值**：

```csharp
// PlayerDefaultStats.cs
s[AttributeType.PassiveSpellBonus]     = 0.05f;   // 被动法术伤害加成 5%
s[AttributeType.PassiveSpellReduction] = 0.02f;   // 被动法术伤害减免 2%
```

`AttributeType` 里 `PassiveSpellBonus = 25` / `PassiveSpellReduction = 26` 也在，
`AttributeUtil.IsPercent` 也把它们当百分比，被动神通表也一直有
「被动法术伤害减免增益」这一列 —— **就差 `AttackKind` 和 `CombatCalculator` 没接上**。

**所以本次补齐了最后一环**：

```
AttackSpec.cs
  AttackKind 新增 被动神通 = 2
  新增 AttackSpec.特殊被动神通 / 物理被动神通
  新增 用被动法术加成

CombatCalculator.CalcDamage()
  主动神通 → 主动法术加成/减免
  被动神通 → 被动法术加成/减免    ← 新增
  其它     → 普攻加成/减免

ICombatStats + 三个实现（PlayerCombatStats / NpcInstance / AttributeCombatStats）
  补上 被动法术伤害加成 / 被动法术伤害减免
```

**千劫雷狱的雷罚走 `AttackKind.被动神通`**，所以：
- **吃**玩家的「被动法术伤害加成」，**不吃**普攻加成、也**不吃**主动法术加成；
- **受**敌人「被动法术伤害减免」影响，不受普攻/主动法术减免影响。

> 三档互不串味，和 `技能倍率` 一起构成完整公式。

## 5. ⚠️ 加新神通时**必须多跑一步**：`修仙/面板/收集面板目录`

`面板.神通`（可用列表）**不是**每次进场景都从 `Generated/` 扫的，
而是 `UIPanelData.EnsureLists()` 从 **`resources/面板/面板库.asset`** 整体拷贝一份。
而 `DataTableImporter`（从配置表生成资产）**不管这个库**。

所以漏跑这一步的症状是：
**新神通明明生成了、物品也学到了、`IsPassiveEnabled` 也是 true，
但组件永远装不上** —— 因为 `PlayerAbilityLoader` 遍历的是那份旧列表。

加新神通 / 新法宝 / 新灵阵 / 新坐骑 / 新真灵后的**完整流程**：

```
1. 改 CSV
2. 修仙/从配置表生成资产        ← 生成 <类型>/<id>.asset + 物品 + 效果
3. 修仙/面板/收集面板目录        ← ★ 刷新 面板库.asset，漏了就白干
4. 在 5 个场景的 PlayerAbilityLoader.被动神通表 里登记组件类名
5. 重载场景验证
```
