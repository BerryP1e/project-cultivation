# 龙祭司动作资源

> **管什么**：龙祭司来源记录、太初伴龙八套成品资源、定稿清理及原始转换差异。
> **不管什么**：五式玩法、成品重定向和运行判定见[太初龙栖诀](武器与修行功法.md)。
> **本文件怎么查**：位置与组织 / 动作清单 / 导出与导入约定 / 验证与限制。
> **来源**：用户指定的同一角色22个3ds Max场景，本机3ds Max 2026批处理导出及团结导入检查。

太初龙栖诀使用 attack、attack02、skill_dircet04、skill_bingci、skill_dircet、guard、run_ren 和 guard03 的伴龙。2026-10-11 用户确认动作定稿后，八套伴龙已提取为独立 Generic 成品，原22个 FBX 和 `TaichuDragonAssets` 重建器已移除。A2/Guard03 玩家 Humanoid 成品保持原样。

## 位置与组织

- 原始文件：仓库外部素材目录 `第三方资源（带转换）/_NULL_(龙祭司的一套动作)_爱给网_aigei_com/龙祭司1`；原始Max文件保持不变。
- 原始Max下载包位于工程外，由 `.gitignore` 排除；本轮未删除用户的外部来源。版本管理只纳入实际运行成品、共享依赖和说明。
- 成品目录：`cultivation/Assets/Art/Characters/DragonPriest`；原 `Art/Characters/Imported/DragonPriest` 已清除。
- `Animations/`：八个独立 Generic `.anim`，保留原时长、龙/祖先骨骼、源髋骨校准及冰晶/火弹召唤曲线；删掉不再显示的人物等部件轨道。
- `Avatars/`：八份对应源骨架的独立 Generic Avatar，不互换骨架。
- `Meshes/`：八份龙蒙皮网格和三枚原生召唤节点网格；A1/A2 保留 Read/Write，其他龙网格保持关闭。权重、绑定姿态与顶点不变。
- `Materials/`：共享的 `DragonPriest.mat`、`DragonPriestSecondary.mat`。
- `Textures/`：共享的 `dragonpriest.dds`、`dragonpriest02.dds`；引擎按Texture2D导入。

源文件虽是同一个角色，但部分动作的骨架层级、手部结构和部件并不完全一致。八套成品继续使用各自的原骨架和绑定姿态，共享材质和贴图；不要把所有动作直接套到某一份骨架。现有 prefab、玩家动作、Definition 配置及材质/贴图 GUID 保留。

原生动画/网格/Avatar使用紧凑二进制序列化，避免逐帧数据改为文本后反而膨胀；项目默认序列化策略保持不变。成品以后直接维护，不保留一次性转换器或整包未用资源。冰晶合批模板、八套精简 prefab 和玩法参数仍在 `resources/Weapons/TaichuDragon`。

本轮工程内来源目录原为112,686,320字节，成品目录为40,547,259字节（含材质、贴图和meta），净减少72,139,061字节，约68.8 MiB。Library导入缓存和历史构建不等于当前资产体积。

## 导出与导入约定

独立3ds Max批处理实例读取源场景，在内存副本中处理旧Physique蒙皮的额外网格节点变换；原始文件不重存。移除场景地板、可见编辑曲线和picker控制器，保留骨骼、手部曲线、模型部件及动画。旧Mental Ray缺失项属于渲染组件，导出的角色使用共享材质。

原 FBX 使用二进制2018格式、Y向上，按原范围逐帧烘焙骨骼动画。单位由导入器转换到米，采用各自 Generic 骨架/Avatar，关闭动画压缩和骨架优化，保留完整 Custom 蒙皮权重。以上为历史转换约定；成品继承这些数据，运行由独立预制体和 PlayableGraph 驱动，具体见[太初龙栖诀](武器与修行功法.md)。

转换工具和临时取样、截图、报告放在仓库 `.local/diagnostics/dragon-priest/`，不加入运行资源。导出调用参考Autodesk的[3ds Max Batch说明](https://help.autodesk.com/cloudhelp/2026/ENU/3DSMax-Batch/files/GUID-48A78515-C24B-4E46-AC5F-884FBCF40D59.htm)及[FBX导出参数](https://help.autodesk.com/cloudhelp/2017/ENU/3DSMax/files/GUID-3242579C-E37D-4A7C-BFA5-F4A2F22653E7.htm)。

## 验证与限制

历史转换中检查过22个 FBX 的帧段、30 fps、Avatar、骨骼路径、蒙皮部件和共享贴图；192次部件取样对照 Max，整体包围盒最大差异约3.2毫米。定稿清理另外对八套伴龙每套121帧进行78,892次必要节点姿势对照，并在40个采样帧比较实际蒙皮顶点，移除无用曲线前后保持一致。

清理后五式真实运行91项、六玩家场景与成品依赖93项、A1短小目标/四朝向/四距离/窗口去重和跳帧补采716项通过（逐帧检查项数随帧率变化）。不再包含源FBX依赖，A1/A2 CPU蒙皮接触及其余龙网格不可读标记保持正确，原腕指与A2/Guard03姿态未变。

旧Physique到FBX蒙皮仍有局部差异：当前稀疏顶点取样的最大位置差异约5.1厘米，出现在attack02，部分其他动作也有较小差异。不能把这项记录理解为所有顶点完全一致；资源保留原骨骼动作，后续接入时应按实际用途确认局部蒙皮表现。guard、attack02、skill_dircet03、walk_ren已在引擎中渲染预览。
