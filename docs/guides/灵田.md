## 1. 它是什么 / 在哪

洞府后山的**挂机养成**设施：种下 → 全天候自动生长 → 一键收取，产物进背包。
要求**无养护损耗**（没有浇水/施肥）；灵田/灵植**没有现成模型**，所以 §7.3 全程序化生成。
灵田是养成闭环的最上游（**规则只写在 [炼丹](炼丹.md) §1**）：
`灵田（挂机产出灵草） → 炼丹（主动消耗） → 破境丹 / 修为提升`

| 文件 | 内容 |
|---|---|
| `Assets/Scripts/SpiritField/灵田.cs` | 格子 / 播种 / 生长 / 收取 / 升级 / 存档 |
| `Assets/Scripts/SpiritField/灵植定义.cs` | `灵田品阶` · `灵植品阶` · `灵植定义` · `灵植库` · `灵田格` |

## 2. 数据结构

| 成员 | 作用 |
|---|---|
| `灵田.品阶`（`灵田品阶`，默认 `一阶下品`） | 决定**能种什么**、**产多少**、**长多快** |
| `灵田.格数`（默认 6） | 种植格上限；`灵田.扩容(加到格数)`，**只能加不能减** |
| `灵田.格子`（`List<灵田格>`） | 每格一个 `灵田格` |
| `灵田.每行格数`（默认 3） | 只影响界面排版 |
| `灵田.升级品阶()` | 品阶 +1，**上限 `三阶上品`**（到顶返回 false） |

数值都从 `灵田品阶说明.中文名() / .产量倍率() / .生长倍率()` 取。

| 灵田品阶 | 能种到什么 | 产量倍率 | 生长倍率 |
|---|---|---|---|
| 一阶下品（初始） | 凡品 | ×1.00 | ×1.00 |
| 一阶中品 | 下品 | ×1.35 | ×1.12 |
| 一阶上品 | 中品 | ×1.70 | ×1.24 |
| …每上一阶 | | **+0.35** | **+0.12** |

**高品阶有三个好处**：能种更稀有的灵植、同样种子产得更多、长得更快。

### 2.1 内置灵植（`灵植库`）

| 名称 | 品阶 | 成熟 | 产量 | 需要灵田 | 种子物品 |
|---|---|---|---|---|---|
| 生灵草 | 凡品 | 3 天 | 2~5 | 一阶下品 | `item_seed_shengling` |
| 凝露花 | 凡品 | 3 天 | 1~3 | 一阶下品 | `item_seed_ninglu` |
| 清心莲 | 下品 | 5 天 | 1~3 | **一阶中品** | `item_seed_qingxin` |
| 赤焰芝 | 中品 | 7 天 | 1~2 | **一阶上品** | （暂无种子） |

定义**内置在 `灵植库` 代码里**（不走 CSV）；以后要挪到 `Assets/Data/Tables/灵植表.csv`，
**只需改 `灵植库` 一个类** —— `灵田` 和 UI 都只通过它取数据。加新灵植见 §6。

### 2.2 生长账本：累加 `已生长天数`

每格记**累加天数**，不是"种下的日期"；每帧按同一条时间尺度算出「过了多少游戏日」，
乘上生长倍率后累加。成熟 = `已生长天数 >= 灵植定义.成熟天数`。

> 【为什么不记日期】记日期的话，中途改「成熟天数」或升级品阶，**已种下的那批不会跟着变**，
> 会出现"同样两株草、一株 3 天熟一株 5 天熟"的怪事。**升级灵田立刻让所有在长的作物加速**。

## 3. 运行流程

### 3.1 播种（会消耗种子）

`灵田.能种(格号, 种子id, out 原因)` 检查三件事，任一不满足就**明确告诉你原因**（不是静默失败）：
1. 格子空不空
2. 灵田品阶够不够（`需要 下品 及以上的灵田（当前 一阶下品）`）
3. **背包里有没有对应的种子**（`没有「凝露花种」了 —— 种子靠任务奖励获得`）

`播种(格号, 种子id)` 成功后扣一颗种子。

### 3.2 一键收取（产物进背包）

`灵田.一键收取(out 明细)` 收掉所有成熟格并返回总株数；产量由 `灵植库.掷产量(定义, 品阶)` 随机。
产物走项目**唯一那条正式入口**：`QuestDatabase.物品库` 按 id 找定义 → `UIPanelData.给物品`；
任务奖励也走这条，所以灵田产出和任务发的**完全等价**（存档、面板、使用器都认得）。

> ⚠️ 物品 id 必须在 `Assets/Data/Tables/物品表.csv` 里存在，否则收成**进不了背包**（只打警告）。

### 3.3 点位与摆放

`灵田.摆到(世界位置, 朝向角度 = 0)` 直接摆放；场景里若存在名为 **`洞府灵田点位`** 的物体，
运行时按它摆 ⇒ **改位置只需挪场景里那个空物体，不用改代码**。

## 4. 界面（`灵田界面`，**F4** 开关）

| 部位 | 内容 |
|---|---|
| 标题行 | `洞府灵田 · 一阶下品` |
| 汇总行 | `已种 3/6　可收 2 格　产量 ×1.00　生长 ×1.00` |
| 按钮 | `[ 一键收取 ]` / `[ 关闭（F4） ]` |
| 格子区 | 每格显示 `1` / `可收` / `1.2/3`（已长/需长）/ `空` |
| 种子栏 | `[生灵草] [凝露花] [清心莲（下品）]` |

**交互是"先点种子、再点格子"** —— 比"每格一个下拉菜单"少一半点击，
而且**品阶不够的种子直接在选种子那步就锁掉**（灰色不可选），一眼看出为什么不能种。

点一个格子按状态分派：**成熟** → 直接收；**长着** → 提示还剩几天；**空格** → 用选中的种子种下。

### 4.1 ⚠️【坑】幕布没跟着面板关 → 所有 UI 点不动

画布下挂两层：**全屏幕布** + **居中面板**（面板挂在幕布下，幕布**不是**面板的子物体）。
只 `面板.SetActive(false)` 的话幕布还在，而它全屏 + `raycastTarget = true` +
`sortingOrder = 2600`（比所有 HUD / 角色面板都高）⇒ **吃掉全部点击，且 Console 无任何报错**。

修法：**打开 / 关闭 / 每帧兜底都调 `同步幕布()`**，让幕布显隐永远跟着面板；
更稳的是**让幕布当面板的父物体、只 SetActive 幕布**。完整分析与自检见 [踩坑总库 H25](../ai/踩坑总库.md)。

## 5. 存档（版本 8）

| 字段 | 说明 |
|---|---|
| `灵田品阶` / `灵田格数` | 对应 `灵田.导出(out 品阶值, out 格数存, out 格)` |
| `灵田格子` | 每格 `种子id\|已生长天数\|已收获`，空格写 `-`、倒序 `-` |

> `灵田格.导入` 会检查种子定义还在不在，**不在就清空那一格** —— 免得留下永远长不出来的僵尸格。
> `灵田.导入` 把品阶夹到 `1 ~ 三阶上品`、格数夹到 `>= 1`。

**老档（版本 < 8）走 `重置()`**（`品阶 = 一阶下品`、`格数 = 6`）而不是套 0：
版本 < 8 的档这些字段根本不存在，直接套会让"今天的机会"永远不发。

## 6. 怎么加一种灵植

1. 在 `灵植库` 里加一条 `灵植定义`：`种子id` / `品阶` / `成熟天数` / `产量下限·上限`。
2. 在 `Assets/Data/Tables/物品表.csv` 里加**产物物品**和**种子物品**两个 id。
3. 跑菜单「**修仙/从配置表生成资产**」。
4. 进游戏点开灵田界面确认：种子出现在种子栏、品阶不够时是灰的。

## 7. 坑与遗留

### 7.1 已知的坑

| 坑 | 规避 |
|---|---|
| 全屏幕布没跟着面板关 → 所有 UI 点不动 | `同步幕布()`（见 4.1） |
| 物品 id 不在 `物品表.csv` → 收成静默丢失（只打警告） | 加灵植时两个物品一起加 |
| **每帧重建网格会卡死**（顶点+三角重算 + GC） | `刷新一格` 里比对 `上次阶段[i]`，**相同就直接返回**，只在**阶段变化**时重建 |
| 存档里种子定义被删掉 → 僵尸格 | `灵田格.导入` 检查不到定义就清空那格 |
| 老档字段不存在 → 直接套 0 会让机会永远不发 | 版本 < 8 走 `重置()` |

### 7.2 还没做的

| 事项 | 说明 |
|---|---|
| **主线任务接线** | 大师兄"带你去后山、赠你灵种"的阶段还没加，要点见 7.3 |
| **真模型** | 灵田/灵植现在是程序化占位 |
| **灵田升级途径** | `升级品阶()` / `扩容()` 有接口，但还没有任务/贡献产出 |
| **护养类玩法** | 需求明确"无养护损耗、全天候自动生长"，暂不加 |

### 7.3 程序化外观（`灵田外观`）

| 部件 | 做法 |
|---|---|
| **土床** | 略微鼓起、带斜边的扁平台 |
| **土垄** | 每格一个小丘，让"这是一块地"看得出来 |
| **灵植** | 动漫风的"几片细长叶片"绕中心铺开，越长大越高、越外张 |
| **花** | 成熟时顶端结一圈小三角面（凝露花有） |
| **可收标记** | 头顶一个**永远朝向相机**的「可收」小标 |

不依赖美术资源；**生长阶段直接改网格**（幼苗 4 片短叶 → 成株 6 片 → 成熟 7 片 + 花），
换固定模型得准备 3 套模型；以后换真模型时只替换 `灵田外观` 里的建造函数。
材质按颜色缓存（`材质池`），共用几份材质，格子再多也不爆 draw call；一律
**Standard + 金属 0 + 光泽 0**，和「全局材质收敛」定的基准一致，不会在统一调色后显得突兀。
