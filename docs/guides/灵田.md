## 操作面板与教学衔接

地块操作窗使用 720×700 深色半透明底，F4 总览为 900×720，两者采用传法阁同款细线角饰 `UISectFineFrame`，由 `SpiritFieldPanelStyle` 构建，不再叠旧白纸金框。`InkUIRuntimeSkin` 排除这两个窗口。近距离地块牌使用深色墨晕底与浅色文字。

主线要求种下至少一块田，并关闭操作窗及总览后才进入下一段对白；之后休息、翌日黑幕和修炼小屋落点见[主线剧情](../design/主线剧情.md)。

## 1. 它是什么 / 在哪

洞府里的**挂机养成**设施，但**操作方式不是面板，而是自己把地摆下去、再走到地里去**。

- **开局一块地都没有**（0 块）。地是玩家在**个人洞府**里用 `item_lingtian_kaituo`（灵田开拓令）**一块一块摆出来的**。
- 摆下来的一块地**就是「待种植」的熟地** —— 已经起好垄、等着下种。
  **没有「荒地 / 待开发」这个状态了**：用户要求「把待开发的灵田的模型转变为**待种植**的灵田模型」，
  「开拓」这个动作 = **把地摆下来**。
- **每块地有自己的一套状态**：品阶、种了什么、长了多久，以及**摆在哪、朝哪边**。
- 玩法循环：**开垦（背包用开拓令 → 摆放态 → 左键放下）→ 走近按 F 种植 → 挂机等它长 → 成熟后回来按 F 收**。
- 没有浇水施肥（需求原文：「无养护损耗、全天候自动生长」）。
- **摆放这套机制已经泛化成「可摆放物」**：灵田只是其中一种。用户追加的需求原文是
  「让**木桩**也像灵田一样是**存在背包里、可以放置**的吧，注意这些东西都是**要能够存档**的哦」
  （追问后他选了「**能打的练功桩**」）⇒ 第二条可摆放物 = **练功木桩**（§4.5）。
  规矩是：**能不能摆**只有一份判定（`摆放校验`），**能摆什么**只有一张表（`摆放物库`）。

| 项 | 值 |
|---|---|
| **场景** | `3C_Testbed`（＝个人洞府）。**场景里没有任何灵田 / 摆设物体、也没有点位** —— 全是运行时按存档里的 `位置` 建的 |
| **允许摆放的场景** | `摆放校验.允许摆放的场景 = { "3C_Testbed" }`（**改名场景记得改这里**）。这个白名单原来挂在 `灵田` 上，泛化后移到 `摆放校验` |
| 能摆什么 | **`摆放物库` 目前两条**：`lingtian`（灵田地块，道具 `item_lingtian_kaituo` 灵田开拓令）+ `muzhuang`（练功木桩，道具 `item_muzhuang` 练功木桩） |
| 开局块数 | **0** —— 一块都不预置，第一块地要自己开垦 |
| 数据结构 | 灵田：`灵田.地块` 是 `List<灵田地块状态>`（每块地有自己的品阶 / 作物 / 生长）；非灵田摆设：`摆设.全部` 是 `List<摆设状态>`（只有类型 id + 位置 + 朝向档）。两个都由跨场景单例持有 |
| 挂载 | `灵田`（跨场景单例）与 `灵田界面`(F4) 由 `场景自举` 自动补；`灵田摆放器` / `摆设` 在第一次需要时自建（也带 `DontDestroyOnLoad`） |

> ⚠️ **只有「允许摆放的场景」才会生成地块 / 摆设视图**（也才用得了这些道具）。宗门 / 村庄 / 镇妖塔里
> **一件都不会生成**，但**灵田数据照旧在长** —— 这是刻意的，见 §2 的架构说明（也见踩坑 B57）。

## 2. 各角色分工，别混在一起

```
【能摆什么】摆放物定义（静态数据）→ 一种"能摆的东西"是什么：id / 名 / 道具id / 占地边长 / 占用边距 /
 │                              占用半边长(算出来的) / 模型路径(留空=外观由代码生成) / npc定义id / 是灵田
 ├─ 摆放物库       （静态表）    → **"能摆什么"的唯一清单**（目前 lingtian 灵田地块 / muzhuang 练功木桩）+ 按道具(道具id)
 ├─ 摆设状态       （可序列化）  → 一件摆设：类型id / 位置 / 朝向档 —— **它本身就是存档类型**（§8）
 └─ 摆放校验       （静态）      → **唯一的"这个位置能不能放"判定**：场景白名单 + 够平的地面 +
                                  没压住别的灵田 + 没压住别的摆设（跨种类）+ 没插进场景物件

【灵田那套】灵田（跨场景单例）→ 只存**灵田**数据 + 推进生长 + 摆放/挪动/种/收/升级的校验与执行
 ├─ 灵田地块状态   （可序列化）  → 第 i 块地的状态：位置 / 朝向档 / 品阶 / 作物id / 已生长天数
 ├─ 灵田规格       （静态常量）  → 尺寸与摆放几何：床边长 / 占用边距 / 吸附中心距 / 朝向档数 / SAT 重叠判定
 ├─ 灵田地块       （场景物件）  → 第 i 块地的**视图 + 信息牌 + 按 F 的交互**
 │   ├─ 灵田地块外观（静态工具）→ 土床网格 / 作物模型 / 材质 / 半透明"幽灵"预览
 │   └─ 灵田地块牌  （纯表现）  → 走近自动浮在田块上方的信息牌（带底板，不用按 F）
 ├─ 灵田界面       （F4）        → **只读**总览 + 一键收取
 └─ 灵田地块界面   （按 F 弹出） → **只针对这一块地**的操作窗

【摆设那套】摆设（跨场景单例）→ 只存**非灵田**的摆设（类型id / 位置 / 朝向档）+ 重建视图
 └─ 摆设物件       （场景物件）  → 把 `摆放物定义.模型路径` 那个 prefab 实例化出来，**别的什么都不做**

【两边共用】灵田摆放器（跨场景单例）→ **摆放态**：幽灵预览跟鼠标、R 旋转、左键放下、右键/ESC 取消（含退还道具）；
 │                                  模式 { 无, 开新地, 挪动, 摆摆设, 挪摆设 } —— 灵田与摆设走同一个摆放器
 └─ 摆放物件效果   （物品效果）  → 道具的「使用」入口：把关（只能在洞府）+ 交棒给摆放器；
                                   **两种道具共用这一个脚本**（靠 `摆放物id` 区分，见 §4.6）
```

> ⚠️ **`摆放校验` 是唯一的判定**，灵田与摆设**都调它**。以前灵田和摆设各判各的，结果
> **跨种类互斥不对称**（木桩插得进田里、田却盖不住木桩）—— 判定收成一份之后两个方向才一致
> （见 §4.4 与踩坑 B76）。**要加"什么情况下不能摆"的规则，只改 `摆放校验`。**

> ⚠️ **灵田与摆设是两个管理者，不是一套**：`灵田` 保留每块地那套丰富状态（品阶 / 作物 / 生长），
> `摆设` 只记 `类型id + 位置 + 朝向档`。硬把木桩塞进 `灵田地块状态` 会让一半字段对它毫无意义，
> 以后每加一种摆设就更脏一层。**要加一种"有自有状态"的新可摆放物时，先决定它归哪一边**（§4.6）。

### 为什么「数据」和「视图」必须分开

用户要的是「**走近某块地**、和它互动」，所以每块地都得是场景里的一个真物件。
但灵田同时又是 `DontDestroyOnLoad` 单例（**逻辑要跨场景继续长**）。
把地块视图挂在单例上，切场景时那一片土床就会**跟着玩家留在宗门里** ——
这正是用户报过的「Sect 里有个棕色的片状物」（踩坑 B57）。

现在的分工从结构上杜绝了这件事：

| | 存活范围 | 谁建 |
|---|---|---|
| **状态** `灵田地块状态` | 跨场景（`灵田` 单例里） | 开局 / 读档 |
| **视图** `灵田地块` + 外观 | **当前场景** | `灵田.重建视图()` 每次进场景重建，**且只在允许摆放的场景建** |

⇒ 「跨场景继续长」和「外观只在洞府出现」两件事天然不冲突，
**不需要靠 `SetActive` 兜底**（更早的版本就是这么兜的，因为视图挂在单例上）。

> ⚠️ **尺寸数字的唯一真相源**：`灵田规格` 管**灵田**的尺寸与摆放几何（`灵田地块外观` 照它造土床网格、
> `灵田摆放器` 照它算吸附位置），`摆放物定义` 管**每一种摆放物**的 `占地边长` / `占用边距`
> （`lingtian` 那一条直接引用 `灵田规格` 的常量，不另抄一份数）。
> 分散在各处各写一套数字，早晚出现"看着没挨着、却提示压住了"这种对不上的 bug ——
> **改一个就要重算另一处**，见 §4.4。

> ⚠️ **改数据只走 `灵田` / `摆设` 上那几个方法**（`放置 / 挪动 / 播种 / 收一块 / 升级`）。
> `灵田地块界面` 与 F4 总览都只是调用者 —— 校验与执行**只有一份**，
> 免得两个入口各写一套规则、出现「面板里能种、地里不能种」这种不一致。

## 3. 数据模型：`灵田地块状态`

| 字段 | 说明 |
|---|---|
| `位置` | 世界坐标 `Vector3`（玩家摆放时定的） |
| `朝向档` | **0~7**，每档 45°。档位化（而不是直接存角度）是为了让吸附只比整数、存档也不会因浮点误差漂移 |
| `品阶` | **这一块地自己的** `灵田品阶`（一阶下品 … 三阶上品，9 档） |
| `作物id` | 种着的灵植 id（`灵植库` 的 id）。空 = **待种植** |
| `已生长天数` | 已经长了多少**游戏日**（按**这块地的**生长倍率算过） |

派生量（都是算出来的，不存）：

| 属性 | 含义 |
|---|---|
| `待种植` | `作物id` 是空的 —— **刚放下的地就是这种状态** |
| `已成熟` | `已生长天数 >= 植.成熟天数`。**成熟天数是灵植自己的，不乘品阶倍率** |
| `进度` | `已生长天数 / 成熟天数`，0~1 |
| `剩余天数` | 还差几天熟（已熟 = 0） |
| `阶段` | **0 待种植 · 1 幼苗 · 2 成长 · 3 成熟** —— 外观按它换模型 |
| `阶段名` | 待种植 / 幼苗 / 成长中 / 已成熟（信息牌用） |

> **为什么用「累加天数」而不是「记种下的日期」**：记日期的话，中途升级这块地、
> 或改「成熟天数」，**已经种下的那批不会跟着变**，会出现
> 「同样两株草、一株 3 天熟一株 5 天熟」的怪事。累加式天然自洽：**升级这块地立刻让这块地上的作物加速**。

> **不是灵田的东西不在这个类里**：练功木桩这类非灵田摆设走 `摆设状态`
> （只有 `类型id` / `位置` / `朝向档`），没有品阶 / 作物 / 生长 —— 见 §4.5 与 §8。

### 品阶（每块地一份）

数值全部来自 `灵田品阶说明.中文名() / .产量倍率() / .生长倍率()`：

| 灵田品阶 | 能种到 | 产量倍率 | 生长倍率 |
|---|---|---|---|
| 一阶下品（初始） | 凡品 | ×1.00 | ×1.00 |
| 一阶中品 | 下品 | ×1.35 | ×1.12 |
| 一阶上品 | 中品 | ×1.70 | ×1.24 |
| …每上一阶 | | **+0.35** | **+0.12** |

灵植也有品阶门槛，`灵植库.可种(植, 地的品阶)` 判的就是 `(int)地的品阶 >= (int)植.品阶`。

## 4. 怎么玩

### 4.1 开垦：在背包里用「灵田开拓令」

1. 拿到 `item_lingtian_kaituo`（**灵田开拓令**）。它的**正规来源是宗门贡献兑换（未做）**，
   验功能可用 **F1 面板发放物品**；主线「收下灵种与开垦令」也会发 **4 枚**。
2. **在个人洞府里**打开背包点它的「**使用**」。
   在别的场景按钮是**灰的**，并把原因写在旁边：**「灵田地块只能在个人洞府里摆放（当前在「Sect」）」**
   （这句话由 `摆放物件效果.不能用原因()` 按 `摆放物定义.名` 拼出来，所以每种可摆放物都自动对）。
3. **不弹配置面板** —— 直接进**摆放态**：地面上浮起一块**半透明的灵田**（**绿 = 能放 / 红 = 不能放**）。
4. 鼠标在地面上滑动（预览跟着走，靠近已有田块会**自动吸附**，见 §4.4）；
   **R 转一档朝向**（共 **8** 档、每档 45°；`Q` 反向转一档，`E` 同 `R`）。
5. **左键放下** ⇒ 出现一块**待种植**的地；同时**它和它周围一圈（占用边距 0.35 米）被标记为不可摆放**。
6. **右键 / ESC 取消** ⇒ 退出摆放态，**开拓令退回背包**。

**别的可摆放物走的是同一条路**：练功木桩也是在背包里用 `item_muzhuang` → 同一个摆放态（见 §4.5）。

摆放态**没有面板**，屏幕底部只有一条**极简提示**（不挡操作、不用点）：按键说明、
当前朝向（第 n/8）、以及**为什么现在这个位置放不了**。

> 【取消为什么要退道具】道具是在**背包里点「使用」那一刻**就被框架扣掉的
> （`物品使用器.使用()`：效果返回 true → 扣一件），"进入摆放态"和"真的摆下去"是两件事，
> 玩家完全可能进去看一眼就取消。所以 `灵田摆放器.取消()` 必须把道具**还回去** ——
> **退还的是"这一种摆放物的 `道具id`"**（灵田 → 开拓令，摆设 → 那种摆设自己的道具）。
> ⚠️ **只有真的扣过才退**：摆放器用一个 `道具已扣过` 标志记录"进来时道具是不是已经被扣了" ——
> **挪动**不涉及道具，调试时直接调进来（没扣）也不会"取消一次白送一张"。

### 4.2 走近按 F：只有四件事

**走近就自动看见信息牌**（§7.2，带底板，不用按 F）。
按 **F** 弹出**只针对这一块地**的小窗（`灵田地块界面`）：

| 这块地的状态 | 主按钮 |
|---|---|
| **待种植** | 列出 `灵植库` 里的灵植，**这块地种不了的直接置灰并写明原因**（品阶不够 / 没种子）；选一株 →「种下」 |
| **长着** | 显示 `生长进度 % / 还需几天 / 这块地的倍率`，主按钮是灰的「还没熟，再等等」 |
| **成熟** | 「收获」——产物按 `灵植库.掷产量(植, 这块地的品阶)` 随机，**进背包** |

窗底还有**两个常驻按钮**：

| 按钮 | 行为 |
|---|---|
| **挪动地块** | 把这块地**拿起来重摆**（进摆放态）。**不退道具、也不多花** —— 用户选的「能挪位置，但不退道具也不多花」。挪动时**这块地自己不参与重叠判定**（否则它会挡住自己） |
| **升级这块地** | 见 §4.3。条件不够就把原因写在下面（"境界不足：需要 3 级（当前 1 级）"这种） |

> 用户 2026-10-01 定死了这里的内容：「按 F **只有种植/收获/挪动地块**」；
> 加上他之前选的"**走到地前按 F 把这块地升品阶**"（升阶令），窗里一共四件事。
> **原来那个「开拓」没了** —— 开拓已经变成"从背包用开拓令把地摆下来"。

「这块地什么情况」不在这里重复：那是**信息牌**的活（走近就看得见），所以这个窗刻意做得小。
**挪动时会把这个窗关掉** —— 摆放态要看地面和鼠标，窗（尤其那块全屏幕布）会挡住画面和点击。

### 4.3 升级这块地的代价

| 操作 | 代价 | 门槛 |
|---|---|---|
| **升级地块** | `item_lingtian_ling`（灵田升阶令）× **`2 + 当前阶`**（升 2 阶 3 张、3 阶 4 张……） | **境界等级 ≥ `3 × 当前阶`** |

- 升到 **一阶上品**时**附赠 `item_seed_chiyan`（赤焰芝种）×2** ——
  赤焰芝要一阶上品才种得下，不给种子这条链就断在这儿。
- ⚠️ **升阶令现在游戏里拿不到**：它按设计由**宗门贡献兑换**，而兑换系统还没做。
  验功能可以直接用 **F1 面板发放物品**（物品表里有它）。
- 换兑换物只需改 `灵田.升阶令id` **一处**。

> 【为什么消耗是升阶令而不是灵草】用户 2026-10-01 明确：
> 「灵田升级**不消耗灵草**，消耗之后在**宗门贡献处兑换**的道具」。

### 4.4 摆放规则（灵田与**所有**可摆放物通用）

**摆放只有一套流程**：背包里用道具 → 进**摆放态** → 左键放下。灵田开拓令与练功木桩走的是同一条路，
区别只在"摆的是哪个 `摆放物定义`"。

摆放态里只有这几个键：

| 键 | 作用 |
|---|---|
| 鼠标移动 | 预览跟着走；靠近**同种类 + 同朝向**的东西会**自动吸附** |
| `R` / `E` | 正向转一档朝向（`E` 同 `R`） |
| `Q` | 反向转一档朝向。共 **8** 档、每档 45° |
| 左键 | 放下 |
| 右键 / `ESC` | 取消，**把道具退回背包**（只有真的扣过才退，见 §4.1） |

**「这个位置能不能放」只有一份判定**：`摆放校验.位置可用(定义, 位置, 朝向档, out 原因, out 地面高, 忽略灵田, 忽略摆设)`。
灵田与摆设**都调它**，所以跨种类互斥是对称的 —— 木桩插不进灵田，灵田也盖不住木桩。
任一条不过就把原因写在底部提示里：

1. **在允许摆放的场景里**（`摆放校验.允许摆放的场景 = { "3C_Testbed" }`，否则是"只能在个人洞府里摆放"）；
2. **底下是够平的地面** —— 向下探地，坡度 ≤ `最大地面坡度 = 15°`，且和地面高差 ≤ 0.6 米；
3. **没压住别的灵田**；
4. **没压住别的摆设**（跨种类也算 —— 木桩 / 灵田互相都算）；
5. **没插进场景里的东西**（树 / 岩石 / 建筑）。

⚠️ **探地必须用 `RaycastAll` 取最低那个命中，不能用单发 `Raycast`**：已经摆好的摆设**是有碰撞体的**
（木桩要能被打就必须有），单发射线会先打到木桩身上，于是报出「这里和地面差太多」这种牛头不对马嘴的原因。
射线上的摆设自己与玩家（`CharacterController`）都要跳过。见踩坑 **B74**。

**判 5 用的是物件本身的半边长、不含占用边距** —— 边距是给别的**可摆放物**留的过道，
拿来判场景物件的话，旁边一根细木桩就能让整块地摆不下去。**判 3 / 4 才用含边距的 `占用半边长`**。

**每种的占地尺寸来自 `摆放物定义`**（`占用半边长 = 占地边长 / 2 + 占用边距`）：

| 摆放物 | 占地边长 | 占用边距 | 占用半边长 | 任意摆放最小中心距 | 吸附中心距 |
|---|---|---|---|---|---|
| `lingtian` 灵田地块 | **1.9 m** | **0.35 m** | **1.30 m** | **2.60 m** | **2.70 m** = `1.9 + 0.8` |
| `muzhuang` 练功木桩 | **0.6 m** | **0.3 m** | **0.60 m** | **1.20 m** | **1.40 m** = `0.6 + 0.8` |

灵田的其它几何量（都在 `灵田规格.cs`）：

| 量 | 值 | 说明 |
|---|---|---|
| 床边长 | **1.9 m** | 正方形土床 |
| 床顶 / 垄高 / 垄数 | **0.10 / 0.08 / 3** | 床面离地高度 / 垄鼓起多少 / 3 条垄（作物种在垄顶） |
| 对齐间隙 | **0.8 m** | 吸附成一排时两块之间的过道宽度 |
| 吸附距离 | **0.9 m** | 鼠标离候选点多近才吸过去。给得比间隙小，免得"离得老远就被吸走" |
| 朝向档数 | **8** | 每档 45° |

**重叠判定用 SAT（分离轴定理），不是圆圈**：把两件东西（各自含占用边距）的 **4 条法线**都当候选轴，
只要在某一根轴上投影不重叠，就一定没压住。**两边的半边长各给一份**
（`灵田规格.压住(..., 甲半边, ..., 乙半边)`）—— 灵田 1.30 与木桩 0.60 差很多，
用同一个数判会出现"木桩明明在田外却算压住"或者反过来漏判。

> 【为什么不用圆圈近似】方块转 45° 时**外接圆比内切圆大 40%**，
> 用圆判会把**明明能并排摆下的两块地判成压住**；用户要的正是整齐并排。

**吸附**（`灵田摆放器.吸一下()` + `灵田规格.吸附候选()`）：
摆放时若附近有**同种类、且 `朝向档` 完全相同**的东西，就从它的 ±X / ±Z 四个方向各取一个候选点，
**候选点离鼠标 ≤ `吸附距离 0.9` 米**就吸过去。
吸过去之后按新的 XZ **重新探一次地**取地面高度（相邻地面可能不一样高）。

- **只吸同种类 + 同朝向**（用户要求「**同一个朝向**的同种物品」）。不同朝向、或不同种类**都不吸附** ——
  它们本来也排不成一条整齐的边。
- **吸附中心距按各自的占地算**（`灵田规格.吸附中心距_按(占地边长)` = `占地边长 + 对齐间隙`）：
  灵田 2.70、木桩 1.40。统一用灵田那套数会让木桩"离得老远就被吸过去"。

### 4.5 练功木桩（第一个**非灵田**的可摆放物）

用户要的是一条**能打**的桩：像灵田一样存在背包里、可以放置、能存档。

| 项 | 值 |
|---|---|
| 物品 | **`item_muzhuang` 练功木桩**（黄品）。物品表：`可使用=1` / `效果类型=摆放物件` / `效果参数id=muzhuang` |
| 摆放 | 和灵田走**同一个摆放态**（同一个 `灵田摆放器`）：鼠标移动 / `R` 转 8 朝向 / 左键放下 / 右键取消退道具；同样**只能在个人洞府**里摆 |
| 占地 | 占地边长 **0.6** / 占用边距 **0.3** ⇒ 占用半边长 **0.60** |
| 放下之后 | 是**一个真 NPC**：prefab 自带 `NpcInstance` + `CapsuleCollider` + `NpcIndicator`（血条）⇒ 能打、有血条 |
| 数值与行为 | **不在摆放系统里**：全部来自 `NPC表.csv` 的 `monster_wooden_dummy`（`阵营=中立` / `气血=10000` / `死亡后立即重生=是` / 重生延迟 0 ⇒ 打空立刻满血） |
| 存档 | 只存 `类型id / 位置 / 朝向档`。**木桩的当前血量故意不存** —— 打空立即满血，没有需要记住的状态（§8） |

> **摆放系统只解决"它在哪里"，"它是什么"由 NPC 表决定。** 想换一个能打的桩
> （换成会还手的、换血量的），改 `NPC表.csv` 里那条定义即可，摆放这边一行都不用动。

**实测（Play 模式）**：用一次道具 → `摆放中=True 预览=True 预览碰撞体=0 预览活逻辑=0 道具 3→2`；
放下后 `摆设数=1 幽灵还在=False`；那根桩 `NpcInstance=True 启用=True Collider=True 血条=True
★MaxHealth=10000 血量比例=1.00 定义=练功木桩 阵营=中立 打空即重生=True`。

#### 模型必须是 Resources 下的 prefab（★ 这是唯一的硬约束）

| 项 | 说明 |
|---|---|
| 加载方式 | `摆设物件` 用 `Resources.Load<GameObject>(摆放物定义.模型路径)` 取 prefab，所以 **prefab 必须在某个 `Resources` 目录下** |
| 木桩放哪 | **`Assets/resources/摆设/练功木桩.prefab`**（`模型路径 = "摆设/练功木桩"`，不带扩展名） |
| 它是什么 | 它是 **`Assets/Prefabs/Npc_WoodenStake.prefab` 的 Prefab Variant** —— 原 prefab 留在原地当**唯一真相源**（改它，Resources 那份跟着变） |
| 为什么要绕这一下 | **原 prefab 不在任何 `Resources` 目录下** ⇒ 运行时 `Resources.Load` 拿不到它，以前只能**手工摆进场景**。做代码加载就得有一份在 Resources 下，而"复制一份"会立刻分叉成两个真相源 |
| 找不到会怎样 | `摆设物件` **明确报 Warning** 并说清"确认它在某个 Resources 目录下"，不会静默消失 |

> ⚠️ **预览会实例化这个 prefab，所以实例化之后要做两件事**：
> **① 去掉所有碰撞体**（否则鼠标射线打到预览自己）；**② 停掉所有 `MonoBehaviour`**
> （`enabled = false`）—— 木桩的预览如果还跑着 `NpcInstance` / AI / 血条，它**会自己动、还顶着一根血条**，
> 而那只是个"瞄准用的影子"。见踩坑 **B75**、B71。

### 4.6 怎么加一种新的可摆放物

**两步数据 + 一次导入，效果脚本一行都不用改**：

1. **`摆放物库` 加一条**（`Assets/Scripts/SpiritField/摆放物定义.cs` 的 `确保()` 里）：
   `id`（存档里存的就是它）/ `名` / `道具id` / `占地边长` / `占用边距` /
   `模型路径`（`Resources` 路径，**留空 = 外观由程序化代码生成**，灵田就是这种）/ 
   `npc定义id`（可选，摆下来顺带生成一个 NPC，木桩就是这么做的）/ `是灵田`。
2. **`Assets/Data/Tables/物品表.csv` 加一行**：新道具 `可使用=1`、`效果类型=摆放物件`、
   `效果参数id = <第 1 步的 id>`，然后跑菜单 **「修仙/从配置表生成资产」**。
3. **模型放进 `Resources`**（例 `Assets/resources/摆设/<名>.prefab`，路径写进 `模型路径`），
   或者留空走程序化外观。用现成 prefab 又不想复制真相源时，用 **Prefab Variant**（§4.5）。
4. **不需要改效果脚本**：`摆放物件效果` 只认 `摆放物id`，所有可摆放物共用它；
   `物品效果导入.cs` 的 `摆放物件` 分支也只按 `效果参数id` 填这一个字段
   （**查不到就 `Debug.LogWarning`**，不会静默留空）。

> 想摆的是"有自有状态"的东西（像灵田那样有品阶 / 生长）时，还要决定它归 `灵田` 还是 `摆设`
> —— 两者是两个管理者（§2）。`摆设` 只记类型 + 位置 + 朝向，没有第三条状态。

### 4.7 为什么灵田的操作在「地里」而不是「面板里」

用户 2026-10-01 原话：

> 「我希望是一个很完整的灵田系统，**可以直接和灵田互动、选择种植什么作物**，
>   而不是**现在一个面板控制一片田地**。」

所以种植 / 收获 / 挪动 / 升级**全部下放到地块**，F4 那个面板降级成只读总览（§5）。
**开垦**则更彻底 —— 它连"走到地里"都不需要，直接在背包里用开拓令摆（§4.1）。

按 **F4** 开一个总览窗，**只做两件事**：看全局 + 一键收取。

```
┌────────────────────────────────────────────┐
│ 洞府灵田 · 总览                             │
│ 地块 4　待种植 1　已种 3　可收 1            │
├────────────────────────────────────────────┤
│  1 块田　一阶下品 　生灵草　51%（还需 1.5 天）│
│  2 块田　一阶中品 　凝露花　57%（还需 1.3 天）│
│  3 块田　一阶下品 　已成熟 ← 可收            │
│  4 块田　一阶下品 　待种植（走近按 F 播种）   │
│ …                                          │
│ 操作要点：走近某块地按 F 就能种植/收获/挪动/  │
│ 升级这一块地；想开新地用背包里的「灵田开拓令」│
├────────────────────────────────────────────┤
│ [ 一键收取全部成熟 ]          [ 关　闭 ]    │
└────────────────────────────────────────────┘
```

**一块地都没有时**（开局就是这种状态）总览不显示空清单，而是**给开垦步骤**：
「还没有灵田 / 在背包里找到「灵田开拓令」点使用 → 鼠标变成半透明灵田 → 在洞府里找块空地放下

留着它的理由：**挂机玩法不该强迫玩家跑图** —— 站在宗门也能一眼看到每块地各自什么情况，
并且**一键收取**（纯收割，不算操作玩法）。
**播种 / 挪动 / 升级不在这里**，必须去地里。

> ⚠️ 清单里「待种植 / 可收」是用 `<color>` 富文本标出来的。
> `UIBuildUtils.CreateText` **默认 `supportRichText = false`**，
> 所以这里显式打开了 —— 不开的话标签会**照字面显示**成 `<color=#FFD96A>…`（实测踩到，见踩坑 B64）。

## 6. 生长是怎么推进的

`灵田.Update()` 每帧做一次：

```csharp
float 现在 = 时间管理器.取().总天数;
float 增量天 = 上次总天数 < 0f ? 0f : 现在 - 上次总天数;   // 首帧只对齐
上次总天数 = 现在;
if (增量天 <= 0f) return;                                  // 没动/倒退（读档、重置）都不长
推进生长(增量天);                                          // 每块地各乘自己品阶的倍率
```

**关键点**：增量取的是**时间管理器总天数的帧间差**，不是 `Time.deltaTime ÷ 秒每天` 反算。

> 原因见踩坑 **B58**：`时间管理器.推进()` 允许**一次跨好几天**
> （「推进天数」任务动作 / 大倍率 / 读档补时间），拿现实时间反算会把这整段跳变丢掉 ——
> 实测「过了一夜」之后草一点没长。生长按**帧**推进（而不是「跨天才长」），
> 这样种下的那一刻就开始长，不用等到跨天。

## 7. 外观、信息牌与素材

### 7.1 三种长相 —— 模型**必须跟着状态变**

| 状态 | 长相 |
|---|---|
| **待种植** | **翻好的深沟**（垄高 0.14）+ 干土色（`灵田待种植土`，染色 `(1.14,1.12,1.06)`）—— 轮廓和颜色都写着"这块等着种" |
| **已种植** | **正常的浅垄**（垄高 0.08）+ 深色湿土（`灵田土床`，染色 `(0.86,0.84,0.80)`）+ 3 株作物模型，随阶段换 `sprout / young / mature` |
| **成熟** | 作物换成成熟模型 + **信息牌底板描金**（§7.2）；土床不变 |

⚠️ **刷新必须每帧同时判"土床材质 + 网格 + 作物阶段"三样**：`灵田地块.Update()` 每帧调
`灵田地块外观.刷新()`。只在 `Start()` 里建一次外观、或每帧只管作物，都会变成"状态变了、长相不变"。

⚠️ **两种状态的区分靠"网格 + 亮度"，不能只靠一点点颜色差**：偏色染色（`1.18/1.10/0.92` 那种暖色）
乘到土质贴图上会把畦烧成**亮橙色**，既不像土、远看又分不出来。三点一起定：

1. **两个不同的网格**（`床网格(true/false)`）—— 待种植垄高 0.14、已种植 0.08，**轮廓**就变了；
2. 染色改成**中性**（R≈G≈B）—— **别再用偏色染色**，要区分就靠"亮度 + 网格"；
3. 作物 **`株缩放` 1.75 → 2.4**（幼苗原来只有 0.14 米高，摆在 1.9 米的畦上就是几个小点）。

### 7.2 信息牌 `灵田地块牌` —— 走近自动显示，**带底板**

用户 2026-10-01 的要求：

> 「现在只有按 F 才会显示灵田信息，我希望**走进后就能显示在灵田上方**，
>   同时**不要是纯文字，加个底板**，按 F 只有种植/收获/挪动地块。」

| 项 | 做法 |
|---|---|
| 形态 | **世界空间 Canvas**（不是 `TextMesh` 那种裸字），`sortingOrder 210`（比 `StationInteractor` 的提示 200 高一档） |
| 尺寸 | `480 × 92`、缩放 `0.004` ⇒ 世界宽 **1.92 米**（刚好和 1.9 米的畦一样宽） |
| 内容 | **底板 Image**（深色 `(0.05,0.06,0.08) @ 0.95`）+ **两行字**：`第N块田 · 品阶` / 状态。**底板不挂 Outline**；两行字各自带**黑色描边** |
| 朝向 | 每帧面向相机（billboard） |
| 高度 | 田块中心上方 **1.65 米** —— 要避开挂在玩家头顶（约 2.1 米）的通用键帽提示框，实测压在一起过 |
| 可见性 | **离玩家 ≤ 5.7 米才显示，超出整个关掉**（`SetActive(false)`）。**不做"半透明淡出"** |
| 提示状态 | **已成熟时底板描金**（深金底），远远扫一眼就知道哪块能收 |
| 与通用提示的关系 | 分工：**信息牌报状态、键帽提示报操作**。所以地块的 `StationInteractable.显示靠近提示` 是 **`true`**，而信息牌里**不写 `[F]`**（之前反过来做，用户反馈"靠近灵田没有按 F 的提示了"） |

⚠️ 【两个坑·都踩过】

1. **"按距离淡出"不能留"最低不透明度"**：上一版把底板 alpha 的下限设成 **0.35** ⇒ 玩家一离远，
   每块田上方都留着一片 35% 不透明的深色板子浮在半空，看上去就像**地还是半透明的**
   （用户原话："放下去之后怎么还是透明的"，实测底板 alpha 就是 `0.350`）。
   正确做法是**要么清楚地显示、要么完全不显示**，没有"半吊子"这一档。
2. **"走近没走近"必须按玩家算，不能按相机算**：相机跟在玩家后上方好几米，
   用 `Camera.main` 的位置量距离时，玩家已站到田边（离田 2 米）而相机离田还有 6~8 米
   ⇒ 牌子被判成"太远"**一次都不显示**。见 `灵田地块.取玩家()`。

> ⚠️ 字色**不要只按"预期的底板颜色"去配** —— 上一版给底板挂了淡黄描边，整块板渲染成发黄的半透明片，
> 浅黄标题压在上面根本读不出来（用户："面板用的字颜色不太搭配幕布，有点分不出来"）。
> 现在两行字**自己带深色描边**，不管底板最终是什么颜色都读得出来。

### 7.3 土床**故意没有碰撞体**（★ 别"顺手补上"）

给土床加 `MeshCollider` 之后**玩家会被卡在田里走不动**，也就走不到里面的地块按 F。
原因是空间余量太小：

| 量 | 值 |
|---|---|
| 土床尺寸 / 高度 | 1.9 m 见方 / **0.18 m 高**（床顶 0.10 + 垄高 0.08） |
| 相邻两块地的过道 | 最小中心距 2.60 → **0.70 m**；吸附排 2.70 → **0.80 m** |
| 玩家胶囊 | `CharacterController` 实测 `radius = 0.300 / height = 1.800` ⇒ **直径 0.6 m** |
| `CharacterController.stepOffset` | **0.300 m** |

⇒ 0.7~0.8 米的过道塞 0.6 米的胶囊容错极小；土床虽然只有 0.18 米高（低于 `stepOffset`），
但它是**斜裙边 + 起垄的网格**，不是台阶，照样顶住。

**所以土床不加碰撞体**（`灵田地块外观.建造()` 里 `挂网格体(..., 加碰撞: false)`）。
走在上面只是**脚陷进去一点点**，第三人称俯视角基本看不出来；换来的是"**整片田随便走**"。
见踩坑 **B67**。

> 同理：摆放态的**幽灵预览也没有碰撞体**（`造幽灵` 传 `加碰撞: false`，
> 那 4 根 `CreatePrimitive` 造的边界条一造出来就 `Destroy` 掉 `Collider`）——
> 否则鼠标射线第一个打到的就是预览自己。见踩坑 **B71**。

### 7.6 土床是**程序化**的 —— 因为它那边没有田块模型

参考项目的 `environment/soil/` 里**只有土质贴图**，**没有田地的 3D 模型**
（那块地是它用 Godot 的 shader/网格自己铺的；只有一个 Godot 专用的 `patches.res`，Unity 用不了）。

所以土床由 `灵田地块外观.造畦网格(垄高)` 按网格生成：
**床面按余弦起垄（3 条垄）+ 四周斜裙边落到地面**，贴它的土质贴图。
"待种植 / 已种植"用的是**两个网格**（`床网格(true)` 垄高 0.14 / `床网格(false)` 垄高 0.08），
再加上两种土色材质 —— 见 §7.1。

> ⚠️ 【坑·已修】裙边**不能**照抄床面边缘的 UV：那样 v 恒为 0 或 1，
> 等于只取贴图的一行再竖着拉满整个侧面，实测侧面会变成一片竖向条纹（像木板不像土）。
> 侧面必须按**自己的长宽**铺 UV（见 踩坑 B65）。

### 7.7 材质与面数

- 一律 **Standard + 金属 0 + 光泽 0.05**，和「全局材质收敛」定的基准一致
  （见 [画面统一调色](画面统一调色.md)），统一调色后不会显得突兀。
- **每块地 3 株作物**（三条垄顶各一株），用**「作物id + 阶段」当随机种子**做抖动 ——
  **不能用 `Random`**，那样每次切场景草的位置都会跳。
- **只在"阶段变化"时重建作物模型**（不是每帧 —— 每帧 `Instantiate` 会卡死）；
  土床网格、材质**全局共享**（静态缓存），地块再多也不重复造。
- 模型在导进来时**已经减过面**（`TARGET_TRIS = 1000`）：原始模型一个阶段 3~6 万面，
  一块田几十株会同时压垮渲染和仓库体积。现行资源分类见[资产与目录](../architecture/资产与目录.md)。

## 8. 存档（**版本 12**）

**摆下来的东西分两张清单存**（灵田一套状态、非灵田摆设一套）：

| 字段 | 格式 |
|---|---|
| `SaveData.灵田地块` | **`List<灵田地块状态>`** —— `JsonUtility` 直接序列化对象，**不再打包成字符串** |
| 每条地 | `位置`(Vector3) + `朝向档`(int) + `品阶` + `作物id` + `已生长天数` |
| `SaveData.摆设`（**v12 新增**） | **`List<摆设状态>`** —— 每件：`类型id`(string) + `位置`(Vector3) + `朝向档`(int 0~7)。**练功木桩就在这里面** |

- `灵田.导出()` / `灵田.导入(List<灵田地块状态>)`；`摆设.导出()` / `摆设.导入(List<摆设状态>)`。
  **两个状态类本身就是存档类型**（`[System.Serializable]`），所以都不用再做字符串打包。
- ⚠️ **`灵田地块状态` 与 `摆设状态` 的字段都必须保持 `JsonUtility` 兼容**
  （`string` / `float` / `int` / `Vector3`）—— **别加 `Dictionary` / 接口 / 属性**，否则存档会**静默丢失**。
- **木桩的当前血量故意不存**：它打空就立即满血（`NPC表.csv` 里 `死亡后立即重生=是`），
  没有需要跨存档记住的状态。存了反而会与"打空自动满血"打架。
- 两边导入时都会**丢掉已经不存在的定义**：`灵田地块状态.导入` 检查作物定义还在不在、不在就清空那块地；
  `摆设.导入` 检查 `摆放物库` 里还有没有这个 `类型id`、没有就丢弃那一件（都带 Warning）——
  免得留下永远长不出来的僵尸地块 / 僵尸摆设。`朝向档` 都会被 clamp 到 `0 ~ 朝向档数-1`。
- 读档后 `上次总天数 = -1f` 重新对齐，**别把「读档」当成「过了很多天」**。

> **版本 12 延续了 v11 的口径**：v10 是「固定 12 块地 + 每块一行字符串
> `已开拓|品阶|作物id|已生长天数`」，v11 起**每块地带自己的位置与朝向**、对象直接序列化；
> v12 只是**多一张摆设清单**，字段本身没有变化。
> **版本 < 12 的老档走重新开局**（用户已明确「不用补老档兼容，老档可以全部删掉」），
> 见 [存档系统](../design/存档系统.md)。

> **实测（Play 模式）**：摆下木桩后 `存档 v12 摆设条数=1 类型=muzhuang 位置=(2.0,0.0,0.0)`；
> 往返读档后 `摆设=1 视图=1 实例=练功木桩`。

## 9. 怎么加一种灵植（含它的 3D 模型）

1. **模型**：导入已经处理好的低面数模型、材质和贴图，放入灵田资产分类，按灵植 id / 阶段命名并维护 prefab 引用。
2. **数据**：在 `Assets/Scripts/SpiritField/灵植定义.cs` 的 `灵植库.确保()` 里加一条 `灵植定义`：
   `id` / `名` / `品阶` / `成熟天数` / `产量上下限` / `产物id` / `种子id`。
3. **物品**：在 `Assets/Data/Tables/物品表.csv` 里加**产物物品**和**种子物品**两行，
   跑菜单 **「修仙/从配置表生成资产」**（否则产物 id 不在物品库里，收成会**静默丢**）。
4. **验证**：进游戏在洞府里摆一块地（或用 F1 发开拓令自己开一块），走近按 F，
   看这株在种子列表里、品阶不够时是灰的；
   种下后应能长出**3 株**模型（幼苗），推进时间后换成成长/成熟模型。

> 模型加载路径是 `Assets/resources/灵田/<灵植id>/<灵植id>_<阶段>`（`sprout/young/mature`），
> 由 `灵田地块外观.载模型()` 用 `Resources.Load` 取。
> 找不到会**明确报 Warning**，不会静默变成空地。

## 10. 坑与遗留

### 10.1 已知的坑

| 坑 | 规避 |
|---|---|
| 视图挂在 `DontDestroyOnLoad` 单例上 → 跑到别的场景 | **数据与视图分开**，视图每场景重建、且只在允许摆放的场景建（§2 / 踩坑 B57） |
| 状态变了模型不变（"开拓完田的模型没有改变"） | 土床材质也纳入**每帧刷新**，别只在 `Start()` 建一次（§7.1） |
| 给土床加碰撞体 → 玩家卡在田里走不动 | **故意不加碰撞体**（§7.3 / 踩坑 B67） |
| 生长用 `Time.deltaTime` 反算 → 时间跳变整段丢失 | 取 `时间管理器.总天数` 的**帧间差**（§6 / 踩坑 B58） |
| 全屏幕布没跟着面板关 → 所有 UI 点不动 | 地块窗把**幕布和面板建在同一个根**，关窗 = 销毁整根；总览靠 `同步幕布()` 每帧兜底（§5 / 踩坑 H25） |
| 富文本标签照字面显示 | `CreateText` 默认关了富文本，要显式打开（§5 / 踩坑 B64） |
| 模型所在目录有同名 FBX 时 `Resources.Load` 会挑错 | `载模型()` 里再用 `Resources.LoadAll` 按名字挑一次（项目踩过这个坑） |
| 两块地摆到**最小中心距**时，站中间会同时够到两块 | `灵田地块.交互距离 = 2.6`（= 最小中心距 2.60）；`StationInteractor` 取**最近**的那块，信息牌也各显各的 —— 站中间按 F 开的是更近的那块 |
| 幽灵预览自己有碰撞体 → 鼠标射线打到它自己 | 预览一律不带碰撞体（§7.3 / 踩坑 B71） |
| **有碰撞体的可摆放物污染"地面探针"** → 单发 `Raycast` 打到木桩身上，报「这里和地面差太多」 | 探地改用 `RaycastAll`，**跳过摆设自己与玩家、取最低那个命中**（§4.4 / 踩坑 B74） |
| 预览实例化的是**带逻辑的 prefab** → 预览自己会动、还顶着血条 | 预览**去掉碰撞体 + 停掉所有 `MonoBehaviour`**（`enabled = false`）（§4.5 / 踩坑 B75） |
| 同一套判定写两遍 → **两个方向不对称**（木桩能插进田里、田却盖不住木桩） | 判定只有一份 `摆放校验`，灵田与摆设都调它（§2 / §4.4 / 踩坑 B76） |
| 要**运行时加载**的 prefab 不在 `Resources` 下 → 根本加载不到，只能手工摆进场景 | 模型放 `Resources`（原 prefab 用 **Prefab Variant** 派生出 Resources 版本，改原 prefab 两边一起变）（§4.5 / 踩坑 B77） |
