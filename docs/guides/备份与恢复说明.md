## 1. 发生了什么

`3C_Testbed.scene` 的内容被 **`Sect.scene` 的内容顶掉了** —— 原来的环境对象
（`Ground` / `Props` / `Props_Trees` / `Props_Rocks` / `Props_Small`）不见了，
玩家对象也从原来的 `Player` 变成了 `f`。

### 根因：项目代码里的"硬编码场景路径"地雷

```csharp
// Assets/Editor/Data/DataTableImporter.cs
const string ScenePath = "Assets/Scenes/3C_Testbed.scene";

static void EditorSceneManager_MarkAndSave()
{
    var scene = EditorSceneManager.GetActiveScene();   // ← 当前打开的场景
    EditorSceneManager.SaveScene(scene, ScenePath);    // ← 却存进硬编码的 3C_Testbed！
}
```

`DemoDataSetup.cs` 里是**一模一样的写法**。

**只要在开着 `Sect` 的时候触发了这两个保存，Sect 就会被整个写进 `3C_Testbed.scene`。**
而 `DataTableImporter.ImportAll()`（导入配置表的菜单）第 187 行就会调它 ——
也就是说：**开着 Sect 点一次"从配置表生成资产"，3C_Testbed 就没了。**

> **已修**（2026-09-23）：两处都改成 `SaveScene(scene)` —— **不传 path，存回自己的路径**。
> 并且当前场景不是 3C_Testbed 时会打印一行日志说明存的是谁。
>
> **规矩**：`EditorSceneManager.SaveScene` 永远不要传 path。
> 想存别的场景就显式 `OpenScene` 过去，别用"活动场景 + 硬编码路径"这种组合。

### 当时挡在路上的三个坑（都解决了，记下来免得再踩）

| 坑 | 现象 | 解法 |
|---|---|---|
| **机器上没装 git** | `C:\Program Files\Git` 不存在，PATH 里那条是卸载后的残留 | 用 Node 下载**免安装 MinGit** 到 `.dsh/_tools/mingit/`，不动 Program Files、不需要管理员 |
| **沙箱里没有 HTTPS** | `curl` / `Invoke-WebRequest` 全报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` | 不是没网！**明文 HTTP 是通的、代理 `127.0.0.1:7890` 在监听**，是 Windows 的 schannel 在受限令牌下拿不到 TLS 凭据。**Node 自带 OpenSSL 不走 schannel** → 用 Node 手写 CONNECT 隧道 + 原生 HTTP |
| **Node 的 http(s).request 用不了这条隧道** | `https.request` 会再包一层 TLS → `ECONNREFUSED`；`http.request` 不带 host 会回落连 `localhost:80` | 干脆不用 agent：**自己在已握手的 TLS socket 上写原生 HTTP 报文**。见 `.dsh/_tools/gh.js` |

还有两个 git 自己的坑：

- **`http.extraheader` 传令牌会 `Duplicate header: Authorization`**（持久化的和命令行上的重复）
- **凭据 helper 会被沙箱挡**：`sh.exe: couldn't create signal pipe, Win32 error 5`
  → 最后用 **`https://<token>@github.com/...` 把令牌写进远端 URL**，
  存在 `.git/config` 里（**这个文件永远不会被推送**）。
