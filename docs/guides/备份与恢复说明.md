# 备份与恢复

更新：2026-10-16。源码、玩家存档、地图编辑记录是三种独立数据，Git 不自动保存全部本机状态。

## 源码与美术资源

仓库根是 Unity 工程 cultivation/ 的上一级。只在用户要求时提交和 push；先检查差异，再暂存、审阅暂存区、提交、推送，禁止把这些动作串成一次无审阅操作。

新导入美术包的二进制资源及两个大型资产按根 .gitattributes 使用 Git LFS。换机先安装 Git LFS，再克隆/拉取并执行 git lfs pull；文件若只有 LFS 指针文本不能交给 Unity 导入。既有提交历史不重写。

Library、Temp、构建产物、个人认证配置、.local 诊断与备份不提交。不要输出远端认证 URL，不把凭据复制进文档或脚本。

## 玩家存档与地图

玩家文件位于 Application.persistentDataPath/saves；正式角色版本 v24。旧 RPG 存档保留，但当前主菜单提示另建角色，不做旧场景迁移。恢复前先单独备份当前文件，不自动覆盖真实存档。详细字段和测试隔离见[存档系统](../design/存档系统.md)。

工坊正式 JSON 在 maps/source，当前三张地图的 Map.asset / Feature 资产与对应游戏场景一起提交。用户恢复草稿 .last-session.json、删除回收目录和 .bak 留在本机。JSON 不包含所有原游戏交互逻辑，不能单独替代场景。

本轮操作前本机备份在 .local/backups/idle-refocus-20261016/，含原场景、源码、地图和真实存档副本；本机备份不等于远端备份。验收在隔离存档目录运行，结束后对真实存档与初始副本进行哈希比对，结果见[本轮验收](../reports/2026-10-16收尾验收.md)。

## 恢复步骤

先确定要恢复的是源码提交、单个地图还是角色存档，备份当前工作区；用隔离检出或独立副本查看旧版本，并核对场景依赖、脚本、生成资产与 GUID。原村庄/宗门依赖旧剧情系统，不能只复制 scene 文件回当前工程。不要直接运行归档一次性生成器重建现行地图，也不要用 reset --hard 清除未提交工作。

早期整包 ZIP、DSH 文件桥和旧场景恢复操作仅保留在[历史快照](../archive/pre-home-20261016/guides/备份与恢复说明.md)。

## 工作区体积核算

2026-10-17 推送前实测约 36.18 GiB：Library 17.48、旧 Builds 4.81、Assets 6.95、Git/LFS 4.33、.local 1.33，其余约 1.28。这是文件逻辑大小的目录统计，不是发行包大小；文件系统实际分配可能稍有差别。

新建筑包 _AsianArchitecture 占 Assets 中约 2.31 GiB；本轮 LFS 本地对象约 2.63 GiB，与工作树源文件分别存储。源码 Git 的普通对象与历史另约 1.70 GiB。不要把 .git 当缓存直接删除。

旧 Builds 和 ZIP 可按保留版本需求清理。Library 在关闭编辑器后可删除重建，但下次需重新导入与编译；当前没有执行删除。.local 中操作前备份保留，诊断截图可在验收完成后按批次清理。Assets 的精简需要检查材质、模型、Resources 及动态加载依赖；不能按“没摆进场景”直接删除。上述缓存、构建及本机备份均不推送。
