## 1. 目录约定（2026-09-28 归拢后）

**所有特效都收在 `Assets/resources/特效/` 下**，按用途分四类：

```
Assets/resources/特效/
├─ 飞弹/     ← 原 QFX。75 个单体飞弹 prefab（Flashes / Impacts / Projectiles_*）
├─ 法术/     ← SpecialSkillsEffectsPack。55 个法术大特效（312 个 prefab）
├─ 传送/     ← 原 Portal Particle。14 个传送门光效 prefab
└─ 命中/     ← 原 resources/FX。2 个近战打击感 prefab（Hit_Physical / _Heavy）
```

> 为什么都放 `resources/` 下：见 §2 —— **所有特效都是按路径 `Resources.Load` 取的**，
> 放外面就取不到，而且**只返回 null、不报错**。

**新导入一个特效包时**，按用途放进对应的子目录；如果是一类新用途（比如"环境氛围特效"），
就在 `特效/` 下再开一个中文子目录，并更新本文的目录树和 §3 的清单表。

### 1.1 不进 `resources/` 的特效
有些特效只是**摆进场景**、不需要按路径取（不走数据表）。那类可以放 `Assets/Effect/`
（那边已有 928 个同类文件，含 `Spells/` `Dynamic/` `Common/`）。

判断标准一句话：**要不要在表(CSV)或 Inspector 里填"路径字符串"？要 → 必须进 `resources/`。**

## 2. 特效是怎么被加载的（**唯一硬性约束**）

全部走 `Resources.Load<GameObject>(路径)`，**路径 = `Assets/resources/` 之后的相对路径、不带扩展名**。

| 系统 | 加载什么 | 字段 |
|---|---|---|
| `ActiveSkillCaster` | **主动神通特效** | `ActiveDivineAbility.特效资源路径` |
| `NpcAiBase` | NPC 子弹特效 / 死亡消散 | `NpcAttackConfig.子弹特效路径`、`死亡消散特效路径` |
| `BasicRemoteAttack01` | 玩家远程普攻三件套 | `弹道/闪光/命中特效路径` |
| `NpcProjectile` | 弹道特效 | `弹道特效路径` |
| `NpcAiMuJi` | 蛋预制体 | `蛋预制体路径` |
| `HitFxBuilder`（编辑器） | 命中特效 | `基础命中路径` / `重击命中路径` |

### ⚠️ 坑 1：`Resources.Load` 读不到**只返回 null，不报错**
所以"路径写错 / 目录放错"的表现是**特效莫名其妙不出来**，日志里一句提示都没有。
排查顺序：① 路径是不是以 `特效/…` 开头；② 有没有把 `.prefab` 扩展名也写进去（**写了会失败**）；
③ 那个 prefab 是不是真的在 `Assets/resources/` 下。

### ⚠️ 坑 2：同目录有**同名 `.fbx`** 时，`Resources.Load<GameObject>` 会挑到 fbx 而不是 prefab
本项目的 `NpcPrefabs.cs` / `MountPrefabs.cs` / `AppearanceDefinition.cs` 都在绕这个坑
（用 `Resources.LoadAll<GameObject>` 把该路径下所有资产取出来再挑 prefab）。
**特效包里的模型别和 prefab 重名**；真要同目录同名，就别用 `Resources.Load`，改成 `LoadAll` 挑。

## 4. 导入新特效包的整理流程

1. **导入**：双击 `.unitypackage`（Unity 会按包内原始目录结构铺开，通常是 `Assets/<包名>/...`）。
2. **看它是什么**：在 `Assets/<包名>/` 里翻一眼有没有 `Demo` / 示例场景 / `Editor` 脚本 / `pdf` 说明。
3. **搬进 `resources/特效/` 下的分类目录**：用 Unity 的移动（编辑器里拖，或 `AssetDatabase.MoveAsset`）——
   **别用系统的剪切粘贴文件**，那样 `.meta`/GUID 会乱，场景里已摆好的实例会断。
4. **改路径引用**：任何脚本里写死了旧前缀的字段都要改（见 §2 那张表）。
5. **重跑清单**：选中新目录 → 菜单生成对应清单。
6. **验证**：抽几个 prefab 用 `Resources.Load` 试一下（改名前后的路径都要试），
   并确认**旧路径已失效**。
7. **不要把包文件本身上交**：`.gitignore` 已经挡了 `*.unitypackage`。
   （历史遗留：`特效/法术/Patch/` 下有 14 个 `.unitypackage` 总计 ~150 MB 是**已入库**的，
   属于清理欠账，见工作日志 P 系列。）

### 4.1 搬运会不会断引用？
**不会** —— 只要走 Unity 的移动，`.meta` 跟着走、GUID 不变，场景/预制体里的引用照样成立。
实测：`特效/传送/Prefab/Teleport_1.prefab` 被 5 个场景按 GUID 引用，
搬运后 GUID 仍是 `fab60cdb67eed3f4bb2d72dd90d3d3d0`，没断。

**会断的只有两类**：① 脚本里写死的**路径字符串**；② shader 里 `Shader "…"` 的自声明路径
（后者只在有 `Shader.Find("旧名")` 时才会真出问题，本项目的 4 个 QFX shader 没人 `Shader.Find` 它们）。

## 5. 改名/搬运的固定动作（照做就不会出事）

```
1. AssetDatabase.MoveAsset(旧, 新)      ← 走 Unity，保住 GUID
2. 核对：随便挑一个 prefab 和 shader，改名前后的 GUID 必须一样
3. 全局搜旧路径字符串：脚本 / CSV / 文档
4. 全工程搜 "旧前缀/" 确认零残留
5. 新旧路径各用 Resources.Load 试一次（新的要成功、旧的要 null）
6. 重跑清单 + 更新文档
7. 编译（0 error）后再交给用户测
```
