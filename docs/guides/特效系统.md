# 特效系统：资源与加载

2026-10-10 已按当前引用整理。动态加载的战斗特效 prefab 放 `Assets/resources/CombatVFX`，共享材质、贴图、网格、Shader 和灯光 Flare 放 `Assets/Art/VFX/Shared`，必要的原生脚本放 `Assets/Scripts/VFX/ThirdParty`。完整规则见[资产与目录](../architecture/资产与目录.md)。

## 分类与加载

| prefab 分类 | 现行内容 |
| --- | --- |
| CombatMagic | 使用中的 Combat Magic 法术，如 frost、lightning |
| ExtremeFX | 实际使用的命中、玄霄四式和陨石落地效果 |
| Projectiles | 实际使用的 NPC 弹丸与箭矢 |
| Hits | 通用物理命中 |
| Teleport | 正式场景传送表现 |
| LegacySpells | 使用中的旧包成品：青山剑砸地、焚天陨石、用户放置的 26/27/28 等 |

提取为游戏能力的 prefab 仍放 resources/Abilities，法宝和武器按各自目录管理；它们共用相同的 Art/VFX/Shared 依赖，不复制材质包。

`Resources.Load<GameObject>(路径)` 的路径是 resources 根之后的相对路径，不带扩展名，例如 `CombatVFX/CombatMagic/frost-fx/frost-ring`。共享材质等由 prefab 的 GUID 引用，不需要留在 Resources。参数既可能来自代码，也可能来自 CSV 和场景序列化字符串，三种入口均要检查。

FBX 和 prefab 不能在 Resources 内具有同一加载路径，否则 Load 可能选到模型；共享网格已移出运行库。对于已存在的同名角色模型，现有 NPC/Mount 加载器使用 LoadAll 后选择 prefab。

## 保留原生表现

不统一修改不同特效的 simulationSpeed、Renderer 模式或寿命。Burst、SubEmitter、灯光、材质混合和淡出都属于资源本身的表现，应在真实释放/命中节点验证。渲染材质中的空 Trail 槽可以是正常配置，不能据此删除效果。

lightning-ray 使用原 Stretch Renderer；LightningRayVfx 拟合宽度、长度与指定改色。雷云与千劫雷狱共用目标脚部竖直落雷，按用户要求只对这两者的运行实例整套粒子加速10倍，销毁时间同步缩短并保留完整淡出；不改源 prefab 或伤害间隔。焚天陨石主体使用 LegacySpells/Effect_13_DangerClose，已从 prefab 清除 Effect_13_Explosion / Effect_13_Explosion_2 和相关子发射器，保留陨石/拖尾；逐颗接触产生 Break_Lava 与局部破坏。

## 清单与新增

清单只有[特效资源清单](特效资源清单.md)一份，由 NpcEffectInventory 扫描 CombatVFX 自动生成，菜单为“修仙 / 资源整理 / 生成特效资源清单（全部）”。建议档位是粗略推断，不能替代检查实际效果。

新增时先选使用的 prefab，再递归收集依赖和必要脚本；样例场景、未用变体和源 unitypackage 不进入运行库。迁移使用 AssetDatabase.MoveAsset 或连同原 .meta 移动，保留 GUID 和 Shader 名称，维护 Shader Include 相对目录；同步代码、CSV、场景路径及当前文档，然后验证全部数据路径加载、编译和实际施放。
