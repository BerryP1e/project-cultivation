## 1. 现在是什么样

两个特效槽都**留空**，代码会**静默跳过特效、但伤害照算**（不报错、不刷警告）：

| 位置 | 字段 | 现在 | 空置后的表现 |
|---|---|---|---|
| 玄霄雷决 普攻 | `BasicThunder01.闪电链特效路径` | `""` | 连锁伤害照旧，只是看不到那道链 |
| 雷云（被动） | `LeiYun.闪电特效路径` | `""` | 雷云照样出手、照样掉血，只是看不到落雷 |

> ⚠️ **玩法没变，只是没有视觉**。若希望"看不到就干脆别触发"，得再改逻辑（现在没改）。

不报错的原因：`BasicThunder01.生成闪电链()` 第一句是 `if (string.IsNullOrEmpty(闪电链特效路径)) return;`；`特效摆放.生成拉伸链()` 第一句是 `if (string.IsNullOrEmpty(特效路径)) return null;`（**不**打警告）。

命中特效 `命中特效路径 = lightning-arc-flash` **没有空置**（资源包原生件，不是自制件）。

## 2. 之前那个 `雷链` 是怎么来的

原方案用 `特效/电特效/…/Electro_Line_01`，表现不好 → 换成 `lightning-ray` 那套（`ground-flashes` 子树）→ 但 `ground-flashes` **不是独立资源**（是 `ground-dust` 下的子节点，`Resources.Load` 取不到），于是把那棵子树的 4 个粒子部件抽出来挂到新根上做成 `雷链.prefab`。结果用户判定"还是一坨"，已删。`Electro_Line_01` / `Electro_Charge_01` 连同整个 `特效/电特效/` 目录也早已删除。

## 3. 以后补特效：照着这几条接

### 3.1 填哪里

玄霄雷决 → `BasicThunder01.闪电链特效路径`；雷云 → `LeiYun.闪电特效路径`。
路径规则：**相对 `Assets/resources`、不带扩展名**（写错只会静默返回 null）。

### 3.2 拉伸是怎么做的

`特效摆放.生成拉伸链()` / `BasicThunder01.生成闪电链()`：让特效的「长度轴」指向终点 → 该轴 `localScale = max(三维距离 − 长度补偿, 最小长度) ÷ 基准长度` → 另外两根轴按 `粗细` 缩放。

### 3.3 被拉伸的 prefab 必须满足两条 ⚠️

| 要求 | 原因（实测踩出来的） |
|---|---|
| `scalingMode = **Hierarchy**` | `Shape` 会把 `localScale` 作用**两次**：实测 `localScale.z=3.42` 时铺开 **11.7m**（≈3.42²）而非 3.42m，链糊成一团 |
| `renderMode = **Billboard**` | `Stretch` 沿**粒子速度**拉，这类粒子速度≈0、方向退化 → **几乎完全看不见** |

若贴图是**有方向的**"闪电条"，所有粒子同朝向会排成"梳齿"，要给每颗粒子**随机 `startRotation`** 打散才像乱窜的电弧。

### 3.4 接上后要标定的三个数

| 字段 | 怎么定 |
|---|---|
| `基准长度` | prefab 在 `scale=1` 时沿长度轴有多长。**用 §4 探针量**，不要看 prefab 里填了多少 |
| `长度补偿` | 探针量"实际沿链长度 − 间距"，多数填 0 |
| `粗细` | `localScale` 的 X/Y，看观感调 |

`探测长度轴()` 按各粒子 `shape.scale` 最长的轴自动判断，不用手填；`闪电链拉伸轴` 只是探不出来时的兜底。

## 4. 怎么量才是对的 ⚠️

**不要用 `ParticleSystemRenderer.bounds` 量尺寸 —— 它对这类特效是虚胖的。** 当初就是看它得出"间距 3/8/15m → 链长 3.00/8.00/15.00m，完全正确"的结论，实际粒子在链轴上**只铺开 0.26m**，链根本是一坨，**结论全错**。

正确做法：`GetParticles()` 拿真实粒子，投影到链轴上：

```csharp
var arr = new ParticleSystem.Particle[ps.main.maxParticles];
int n = ps.GetParticles(arr);
for (int i = 0; i < n; i++) {
    // ⚠️ simulationSpace = Local 时 position 是**本地**坐标，必须先转世界
    var wp = ps.main.simulationSpace == ParticleSystemSimulationSpace.Local
           ? ps.transform.TransformPoint(arr[i].position) : arr[i].position;
    float a = Vector3.Dot(wp - 链.transform.position, 链轴);
    minA = Mathf.Min(minA, a); maxA = Mathf.Max(maxA, a);
}
```

## 5. 怎么拍特效做视觉复核

Edit 模式截图和 Game View 的 MP4 **都拍不到这些粒子**。可靠办法是在 `exec_runtime_script` 里**把相机渲进 `RenderTexture` 再 `EncodeToPNG`**（存到已 gitignore 的 `cultivation/screenshots/`）：

```csharp
var rt = new RenderTexture(1280, 720, 24);
var 图 = new Texture2D(1280, 720, TextureFormat.RGB24, false);
var 旧 = 相.targetTexture; 相.targetTexture = rt; 相.Render(); 相.targetTexture = 旧;
var 前 = RenderTexture.active; RenderTexture.active = rt;
图.ReadPixels(new Rect(0, 0, 1280, 720), 0, 0); 图.Apply(); RenderTexture.active = 前;
System.IO.File.WriteAllBytes("screenshots/x.png", 图.EncodeToPNG());
```

两条必须做的自检（没做就会把"看不见的特效"当成"通过"）：
1. **先拍"没有特效"的基准图，再拍"有特效"的，比像素差** —— 证明渲染真的更新了，而非拿到同一张旧图；
2. **另起一台特写相机**（`CopyFrom(主相机)` → 改位置 → `clearFlags = SolidColor` → `enabled = false`），否则链在主相机 1280×720 里只有几十像素，肉眼判不出来。
