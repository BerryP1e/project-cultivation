# 主线：任务与对话系统设计

> 权威范围：任务/阶段/条件/动作、标记机制、触发区、对话选段与入口、跨场景时那一堆坑。
> 相关：[reference/配置表字段](../reference/配置表字段.md) · [design/存档系统](存档系统.md) ·
> [guides/对话系统使用说明](../guides/对话系统使用说明.md)（对话 UI 原始文档）

---

## 0. 核心思路

> **策划表里一行 = 剧情的一个阶段。** 引擎不认剧情，只认
> 「条件满足 → 执行动作 → 进下一行」。对话、NPC、镜头、场景、黑幕
> 全都是同一张任务表的**动作列**。

所以改剧情 = 改 `任务表.csv`，不用碰代码。

---

## 1. 三层结构

```
策划改这里（唯一真相源）
  Assets/Data/Tables/任务表.csv     ← 一行一个阶段
  Assets/Data/Tables/对话表.csv     ← 一行一段对话
            │  菜单：修仙/从配置表生成资产
            ▼
生成的 ScriptableObject（编辑器产物，不要手改）
  Assets/Data/Generated/QuestDefinition/<id>.asset
  Assets/Data/Generated/DialogueDefinition/<id>.asset
            │  菜单内部自动跟着跑：收集
            ▼
运行时库（Resources 下，运行时才读得到）
  Assets/resources/任务/任务库.asset
  Assets/resources/对话/对话库.asset
            │
            ▼
代码：QuestDatabase.取() / DialogueDatabase.取()（静态缓存）
```

## 2. 任务模型：阶段链

一行任务表 = 一个 `QuestDefinition`。同一个 `任务id` 的多个阶段按 `阶段` **升序串成链**。

运行时只记一张表 `当前阶段[任务id] = 阶段号`；导出进度是一行字符串
`q_main_004:7;q_main_002:0`（`:0` = 整条已完成）。

```csharp
// 推进一格
var 下一 = db.取阶段(任务id, 阶段.阶段 + 1);
if (下一 != null) 进入阶段(任务id, 下一);      // 内部会 执行动作 + 加接取标记
else { 当前阶段.Remove(任务id); 已完成任务.Add(任务id); }   // 整条完成
```

`Update()` 每 `检查间隔`（默认 0.25 秒）轮一次条件。

## 3. 两条独立轴：条件 / 动作

### 3.1 完成条件（`任务条件`）

| 条件 | 判定 |
|---|---|
| `无` | 成为当前阶段的**下一帧**就完成 → **一个阶段只能挂一个动作** |
| `等待秒数` | `Time.time - 阶段开始时间 >= 等待秒` |
| `到达` | 玩家与 `坐标` 水平距离 ≤ `到达半径` |
| `对话` | **玩家按下某一段的「回答 / 继续」时**才完成（见第 5 节 ⚠️） |
| `提交物品` | 背包有 `物品id × 数量`（完成时真扣掉） |
| `击杀` | 目标 `目标npcId` 死亡（留空 = 任意 NPC 死一个） |
| `NPC到位` | 目标 NPC 走到（最近一次「飞到」记下的）落点 1.5 m 内 |
| `落点结束` | 玩家落点流程结束（「移动玩家」/「移动玩家且黑幕」把主角放到位） |

### 3.2 动作（`任务动作`）

分三类：

```
【过场演出类】不需要目标 NPC
  黑幕字幕      台词列按 | 拆行，逐字打出；等待秒 = 打完后再停留多久
  闪白          白屏闪一下
  播放对话      强制弹框（不用玩家按 F）
  镜头看目标 / 镜头回玩家
  移动玩家      把玩家挪到「坐标」（落点，见第 6 节）
  移动玩家且黑幕 同上，但**同帧先落黑幕**当遮罩（四幕切到宗门用）
  切换场景      LoadSceneAsync 单场景加载
  生成NPC       按「动作参数」的预制体路径生成到「坐标」
  确保NPC       不在场就按「动作参数」重建
  接取任务      动作参数 = 要接取的任务id

【NPC 调度类】需要先找到目标 NPC（按 目标npcId 找 NpcInstance.定义.id）
  播动画 / 攻击玩家 / 销毁 / 走向 / 飞到 / 处决

【其它】
  无
```

> ⚠️ **「找到目标 NPC」失败会静默跳过**（只打一条 Warning），
> 但**阶段照样推进**。所以"NPC 没出现 / 没飞过来"这类问题，
> 表现常常是"对话弹了但人不在"——去 Console 搜 `动作的目标 NPC 不在场景里`。

## 4. 标记（flags）：任务与对话解耦的桥

任务**不直接改对话**，对话**不直接看任务**，两边都只认一个全局集合：

```csharp
// 任务侧
对话标记.添加一批(阶段.接取加标记);   // 进入阶段时
对话标记.添加一批(阶段.完成加标记);   // 完成阶段时
```
```csharp
// 对话侧：每条对话行都带条件
对话条件.满足(d) = 「需要标记」全中 且 「排除标记」一个都没中
```

于是"任务到某一步时 NPC 多一个专属回答" =
任务写标记 + 对话行填「需要标记」并给个**更高的优先**。

反方向靠对话表的 `触发任务` / `完成任务` 两列（在**按下回答时**执行，
见 `DialogueUI.按下回答` → `任务管理器.处理对话绑定`）。

> ⚠️ `对话标记` 是**静态内存**，**不进存档**（直到 v5 才加进去，见
> [design/存档系统](存档系统.md)），而且**会跨 Play 会话残留** ——
> 编辑器里测新流程**先重启 Unity**。

## 5. 对话系统怎么和任务接上 ⚠️ 最容易错的地方

### 5.1 入口段 = 最小分段

按 F 打开对话时，走的是 `DialogueDatabase.最小分段(npcId)` —— 也就是**第 1 段**；
之后靠每段自己的「跳转」往后走。

**所以任务阶段 `条件=对话` 的 `对话id` 必须填「入口段」或「入口链路能到达的段」。**

实际踩过的坑（2026-09-27）：
`q_main_003` 第 12 阶段填了 `对话id=dlg_act3_dashi_7`，但那是个**第 7 段**、
入口是 `dlg_act3_dashi_1`（第 1 段）→ **该阶段永远达不成**，
玩家每次按 F 都只看到第 1 段 → **招募对话无限循环**。
改成 `dlg_act3_dashi_1` 后正常。

**自查方法**：对每个 `条件=对话` 的阶段，比对
「该段的分段号」与「该 NPC 的最小分段号」；不等就要确认有跳转链能走到。

### 5.2 什么时候算"说完了"

**按下「回答 / 继续」时**才 `通知对话`（`DialogueUI.按下回答`）。

旧语义是"这一段刚显示就算完成"，**是错的**：玩家还没回复任务就推进了。
四幕实测症状：按下「仙人，我准备好了」、21 段文字刚显示，黑幕当场就起了，
而回答「好」还没按。

> 相关：多段对话做阶段边界时，`对话id` 填**你希望玩家按下回复的那一段**；
> 同一行**不要**再挂 `完成任务`，否则双重推进。

### 5.3 同一段有多条候选时怎么选

`DialogueDatabase.候选()` 的排序：

1. **优先大者胜**
2. 平手 → **NPC 专属**压过**通用**（`npcId` 为空的是通用兜底）
3. 再平手 → **带「需要标记」的**压过无条件的
4. 最后按 `id` 稳定排序

⚠️ 所以**同段位要多条时优先值必须拉开**，否则你写的任务回答会被默认回答顶掉。

### 5.4 对话门槛：没有可用段就不给交互

`NpcDialogue` 每帧判定「这个 NPC 当前有没有任何满足条件的对话段」，没有就把
`StationInteractable.现在可交互` 置 false —— 于是**不显示「F 对话」提示、按 F 也没反应**
（`StationInteractor.找最近设施()` 会跳过不可交互的设施）。

为什么需要：任务生成的 NPC 出场往往**早于**它该说话的时候。
四幕实测 —— 大师兄在第 7 阶段就生成了，而招募话要到第 12 阶段才打 `q_主线_招募中` 标记；
玩家提前按 F，标记还没上，招募段/可启程段都不满足，只剩下招募链的**中间段落**可入口 →
弹出"默认对话"。

三道放行条件（避免误伤）：
- `DialogueDatabase.取()` 为空（库没就绪）→ 放行
- 该 NPC 压根没配对话（`有对话` 为 false）→ 放行
- 战斗中的 NPC（`NpcAiHuman.现在可对话` 为 false）→ 拦

> ⚠️ 这道门槛是**通用**的：任何"当前没有任何可用对话段"的 NPC 都会不可对话。
> **给 NPC 配对话时留一个无标记的兜底入口段**，否则他在标记没满足时会变哑巴。

## 6. 跨场景：这套东西最复杂的地方

根因：`LoadSceneMode.Single` 会**销毁旧场景的一切**。

### 6.1 数据接力（`跨场景数据.cs` + 静态字段）

```
旧场景销毁前：OnDestroy → 拍下()  → 快照（背包/功法/神通/任务进度）
新场景 Awake：        → 灌回()   → 导入进度()
```

存储是**静态字段**，不随对象销毁。玩家靠 `DontDestroyOnLoad` 宿主跨过去。

⚠️ **进度接力曾经是竞态**：`OnDestroy` 里用 `FindObjectOfType<任务管理器>()` 导出进度，
而 `LoadSceneAsync` 完成那一瞬**新旧场景短暂共存**，可能抓到即将销毁的旧管理器 → 导出残缺甚至空串。
现在改为**切场景之前**就 `跨场景数据.钉住任务进度(导出进度())`。

### 6.2 动作接力（`跨场景待发动作` 静态队列）

切场景那个阶段是在**旧场景**的管理器上跑的，动作不能当场发（新场景还没激活完）。
所以：推进一格 + 把任务id塞进静态队列 + 钉住进度 → 新场景第一帧 `Update` 再取出来执行。

### 6.3 协程的生命周期：**这一串 bug 的共同根因** ⚠️

`StartCoroutine` 挂在 MonoBehaviour 上，**对象被销毁 → 协程直接没了**。
切场景会销毁旧场景的一切，所以**任何跨场景的长过程都不能用协程**。

实测踩过的：

| 症状 | 真因 | 现在的做法 |
|---|---|---|
| 主角落点不生效，停在场景初始摆放处 | 落点协程挂在旧场景管理器上，`LoadSceneAsync` 一完成就被销毁（只打出入口日志，协程体内一次没跑） | 改成**静态状态** `请求落点()` + `Update` 处理，不用协程 |
| 黑幕起了却不解除（一直黑） | 落黑幕的协程随场景销毁，没人收幕；黑幕对象是 `DontDestroyOnLoad` 的 | 黑幕**自己**按「字打完 + 停留 N 秒」收幕（挂在它自己的 `Update`） |
| 黑幕整段被漏掉 | `播黑幕` 里顺序反了：先 `WaitForSeconds` 才上锁打字，协程死在"等"这一步 | 改成先落黑幕 + 开始打字 |
| 大师兄不见了 / 不飞过来 | 任务生成的 NPC 是**场景内对象**，玩家在等待期间切场景把它销毁了，之后「飞到」找不到目标静默失败 | `生成NPC` 记住预制体路径；`找NPC` 找不到时**就地重建**；`飞到` 支持飞向玩家实时位置；新增 `条件=NPC到位` |

**新增跨场景动作时的判断标准**：这个流程会不会跨越一次 `LoadSceneAsync`？
会 → 就不要用协程，改成静态状态 + `Update` 驱动。

### 6.4 其他必须跨场景活着的东西

| 状态 | 存在哪 | 为什么 |
|---|---|---|
| 黑幕字幕 | `DontDestroyOnLoad` | 黑屏 + 切场景时画面不能露出来 |
| 落点目标 / 是否仍在接管 | 静态字段 | 见 6.3 |
| 未走完的等待秒 | 静态字段 | 否则「等候 60 秒」一切场景就清零重来 |
| 已执行动作 | 静态 `HashSet` | 三条派发路径不能重复执行同一阶段 |
| `演出中` | **`static`** | 黑幕跨场景，而任务管理器随场景重建；实例字段会让新管理器读到 `false` |

## 7. 重复派发：另一个踩过的坑

切场景那一帧有**三条路径**会碰到同一个阶段：

1. `进入阶段()` 自己（直接调 `执行动作`）
2. `导入进度` 的 `待发动作` 队列
3. 跨场景静态队列 `跨场景待发动作`

实测「生成NPC」因此**跑两遍**，后一个大师兄顶掉前一个 → 对话不出现。

**现在的做法**：静态 `已执行动作`（`任务id#阶段`），由 `执行动作` **入口**登记，
两条队列在派发前先查它。

> ⚠️ 一度用 `阶段开始时间` 当判据是**错的** ——
> `导入进度` 会给所有接手阶段写那个时间戳（「等待秒数」计时要用），
> 于是本该补发的动作全被跳过、主线直接卡死。**两者语义必须分开。**

## 8. 落点机制（`移动玩家` / `移动玩家且黑幕`）

```
请求落点(坐标, 接管秒)  →  记静态目标 + 截止时刻
Update 每帧 处理落点():
   · 登记当帧不动（让新场景先摆完）
   · 只在偏离超过 容差(1m) 时才纠正
   · 到截止时刻无条件放权（默认 0.6 秒）
```

要点：

- **不是协程**（见 6.3）
- 只负责"放到位"，**不负责按住玩家** —— 早期版本每帧硬写 `position` + 反复开关
  `CharacterController`，把玩家锁死在落点上（往外跑又被拉回来）
- `移动玩家且黑幕`：同帧落黑幕 + 登记落点，黑幕盖住那段拉扯。
  四幕流程：`1 等2秒 → 2 切场景 → 3 移动玩家且黑幕 → 4 等「落点结束」`
- 找玩家优先 `GameObject.Find("Player")`，再退到按 `PlayerVitals` 组件找
  （`物品使用器.取玩家物体()` 的静态缓存在切场景后可能还指向旧玩家）

## 9. 任务触发区（`任务触发区.cs`）

挂在场景里的圆柱上，管三件事：

```
进圈 → 接取「触发任务id」/ 推进一格「完成阶段任务id」/ 写「加标记」
前置：需要完成任务id（推荐，会存档）| 需要标记（不存档）| 高度容差
```

设计细节：

- **半径跟随范围圈**：`实际半径 = 范围圈.lossyScale.x / 2` ——
  策划在场景里缩放那个圆柱就是改触发范围，所见即所得
- **用玩家碰撞体中心判高度**，不用脚底根坐标（地面不平时脚底偏低会误挡）
- **进圈不触发会说明原因**（哪条前置没满足、高度差多少），专门为了排查"没反应"
- 菜单 `修仙/主线/触发区一览（当前场景 / 全部场景）` 做体检

## 10. 演出锁：挡住玩家 + 挡住推进

两件事，别混：

```csharp
// ① 挡玩家操作（Player 上的 演出锁 组件）
演出锁.cs：该锁 = 黑幕字幕.演出中 || (对话也锁 && DialogueUI.正在显示)
// ② 挡阶段推进（任务管理器.Update）
if (演出中) return;
```
