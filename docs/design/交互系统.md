# 交互系统：靠近提示 → 按 F → 开关界面

> 覆盖：`StationInteractable` / `StationInteractor` / `UiEscRegistry` / `DialogueUI` / `Teleporter` 的面板部分。
> 一句话：**全项目只有一套"走近可交互物 → 提示 → 按键 → 界面"的机制**，NPC 对话 / 建筑 / 传送圈都挂在这套上。

---

## 1. 三件套的分工

| 角色 | 谁 | 挂在哪 | 职责 |
|---|---|---|---|
| **可交互物** | `StationInteractable` | 物件自己（NPC / 炼丹炉 / 传送圈…） | 我是谁（`类型`）、显示什么名（`显示名`）、玩家要离多近（`交互距离`）、按哪个键（`交互键覆盖`） |
| **交互器** | `StationInteractor` | **玩家身上** | 每帧找"最近的、在范围内的"那一个 → 画头顶提示 → 收按键 → 开关界面 |
| **界面** | 各自实现 | — | 对话 `DialogueUI` / 传送 `Teleporter.面板` / 其它 `界面预制体` 或占位幕布 |

**关键设计：`StationInteractor` 是唯一的交互入口。**
其它模块（`NpcDialogue` / `NpcTargeting`）都主动让开，别自己抢 F 键
（历史上 NPC 和建筑各做一套，实测"点开一块空白幕布"叠在对话框上）。

### 1.1 `StationKind`（类型）

`修炼` · `炼丹` · `炼器` · `布阵` · `对话` · **`传送`**

`类型` 决定两件事：
1. 提示怎么画（见 §3）
2. **界面由谁负责**（见 §4）

---

## 2. 「在不在范围内」只有一个判定 ⚠️

```csharp
// StationInteractable
bool 玩家在范围内(float 玩家距离, float 高度差)
    => 现在可交互
    && 玩家距离 <= Mathf.Max(0.1f, 交互距离)
    && Mathf.Abs(高度差) <= 最大高度差;
```

`StationInteractor.在范围内(设施)` 包一层（算水平距离 + 高度差），
**`找最近设施` 和"走出范围自动关界面"共用它**。

> **别在各自的界面里再抄一套距离判定** —— 会出现"提示没了但界面还开着"这种半开状态。
> 2026-09-28 就踩过：传送面板有自己的一套，结果走出范围界面不关。

**是距离判定，不是物理触发器。** 所以：
- 传送圈的 `SphereCollider`（trigger）**不是**用来判定交互的，只是别的东西可能用到它的物理边界；
- 走进走出**不需要** `OnTriggerEnter/Exit`。

### 2.1 `现在可交互`（运行时闸门）

默认 true。目前只有 NPC 对话会改它：**这个 NPC 当前没有任何满足条件的对话段**时置 false
→ 不显示「F 对话」、按 F 也没反应。
（判据是对话表自己的条件列，所以不用给每个 NPC 单独配规则。踩过：大师兄杀野猪前按 F 出默认对话。）

## 3. 提示怎么画

每帧 `更新头顶提示()`，只画**最近的那一个**：

| 类型 | 头顶 | 身侧 |
|---|---|---|
| `对话` | **NPC 名字**（`StationName`，无框白字+描边） | 「F 对话」小框（`rt.pivot` 在左边缘，往屏幕右方向挪 `身侧距离`） |
| 其它（含 `传送`） | 「F 炼丹」/「F 前往古古镇」整框 | — |

- 键帽上的字由 `StationInteractable.按键名(键)` 翻译（F / E / 空格 / 回车 / 右键…）。
- 位置 = 物件**渲染体包围盒顶部** + `提示抬高`。
  ⚠️ **平的物件（传送圈）算不出高度** → `Teleporter` 把 `提示抬高` 当"离地高度"用（默认 1.6m）。
- 提示是**独立 WorldSpace Canvas**，不挂成玩家子物件（否则玩家的缩放/旋转会一起作用到它）。
- `raycastTarget = false`：提示不挡点击。

## 3.1 界面开着时提示要让开

`Update` 在"界面已打开"时直接 `return`（不画提示、不响应 F）。
对话框显示时也 `隐藏提示()`。

## 4. 界面的开关（**踩过 bug 的地方**）

### 4.1 两个状态标记

```csharp
public GameObject 当前界面 { get; private set; }        // 界面物件；null = 没开
public static bool 有界面打开 { get; private set; }      // 静态：给别的模块看（右键锁敌、ESC 协调器）
public bool 界面已打开 => 当前界面 != null;              // ★ 本组件内部"要不要处理关闭"的开关
```

### 4.2 ⚠️ `当前界面` 必须指向**真实存在的**界面物件

`Update` 里有一行**自愈**：

```csharp
if (有界面打开 && 当前界面 == null) 有界面打开 = false;
```

意思是"标记说是开着，但界面物件没了 → 收回标记"。

**踩过的坑（2026-09-28，表现是「按 ESC 关不掉传送面板」）**：
传送面板是 `Teleporter` 自己造的，开面板时**没把面板根交给 `StationInteractor`**
→ 下一帧自愈逻辑把 `有界面打开` 清成 false
→ 而 `界面已打开`（= `当前界面 != null`）也是 false
→ `Update` 里 `if (界面已打开) { if (Input.GetKeyDown(关闭键)) 关闭界面(); }` **根本走不到**
→ ESC 完全没反应。

**规矩**：**任何**界面在打开时都必须把根物件写进 `当前界面`，哪怕是别人造的。
（`Teleporter.面板根` 就是为此暴露的。）

### 4.3 三种界面，关闭方式不同

| 界面 | 谁造的 | 关闭怎么做 |
|---|---|---|
| 对话 | `DialogueUI` 自己 | 不归 `StationInteractor` 管（它只在对话框显示时把 `有界面打开` 同步上） |
| **传送面板** | **`Teleporter` 自己** | **不能 `Destroy`！** 只调 `Teleporter.关面板()` 收起来（下次还要复用同一个面板实例） |
| `界面预制体` / 占位幕布 | `StationInteractor` | `Destroy(当前界面)` |

`关闭界面()` 的分发就按这张表。

### 4.4 走出范围自动关（2026-09-28 加）

```csharp
if (界面已打开)
{
    if (Input.GetKeyDown(关闭键) || Input.GetKeyDown(交互键)) { 关闭界面(); return; }
    if (当前设施 != null && !在范围内(当前设施)) { 关闭界面(); return; }   // ★
    return;
}
```

只查 `当前设施` 一个 —— 它本来就是"开这个界面的那个物件"。

### 4.5 `关闭冷却`

关闭后 0.25s 内不再响应，否则"关掉的那一下"会顺手又开一个。
界面开着时提示也让开。

## 5. ESC 的三个界面怎么不打架（`UiEscRegistry`）

三个阶段都用 ESC：**角色面板**（I 开）、**设施界面**（F 开）、**暂停菜单**（ESC 开）。
而**同一帧里多个脚本的 `Update` 顺序不保证**，于是：

- 一次 ESC 既关了面板、又弹了暂停菜单；
- 更糟：暂停菜单记下的"原来的 `timeScale`"正好是面板设的 0，退出暂停时恢复成 0 → **游戏永远卡在暂停**。

**做法：时间戳，不是布尔标记**（布尔标记又会变成"谁先跑谁赢"）：

```csharp
UiEscRegistry.NotifyClosed();                 // 任何界面关闭时记一笔
UiEscRegistry.JustClosed(window = 0.15f);     // 暂停菜单开之前先问"是不是刚关过"
UiEscRegistry.AnyOtherUiOpen();               // 现在有没有别的全屏界面开着
```

用 `Time.unscaledTime` —— 暂停菜单会把 `timeScale` 设成 0，普通时间会冻住。

**新加全屏界面时要做的两件事**：
1. 关闭时调 `UiEscRegistry.记录关闭()`；
2. 让 `AnyOtherUiOpen()` 能发现你（或走 `StationInteractor.有界面打开` 这条现成的路）。

## 6. 给新"可交互物"接线的步骤

1. 物件上加 `StationInteractable`：填 `类型` / `显示名` / `交互距离`；
   要固定用某个键就填 `交互键覆盖`（NPC 和传送圈都固定 F）。
2. 如果界面是**现成的占位幕布**：填 `界面预制体`（留空则 `StationInteractor` 造一块空白幕布）。
3. 如果界面要**自己画**（像传送面板要按选项数动态生成按钮）：
   - 在 `StationInteractor.打开界面` 里加一个 `类型` 分支，**只负责"按键那一下"**，调你自己的开面板；
   - **必须**把界面根物件写进 `当前界面`（见 §4.2，不写 ESC 就废）；
   - 在 `关闭界面` 里加对应分支：**别人造的面板不能 `Destroy`**，只让它自己收起来。
4. ✅ **能用运行时补的就别手挂**：`Teleporter` 就是在 `Awake()` 里
   `AddComponent<StationInteractable>()` 的 —— 5 个场景 7 个传送圈，手挂必然漏
   （这正是「场景一致性」那类 bug 的成因）。
