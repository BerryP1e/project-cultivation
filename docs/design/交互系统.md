# 交互系统：靠近提示 → 按 F → 开关界面

> 覆盖：`StationInteractable` / `StationInteractor` / `UiEscRegistry` / `DialogueUI` / `Teleporter` 的面板部分。
> 一句话：**全项目只有一套"走近可交互物 → 提示 → 按键 → 界面"的机制**，NPC 对话 / 建筑 / 传送圈都挂在这套上。

---

## 1. 三件套的分工

| 角色 | 谁 | 挂在哪 | 职责 |
|---|---|---|---|
| **可交互物** | `StationInteractable` | 物件自己（NPC / 炼丹炉 / 传送圈 / 宗门各楼…） | 我是谁（`类型`）、显示什么名（`显示名`）、玩家要离多近（`交互距离`）、按哪个键（`交互键覆盖`） |
| **交互器** | `StationInteractor` | **玩家身上** | 每帧找"最近的、在范围内的"那一个 → 画头顶提示 → 收按键 → 开关界面 |
| **界面** | 各自实现 | — | 对话 `DialogueUI` / 传送 `Teleporter.面板` / 其它 `界面预制体` 或占位幕布 |

**关键设计：`StationInteractor` 是唯一的交互入口。**
其它模块（`NpcDialogue` / `NpcTargeting`）都主动让开，别自己抢 F 键
（历史上 NPC 和建筑各做一套，实测"点开一块空白幕布"叠在对话框上）。

### 1.0 交互键：全项目统一 **F**（2026-09-28 改）
原来是"NPC 用 F、**建筑用右键**"。用户要求统一：**建筑也靠近后按 F**，
所以现在 `StationInteractor.交互键 = F`，建筑不再用右键。

⚠️ **改这个默认值不够** —— `交互键` 是**序列化在场景里**的，
`Player` 上那份 `StationInteractor` 存的是旧值 `Mouse1`。
必须**逐个场景改组件上的值**（本次 5 个场景都改了），光改代码默认值在已有场景里不生效。

### 1.1 `StationKind`（类型）

`修炼` · `炼丹` · `炼器` · `布阵` · `对话` · **`传送`**

`类型` 决定两件事：
1. 提示怎么画（见 §3）
2. **界面由谁负责**（见 §4）

## 2. 「在不在范围内」只有一个判定 ⚠️

```csharp
// StationInteractable
bool 玩家在范围内(float 玩家距离, float 高度差)
    => 现在可交互
    && 玩家距离 <= Mathf.Max(0.1f, 交互距离)
    && Mathf.Abs(高度差) <= 最大高度差;
```

`StationInteractor.在范围内(设施)` 包一层（算水平距离 + 高度差），
**`找最近设施` 和"走出范围自动关界面"共用它**。

> **别在各自的界面里再抄一套距离判定** —— 会出现"提示没了但界面还开着"这种半开状态。
> 2026-09-28 就踩过：传送面板有自己的一套，结果走出范围界面不关。

**是距离判定，不是物理触发器。** 所以：
- 传送圈的 `SphereCollider`（trigger）**不是**用来判定交互的，只是别的东西可能用到它的物理边界；
- 走进走出**不需要** `OnTriggerEnter/Exit`。

### 2.1 `现在可交互`（运行时闸门）⚠️ **它是 `[NonSerialized]`，场景里存不住**

默认 true。目前只有 NPC 对话会改它：**这个 NPC 当前没有任何满足条件的对话段**时置 false
→ 不显示「F 对话」、按 F 也没反应。
（判据是对话表自己的条件列，所以不用给每个 NPC 单独配规则。踩过：大师兄杀野猪前按 F 出默认对话。）

> ⚠️ **2026-09-29 踩到的坑**：`现在可交互` 上面有 `[System.NonSerialized]`
> → **在场景/预制体里改它根本存不住**，每次加载都回到默认 `true`。
> 工作日志里曾经写过「4 座待开发楼：`显示靠近提示=false`、`现在可交互=false`」——
> 后半句**从来没生效过**，于是那 4 座楼变成「**按 F 有反应、但头顶没提示**」
> （用户就是这么报的：「按 F 可以正常互动，但是没有弹出提示」）。
>
> **想"整座关掉"应该用序列化得到的手段**（按推荐顺序）：
> 1. `交互距离 = 0`（序列化 ✓，判定直接不过）；
> 2. 把 `StationInteractable` 组件 `m_Enabled` 设 0（`isActiveAndEnabled` 为假，重扫时就不收了）；
> 3. **别只关 `显示靠近提示`** —— 那只藏提示，F 照样能按（正是这次的 bug）。
>
> 反过来说：**`显示靠近提示` 是序列化的** ✓，改它有效。

## 3. 提示怎么画

每帧 `更新头顶提示()`，只画**最近的那一个**：

| 类型 | 头顶 | 身侧 |
|---|---|---|
| `对话` | **NPC 名字**（`StationName`，无框白字+描边） | 「F 对话」小框（`rt.pivot` 在左边缘，往屏幕右方向挪 `身侧距离`） |
| 其它（含 `传送`） | 「F 炼丹」/「F 前往古古镇」整框 | — |

- 键帽上的字由 `StationInteractable.按键名(键)` 翻译（F / E / 空格 / 回车 / 右键…）。
- 位置 = 物件**渲染体包围盒顶部** + `提示抬高`，**再按 `提示最高点` 封顶**（见下）。
  ⚠️ **平的物件（传送圈）算不出高度** → `Teleporter` 把 `提示抬高` 当"离地高度"用（默认 1.6m）。
- 提示是**独立 WorldSpace Canvas**，不挂成玩家子物件（否则玩家的缩放/旋转会一起作用到它）。
- `raycastTarget = false`：提示不挡点击。

### 3.0 ★ 提示挂在哪：**挂在玩家身上**（2026-09-29 用户要求，默认行为）

用户报：「提示看不到 —— **你生成的位置被建筑本身的模型盖住了**。以后这个互动提示**生成在玩家的高度**。」

**真因**：「非对话」设施原本把提示放在**物件渲染体包围盒顶部**（再按 `提示最高点` 封顶 3m）。
宗门那些 12~19 米的楼 → 提示被封到 3m，而 3m 处**正好在楼体内部**，从外面完全看不到。

**现在**（`StationInteractor`）：

| 字段 | 默认 | 作用 |
|---|---|---|
| `提示挂玩家` | **true** | 非对话设施的提示改挂**玩家**：水平 = 玩家 + 朝设施方向偏 `提示朝设施偏移`，高度 = 玩家 + `提示玩家抬高` |
| `提示玩家抬高` | 2.1 m | 比玩家脚底高多少（≈ 头顶稍上） |
| `提示朝设施偏移` | 0.5 m | 朝设施方向水平偏一点（0 = 就在玩家正上方）；**别给太大**，否则又可能钻进建筑里 |

- 相机本来就看着玩家 → 提示**永远不会被建筑挡住**，也不受楼高影响。
- **`对话` 那一套不变**：NPC 名字在 NPC 头顶、「F 对话」小框在 NPC **身侧**、高度取肩胸之间
  （1.2~2.2m）—— 本来就在玩家的高度附近，也不会被挡。
- 关掉 `提示挂玩家` 就退回老逻辑（物件顶部 + `提示最高点` 封顶），下面 3.0.1 描述的就是那套。

### 3.0.1 ⚠️（旧）高建筑的提示会被摆到看不见的地方（2026-09-28 修）
**症状**（用户报）：「建筑的互动信息显示在建筑顶端，如果建筑比较高的话就看不到了」。

**真因**：提示取的是**渲染体包围盒顶部**，而宗门那些楼有 12~19 米高
（实测炼丹阁顶 y=18.70、宗门大殿顶 y=26.89）→ 提示被摆到十几米高空，
相机是俯视角、视野里根本没有那个高度。

**两道保险**（都在 `StationInteractor`）：
1. **`StationInteractable.提示最高点`（默认 3 米，0 = 不限）** —— 世界高度封顶。
   矮物件（NPC 2m、炼丹炉 1.6m、传送圈）本来就在 3 米内，行为不变；
   高楼统一压到 3 米。⚠️ 别改成"取物件中心和顶部之间" —— 15 米的楼取一半也有 7.5 米，照样在画面外。
2. **屏幕内收**（`夹进屏幕()`）—— 万一还是被摆到画面外（相机贴太近 / 视角很偏），
   用 `WorldToScreenPoint` 夹进安全边距再转回去。边距由 `屏幕边距比例`（默认 0.08）控制。

**实测**：炼丹阁高 15.3m → 提示世界位置离地**正好 3.00m**，
屏幕坐标 (960, 697) 落在 1920×1080 内 ✅

## 3.1 界面开着时提示要让开

`Update` 在"界面已打开"时直接 `return`（不画提示、不响应 F）。
对话框显示时也 `隐藏提示()`。

## 4. 界面的开关（**踩过 bug 的地方**）

### 4.1 两个状态标记

```csharp
public GameObject 当前界面 { get; private set; }        // 界面物件；null = 没开
public static bool 有界面打开 { get; private set; }      // 静态：给别的模块看（右键锁敌、ESC 协调器）
public bool 界面已打开 => 当前界面 != null;              // ★ 本组件内部"要不要处理关闭"的开关
```

### 4.2 ⚠️ `当前界面` 必须指向**真实存在的**界面物件

`Update` 里有一行**自愈**：

```csharp
if (有界面打开 && 当前界面 == null) 有界面打开 = false;
```

意思是"标记说是开着，但界面物件没了 → 收回标记"。

**踩过的坑（2026-09-28，表现是「按 ESC 关不掉传送面板」）**：
传送面板是 `Teleporter` 自己造的，开面板时**没把面板根交给 `StationInteractor`**
→ 下一帧自愈逻辑把 `有界面打开` 清成 false
→ 而 `界面已打开`（= `当前界面 != null`）也是 false
→ `Update` 里 `if (界面已打开) { if (Input.GetKeyDown(关闭键)) 关闭界面(); }` **根本走不到**
→ ESC 完全没反应。

**规矩**：**任何**界面在打开时都必须把根物件写进 `当前界面`，哪怕是别人造的。
（`Teleporter.面板根` 就是为此暴露的。）

### 4.3 三种界面，关闭方式不同

| 界面 | 谁造的 | 关闭怎么做 |
|---|---|---|
| 对话 | `DialogueUI` 自己 | 不归 `StationInteractor` 管（它只在对话框显示时把 `有界面打开` 同步上） |
| **传送面板** | **`Teleporter` 自己** | **不能 `Destroy`！** 只调 `Teleporter.关面板()` 收起来（下次还要复用同一个面板实例） |
| `界面预制体` / 占位幕布 | `StationInteractor` | `Destroy(当前界面)` |

`关闭界面()` 的分发就按这张表。

### 4.4 走出范围自动关（2026-09-28 加）

```csharp
if (界面已打开)
{
    if (Input.GetKeyDown(关闭键) || Input.GetKeyDown(交互键)) { 关闭界面(); return; }
    if (当前设施 != null && !在范围内(当前设施)) { 关闭界面(); return; }   // ★
    return;
}
```

只查 `当前设施` 一个 —— 它本来就是"开这个界面的那个物件"。

### 4.5 `关闭冷却`

关闭后 0.25s 内不再响应，否则"关掉的那一下"会顺手又开一个。
界面开着时提示也让开。

## 5. ESC 的三个界面怎么不打架（`UiEscRegistry`）

三个阶段都用 ESC：**角色面板**（I 开）、**设施界面**（F 开）、**暂停菜单**（ESC 开）。
而**同一帧里多个脚本的 `Update` 顺序不保证**，于是：

- 一次 ESC 既关了面板、又弹了暂停菜单；
- 更糟：暂停菜单记下的"原来的 `timeScale`"正好是面板设的 0，退出暂停时恢复成 0 → **游戏永远卡在暂停**。

**做法：时间戳，不是布尔标记**（布尔标记又会变成"谁先跑谁赢"）：

```csharp
UiEscRegistry.NotifyClosed();                 // 任何界面关闭时记一笔
UiEscRegistry.JustClosed(window = 0.15f);     // 暂停菜单开之前先问"是不是刚关过"
UiEscRegistry.AnyOtherUiOpen();               // 现在有没有别的全屏界面开着
```

用 `Time.unscaledTime` —— 暂停菜单会把 `timeScale` 设成 0，普通时间会冻住。

**新加全屏界面时要做的两件事**：
1. 关闭时调 `UiEscRegistry.记录关闭()`；
2. 让 `AnyOtherUiOpen()` 能发现你（或走 `StationInteractor.有界面打开` 这条现成的路）。

## 6. 给新"可交互物"接线的步骤

1. 物件上加 `StationInteractable`：填 `类型` / `显示名` / `交互距离`；
   要固定用某个键就填 `交互键覆盖`（NPC 和传送圈都固定 F）。
2. 如果界面是**现成的占位幕布**：填 `界面预制体`（留空则 `StationInteractor` 造一块空白幕布）。
3. 如果界面要**自己画**（像传送面板要按选项数动态生成按钮）：
   - 在 `StationInteractor.打开界面` 里加一个 `类型` 分支，**只负责"按键那一下"**，调你自己的开面板；
   - **必须**把界面根物件写进 `当前界面`（见 §4.2，不写 ESC 就废）；
   - 在 `关闭界面` 里加对应分支：**别人造的面板不能 `Destroy`**，只让它自己收起来。
4. ✅ **能用运行时补的就别手挂**：`Teleporter` 就是在 `Awake()` 里
   `AddComponent<StationInteractable>()` 的 —— 5 个场景 7 个传送圈，手挂必然漏
   （这正是「场景一致性」那类 bug 的成因）。

## 7. 鼠标索敌：选中 / 锁定都受**神识范围**限制（2026-09-28 新增）

### 7.1 规则

`NpcTargeting` 是全局的"选中 / 锁定"管理器（挂 Player 上）：

| 操作 | 键 | 效果 |
|---|---|---|
| 选中 | 左键 `Mouse0` | 绿环，用来看信息 / 接任务 |
| 锁定 | 右键 `Mouse1` | 红环 + 血条，用来攻击 |

**两者都必须落在「神识范围」内**——够不着的目标不选中、不锁定。

```
神识范围 = 基础 4 + 神识 × 0.8，封顶 40     （当前神识 12.5 → 14 米）
```

系数由 `NpcTargeting` 上的 `基础神识范围 / 每点神识范围 / 神识范围上限` 暴露，
换算式子走全项目唯一那份 `PlayerCombatStats.算神识范围`。

### 7.2 ⚠️ 以前根本没有这道限制（这是 bug，不是设计）

`RaycastNpc()` 原来只判 `最远距离`（默认 **200 米**），神识范围对索敌**完全没有作用**。
实测证据（修改前）：神识 12.5 → 神识范围 14 米，把练功木桩搬到 **30 米**外
（射线距离 39.5 米），`Physics.Raycast` **照样命中**、`Lock()` **照样锁上**。

**为什么不能在武器脚本里各自限制**：那样每个武器一套口径，加第 5、6 把武器就会不一致。
所以限制放在**唯一的输入入口** `NpcTargeting` 里；武器只读 `LockedNpc`。

### 7.3 量的是"体表最近点"，不是碰撞点

```csharp
public float 到目标距离(NpcInstance npc)   // 遍历碰撞体取 ClosestPoint 最小值
```

- ❌ 不能用鼠标射线的**碰撞点**：那是怪身上朝向镜头的那一点，会**低估**距离。
- ❌ 不能用 `transform.position`：大体积目标（龙、巨兽）中心很远但身体已经贴脸。
- ✅ `Collider.ClosestPoint(玩家位)` 取最小 → "我感知得到它"的直觉。

实测：木桩中心距 30 米时体表最近点 29.37 米；6 米时 5.39 米。

### 7.4 键盘旁路与开关

| 情况 | 行为 |
|---|---|
| 目标在范围外 | 不锁、不选中，**也不清掉已有锁定**（够不着 ≠ 右键点空地），右上角 Toast 提示 |
| 提示 | 「超出神识范围（29.4m / 14m）」，1 秒内只飘一次，避免刷屏 |
| `受神识范围限制 = false` | 退回旧行为（`神识范围` 返回正无穷，只受 `最远距离` 限制）。排查问题用 |
| 代码里直接调 `Lock()` / `Select()` | **不受限制**（自动索敌、剧情脚本要走的就是这条路） |

⚠️ **自动索敌本来就有这道限制**：`BasicSword01.找下一个目标()` 里判 `d > 索敌半径` 就跳过，
而 `索敌半径 = 4 + 神识×0.8`。所以改完之后**鼠标锁定和自动索敌口径一致了**。
