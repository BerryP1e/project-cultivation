# 遮挡透视：挡住"相机 → 主角"的东西自动变透明

> 组件：`OcclusionTransparency`（挂在**主相机**上）+ 工具 `遮挡素材.cs`
> 覆盖两类遮挡物：**建筑/场景**（走射线）和**树冠**（走包围盒）。

---

## 1. 为什么要做、以及为什么原来没做成

第三人称俯视角下，树冠和楼房经常正好挡在相机和主角中间 → 看不见自己在哪。

工程里**早就有** `OcclusionTransparency`，做的是"相机→主角连线上的东西变透明"。
但树冠一直没被解决，根因很具体：

> **树冠没有碰撞体。**
> 实测（village 场景）：树干有 **153 个 `CapsuleCollider`**，
> 而树冠的 **365 个子渲染体一个都没有**。
> 原实现是**打射线看命中**的 → **射线永远打不到树冠** ✗。

所以不是"没写这个功能"，而是"树冠进不了那个判定通路"。

---

## 2. 两条通路

```
主相机上的 OcclusionTransparency（LateUpdate，每帧）
 ├─ ① 射线通路  从相机朝主角身上 5 个高度点 RaycastAll
 │              → 命中的渲染体变透明      ← 管建筑 / 墙 / 石头（有碰撞体）
 └─ ② 包围盒通路 遍历树冠，做「线段 vs AABB」相交
                → 相交的树冠变透明        ← 管树（没有碰撞体）
```

### 2.1 树冠怎么认出来
按**物件名**：树根和它的子件都以 `environment_Tree` 开头
（实测 9 个品种：`environment_Tree_dashu_003` / `_zhangshu_01` / `_songshu_002` / `_taoshu_001` …）。
一棵树 = 往上找到**最外层**的 `environment_Tree*` 根，把这个根下面所有渲染体算作一棵树，
包围盒取它们的并集。

### 2.2 性能怎么保证
每帧对**每棵树**都要做一次"线段 vs AABB"，所以先剔掉大部分：

1. **只测在相机视锥里的树**（`GeometryUtility.CalculateFrustumPlanes` + `TestPlanesAABB`）
   —— 身后的、屏幕外的直接跳过。
2. **树表 5 秒重建一次**（不是每帧遍历全场景找树）。

规模参考：village 168 棵、Sect 31 棵、**宗门野外 1573 棵**。经视锥剔除后每帧只有几十棵参与相交测试。

### 2.3 相交判定
`线段近包围盒()`：把包围盒往外扩 `树冠余量`（默认 0.35m），
再做标准的 **slab 法**线段 vs AABB 相交测试。比 `Physics.Linecast` 便宜，而且**不依赖碰撞体**。

## 3. 材质怎么换（**不能污染资产**）⚠️

抽在 `遮挡素材.cs`（`遮挡素材.台账`），两条通路共用同一份逻辑。

```
渲染器 r 第一次被判定为遮挡：
  · 把 r.sharedMaterials（原数组）存进台账
  · 造一份透明材质【按源材质缓存】
  · r.sharedMaterials = 透明副本数组
不再遮挡（超过 保持 秒）：
  · r.sharedMaterials = 原数组
```

**三条铁律**：

1. **绝不改 `sharedMaterial` 指向的那个材质本身。**
   树冠材质是**多棵树共用**的（实测 9 个品种、几十个材质服务 563 个物件）——
   改一处会让**所有**树一起变透明。只改渲染器的 `sharedMaterials` **数组**，指向副本。
2. **透明副本按「源材质」缓存，不是按渲染器** → 500 棵树只有几十个材质实例，不会爆内存。
3. **离场必须原样还回去**（`OnDisable` / `OnDestroy` 调 `全还原()`），
   否则退出 Play 后场景文件里会留下被改过的材质引用。

### 3.1 透明 shader 的选择
优先 `Legacy Shaders/Transparent/Diffuse`（真混合、能和原色一致地变淡），
被剥离时退到 `Legacy Shaders/Transparent/Cutout/Diffuse`，再退 `Unlit/Transparent`。

> 树冠原材质本来就有三种（`Diffuse` 153 / `Transparent/Cutout/Diffuse` 140 /
> `Transparent/Diffuse` 67），统一换成真混合版本，观感一致。

### 3.2 建筑和树冠用不同透明度
- `透明度`（默认 0.22）= 建筑
- `树冠透明度`（默认 **0.12**）= 树冠，更透一点，尽量别挡视线

> 注意 `场景特效开关.自己该生效()` 这个老辅助方法**现在只有 `OcclusionOutline` 在用**了
> —— `OcclusionTransparency` 改成读两个独立开关（`场景特效开关.取(场景)`）之后就不走它了。

## 4. 生效范围：`场景特效开关.asset`

**不是**"哪个场景挂了组件就生效"—— 那样会被**通用装配同步**冲掉
（踩过：Sect 的玩家描边就是这么丢的）。

组件在 `Awake` 里读表，拿到**两个独立开关**：

| 开关 | 管什么 | 走哪条通路 |
|---|---|---|
| **建筑透明** | 建筑 / 墙 / 石头 | ① 射线 |
| **树冠透明** | 树冠 | ② 包围盒 |

> ⚠️ **这两个开关必须保持独立**（2026-09-28 用户明确要求：
> 「我只是要树冠，不要房屋」）。
> 最早的版本只有一个「建筑透明」同时管两者 —— 那会让用户**想开树冠就必须接受楼房也变透明**，
> 无法组合。拆开之后四种组合都能要。

当前配置（`Assets/resources/场景特效开关.asset`）：

| 场景 | 建筑透明 | 树冠透明 | 玩家描边 | 树的数量（实测） |
|---|---|---|---|---|
| village | — | ✅ | ✅ | 168 棵 |
| Sect | **✅（2026-09-29 开）** | ✅ | ✅ | 31 棵 |
| Sect_Wilderness | — | ✅ | ✅ | 1573 棵 |
| Demon-Suppressing Tower | ✅ | — | — | 0 |
| 3C_Testbed | — | — | — | 0 |

镇妖塔的「建筑透明」保持它原本的值（那是用户之前自己开的，与本次无关）；
3C_Testbed 没树，两个都关。

> **2026-09-29**：用户要「把树那套按子部件半透明的效果，也给 Sect 的建筑安排上」
> → 只改了这张表里 **Sect 的「建筑透明」= ✓**（资产 **1 行 diff**，没动任何代码 ——
> 组件早就在 Sect 的主相机上、20 座楼的**每个渲染体都带碰撞体**，① 射线通路本来就能命中）。
> 实测见 §5.3。

**改法**：`Assets/resources/场景特效开关.asset` 勾选对应列即可。没有资产时用
`场景特效开关.取表()` 里的内置默认。

## 5. 实测（2026-09-28）

### 5.1 树冠遮挡本身
| 检查 | 结果 |
|---|---|
| 识别树 | village 场景识别到 **168 棵** ✓ |
| 树挡在相机与主角之间 | 2 个树冠渲染体变透明（`environment_Tree_zhangshu_01_a0 → 透明_environment_Tree_zhangshu_01_02`）✓ |
| 走开不再遮挡 | 透明渲染体回到 **0**，材质**完好还原** ✓ |

### 5.2 拆分开关后（**决定性验证**，Sect 场景，既有树又有楼）
```
组件 enabled = True
   建筑遮挡启用 = False   ← 只要树冠
   树冠透明     = True
① 站在树后面       → 树冠变透明渲染体 = 2            ✅ 树冠透明生效
② 站在炼丹阁后面   → 建筑变透明渲染体 = 0 / 共 11    ✅ 建筑完全不变透明
```

---

### 5.3 建筑透明（Sect，2026-09-29 用户要求）

用户原话：「当树处于摄像机和角色之间时，树的那种**按照不同子部件**来半透明隐形的效果非常不错，
给 sect 的建筑也安排上吧。」

**改法**：`场景特效开关.asset` 里把 **Sect 的「建筑透明」勾上**（资产 **1 行 diff，零代码改动**）：

- Sect 主相机**早就有** `OcclusionTransparency`（enabled）✓；
- 20 座建筑的**每个渲染体都自带碰撞体**（渲染体数 = 碰撞体数，例：炼丹阁 11/11）✓
  → ① 射线通路本来就能命中，不需要额外登记。

**实测**（把玩家摆到炼丹阁背面、相机在楼另一侧）：

| 检查 | 结果 |
|---|---|
| 组件状态 | `enabled=True`、`建筑遮挡启用=True`、`树冠透明=True` ✓ |
| 变透明渲染体 | **3 个**，全是炼丹阁的**子部件**（`…_o10` / `…_o09` / `…_o02`）✓ 只透"挡路的那几块" |
| 全场景渲染体 | 271 个 → 只有挡路的 3 个被动到 ✓ |
| 观感 | 屋顶/上层结构半透明（α = `透明度` 0.22），玩家（黄描边）**透过楼体清晰可见** ✓ |

⚠️ **两个几何事实**（不是 bug，是俯视角的必然）：

1. 只有**足够高**的楼挡得住这条射线。实测**矮凉亭**（5×4.6×4.2m）站在它背后**不会**变透明
   （射线从它头顶掠过 ✓ 行为正确）；同一时刻旁边**树冠**照常变透明（3 个）✓。
2. 高楼挡路时相机往往已经**悬在楼顶上方**（相机在玩家上方 ~13.5m，楼高 15m）→
   画面像"从楼顶往下看" —— 而这正是**最需要这个效果**的机位（否则完全看不见角色）。
   想拍好看的演示图，可以**手动把相机摆到楼的另一侧**再截图（`screenshots/建筑遮挡透明_宗门.png` 就是这么拍的）。
