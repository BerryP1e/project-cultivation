# 家园与镇妖阁

2026-10-16 用户决定缩减 RPG 内容，以洞府、种植生产、修炼挂机和镇妖阁战斗为核心。本文件取代此前“保留五个游戏场景、继续主线”的安排。宗门野外按用户随后补充保留，悬赏不迁入塔内。

## 入口与场景

从 `StartScene` 新建 v26 存档，进入 `3C_Testbed` 个人洞府。当前正式游戏场景为洞府、`Sect_Wilderness` 宗门野外、`Demon-Suppressing Tower` 镇妖阁内部。独立工坊仍用于编辑这三张地图。

古古村和宗门主场景、对应正式地图、主线任务管理器、开场剧情、主线追踪、剧情触发器及生成任务阶段已移出 Assets。当前本机操作前副本在 `.local/backups/idle-refocus-20261016/`，不参与编译、构建和菜单。可复用的建筑、树石、人物原始模型不作无依赖分析的批量删除。

洞府传送阵可往返宗门野外。执事阁的交货委托仍在洞府提交；悬赏仍由野外既有空地刷怪、记录逐只击杀、回洞府执事阁领奖。原来的任务进度字段不再驱动主线。原 `QuestDatabase` 聚合资产暂作物品 ID 索引使用，其任务阶段集合为空，并非仍在运行任务管理器。

## 镇妖阁法宝

`treasure_tower_realm` 的模型使用原宗门镇妖阁建筑。它属于现有独立 Q 键法宝槽，不占神通栏。

- 在洞府装备镇妖阁后按 Q，记录玩家的位置与朝向，展开塔内场景。
- 原 `TowerController` 继续管理层表、刷怪、清层出口、下一层和层数进度。
- 在塔内随时按 Q 退出，不要求等待清怪；即使切换了装备，塔内 Q 仍用于出塔。
- 死亡直接退出到现实，不再弹旧的“上一层／出塔”倒数选择。
- 正常退出和死亡退出均回到实际施放处。返回点写入 `SaveData.镇妖阁返回点`，塔内存档、从主菜单读档后仍可返回。
- 楼层自动记录使用当前选择的存档槽，不再默认写槽位 0。它仍是楼层记录，不等同于自动全量保存背包。

场景落点和每局首次角色恢复已从任务管理器移到 `SaveApplier`。主菜单明确选档时重置一次恢复闸门；普通传送使用 `跨场景数据` 接力，不重新套用旧存档。

达到筑基/金丹时各赠送一次“筑基着装”/“金丹着装”学习物品，使用后才永久记入外观拥有记录并换上。P 调试面板可搜索这两个物品直接加入背包。领取标记写入通用存档状态，防止读档、换场景或转修反复赠送。沿用原玩家骨架、兼容绑定网格、外观列表和存读档；模型中的 NPC 战斗／对话脚本已剥离。半身立绘与列表图标按外观 ID 导入。见[外观系统](../guides/外观系统说明.md)及[立绘制作记录](../reports/筑基金丹着装立绘.md)。

练气只增加衣摆随动；村中少年和短发不增加骨链。筑基/金丹增加宽袖、衣摆及长发骨链，使用受约束弹簧与身体胶囊避让，不是布娃娃。默认村民沿用原绑定，新增外观成品单独重定位；预览复制独立骨链。正常动作、转头、飞行、传送复位和切换已运行验证，详见外观说明。

相邻拓境地块会补齐内部圆角空洞，保留外侧包边。保存的拓境坐标在当前基图上重放。丹方等通用对话标记从存档恢复，不依赖已退役的任务管理器。

## 存档与验证边界

本轮使用新建 v26 存档，不增加旧 RPG 存档迁移。旧文件保留；主菜单会提示旧版存档另建角色，避免加载已退役的场景。所有自动化 Play 检查必须使用 `SaveSystem.验证目录键` 隔离目录，并在结束时核对真实存档哈希、清除隔离设置。

当前回归入口为 `devtools/validation/home-tower-runtime.cs.txt` 与 `home-idle-integration.cs.txt`。工坊、植物生产、原战斗系统继续复用现有实现；不为本轮迁移保留新的日常重建器。
