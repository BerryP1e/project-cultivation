## 1. 一条铁律：所有物品都从物品表出发

曾经的错误做法是**两套来源**：

| 来源 | 产物 |
|---|---|
| `物品表.csv` → `DataTableImporter` | `Generated/ItemDefinition/` 里的材料、消耗品 |
| `能力物品生成器.cs`（编辑器菜单） | `Generated/能力物品/` 里的「秘籍 / 神通玉简 / 心得」+ 门派便服 |

后果：**「门派便服」和所有"学习物品"在物品表里查不到** —— 它们是另一个编辑器脚本直接造出来的资产。现在 `能力物品生成器.cs` **已删除**，物品的唯一来源是 `cultivation/Assets/Data/Tables/物品表.csv`（凡物品类的东西，不论能否使用，都必须从物品表出发）。

| 谁 | 干什么 |
|---|---|
| `物品表.csv` | **唯一**的物品定义（含便服、秘籍、玉简、心得） |
| `DataTableImporter` | 把每行生成成一个 `ItemDefinition` 资产 |
| `物品效果导入.cs` | 消费物品表的三个「效果列」，建/复用效果资产并挂到物品上 |
| `物品调试工具.cs` | 只剩**场景侧调试**（清空面板 / 用物品表填满背包），不再造物品 |

## 2. 表 → 资产 → 运行时

```
物品表.csv（一行一件）
   │  修仙/从配置表生成资产
   ▼
Assets/Data/Generated/ItemDefinition/<物品id>.asset
Assets/Data/Generated/能力物品/<效果类型>效果_<物品id>.asset   ← 由「效果列」自动建
   │
   ▼
QuestDatabase.取().物品库（任务奖励按 id 找物品用）
UIPanelData.物品（背包：一件有 N 个 = 列表里出现 N 次）
```

## 3. 物品表的列

| 列 | 说明 |
|---|---|
| `物品id` | 全局唯一，生成资产的文件名就是它 |
| `物品名` | 面板显示名 |
| `最大堆叠数量` | 1 = 不可堆叠（**目前只是数据，背包实际按"一件一条"记数**） |
| `品阶` | `凡品/黄品/玄品/地品/天品`，列表着色排序用 |
| `介绍` | 背包里的说明文本 |
| `可使用` | `0`/`1`。1 = 背包里多一个「使用」按钮。**写了效果类型时会被自动置 1** |
| `效果类型` | 见下表。留空 = 不能用的物品（材料 / 提交物） |
| `效果参数id` | 效果的目标 id（功法id / 神通id / 外观id / **丹药id**） |
| `效果说明` | 面板上给玩家看的效果说明；留空则用物品自己的介绍 |

⚠️ `可使用 / 效果类型 / 效果参数id / 效果说明` **不是** `ItemDefinition` 的字段名，所以 `ApplyRow` 认不出来会跳过，由 `物品效果导入.处理物品()` 单独消费。

### 3.1 支持的效果类型

| 效果类型 | 参数id 填什么 | 生成的资产 | 运行时行为 |
|---|---|---|---|
| `学功法` | `功法id`（如 `gongfa_taixu_lianqi`） | `学功法效果_<物品id>` | 学会该功法；还没有当前功法就自动设为当前 |
| `学主动神通` | `神通id`（如 `ability_yujian_shu`） | `学主动神通效果_…` | 获得该主动神通（**不可重复习得**） |
| `学被动神通` | `神通id`（如 `ability_pingxu_yufeng`） | `学被动神通效果_…` | 获得该被动神通，并从「已停用」里摘掉 |
| `学外观` | `外观id`（如 `app_player`） | `学外观效果_…` | 获得该外观并立刻换上（不可重复获得） |
| `服丹` | **丹药 id**（= `灵丹库` 里那条 `灵丹定义.id`，通常就是物品自己的 id） | `服丹效果_…` | 按 `灵丹定义.作用` 分流：`加修为` / `回气血` / `回灵力` **立即生效**；`破境` 把 `PlayerCultivation.当前破境成功率` 提上去（实时值，进存档） |
| `属性增益` | 表里给不了 | `属性增益效果_…` | **需要进 Inspector 补属性/百分比/时长**，表里只给了说明 |

> ⚠️ `服丹` 的 `效果参数id` **必须能对上 `灵丹库` 的一条 `id`**（先按 `服丹效果.丹方id` 查、
> 查不到再按物品 id 兜底；两条都对不上就**静默无效**）。`物品效果导入` 会对查不到的 id 打警告。
> `作用 = 无` 的丹（例：回春丹）**故意不写 `服丹`**，它的效果挂在 `属性增益` 上。

认不出的效果类型会打 `Debug.LogWarning` 并把效果清空。

## 4. 效果为什么用「id」而不是资产引用

CSV 里只能填字符串，没法引用资产。所以「学功法 / 学主动 / 学被动 / 学外观」这四个效果都同时有 **引用字段** 和 **id 字段**：

```csharp
public GongFaDefinition 功法;   // 引用（可选）
public string 功法id = "";      // 物品表填的就是这个
```

取值时走 `取功法() / 取神通() / 取外观()`：**引用为空且 id 非空 → 用 `能力查找.按id<T>()` 反查并缓存回来。**
`能力查找.按id<T>()`（在 `物品使用效果.cs` 里）：按 id 扫 `Assets/Data/Generated/<类型名>/`，找不到再全工程扫。

> ⚠️ 它用 `AssetDatabase`，**只在编辑器下有效**；打包后那条分支不编译、返回 null。所以**正式出包前要保证效果资产上的引用已经填好** —— 目前导入器只写 id、不填引用，出包前需要补一个"回填引用"的步骤（**尚未实现，属已知待办**）。

## 5. 使用一件物品

`物品使用器.cs` 拿着 `物品使用请求 { 面板, 玩家, 物品 }` 调效果的三个方法：

```csharp
bool 能使用(请求)      // 能不能用（已经学会的功法 → false）
string 不能用原因(请求) // 不能用时给玩家看的理由
bool 使用(请求)        // 返回 true = 消耗掉一个
```

新增一种效果 = 写一个 `物品使用效果` 子类 + 在 `物品效果导入.处理物品()` 的 switch 里加一个 case。**不用改 UI、不用改物品表结构。**

## 6. 背包（`UIPanelData.物品`）

- 类型是 `List<ItemDefinition>`，**一件物品有 N 个就是 N 条**（不是 `(物品, 数量)` 对）
- `物品数量(物品)` 数条数；`给物品(物品, 数量)` 塞 N 条；`移除物品(物品, 数量)` 删 N 条
- **新档背包是空的**：清空口径与第二层保险见 [存档系统](存档系统.md)。

> 场景面板里之所以可能有东西，是因为编辑器里跑过调试菜单 `修仙/调试/用物品表填满当前场景背包`（它会把物品表里每件物品塞 1 个进当前场景，**并标脏场景**）。测完记得 `修仙/调试/清空当前场景面板（新档口径）` 再保存场景。

## 7. 物品图标

`Assets/resources/物品图标/` 下放图标资源，`ItemDefinition.图标` 是 Sprite。
目前**导入器不填图标**（物品表没有图标列）。要加的话：加一列 `图标`（资源名），在 `物品效果导入` 或 `ApplyRow` 里 `Resources.Load<Sprite>("物品图标/" + 名)`。

## 8. 已知待办

1. **出包前回填效果引用**（见第 4 节）—— 否则打包后 `能力查找` 失效，学习物品用不了。
