# 当前游戏体系

更新：2026-10-22。本文描述当前可运行的游戏规则与系统关系，作为全局入口；数值细表和维护方法由各主题文档负责。已经退役的主线、独立旧面板和功法不能根据历史记录恢复。

## 1. 核心循环与场景

游戏围绕洞府经营、修炼、装备搭配及战斗展开。玩家在洞府扩建和摆放设施，种植灵草并组织生产，取得丹药、贡献、功法和神通；通过修炼与法则提高角色能力，前往宗门野外完成悬赏，或使用镇妖阁法宝挑战楼层，再回到洞府整理与生产。

| 场景 | 当前职责 |
| --- | --- |
| StartScene | 新建角色、选择五个存档槽之一、读取角色并进入场景 |
| 3C_Testbed | 正式个人洞府；名称保留，不代表仅测试地图 |
| Sect_Wilderness | 宗门野外探索及悬赏妖群；与塔内挑战独立 |
| Demon-Suppressing Tower | 镇妖阁层表、刷怪、清层、楼层进度 |
| WorldAuthoring/RuntimeMapEditor.unity | 独立制作工具，编辑正式地图，不属于玩家存档 |

古古村、宗门主场景、主线开场、巡览教学、主线任务调度和剧情触发区已退役。保留可复用美术、通用对话及标记，不代表旧玩法仍在运行。

## 2. 新角色、成长资源与存读档

正式新角色从主菜单建立v26角色数据，进入洞府。`HomeFacilityStarter`一次性给予五种功能建筑令、太虚炼气诀秘籍、聚气丹丹方、练功木桩、4张灵田开拓令、8张拓境令、基础种子、100贡献和已装备的镇妖阁法宝。秘籍仍须使用后学会；新档不直接赠送三把武器，也不会自动学会目录中的全部神通。

目录定义、玩家拥有与当前装备是三层数据。`PanelDatabase`保存所有可用定义，`UIPanelData`保存玩家已学、已获得和槽位，`SaveData`按稳定ID或实例数据持久化。目录存在不等于玩家已经拥有。

当前存档版本26，增加武器拥有记录和当前武器；此前的灵阵编排、法则实例、家园生产、外观、委托、时间与返回点一起保存。普通传送使用最新会话快照，不重新套用旧磁盘数据；主菜单明确选档才开始新一轮读取。地图地形及物件由正式Map.asset提供，角色存档只保存角色及其扩建/生产状态。

编辑器直接启动洞府有专用测试背包，见第15节。正式文件、测试文件与地图源数据必须分开，详见[存档系统](存档系统.md)。

## 3. 操作与输入优先级

| 输入 | 作用 |
| --- | --- |
| 方向移动、Shift | 按当前角色控制器移动/奔跑；动作姿态由武器和行游状态选择 |
| 左键 | 当前修行功法的一段特殊普通攻击；按住不连续出招 |
| E | 当前武器的一段物理普通攻击 |
| Q | 当前法宝功能；需要引导的法宝先引导、左键确认，镇妖阁直接进出 |
| 右键 | 手动锁定目标；引导时用于取消；法宝HUD图标右键打开其专属界面 |
| 1–6 | 主动神通按住引导、松开施放；右键/Esc取消，不提前扣费 |
| Alt＋滚轮 | 已拥有法宝循环切换，图标上下平滑换位；期间相机不缩放 |
| F | 设施、灵田、NPC、传送等上下文交互 |
| I | 打开角色背包入口 |
| Tab | 行游轮盘，选择御风或坐骑 |
| 空格＋方向 | 稳定御风期间闪避；无方向按原后闪规则 |

面板、死亡、演出、摆放等状态优先阻断场景输入。UI动画使用非缩放时间，游戏暂停时仍可操作。`UiEscRegistry`负责多界面输入锁，不靠timeScale单独判断是否允许攻击。

## 4. 修行功法与境界

功法负责修炼难度、成长属性及功法普攻。当前三门为太虚炼气诀、玄霄雷决、沧澜寒渊录，分别提供远程四式、雷法四式及寒渊四式。学习记录与当前转修功法分开；切换功法不切换武器，也不改武器待机。

境界共9大境界、每境10层，对应1–90级。难度系数由功法难度等级/100得出；总灵气积累、已解锁最高等级和当前层进度分开。灵气满不会自动跳过破境；小境界手动按概率破境，先服对应破境丹可增加成功率。大境界专属突破材料流程目前仍明确拒绝，不能在说明中写成全部90级自然可通关。

时间管理器决定游戏日与修炼机会，日常清单记录收灵草、成功炼丹、打坐、入塔四项。它们不再依赖旧主线教学解锁。数值与规则见[境界与功法](境界与功法设计.md)、[修炼实现](../architecture/修炼与境界.md)、[时间](../guides/时间系统.md)。

## 5. 独立武器与动作

| 武器 | 类型 | 连招来源 |
| --- | --- | --- |
| 基础长戟 | 长戟 | 原八九玄功四式 |
| 基础灵剑 | 灵剑 | 原太虚剑决三式 |
| 基础飞剑 | 飞剑 | 原灵虚剑决三式 |

八九玄功、太虚剑决、灵虚剑决和太初龙栖诀已移出可学习功法及秘籍目录。前三者必要模型、动作和攻击代码作为武器模组继续使用。武器从独立武器表定义，通过获得武器物品进入拥有记录，再装备到武器槽。

两种普攻各自维护连招索引，共享角色动作占用，不能同时结算或跨类型补位。长戟/灵剑持械时，功法A1–A4使用atk_energy07/04/08/05；飞剑不手持，保留功法原施法动画。飞剑地面也采用御风悬停及八方向姿态，这是明确设定。

灵剑御风必须保留地面定稿的斜下持握与剑安装角，长戟A1/A3为水平前刺。所有动作源、定稿限制和重建范围见[动作定稿登记](../guides/动作定稿与重建边界.md)，不能根据片段名称自行重新拟合。

## 6. 战斗、伤害与表现

一次攻击有两个独立维度：伤害属性为物理/特殊，攻击类别为普通攻击/主动神通/被动神通。左键功法是特殊普通攻击，E武器是物理普通攻击，不能因为由按键主动施放就归为主动神通。

物理进入公式后必中并走暴击，特殊走闪避与会心；实际武器接触、射程、目标存活等仍需满足。所有生物伤害共用`CombatHitContext → CombatDamagePipeline → CombatCalculator → ICombatTarget`，表现由`CombatImpactPipeline`统一派发。地表接触与破坏另走环境路径，不额外扣一次生物气血。

近战使用实际剑身/长戟网格扫掠和每轮去重，挥空不能预扣血。飞弹采用连续运动段检测，主体位移与世界拖尾分工。护盾、无敌、死亡、实际伤害与过量伤害在统一管线处理。命中特效、局部顿帧和飘字不改变伤害公式。

详见[战斗与伤害](../architecture/战斗与伤害.md)、[命中特效](../guides/战斗命中特效管线.md)、[飞弹](../guides/飞弹与子弹.md)。

## 7. 神通、护罩与法则

神通目录包含主动和被动，只有已掌握内容进入装备列表。六个主动槽支持拖入、交换和拖回卸下；被动在简介旁启停，不占主动槽。主动依各自定义支付灵力、执行动作节点、产生执行体并管理冷却，取消未施放的引导不扣费。

三种属性减伤护罩互斥，持续消耗与耗尽关闭沿用原规则；主动四御是次数型免伤，剩余次数、激活状态保存。护罩特效跟随角色位置，世界朝向保持稳定，不随转身整体旋转；能力特效排除角色全局描边。

法则由宝箱生成独立UUID实例，主副词条、品质和评分生成后保存，读档不重抽。内圈六槽装备，按既有百分比/固定值规则及敏感属性上限合成。洗练、精粹和熔炼业务及保存继续保留，但新装备页暂不提供入口，等待用户重新安排位置；不能写成已经删除业务，也不能擅自补回按钮。

具体门派神通、数值、生成区间与公式由[主动神通](../architecture/主动技能与神通.md)、[法则碎片](../guides/法则碎片.md)、[护罩](../guides/防护罩.md)维护。

## 8. 法宝、灵阵与真灵战阵

法宝是独立Q槽，不占六个神通槽。已拥有、当前装备及HUD切换分别管理；Alt滚轮只列出已持有法宝，保持首尾循环、移动中反向与连滚的连续视觉。

| 法宝 | 当前作用 |
| --- | --- |
| 镇妖阁 | 进入塔内及返回真实施放点，塔内Q始终用于返回 |
| 镇妖葫 | 收服、真灵拥有与战阵管理 |
| 青山剑 | 独立剑法宝与万剑归宗等原功能，右键图标查看专属信息 |
| 浮世万象 | 编排并施放玩家保存的灵阵方案 |
| 邪眼 | 接管自动索敌、功法普攻与激光；卸下或主动暂停后停止接管 |

浮世万象保留六个可编辑方案，控制节点、正逆打包、多重分支与生成/追踪/分裂/强化/加速/方向修饰按实际空间顺序执行。灵弹穿阵时逐次支付灵力，节点完成功能后淡出；玩家编排独立保存，默认方案资产只读。

镇妖葫的真灵九宫战阵是另一系统，不能和浮世万象六个编排槽混用。真实捕获记录决定可用真灵，中心玩家位不放真灵，其余遵守现有站位数量、跟随与原生NPC动作规则。

详见[法宝与收服](../guides/镇妖葫与真灵收服.md)、[真灵战阵](../architecture/战阵真灵.md)、[灵阵体系](灵阵体系.md)、[邪眼](../guides/邪眼.md)。

## 9. 洞府、种植与生产

拓境令扩展洞府地块并补齐内部接缝。建筑令和灵田开拓令沿用摆放预览、旋转、取消返还、占地/碰撞检查、挪动及存档。建筑的地图美术与功能模板分别管理，不能仅根据模型名推断已实现的功能。

| 设施 | 功能 |
| --- | --- |
| 炼丹阁 | 原手动炼丹、丹方及消耗/产出 |
| 功德堂 | 贡献兑换种子、建筑和物品 |
| 传法阁 | 功法、神通等学习物品兑换 |
| 执事阁 | 交货委托及宗门野外悬赏 |
| 炼器阁 | 建筑与交互占位；炼器配方、材料和产出未定义 |

灵田保留播种、浇水、生长、收获和施肥，傀儡、基站和仓库负责既有自动农务。兽栏处理食槽、饱食、五种动物产物与同种繁育；粪便进入堆肥，再将肥料用于灵田。自动炼丹炉使用独立输入/成品仓位、已学丹方和游戏日计时，不自动抽取玩家背包材料；开炉扣材和待产状态一起保存，读档不重掷。

生产随游戏日推进，暂停不计时，离开洞府可继续，退出游戏不离线补算。满仓、缺材、饥饿和容量不足按各自规则暂停，不无限累积产出。详见[灵田](../guides/灵田.md)、[生产建筑](../guides/家园生产建筑.md)、[炼丹](../guides/炼丹.md)。

## 10. 委托、贡献与镇妖阁

执事阁保留实际交货和野外悬赏。交货扣除真实物品，悬赏统计本次妖群的真实死亡事件；回执事阁结算，不重复领奖。野外悬赏不搬入塔内，塔内击杀不冒充悬赏完成。

镇妖阁记录当前/最高层、清怪与下一层。洞府Q入塔时保存实际施放位置和朝向；塔内Q或死亡返回同一点，塔内存档并重新读档后仍可返回。楼层落盘使用当前存档槽，不等于自动全量保存背包。

贡献、学习物品和生产奖励构成现有成长循环。旧主线进度、巡览要求和旧教学对白不再驱动这些系统。详见[委托](../guides/执事阁与宗门任务.md)、[镇妖阁](../guides/镇妖塔.md)。

## 11. 行游、坐骑与外观

Tab轮盘选择御风或已解锁坐骑，准备状态与实际运行分开，骑乘和御风按原互斥规则切换。对地高度由运动系统维护，水平转向、飞行动画、上下坐骑与升降过渡分别管理；不能用换一条动画来替代实际运动状态。

稳定御风才允许方向闪避，经过统一动作入口、免疫与打断处理。坐骑目录、学习拥有和当前选择分开，实际骑乘检查门槛。飞剑地面御风视觉是武器姿态规则，不应据此擅自改变已保存的坐骑或神通状态。

外观使用同一人体Animator，立绘与模型随当前外观同步。境界赠送学习物品后仍须使用解锁，领取标记防止反复赠送。当前衣发使用已有分区、骨链和并行随动，不重生成用户已调整的袖子或骨架；动作数值检查不代表所有视角已经美术验收。

## 12. 背包、装备与通知

右下导航为背包、装备、坐骑。背包四类是学习、使用、草药、其他；四类两端与五列格子区域对齐，首屏25格，只有溢出才显示滚动条。整理按钮按格子区域居中。选中格四边高亮并锁定简介，再点当前项解除；经过其他物品不能覆盖锁定内容。

装备页沿用同套宣纸和简介，下方神通/法则/武器三类显示实际已掌握或拥有内容。上方角色立绘虚化作底，内圈法则、外圈主动神通保留真3D环绕与星光，武器斜置于中心。切分类平滑突出对应对象，后景槽虚化；拖放、交换、卸下走原数据接口。装备页不保留外观按钮，背包页保留圆形外观入口。

简介固定在纸面外侧，图标、名称、数量、品阶与正文有独立留白和分隔线，上下长渐隐；使用/装备按钮放选中格旁。格子悬停、按下变暗下沉、内部松开才选中，文字不随意换色。面板快速淡入淡出，关闭时正确归还输入。

获得、学习、装备等通知统一在上方中部，按文字宽度扩展黑底，两侧淡出且文字完全落在黑底。自下淡入滑入，新项平滑推旧项上移，压紧后再展开间距；同批通知在1.5秒开始淡出、1.7秒消失。鼠标使用生成的常态/按下形变两态，保留高分辨率原图，以UV和显示尺寸控制实际可见大小。

细节见[角色界面](../guides/角色界面统一布局.md)、[获得通知](../guides/获得与学习通知.md)、[素材来源](../reference/UI素材/生成鼠标光标.md)。

## 13. 画面与地图工具

正式项目为Built-in、Linear，尚未整体迁移URP。地图地形、草、水、雾、树石和建筑由运行式工坊维护，工坊数据与玩家存档分离。独立工坊制作三张正式地图，不能执行旧村庄生成器恢复已退役场景。

角色轮廓、环境墨线、辉光和调色分别处理；生成能力特效不应被角色全局描边包围。护罩根保持世界朝向，原粒子内部旋转继续。树叶抗锯齿、原材质、源模型、体素代理和地图碰撞都有各自维护边界，不用全工程重序列化代替局部修复。

## 14. 配置、资产与可扩展方式

配置链为`CSV → DataTableImporter定向导入 → Generated定义/使用效果 → Resources聚合库 → 运行组件`。CS/CSV统一UTF-8 BOM和LF；修改CSV后必须同步生成资产。武器、功法、主动/被动、法宝、物品、NPC、境界、坐骑、外观等各表字段与生成类型见[配置表字段](../reference/配置表字段.md)。

新增物品须登记使用效果与对应ID，并进入统一物品索引；新增武器同时登记武器表、获得武器物品及面板目录；新增神通同时考虑学习物品、图标、执行类型、资源、动作、费用、冷却和存读档。聚合目录更新不代表自动发给玩家。导入优先`ImportTables(false, 指定表)`，不重接正式场景。

美术源、成品、派生动作、生成图片和提示词分开登记；保留成品GUID。尤其动作维护先读[动作定稿登记](../guides/动作定稿与重建边界.md)，不能仅根据现有烘焙器重建所有历史定稿资源。

## 15. 测试、交付与现有边界

编辑器直接启动3C_Testbed且无正式SaveSession、无QA隔离覆盖时，提供当前目录全部物品各一件、三把已拥有武器；法则只给宝箱，不预塞随机碎片。新增定义随目录同步。该模式保存到Library测试目录，正式菜单进入不执行。

自动Play回归先记录真实存档指纹并设隔离目录，结束停止、清除覆盖、核对指纹和Game View分辨率。尽量用独立编辑器预览做纯动作/素材检查，不把测试角色状态留给用户。检查结果必须写明范围：编译、数值、真实操作、逐帧姿态及用户美术验收不是同一结论。
