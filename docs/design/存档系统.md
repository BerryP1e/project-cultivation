# 存档系统设计

> 权威范围：存什么、什么时候存、什么时候恢复、加字段怎么迁移。
> 相关：[design/物品系统](物品系统.md) · [design/主线-任务与对话](主线-任务与对话.md)

## 1. 文件与入口

| 项 | 值 |
|---|---|
| 读写 | `Assets/Scripts/Save/SaveSystem.cs`（静态类） |
| 数据结构 | `Assets/Scripts/Save/SaveData.cs`（`[Serializable]`，`JsonUtility` 序列化） |
| 落盘位置 | `Application.persistentDataPath/saves/slot_<n>.json` |
| 槽位数 | `SaveSystem.槽位数` = 5 |
| 版本号 | `SaveData.当前版本`（**加字段必须 +1**，旧档缺字段会拿默认值） |
| 应用到角色 | `Assets/Scripts/Save/SaveApplier.cs`（挂在 Player 上，`Start()` 里跑一次） |
| UI | `MainMenuUI`（新游戏/读档）、`PauseMenuUI`（存/读） |

Windows 上的实际路径形如
`C:\Users\<用户>\AppData\LocalLow\<公司名>\<产品名>\saves\slot_0.json`。

## 2. 这条时序是理解一切的关键 ⚠️

```
主菜单选档 → SaveSystem.当前存档 = 数据
           → MainMenuUI.进游戏(): SceneManager.LoadScene(数据.场景名)
                        │
                        ▼
              游戏场景加载
                        │
        ┌───────────────┴────────────────┐
        ▼                                ▼
跨场景数据.Awake()                   任务管理器.Start()
  → 从静态快照灌回面板数据            → 应用存档() / 恢复存档进度()
    （切场景接力用；新开局没有快照）      → SaveSystem.取挂起的进度()
                                        → 导入进度() / 对话标记 / 补齐进度标记()
```

> ⚠️ **`SaveApplier` 并没有挂在任何游戏场景里**（查过 Village / Sect，0 个实例）。
> 所以 `SaveSystem.应用到角色()` 实际由 **`任务管理器.Start()` 里的 `应用存档()`** 调 ——
> 任务管理器在每个游戏场景都保证有（现在还有 `场景自举` 兜底）。

**为什么任务进度要挂起**：`应用到角色` 在面板/角色就绪前跑，那时 `任务管理器` 还不存在。
所以 `SaveSystem` 把 `待恢复任务进度 / 待恢复对话标记` 存成静态字段，由 `任务管理器.Start()` 调
`SaveSystem.取挂起的进度(out ...)` 取走（**取完即清，只恢复一次**）。

> 同理，`位置` 的恢复杂交着一堆东西：`应用到角色` 会写玩家坐标，
> 但**位置为 `Vector3.zero` 时跳过**（新档不认识"原点"）。
> 主线里"把玩家放到宗门落点"是任务动作干的（见 [design/主线-任务与对话](主线-任务与对话.md) 的落点机制）。

### 2.1 `应用存档()` 只跑一次 ⚠️（2026-09-27 修的严重 bug）

```csharp
static bool 本局已应用存档;          // 静态：本局只应用一次
void 应用存档()
{
    if (本局已应用存档) return;
    if (SaveSystem.当前存档 == null) return;
    本局已应用存档 = true;
    SaveSystem.应用到角色(SaveSystem.当前存档);
}
```

**为什么要挡**：`应用存档()` 原来**每个场景的 Start 都跑**，而它内部有
`是新档 = 存档里背包/法宝/灵阵/坐骑/真灵全空 → 清空玩法数据()` 和
`恢复面板()`（**无条件** `面板.物品 = new List<>()` 再按存档灌）。
存档是空的时候（新开档还没存过），每次切场景都会把**刚接力过来的数据清掉**：

```
[跨场景] 已把上一场景的数据接过来：背包 25 件
[存档] 判定为新档：已清空场景面板          ← 刚接过来就被清
```

症状：**传送后背包全丢、学会的神通全没**。存档是"每局开局"的东西，不该在换场景时重放。

### 2.2 接力期间不按存档位置摆玩家 ⚠️

`应用到角色` 里：

```csharp
if (跨场景数据.正在接力)
    Debug.Log("[存档] 正在跨场景接力 → 跳过「按存档位置摆放玩家」（落点由切场景过渡负责）");
else
    玩家.transform.position = 数据.位置 == Vector3.zero ? 玩家.transform.position : 数据.位置;
```

**为什么**：切场景的目标是「传到**目的地的落点**」，而存档位置是"上次存档站的地方"。
用存档位置盖会**把玩家从落点搬回存档点**（用户报的"没生成在应该在的落点上"）。

## 3. 存档里有什么（版本 5）

| 分组 | 字段 |
|---|---|
| 身份 | `版本` `角色名` `境界` `最后存档时间` |
| 进度 | `场景名` `位置` `朝向Y` |
| 资源 | `当前气血` `当前灵气`（-1 = 用满值） |
| 配置 | `功法id` `已装备神通` `已启用被动` || 修炼 | `总灵气` `修炼次数累积` `境界等级` `已学功法` |
| 能力 | `已获得主动神通` `已获得被动神通` |
| 战阵 | `战阵站位`（固定 9 格，空位写空字符串） |
| **背包/装备（v5）** | `背包物品`（一件一条，重复出现）`法宝` `灵阵` `坐骑` `当前坐骑` `主动技能槽` `已停用被动` `已获得真灵` |
| **主线（v5）** | `任务进度`（格式同 `任务管理器.导出进度()`）`对话标记`（分号分隔） |
| **经验（v5）** | `当前经验` `突破所需总经验` |
| 属性快照 | `属性键` / `属性值`（平行列表，`写属性/读属性` 访问） |

### 版本历史

| 版本 | 加了什么 |
|---|---|
| 2 | 修炼系统（总灵气 / 修炼次数 / 已学功法） |
| 3 | 战阵站位 |
| 4 | 已获得的能力（主动/被动神通） |
| 5 | 背包物品 / 法宝 / 灵阵 / 坐骑 / 主动技能槽 / 已停用被动 / 已获得真灵 / **任务进度** / **对话标记** / 境界经验 |

> `JsonUtility` 的特性：**旧档缺字段 = 拿默认值**，不会读不出来。
> 所以加字段基本安全；删字段/改语义才需要按 `版本` 做迁移。

## 4. 采集与恢复是对称的两半

| 采集（存档时） | 恢复（读档时） |
|---|---|
| `SaveSystem.从角色采集(数据)` | `SaveSystem.应用到角色(数据)` |
| `采集面板(数据, 面板)` | `恢复面板(数据, 面板)` |
| 位置/朝向/气血/灵气/修炼/功法/能力（写在 `从角色采集` 里） | 对应写在 `应用到角色` 里 |
| 战阵站位（9 格遍历） | `找真灵定义(id, 面板)` 按 id 还原 |
| 任务进度 `任务管理器.导出进度()` | 挂起 → `任务管理器.导入进度()` |
| 对话标记 `对话标记.全部标记()` | 挂起 → `对话标记.清空()` + 逐个 `添加` |

**加一个要存的东西 = 动四处**：
`SaveData` 加字段并 `当前版本 +1` → `采集面板/从角色采集` 里采集 →
`恢复面板/应用到角色` 里恢复 → 若涉及新系统，注意恢复时机（见第 2 节）。

主动技能槽存的是 `UnityEngine.Object`（神通/法宝/灵阵共用），
用 `取内容id()` 按类型取 id，恢复时用 `找内容()` 先按 id、再按资源名兜底。

## 5. 新档（`SaveSystem.建新档`）

**用户口径（2026-09-27）：最开始创建的角色，背包里什么都没有。**

所以 `建新档` 会调 `面板内容全清(数据)`，把
背包 / 法宝 / 灵阵 / 坐骑 / 技能槽 / 已停用被动 / 已获真灵 / 战阵 / 经验 /
**任务进度 / 对话标记** 全部置空。

另外 `应用到角色` 里还有一层保险：若判定为**新档**（背包/法宝/坐骑/真灵全空），
就把**场景面板里预置的**那些也清掉，并 `对话标记.清空()`（清静态残留）。

> 为什么需要第二层：场景里的 `CharacterUI` 可能被编辑器调试菜单塞过东西
> （`修仙/调试/用物品表填满当前场景背包`），那份数据是**场景资产**的一部分，
> 光靠 `SaveData` 清不掉。

### 5.1 新档**没有功法**（2026-09-27 用户确认）

```
开局：没有任何功法
学第一本秘籍：学会它，并且它成为「当前修炼的功法」
后续学其他秘籍：只是学会（进 已学功法），不改变当前功法
转修：必须去修炼小屋（CultivationUI 第三页「转修功法」，只能从已学里选）
```

`建新档()` 里 `功法id = ""`。

> 原来写死 `功法id = "gongfa_taixu_lianqi"` —— 那和"已学功法为空"自相矛盾，
> 而且 `应用到角色` 里有 `if (功法 != null) 面板.当前功法 = 功法;`，
> 一旦 `取功法` 取得到就会让主角**凭空多出一门功法**。
>
> ⚠️ 我曾在没查证的情况下**编造"主角开局自带太虚炼气诀"**，并据此改了
> `学功法效果`（加了个自创的"学会即转修"）。那是错的，已还原。
> **不要凭猜测改玩法语义 —— 先查、或先问。**

### 5.2 读档时补齐对话标记

`恢复存档进度()` 在 `导入进度()` 之后调 `任务管理器.补齐进度标记()`：
按当前进度重放每个阶段的 `打标记` 列，把**阶段早已过去、标记却从来没打上**的补回来。
（原因见 [design/主线-任务与对话 §4.1](主线-任务与对话.md)。）

## 6. 已知待办

1. **玩家位置只在存档时采集**。主线跑动过程中不自动存，所以中途关游戏会回到上次存档点。
   若要"自动存档"，建议挂 `PauseMenuUI` 那套之外的定时/节点存档。
2. **战斗中的 NPC / 掉落物 / 场景临时物体不存**，读档回到场景初始状态。
3. `已装备神通 / 已启用被动` 这两个旧字段与 `主动技能槽 / 已停用被动` 有重叠，
   实际生效的是后者；前者是否还需要存待确认。
4. **`对话标记` 是无序 `HashSet`**，存出来的字符串顺序不固定；只要读档是"全量覆盖"就无害，
   但**不要**用字符串比较来判断"标记有没有变"。
