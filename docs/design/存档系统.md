# 存档系统

更新：2026-10-17，当前 SaveData 版本 25，新增角色独立的灵阵编排。v24 家园档可缺省新增字段，使用默认方案；更早 RPG 文件保留，菜单仍提示另建角色，不迁移旧场景。

采集时深复制 UIPanelData.灵阵编排，载入时校验并按 ID 恢复；六个默认方案资产保持只读。编排保存按钮提交角色内存，游戏保存写入当前角色槽位；跨场景快照复用同一采集/恢复流程。

## 文件与入口

正式文件为 Application.persistentDataPath/saves/slot_<n>.json，共五个槽位。实际路径随机器和用户名变化，不能把某台电脑的路径写死。主菜单选择槽位后设置当前存档/当前槽位，再调用 SaveApplier.开始读取存档并加载目标场景。3C_Testbed 是洞府，不能重定向到村庄。

SaveApplier 在场景角色就绪后每局应用一次数据。普通传送使用跨场景快照，保持目的地坐标和当前会话；不重新加载旧磁盘位置。再次从主菜单选档会重置恢复闸门、旧落点和接力快照。直接打开编辑器场景不会自动读取正式角色文件。

## 保存的职责边界

| 数据 | 保存和恢复 |
| --- | --- |
| 角色与资源 | 身份、修为、境界、属性相关状态、气血灵力、已学功法与神通 |
| 背包与装备 | 物品 ID、法宝、灵阵、坐骑、真灵、战阵与技能槽 |
| 外观 | 当前外观 ID 与永久拥有记录；11/31 级赠送学习物品，使用后解锁；已赠标记存于通用对话标记，防读档重发 |
| 位置 | 玩家所属场景、有效位置与朝向；附加场景成为 active scene 时仍取玩家的场景 |
| 家园 | 拓境坐标、灵田、摆设、仓库、动物、堆肥、炼丹等原有生产状态 |
| 委托 | 宗门任务记录、已接任务、剩余悬赏成员和追踪对象 |
| 通用标记 | 丹方学习、炼成记录等直接由 SaveSystem 恢复，不等待已退役的任务管理器 |
| 时间与每日清单 | 时间管理器恢复纪年；日常循环领取挂起的清单天数与掩码 |
| 镇妖阁 | 当前/最高层与镇妖阁返回点；返回点包括洞府场景、位置和朝向 |

地图地形、物件和素材来自正式 Map.asset，不打包进每个角色存档。工坊修改并应用正式地图后，再读角色存档应看到新地图，同时恢复该角色的位置、扩建和生产状态。

## 镇妖阁存读档

洞府按 E 施放法宝时记录实际位置与朝向，再进入塔内。塔内正常 E 退出或死亡均调用同一返回流程。塔内保存后从主菜单读取，仍恢复返回点；退出时使用该点，不传去已退役的宗门。落点在 LateUpdate 只应用一次，再同步物理和相机。

楼层记录写当前选择的槽位，不默认写槽位 0。楼层落盘只更新塔层字段，不能把它称为自动全量保存背包。

## 标记与会话

采集保存时保留通用对话标记串。读档时清除上一局未保存的标记，再导入这份存档的内容；普通跨场景接力不覆盖当前标记。任务进度字段保持空值，不再调度主线阶段。角色空背包不等于新角色：已学功法、能力、丹方、法宝或委托记录存在时不能清空进度。

## 验证与保护

自动化 Play 必须先运行 world-maps-play-setup，通过 Editor SessionState 的 Cultivation.Validation.SaveDirectory 指向工作区隔离目录。该脚本先对真实存档建立指纹；结束运行后执行 world-maps-play-teardown 核对真实文件并清除覆盖。不要重复 setup 覆盖原指纹，不要自动用旧备份回盖用户存档。

核心验收包含实际菜单新建/读档、旧版文件原字节保留、学丹方再读档、日常清单、家园扩建、塔内存档后退出位置/朝向、死亡返回和野外悬赏。配方见[验证入口](../../devtools/validation/README.md)。旧版流程仅供[历史查阅](../archive/pre-home-20261016/design/存档系统.md)。
