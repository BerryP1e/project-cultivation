## 2. 启动时序 ⚠️

```
选档 → SaveSystem.当前存档 = 数据 → MainMenuUI.进游戏(): LoadScene(数据.场景名)
场景加载后两路：
  跨场景数据.Awake() → 从静态快照灌回面板数据（切场景接力；新开局无快照）
  任务管理器.Start() → 应用存档() / 恢复存档进度() → SaveSystem.取挂起的进度()
                     → 导入进度() / 对话标记 / 补齐进度标记()
```

⚠️ `SaveApplier` 没挂在任何游戏场景里（查过 Village / Sect，0 个实例）→ `应用到角色()` 实际由 `任务管理器.Start()` 的 `应用存档()` 调（任务管理器每个游戏场景都有，`场景自举` 兜底）。
进度为什么挂起：`应用到角色` 跑在面板/角色就绪之前，那时 `任务管理器` 还不存在 → `待恢复任务进度 / 待恢复对话标记` 存成 `SaveSystem` 静态字段，由 `取挂起的进度(out ...)` 取走（取完即清，只恢复一次）。

### 2.1 `应用存档()` 只跑一次 ⚠️

```csharp
static bool 本局已应用存档;          // 静态：本局只应用一次
void 应用存档()
{
    if (本局已应用存档) return;
    if (SaveSystem.当前存档 == null) return;
    本局已应用存档 = true;
    SaveSystem.应用到角色(SaveSystem.当前存档);
}
```

现象：传送后背包全丢、学会的神通全没。
根因：原来每个场景 Start 都跑，而它内部有"新档判定 → `清空玩法数据()`"和 `恢复面板()`（无条件 `面板.物品 = new List<>()` 再按存档灌）；新开档存档为空 → 每次切场景都把刚接力过来的数据清掉。
修法：加静态闸门（见代码）。存档是每局开局的东西，不该在换场景时重放。

### 2.2 接力期间不按存档位置摆玩家 ⚠️

```csharp
if (跨场景数据.正在接力)
    Debug.Log("[存档] 正在跨场景接力 → 跳过「按存档位置摆放玩家」（落点由切场景过渡负责）");
else
    玩家.transform.position = 数据.位置有效 ? 数据.位置 : 玩家.transform.position;
```

现象：没生成在应该在的落点上。根因：切场景要的是目的地的落点，存档位置是上次存档站的地方，用它盖会把玩家搬回存档点。修法：接力期间跳过（见代码）。
同一段的约定：**用 `位置有效` 这个显式标志**判断要不要套用位置 ——
⚠️ **不能拿 `位置 == Vector3.zero` 当哨兵**（老代码就是 `数据.位置 == Vector3.zero ? 保持现状 : 应用`，
于是"正好站在原点"的档不会恢复位置）。
把玩家放到宗门落点是任务动作干的（见 [传送系统](../architecture/传送系统.md)）。

## 3. 存档里有什么（版本 13）

| 分组 | 字段 |
|---|---|
| 身份 | `版本` `角色名` `境界` `最后存档时间` |
| 进度 | `场景名` `位置` `位置有效` `朝向Y` |
| 资源 | `当前气血` `当前灵气`（-1 = 用满值） |
| 配置 | `功法id` `外观id` `已装备神通` `已启用被动` |
| 修炼 | `总灵气` `修炼次数累积` `境界等级` `已解锁最高等级`（v8，**破境成功才 +1**）`破境加成`（v9，服破境丹吃出来的成功率加成）`已学功法` |
| 能力 | `已获得主动神通` `已获得被动神通` |
| 战阵 | `战阵站位`（固定 9 格，空位写空字符串） |
| 背包/装备 v5 | `背包物品`（一件一条，重复出现）`法宝` `灵阵` `坐骑` `当前坐骑` `主动技能槽` `已停用被动` `已获得真灵` |
| 主线 v5 | `任务进度`（格式同 `任务管理器.导出进度()`）`对话标记`（分号分隔） |
| 经验 v5 | `当前经验` `突破所需总经验` |
| 镇妖塔 v6 | `镇妖塔当前层` `镇妖塔最高层` |
| 纪年 v8 | `天数` `日内进度` `日常机会`（JSON 字典）`打怪机会` |
| 灵田 v11 | `灵田地块`（**`List<灵田地块状态>`**，**每条地一个对象**：`位置` Vector3 / `朝向档` int 0~7 / `品阶` / `作物id` / `已生长天数`）。旧字段 `灵田品阶` / `灵田格数` / `灵田格子` 已删除；v10 的 `List<string>`（一行一块地）也已改掉 |
| 摆设 v12 | `摆设`（**`List<摆设状态>`**，**每件一个对象**：`类型id` string / `位置` Vector3 / `朝向档` int 0~7）—— **非灵田的可摆放物**（练功木桩等）。摆的是哪种东西由 `类型id` 去 `摆放物库` 反查 |
| **宗门贡献 v13** | `宗门贡献`（`int`）—— 宗门通用货币，**落盘处**（内存里的真值在静态类 `宗门贡献.当前`）。来路 = 打塔清场 + 任务表 `奖励贡献`，去处 = 功德堂兑换，见 [guides/宗门贡献与兑换](../guides/宗门贡献与兑换.md) |
| 属性快照 | `属性键` / `属性值`（平行列表，`写属性/读属性` 访问） |

> ⚠️ **`灵田地块状态` 与 `摆设状态` 本身就是存档类型**（`SaveData.灵田地块` / `SaveData.摆设` 直接装它们，
> `JsonUtility` 序列化对象）⇒ 它们的字段**必须保持 `JsonUtility` 兼容**（`string` / `float` / `int` / `Vector3`）。
> **别加 `Dictionary` / 接口 / 属性** —— `JsonUtility` 会**静默丢**这些字段，存档看起来正常、读回来就少东西。
> 同类约束适用于所有"直接被 `JsonUtility` 序列化的类"。

**刻意不存的**：摆下来的**练功木桩的当前血量**。它打空后**立即满血**（`NPC表.csv` 里
`死亡后立即重生=是`、重生延迟 0），没有需要跨存档记住的状态；存了反而会和"打空自动满血"打架。

**版本历史**（真值在 `SaveData.当前版本`，加字段必须 +1）：
`2` 修炼系统｜`3` 战阵站位｜`4` 能力（主动/被动神通）｜`5` 背包物品/法宝/灵阵/坐骑/主动技能槽/
已停用被动/已获得真灵/任务进度/对话标记/境界经验｜`6` 镇妖塔层数｜`7` 场景名/朝向/外观｜`8` 纪年/灵田/已解锁最高等级｜`9` 破境加成｜`10` 灵田改成每块地独立状态｜`11` 灵田改成玩家自由摆放（每块地带位置与朝向）｜`12` 新增「摆设」（可摆放物：练功木桩等）｜`13` 新增「宗门贡献」（兑换用货币）。

> ⚠️ **v13 和 v11 / v12 不是一类**：v11 / v12 是**破坏性升级**（字段结构变了 ⇒ 老档重新开局），
> 而 v13 是**加法字段**：`JsonUtility` 读老档缺字段 = 拿默认值 `0`，
> 而 `0` 正好等于"新玩家一点贡献都没有" ⇒ **语义天然对齐，不需要版本门槛**。
> `SaveSystem.应用到角色` 里那行还多了个 `数据.是空的 ? 0 : 数据.宗门贡献` 的兜底（空档一律 0）。

> ⚠️ **恢复顺序有讲究**：读档时**先恢复 `已解锁最高等级`、再恢复 `总灵气`**，
> 否则 `查境界` 会按没封顶的算法把等级顶上去（见 [修炼与境界](../architecture/修炼与境界.md)）。

`JsonUtility`：旧档缺字段 = 拿默认值 → 加字段安全；删字段或改语义才按版本迁移。
> **老档兼容已明确放弃**（用户：「不用补老档兼容，老档可以全部删掉」）——
> 所以不需要写 v1~v7 的迁移代码。

## 4. 采集与恢复是对称的两半

| 采集（存档时） | 恢复（读档时） |
|---|---|
| `SaveSystem.从角色采集(数据)` | `SaveSystem.应用到角色(数据)` |
| `采集面板(数据, 面板)` | `恢复面板(数据, 面板)` |
| 位置/朝向/气血/灵气/修炼/功法/能力（写在 `从角色采集` 里） | 对应写在 `应用到角色` 里 |
| 战阵站位（9 格遍历） | `找真灵定义(id, 面板)` 按 id 还原 |
| 任务进度 `任务管理器.导出进度()` | 挂起 → `任务管理器.导入进度()` |
| 对话标记 `对话标记.全部标记()` | 挂起 → `对话标记.清空()` + 逐个 `添加` |
| 摆件 / 地块 `摆设.导出()` · `灵田.导出()` | `摆设.导入(数据.摆设)` · `灵田.导入(数据.灵田地块)`（两个都是**对象列表直接序列化**，不用挂起；导入后各自重建场景视图） |
| 宗门贡献（v13）`数据.宗门贡献 = 宗门贡献.当前` | `宗门贡献.从存档设置(数据.是空的 ? 0 : 数据.宗门贡献)`（静态类的值，直接抄进 / 抄出，不用挂起 —— 同 `对话标记` 那一类） |

加一个要存的东西 = 动四处：`SaveData` 加字段（版本 +1）→ 采集 → 恢复 → 注意恢复时机（第 2 节）。
主动技能槽存 `UnityEngine.Object`（神通/法宝/灵阵共用）：`取内容id()` 按类型取 id，`找内容()` 恢复（先按 id，再按资源名兜底）。

## 5. 新档（`SaveSystem.建新档`）

口径：新创建的角色背包里什么都没有 → `建新档` 调 `面板内容全清(数据)`，置空 背包/法宝/灵阵/坐骑/技能槽/已停用被动/已获真灵/战阵/经验/任务进度/对话标记。
第二层保险：判定为新档（背包/法宝/坐骑/真灵全空）时，把场景面板预置的也清掉并 `对话标记.清空()`（清静态残留）—— `CharacterUI` 上的东西属于场景资产（调试菜单 `修仙/调试/用物品表填满当前场景背包` 塞的），`SaveData` 清不掉。

### 5.1 新档没有功法

```
开局：没有任何功法
学第一本秘籍：学会它，并且它成为「当前修炼的功法」
后续学其他秘籍：只是学会（进 已学功法），不改变当前功法
转修：必须去修炼小屋（CultivationUI 第三页「转修功法」，只能从已学里选）
```

`建新档()` 里 `功法id = ""`。
坑：原来写死 `功法id = "gongfa_taixu_lianqi"`，与已学功法为空矛盾；`应用到角色` 的 `if (功法 != null) 面板.当前功法 = 功法;` 会让主角凭空多出一门功法。另曾编造"开局自带太虚炼气诀"并据此改 `学功法效果`（自创"学会即转修"），已还原 —— 不要凭猜测改玩法语义，先查或先问。

### 5.2 读档时补齐对话标记

`恢复存档进度()` 在 `导入进度()` 之后调 `任务管理器.补齐进度标记()`：按当前进度重放每个阶段的 `打标记` 列，补回阶段早已过去、标记却从没打上的（原因见 [任务系统](任务系统.md)）。

## 6. 已知待办

1. 位置只在存档时采集，跑动中不自动存；中途关游戏回到上次存档点。要自动存档，另挂 `PauseMenuUI` 之外的定时/节点存档。
2. 战斗中的 NPC / 掉落物 / 场景临时物体不存，读档回到场景初始状态。
3. `已装备神通 / 已启用被动` 与 `主动技能槽 / 已停用被动` 重叠，生效的是后者；前者是否还要存待确认。
4. `对话标记` 是无序 `HashSet`，存出来顺序不固定；读档是全量覆盖就无害，但**不要**用字符串比较判断标记有没有变。
