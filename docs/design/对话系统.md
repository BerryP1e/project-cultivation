## 1. 数据与运行链路

```
Assets/Data/Tables/对话表.csv            ← 你唯一要手改的地方
        │  菜单：修仙/从配置表生成资产
        ▼
Assets/Data/Generated/DialogueDefinition/*.asset     （一条对话 = 一个资产）
        │  自动跟着跑 / 或菜单：修仙/对话系统/收集对话资产
        ▼
Assets/resources/对话/对话库.asset        ← 运行时唯一入口（Resources 才能被运行时读到）
        ▼
DialogueDatabase.取().取段(npcId, 分段)  →  DialogueUI 显示
```

**为什么要「收集」这一步**：生成出来的资产在 `Assets/Data/Generated/` 下、**不在 Resources 里**，
运行时 `Resources.Load` 拿不到（这是本项目的既有约束）。所以摊平成一份库资产放在 Resources 下。
`修仙/从配置表生成资产` 结束时已经会自动调一次收集，一般不用手点。

## 2. 对话表字段（`对话表.csv`）

| 列 | 说明 |
|---|---|
| `id` | 本条唯一 id，建议 `dlg_<谁>_<第几段>` |
| `npcId` | 写 `NpcDefinition.id`（如 `npc_cunmin_chengnan`）。**留空 = 通用段**，谁都能用 |
| `分段` | 同一 NPC 从 1 开始；`跳转` 也指到这里。同一个 `分段` 可以写多条（靠条件/优先挑一条） |
| `说话人` | 留空 = 用 NPC 自己的显示名 |
| `文本` | 这一段说什么 |
| `立绘` / `玩家立绘` | 旧表兼容列，当前界面不读取图片，见2.2 |
| `回答1..3` | 回答选项文字，**留空即没有这个选项**（最多 3 个） |
| `跳转1..3` | 选了对应回答跳到哪个 `分段`；**0 = 结束对话** |
| `需要标记` / `排除标记` | 条件，分号分隔。留空 = 无条件 |
| `优先` | 同分段多条都满足条件时，取 `优先` 大的（**优先相同则 NPC 专属压过通用**） |
| `情绪` / `情绪强度` | 见 2.3。留空 = 不表演情 |
| `触发任务` / `完成任务` | 任务接线，在**按下回答时**执行（见 4.5） |

### 2.1 通用段 / 无回答段

- **通用段（`npcId` 留空）**：**任何 NPC** 都能取到。典型用法：给所有村民写一段"兜底第 4 段"，
  只有没写第 4 段的 NPC 才会走到它。⚠️ 同 `分段` 同时有专属段和通用段时，专属段赢（按"优先→是否专属→id"排序）。
- **没有回答的段落**：`回答1..3` 全空 → 界面给一个「继续 ▸」按钮：能进下一段就进，否则「结束」。
  键盘上按 `继续键`（默认 `F`）或空格也等于点它。

### 2.2 立绘兼容字段

当前对话按用户新要求取消双方立绘、占位与说话方缩放。表字段与旧资源保留以兼容导入和历史数据，DialogueUI不再加载或生成立绘节点；无需为当前对话补立绘。

### 2.3 情绪特效

`情绪` 列写名字，`情绪强度` 写倍率（1 = 标准，0.5 = 弱一半，留空按 1 算）。

| 名字 | 表现 |
|---|---|
| `震动`（也认 `震惊`/`惊讶`） | 整个对话框抖动0.45秒 |
| `冒泡`（也认 `冒泡泡`） | 对话框姓名附近冒出泡泡 |
| `发怒`（也认 `生气`） | 文本框闪红 |
| `害羞` | 文本框闪粉 |

**加新情绪（不用改表结构、不用改 `switch`）：**

```csharp
// 在任意初始化处（例如你自己的剧情脚本 Awake）注册一次
DialogueUI.自定义情绪["彩虹"] = (ui, 强度) =>
{
    ui.StartCoroutine(ui.冒泡(强度));      // 复用内置表现
    ui.StartCoroutine(ui.闪色(强度, Color.cyan));   // 或者自己组合
};
```

之后对话表里 `情绪` 列写 `彩虹` 就能用。写了一个没注册的名字：只会在 Console 里提示一句，不会崩。
`DialogueUI` 上的 `震动/冒泡/闪色` 都是 `public IEnumerator`，可以从外面直接起。

## 3. 选段与入口

### 3.1 条件判定

`对话条件.满足(d) = 「需要标记」全中 且 「排除标记」一个都没中`。
**规则**：`需要标记` **全部**具备、`排除标记` **一个都不**具备 → 这条才算候选；多条候选按 `优先` 选大的。

`需要标记` 里有一类**特殊标记 `场景_<场景名>`**（由 `场景自举` 每进一个场景维护，用来做"某段话只在某个场景能说"）——
**它也是条件的一部分**，写法与用途见 [reference/配置表字段 §5.1](../reference/配置表字段.md)，
由来见 [踩坑总库 C10](../ai/踩坑总库.md)。

| id | npcId | 分段 | 文本 | 需要标记 | 排除标记 | 优先 |
|---|---|---|---|---|---|---|
| dlg_cunzhang_01 | npc_cunzhang | 1 | 你来得正好，帮我去采三株灵芝。 | | 任务_采药_已接 | 0 |
| dlg_cunzhang_01b | npc_cunzhang | 1 | 灵芝采到了吗？ | 任务_采药_已接 | | 0 |
| dlg_cunzhang_01c | npc_cunzhang | 1 | 多谢道友！ | 任务_采药_已交 | | 10 |

### 3.2 入口段 = 最小分段

按 F 打开对话时，走的是 `DialogueDatabase.最小分段(npcId)` —— 也就是**第 1 段**；之后靠每段自己的「跳转」往后走。
**所以任务阶段 `条件=对话` 的 `对话id` 必须填「入口段」或「入口链路能到达的段」。**

实际踩过的坑：`q_main_003` 第 12 阶段填了 `对话id=dlg_act3_dashi_7`，但那是个**第 7 段**、入口是
`dlg_act3_dashi_1`（第 1 段）→ **该阶段永远达不成**，玩家每次按 F 都只看到第 1 段 → **招募对话无限循环**。
改成 `dlg_act3_dashi_1` 后正常。
**自查方法**：对每个 `条件=对话` 的阶段，比对「该段的分段号」与「该 NPC 的最小分段号」；不等就要确认有跳转链能走到。

### 3.3 同一段有多条候选时怎么选

`DialogueDatabase.候选()` 的排序：

1. **优先大者胜**
2. 平手 → **NPC 专属**压过**通用**（`npcId` 为空的是通用兜底）
3. 再平手 → **带「需要标记」的**压过无条件的
4. 最后按 `id` 稳定排序

⚠️ 所以**同段位要多条时优先值必须拉开**，否则你写的任务回答会被默认回答顶掉。

#### 3.3.1 最优先的一条：**当前主线阶段「点名」的那段**

`取段()` 在 `候选()` 之前先看 `当前阶段点名的对话()`：**正在跑的主线阶段**如果 `条件=对话`
且填了 `对话id`，那一段就压过 `优先` 抢（否则阶段16 会被同段 `优先` 更高的阶段18 台词顶掉，
永远完不成）。它还负责"点名的是靠后的段"这种情况：点名段的分段号 **>** 这次要的段、
且这次要的正是这棵树的入口段 → 用**入口段**开场，靠回答/跳转走到点名那一段。

> ⚠️⚠️ **「点名」只是优先，不是豁免**：`取段()` 会先判 `对话条件.满足(点名)`，
> **不满足就当作"没有点名"**，回到普通的"同段里挑优先最高"。
> 这条是 2026-10-02 补的：原来第 ① 条是 `if (点名.分段 == 分段) return 点名;` ——
> **直接返回、绕过条件**，于是给洞府台词加了 `场景_3C_Testbed` 门禁也拦不住，玩家在宗门照样能听
> （实测日志：`引导=洞府传送点`（对）但 `取段=dlg_act5_dongfu_1`（错））。见 [踩坑总库 C11](../ai/踩坑总库.md)。

### 3.4 对话门槛：没有可用段就不给交互

`NpcDialogue` 每帧判定「这个 NPC 当前有没有任何满足条件的对话段」，没有就把 `StationInteractable.现在可交互`
置 false —— 于是**不显示「F 对话」提示、按 F 也没反应**（`StationInteractor.找最近设施()` 会跳过不可交互的设施）。

**为什么需要**：任务生成的 NPC 出场往往**早于**它该说话的时候。实测 —— 大师兄在第 7 阶段就生成了，
而招募话要到第 12 阶段才打 `q_主线_招募中` 标记；玩家提前按 F，标记还没上，招募段/可启程段都不满足，
只剩下招募链的**中间段落**可入口 → 弹出"默认对话"（看起来像"说错了话"，等剧情演完再按 F 就正常）。

三道放行条件（避免误伤）：`DialogueDatabase.取()` 为空（库没就绪）→ 放行；该 NPC 压根没配对话（`有对话` 为 false）
→ 放行；战斗中的 NPC（`NpcAiHuman.现在可对话` 为 false）→ 拦。

> ⚠️ 这道门槛是**通用**的：任何"当前没有任何可用对话段"的 NPC 都会不可对话。
> **给 NPC 配对话时留一个无标记的兜底入口段**，否则他在标记没满足时会变哑巴。

## 4. 对话 UI

### 4.1 交互提示与朝向（`NpcDialogue`）

- **提示**：复用建筑那一套 `StationInteractable` + `StationInteractor`，**没有第二套**。
  NPC 类型是 `对话`、键位 `F`、距离 3.5m，同屏多个时取**根节点更近**的那个。

| 排版对象 | 做法 |
|---|---|
| NPC 头顶 | **只有 NPC 名字**（`StationName` 画布，白字加粗 + 深色描边、不带框） |
| NPC 身侧的「F 对话」小框 | `StationHint` 画布（圆角深色底 + 亮键帽 + 动作名"对话"）；沿**屏幕右方向**离身体 `StationInteractor.身侧距离`（默认 0.55m）、高度取肩胸之间（`顶 × 0.62`，夹在 1.2~2.2m）；画布轴心设在**左边缘** —— 小框从身体旁边往外长，不会压住人 |
| 建筑 | 保持老样子：头顶一个「F 炼丹」（`提示文字 = 设施.标题`，没有名字画布） |

实测：名字高度差 2.44m / 水平偏移 0.00m；小框高度差 1.51m / 水平距离 0.55m；跑远了两块一起隐藏。

- **朝向**：玩家进 `看向距离`(8m) 才看；距离 ≤ `只转头距离`(4.5m) 且所需偏角 ≤ `最大偏角`(70°) →
  **只转 Head 骨骼**；超了就交给身体（`NpcAiBase.转向`，带阻尼）；离开范围把头恢复原状。
- 头骨自动找名字含 `Head` 的骨骼（找不到退 `Neck`）；本项目村民是 `Head` / `NeckTwist01-02`。
- **偏角用的是项目自己的朝向公式**：`LookRotation(方向) * Euler(0, 模型朝向补偿, 0)`
  （和 `NpcAiBase.转向` 一模一样），所以头和身体对"正面在哪"的理解必然一致 ——
  别改成 `transform.forward` 去猜，村民的根节点 forward 不是模型正面。

### 4.2 组件与画布

- 对话框 `DialogueUI` 的 UI 是**照示意图的比例程序化搭的**（不是预制体拼的）。
- 上方偏中的深色墨边正文框，姓名在框内左上；双方无立绘。StationInteractor在对话打开时隐藏头顶姓名和F提示，关闭后按距离恢复。
- 回答在屏幕下方居中，横向墨边条；默认高度78、间距14，长回答按文本高度增高。回答视口支持滚轮、拖动、背包同款滚动条，内容溢出才显示滚动条。
- UIInkDialogueBackdrop与Resources中的InkDialogue.shader按实际尺寸渲染墨边。正文暖白32号、可缩到24号；回答27号、自动换行。回答文字复用UIInkViewportFade与UIInkFadeCoordinates；Canvas必须启用TexCoord1，否则滚动文字无法在视口边缘消隐。墨底独立按局部视口裁剪，射线过滤器拒绝视口外点击。
- InkUIRuntimeSkin不再重新套对话纸卷/金框；改展示不改条件、跳转、任务回调。F/空格继续、ESC与框内×关闭沿用原功能。
- **对话框画布 `2600`** —— 高于占位幕布 `2500`、低于暂停菜单 `3000`，万一两者同时存在也让对话框赢。
- `NpcDialogue` 在玩家身上有 `StationInteractor` 时**不再自己处理 F**：交互器是全项目唯一的 F 入口
  （建筑 `F 炼丹`、NPC `F 对话`、同屏取离根节点更近的）。漏挂模块的老实例由交互器补一个。

### 4.3 黑幕字幕：逐行打、收幕、防重入

任务动作 `黑幕字幕` 与 `落黑幕` 用的组件，几条必须守住的：

| 规则 | 说明 |
|---|---|
| `逐行打` 不要自动开「打完自动收幕」 | `落幕后自动收` 只由 `下落并定时收起()`（"整段过场"）开启；`说()` 只负责打字 + 落一次幕，收盘交给调用方（`主线开场` 最后自己调 `收幕()`） |
| 设标志的时机 | 必须在 `StartCoroutine` **之前**设：协程第一帧会调 `落下()`，而 `落下()` 会把它清成 false |
| `收起()` 已是协程 | 已经是隐藏状态时**不再排协程**，当场生效；**同一帧内「开始演出 → 收幕」忽略收幕**（`演出开始时刻` 判定）并打 Warning；`落下()` 起幕时清掉一切残留的收幕/自动收状态 |
| 收幕防重入标志 | `正在收幕 = true` 放在 `立即收掉()` 里**同步**设，`淡出幕` 收尾时清掉；`落下()` 起幕时要能打断正在进行的淡出，否则两边抢 alpha |
| 黑幕自己收幕 | 黑幕对象是 `DontDestroyOnLoad` 的，所以收幕计时用**它自己的实例字段**，按「字打完 + 停留 N 秒」收幕（挂在它自己的 `Update`） |

> 症状对照：`逐行打` 自动收幕 → 开场三句黑幕一黑一亮三次；`收起()` 排协程 → 新档开场的第一个黑幕被抹掉；
> 防重入标志设在协程体内 → 幕永远关不掉（阶段其实已推进过一次，`演出中` 永远为真）。

### 4.4 UI 侧的已知坑

点开对话是「空白幕布」或幕布与对话框叠着 —— 是 `StationInteractor.打开界面` 给 `类型=对话` 也造了占位幕布
（`sortingOrder = 2500` 盖住对话框），同时 `NpcDialogue` 也在同一帧抢 F。修法三条见 6.10。
### 4.5 任务管理器怎么接

**核心就一个静态标记集合**：`对话标记`（`Assets/Scripts/Data/对话标记.cs`）

```csharp
对话标记.添加("任务_采药_已接");        // 接任务
对话标记.添加一批("任务_采药_已接;见过村长");
对话标记.移除("任务_采药_已接");
bool 有 = 对话标记.具备("任务_采药_已接");
对话标记.清空();                        // 读档/重开时
对话标记.变化 += (标记, 新增) => { /* 需要的话刷新界面 */ };
```

**对话侧不用写代码**：对话表里同 `分段` 写两条，用标记区分即可（例见 3.1）。

- **`完成任务` 填的是任务id，不是阶段id**：走 `处理对话绑定` → `完成当前阶段(任务id)`，推进的是**该任务当前的阶段**。
- **什么时候算"说完了"**：**按下「回答 / 继续」时**才 `通知对话`（`DialogueUI.按下回答`）。
  旧语义是"这一段刚显示就算完成"，**是错的**：玩家还没回复任务就推进了。
  实测症状：按下「仙人，我准备好了」、21 段文字刚显示，黑幕当场就起了，而回答「好」还没按。
- **「结束」按钮**是 `DialogueUI` 给**没有回答的段落**自动加的（`加按钮("结束", …)`），
  所以「仙人，我准备好了」→「好」→「结束」这三下**都是真实按键**，都能触发接线。
- **两套接线都在 `按下回答()` 里，顺序是先 `处理对话绑定`、再 `通知对话`**
  （前者会把阶段往前推，后者再去比对新的当前阶段，就不会误伤）：

| 接线 | 数据来源 | 作用 |
|---|---|---|
| `通知对话(id)` | 任务表 `对话id` | 完成「条件=对话」的那一阶段（按 id 比对） |
| `处理对话绑定(触发任务, 完成任务)` | 对话表 `触发任务` / `完成任务` 列 | 显式接取/完成某个任务 |

> 相关：多段对话做阶段边界时，`对话id` 填**你希望玩家按下回复的那一段**；同一行**不要**再挂 `完成任务`，否则双重推进。

**其它已经留好的口子：**

- `DialogueUI.当前NPC` / `NpcDialogue.当前对话中`：谁在跟玩家说话（过场、禁移动、禁攻击都能问它）
- `NpcDialogue.请求对话`（静态事件）：按 F 的那一刻广播，剧情系统可以先接一手再让 UI 打开
- `NpcDialogue` 上的 `交互距离 / 看向距离 / 只转头距离 / 最大偏角 / 交互键`：全 NPC 通用，预制体上可单独覆写
- `跳转 0` 收尾：点完根节点 `activeSelf=False`、`当前对话中=null`

## 5. 怎么加一段对话

**第 1 步**：在 `Assets/Data/Tables/对话表.csv` 里加行（字段见第 2 节）。

**第 2 步**：跑菜单 **修仙/从配置表生成资产**（会顺带重建对话库）。

**第 3 步**：确认 NPC 的预制体/实例身上有 `NpcDialogue`（`Assets/resources/NPC/Human/` 下 83 个人类预制体已经全挂好了）。
没挂的：加 `NpcDialogue` 组件即可，它自己在 `Start` 里补一个「F 对话」的 `StationInteractable`。

## 6. 坑与注意

### 6.1 【坑】导入器不会清空单元格

CSV 里把某一格改空、重新导入，旧值会留着（`ApplyRow` 里 `if (!string.IsNullOrEmpty(val))`）。
**改了列内容（尤其变空）后，先删掉 `Assets/Data/Generated/DialogueDefinition/` 再重新生成。**

### 6.2 【坑】同优先时通用段会盖掉专属段

已经改成"专属优先"，但你自己写条件时也要留意 `优先` 别乱设。

### 6.3 【坑】对话资产不在 Resources 下

忘了跑"收集对话资产" → 运行时找不到库，Console 会明确提示，照提示跑菜单即可。

### 6.4 【坑】手改 CSV 的逗号数量

字段数必须和表头一致（空列也要留逗号）。改完用脚本数一遍字段数最稳（本项目就被这个坑过一次：7 行错位）。

### 6.5 【坑】用 pwsh 替换 C# 源码里的中文

会把换行写成字面量 `` `n ``，导致后面的语句被吞进注释（能编译、但整行不生效）。
**改源码用编辑器/编辑工具，别用 shell 拼中文。**

### 6.6 【坑】`NpcInstance.IsDead` 在运行时刚 `Instantiate` 的 NPC 上是 true

（气血还没初始化）—— 判断"能不能对话"别用它。

### 6.7 【坑】挡 AI 转身要挡在 `NpcAiBase.转向()` 源头

只挡 `执行待机` 里的那一次，别的状态照样把身体转过去（实测偏角恒为 0、身体还是转了）。

### 6.8 【坑】调试瞬移玩家会被胶囊挤开

测试里把玩家 `transform.position` 硬设到 NPC 旁边，碰撞会把玩家推走，量出来的偏角是假的。
要么挪 NPC 根节点，要么挑空地。

### 6.9 【坑】NPC 僵在原地、完全没有 idle 动作 ✗→✓

**场景文件里存下来的实例**，Animator 的 playable 是断的 —— `normalizedTime` 在涨、`isInitialized=true`、
`hasBoundPlayables=true`、`weight=1.0`、`cullingMode=AlwaysAnimate`，**但 87 根骨头 0.8 秒内 0 根动、姿势一个字节不变**。
实测对照：同一实例 `Rebind() + Update(0f)` 后 17/87 根动；从预制体**新 Instantiate** 的实例本来就 23/87 根动
→ **预制体没坏，坏的是场景里那份序列化状态**。
修法：启动时补一次 `Animator.Rebind(); Animator.Update(0f);`（`Assets/Scripts/Npc/Npc动画自检.cs`，
`NpcDialogue.Start` 里也会兜一次）。修完复验：**9/9 个村民 14/87 根骨头在动、最大 2.31°**。
注意：这份 idle 本来就**很含蓄**（2° 上下），觉得不够明显就换 `swagger`/`agree` 那种幅度大的当待机。

### 6.10 【坑】点开对话是一块「空白幕布」，或幕布和对话框叠在一起 ✗→✓

`StationInteractor.打开界面` 对**所有**类型都开界面，`界面预制体` 为空时就造一块占位幕布（全屏半透明黑 + 标题），
而且它 `sortingOrder = 2500` 比当时的对话框(900) 高 → **幕布永远盖在对话框上面**；同时 `NpcDialogue`
也在同一帧响应 F → 两个系统抢同一个键，谁先谁后由组件执行顺序（未定义）决定，所以表现忽而是"只有幕布"、
忽而是"幕布 + 对话叠着"。修法三条：

1. `StationInteractor` 遇到 `类型=对话` **不造幕布、也不用界面预制体**，直接回调 `NpcDialogue.打开对话()`
   （漏挂模块的老实例它会补一个）；
2. `NpcDialogue` 在玩家身上有 `StationInteractor` 时**不再自己处理 F** —— 交互器是全项目唯一的 F 入口
   （建筑 `F 炼丹`、NPC `F 对话`、同屏取离根节点更近的）；
3. 对话框画布提到 `2600`（高于幕布 2500、低于暂停菜单 3000），万一两者同时存在也让对话框赢。

实测：走同一条 F 路径后「**没有幕布** ✓、对话框显示 ✓、说话时头顶提示自动让开 ✓、关闭后 `有界面打开` 收回 ✓」，
建筑那条路照旧出幕布 ✓（回归验过）。

### 6.11 【坑】`对话标记` 是静态内存、会跨 Play 会话残留

编辑器里测新流程**先重启 Unity**。存档 v5 起标记会进存档（见 [design/存档系统](存档系统.md)）。

### 6.12 【坑】出场比"该说话的时候"早的 NPC 会弹出默认对话

见 3.4 的门槛与"留一个无标记的兜底入口段"。
