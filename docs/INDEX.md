## 0. 开工三步（每台电脑都要做）

```powershell
git rev-parse --show-toplevel                                   # 1) 仓库根
where.exe git                                                   # 2) git 在哪（免安装，随机器变）
git pull                                                        # 3) 先拉最新
```

- **工程根** = `<仓库根>\cultivation\`（Unity 工程在其下；`<仓库根>` 两台电脑不同，
  所以文档一律用**相对路径**，不写死盘符）
- 引擎：**团结 Tuanjie 2022.3.61t14**（基于 Unity 2022.3），Built-in 渲染管线，**无 asmdef**
- **换新环境永远用 `git clone`，不要下载 zip** —— zip 没有 `.git` 历史，
  重新 `init` 出来的提交与远端没有共同祖先，push 会把整个项目重传一遍

## 3. 数据流：改一处要知道影响哪几层（**最重要的一张图**）

```
① 策划表（唯一真相源，人手改这里）
   cultivation/Assets/Data/Tables/*.csv
            │
            │  菜单：修仙/从配置表生成资产
            │  （DataTableImporter + 各专用导入步骤）
            ▼
② 生成资产（编辑器产物，**不要手改**，会被下一次导入覆盖）
   cultivation/Assets/Data/Generated/<类型名>/<id>.asset
            │
            │  菜单内部自动跟着跑：收集 → Resources
            ▼
③ 运行时库（Resources 下，游戏只读这里）
   cultivation/Assets/resources/任务/任务库.asset
   cultivation/Assets/resources/对话/对话库.asset
            │
            ▼
④ 代码（运行时单例缓存：QuestDatabase.取() / DialogueDatabase.取()）
```

**三条铁律**（都踩过，详见 [ai/踩坑与注意事项](ai/踩坑与注意事项.md)）：

1. **改了表必须重新生成资产**，否则游戏读的还是旧资产 →「明明改了表，游戏里没变化」。
2. **让某字段变空时，必须先删掉对应生成资产再重导** —— 导入器只写非空值，旧值会残留。
   **而且删完要导两次**：删完立刻导，`AssetDatabase` 还没注册完，会写出**空壳资产**
   （字段全空、文件明显变小）。第二次导才正常。
3. **CSV 表头必须在第一行**。往文件开头插入数据行会把表头挤下去，整张表读不出来。

## 4. 协作约定

- **提交只用定向 `git add <具体文件>`，不要 `git add -A`**。
  工作区长期有 1000+ 个引擎重写的 `.mat`/`.prefab`（序列化迁移）噪音，
  `-A` 会把它们一起扫进提交。
- 改完代码：`Uni "refresh"` 触发编译（见 [ai/工程与工具链](ai/工程与工具链.md)）。
- 改完表：跑 `修仙/从配置表生成资产`。
- **做完一件事就更新文档**：机制写进 `design/`，踩的坑写进 `ai/踩坑与注意事项.md`，
  本次做了什么写进工作日志（第 5 轮起写 [ai/工作日志-主线开发-第五轮起](ai/工作日志-主线开发-第五轮起.md)）。
- 编辑器里测新流程**先重启 Unity** —— 对话标记、任务完成状态都是**静态**的，会跨 Play 会话残留。
